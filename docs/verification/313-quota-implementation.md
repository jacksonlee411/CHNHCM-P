## 3 页面、失败与复验

AC072 从正常菜单搜索岗位。管理员保存 2 和 3、查看变更日志和第一次核编原件，取消一次未保存的更正。只读者按 03-31 与 04-01 查得 2 和 3。页面只显示当前已有的核定事实。浏览器另以业务单元表单作参照，在 Chromium 原生 200% 和 400% 缩放下操作。[浏览器场景](../../tests/e2e/staffing313.spec.ts)

- 首轮旧前缀构造保留了新版核编授权，恢复旧约束报 23514。修正测试库重建顺序后重新运行迁移准入。岗位恢复、调部门的样本先后使用了旧合同外的理由值，改用岗位合同中的恢复和重分配原因。
- 按指定日验证停用时，原列表误用当日岗位投影，导致五月合计错误。改用同一业务日的岗位、部门和额度投影，重新验证三个月份及部门变更。
- 首次并存联验在未获字段权时读取旧职类名称失败。复验分两步，核编时保持旧字段权，补登职类前显式赋权。
- 首轮浏览器套件未登记，生产构建未找到用例；首次静态检查也报告浏览器影响清单缺项。补齐运行配置和 CI 文件映射。早期窄屏测试曾在登录后的菜单、历史原因断言或只读日期断言失败。一次失败截图显示只读者仍在列表，列表已显示核定 2。复验等待搜索响应，进入详情核对岗位路径和页签，再查询指定日。
