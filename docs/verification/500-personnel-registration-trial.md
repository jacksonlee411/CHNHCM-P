## 1 实施范围

基线为 `wt-dev-f` 的 `f7d84f192ff518555a60dfe939a78455d8a48597` 和已有 T01 工作区。在「人员 → 员工」登记时，只填姓名即可保存。有主要证件时，只按同一客户内的现用主要证件号码判断是否重复建档。同名可直接办理。经办人手上有带编号的人事登记单时，可以填上登记单号，日后凭同一张单查回原办理结果。[业务规则和样例](../specs/m01/501-person-registration-requirements.md#m01-registration-examples) · [方案评审](500-registration-without-name-prompts.md)

## 2 已有档案

从原 T01 手工验收库只读导出 00026 版备份，在独立 PostgreSQL 数据库恢复，连续执行两次升级。升级前后核对了 12 张表。3 份人员档案、4 个现用和历史人员编号、5 次资料记录、3 个单据引用、5 笔办理结果逐项一致。原档的主要证件号码均为空，登记单号继续保存在原单上。启动新版服务后，凭原提交号或原登记单都能查回原办理结果。[数据库升级](../../db/migrations/00030_person_primary_document.sql) · [恢复与权限实测](../../internal/bootstrap/personnel_restore_integration_test.go)

经办人原有的材料权限只用于登记单。给经办人授予这份档案的证件读写权限后，已在原档补填证件，人员编号沿用原号。再查最初的登记记录，仍能看到原单据和当时的证件填写情况。该轮试办时原手工验收环境运行 00026 版，升级及补证操作都在副本上完成。4380 随后的实际更新见第 5 节。[原环境交接](500-t01-personnel-registration.md#6-默认端口手工验收环境)

## 3 人事试办

在独立验收环境使用虚构资料，从「人员 → 员工 → 登记人员」办理。需要两人操作的情况，分别用两个有登记权限的账号登录。每次保存后回到员工名录核对档案份数。[浏览器办理步骤](../../tests/e2e/personnel.spec.ts)

| 人事怎样办 | 实际办理结果 |
| --- | --- |
| 有两名员工都叫王伟，按各自的身份证号码先后登记。 | 两人都保存成功，分别取得人员编号 `P00000030` 和 `P00000031`。登记时没有同名提示，也没有查询同名人员。回到名录查「王伟」，共有两份档案。 |
| 两位经办人同时录入同一个身份证号码，一人把姓名写成「张敏」，另一人写成「张旻」，同时点保存。 | 一人保存成功，系统提示另一人这个证件号码已经登记。名录里只有一份档案，人员编号为 `P00000032`。 |
| 两位经办人先后收到李娜的同一张人事登记单 `RS-018`，第二位照原单又录了一遍。 | 第一位办成的人员编号为 `P00000033`。第二位看到「这张登记单已办过」和同一个人员编号，两次都能查到第一次的登记记录。名录里只有一份李娜的档案。 |

另外试办了暂缺证件的情况。只填姓名就能登记，随后在原档点「更正资料」补填证件，再办理换证，人员编号始终相同。档案里的证件号码默认遮盖，获授权的经办人可以点「查看完整号码」。
