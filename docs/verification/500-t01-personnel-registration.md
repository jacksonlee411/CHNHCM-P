## 2 十项业务条件

| 条件 | 实际操作与结果 |
| --- | --- |
| AC-001 未任职 | 新表未保存时取消。用新的单人材料登记，不依赖组织、岗位或工作关系。空库首次登记的号码为 P00000001，无联系方式也能保存。经办人从浏览器重登后按号找回。 |
| AC-002 同名与判重 | 两个连接登记同据只得一人，同名不同据需要按最新候选核对。换提交号重送原语义仍指原人，同据换内容拒绝。更正姓名后重送原始内容仍定位原人。并发第二次提交不能沿用已过期的候选结论。 |
| AC-003 范围 | 同名两人可只见一人。跨客户、只有原组织权限、仅遮罩和撤去读权分别验证名录、直达、候选及回执。授予按人和完整字段求值，名录在服务端裁剪后才计数、分页。 |
| AC-004 资料项 | 更新电话后邮箱的值、项标识和修订一致。只改姓名时隐去的两项联系资料保持不变。移除邮箱后当前仅保留原电话，旧原件仍有两项。两个连接改同一项的旧修订仅先到者成功。电话可维护而邮箱只可遮罩读取时，跨类型修改整笔拒绝。 |
| AC-005 改号 | 带客户决定将 P00000001 改为 R-01，原号精确命中同人并标历史号。已截止决定拒绝，争用同一新号至多一人成功。登记来源保有原号。 |
| AC-006 历史与撤权 | 原件和按需展开的前后值使用当前字段权。撤去电话后，原件不返电话行，展开差异为空。只撤写权可确认原办理，失去基本读权时回执不含对象标识。 |
| AC-007 失联 | 经办人的真实登记事务提交后，浏览器丢弃成功回包，通过原提交号恢复。两连接倒置顺序，查回先取得守卫则固定未执行，迟到命令拒绝。故障注入让 Outbox 插入失败，人数、号位、来源、计数器和回执均无部分写入。 |
| AC-008 正常菜单 | 两个角色分别穿过两页同名结果、旧来源及返回，恢复第 21 个对象、第二页、条件和焦点。经办人另走登记、离开保护、更正与保存。视口见第 3 节。 |
| AC-009 到期与保全 | 按北京时间核对截止日边界。真实库将普通和证据期限移过测试时刻，名录和回执随之收缩。指定原件的证据资格只返回相应材料。保全只阻止指定来源类别的处置，解除后重跑清除原值并保留处置记录及号位。 |
| AC-010 容量 | 10000 人，两档真实登录会话、六条 HTTP 链路和独立结果核对。十二组均达 503 的 P95 目标，见第 4 节。 |

可复验的入口为 [Go 领域](../../internal/contexts/personnel/domain/profile_test.go)、[X03 范围](../../internal/contexts/access/public/personnel_test.go)、[DB/API 场景与屏障](../../tests/integration/personnel_test.go)及[浏览器办理](../../tests/e2e/personnel.spec.ts)。

## 5 首次失败与交接

首轮严格 JSON 解码暴露了登记 DTO 内嵌字段问题，改为显式字段并重跑实际登记。浏览器首次跨页返回时页码被回调重置，初次检索也遇到晚到响应覆盖草稿。修正排序分页模型、返回页码和输入初始化后，两角色重走菜单。原生缩放初试的 Playwright 上下文继承了设备比例，显式使用非仿真视口后两档实际缩放通过。旧备份试验首轮用了错误的企业基线开始日期，按旧产品生成的事实修正后从备份完整重跑。新增浏览器套件最初未进入 CI 影响映射，现已登记所属域与参照消费者。

`make check` 通过，包含 137 个 Python 脚本用例、文档及资产检查、Go 导入边界、31 个运行脚本测试、Go 单元、vet、前端类型和差异检查。另行执行旧账本准入、地点及岗位迁移等七项真实库回归。`make ci-preflight` 通过，两项旧库准入测试及八个既有浏览器场景实际执行，覆盖企业、授权、职务和职级。用临时索引将新增文件及既有 T00 工作一并纳入差异检查，共 63 个文件。

自建的 t01-acceptance-f Web、API、数据库、卷、网络及仓外临时备份均已回收。再次执行临时 profile 回收时返回已不存在。其余固定验收环境由原责任工作树保留。
