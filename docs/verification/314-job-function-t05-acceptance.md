# CHNHCM-314 T05 职类分层验收与交接

## 1 候选与执行范围

在固定工作树 wt-dev-b 的 `1a9699dff3b57434afe6de9f236430dc26b7480b` 和开工时已有的 T04 改动上执行。开工时分支领先本地远端跟踪分支三次提交，stash 为空。业务预期取自 [308 第 14 节](../specs/m03/308-job-foundation-contract.md#m03-job-function)和 [314 计划第 4、5 节](../plans/314-m03-job-function-roadmap.md)。本轮使用仓内构建的 Go 服务、真实 PostgreSQL 和 Chromium，保存产品输入、API 二进制及 Web 产物的 SHA-256。角色走查从登录和正常菜单进入。部分前置资料由 API 建立。跨升级下载专项在浏览器中恢复旧会话及其已保存的草稿引用。

## 2 两个角色的页面与受影响业务

职务管理员先在职类目录新建管理类，再进入职务新建表单，选该职类及人力资源系列并保存。从 API 核对职务保存后的职类、系列身份。创建同系列的另一份职务后，查询者先按系列找出两份，再加职类只剩目标经理。核对服务端唯一成员、详情位置和返回列表后的键盘焦点。[跨菜单用例](../../tests/e2e/staffing314.spec.ts)

七组视口按[共享页面合同](../specs/m02/012-m02-functional-and-interaction-design.md#m02-ui-viewport-matrix)执行。职务系列用作页面样板，核对顶栏、操作区、页面滚动、表单标签和输入布局。管理员实际执行字段错误、继续编辑、放弃修改、新建和保存。查询者执行按权查看、准确来源和返回。日期轴、来源日志和恢复操作见[共用菜单旅程](../../tests/e2e/staffing308-journey.ts)。

## 3 按合同复核

| 验收项 | 本轮核对的业务事实 |
| --- | --- |
| AC082 目录 | 首建默认 1900-01-01，未来更名按日读取，取消更正后来源版本相同。管理员新建管理类与专业类，同码在不同目录成立，同一目录拒绝重码并定位字段。只读者查询与下载后直接提交返回 403。 |
| AC083 双维 | 三份职务依次按管理类、追加人力资源、取消修改、清除职类，桌面与窄屏的命中数均为 2、1、1、2。单换一维后另一维原采用完整。 |
| AC084 存量 | 核对 2027-03-31 未登记、04-01 补登、07-01 原独立记录未登记。重启后核对原岗位采用、来源、修订与四条旧日志。 |
| AC085 恢复 | 固定期间停用和恢复采用各自日期的分类。移动停用端保留恢复端的两份原采用，有限资格覆盖不了开放恢复段时整笔拒绝。 |
| AC086 回退 | 移动未登记边界后五月变为管理类，删除已登记节点可回退未登记，两案均检验字段权和原件。 |
| AC087 竞争 | PostgreSQL 双连接交换首次采用和停用次序，另一笔冲突时无业务写入。对调两职务分类后身份与采用逐份相符，隐藏未来引用继续受保护。 |
| AC088 投影 | 一页同时展示未登记、可见、受限，查未登记只命中第一份。字段撤权后投影裁剪，受限成员入选时整次导出返回 403。 |
| AC089 页面与查回 | 两种选择顺序均能保存，缺另一维读权仍可办理本维。恢复端撤掉过期候选，迟到响应无法改回。取消零写，丢响应后按原号查回一次写入。 |
| AC091 旧记录 | 旧未登记首条改日、旧停用改启用和仅更正职责区分处理。对显式回送、异值、清空分别检查 403 或字段 400。 |
| AC092 企业起日 | 已停用且无引用的职类仍限制企业首日。两连接互换先后验证下界，跨域读取故障时保持原事实。 |
| AC093 跨升级 | 原主体从原写入地址重送与 resolve 查回得到同一终态，同号异载荷 409，新号缺职类 400。原八列文件逐字节相同，原选择经页面重导九列，保留第四列职务系列、原排除与成员。 |

## 5 评审、首次失败与复验

本轮样本由原版程序在本机重新建立。维护方保存的 T01 私有备份位于另一台机器。跨升级验证按本轮旧身份、旧提交、备份摘要及原选择核对，另与仓内旧下载原件逐字节比较。历史 T03 演练沿用默认目标 00025，本轮显式指定 00026 及其单一管理汇报存储合同。

之前的建类、职务保存、组合筛选各有专项。本轮新增连续业务用例，将管理员新建的职类身份带入职务，换成只读者核对交集成员，并断言从详情返回后名称链接确实获得键盘焦点。评审还发现原 T03 演练绑定首次留样的私有身份、文件目录和 00025 的存储合同。本轮增加显式重建样本和目标版本参数，对照 T01 已登记的八列文件及分类型事实数量，再按实际捕获的原件逐行比较。原版样本和默认 00025 判据保留。[升级演练](https://github.com/jacksonlee411/CHNHCM/blob/061d28105966bd10eb1e3b0032cf2976a6448de4/docs/verification/data/314-job-function-t03/upgrade.py)

升级演练首次启动时，临时 profile 还在导入地理目录，生命周期锁拒绝第二次操作。等待该 profile 的 API 就绪后顺序重跑。两份升级库分别核对 10 项旧依据和 44 行原事实、17 项旧依据和 73 行原事实。两次都在切换末尾注入中断，核对事务回滚，再重试并重建读索引。原 00022、00023 来自 `7673aed5`、`94e9aefb`，00024 来自 `48e84fc7`。本轮端到端下载与登记的八列文件 SHA-256 一致。

真实库专项以 `GOFLAGS` 的 `-run` 限定 `make integration` 的范围，覆盖 307、308、309、310、312、314 和管理汇报迁移，27 项顶层用例通过。另以 `CHNHCM_STAFFING308_CLOCK_BROWSER=1` 单跑固定时钟浏览器，核对系列和职务的北京时间、原时刻及新建默认日期。业务回归覆盖职务可用职级的集合写入及采用、岗位原采用和企业日期下界。
