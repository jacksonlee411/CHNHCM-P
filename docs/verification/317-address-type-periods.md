# CHNHCM-317 地址类型单个启用区间实施与验证

## 1 实施范围与影响

以默认分支 `8b1f1c9` 的 00061 交付为基线。配置维护人从「设置 → 人员配置 → 地址类型」操作，人事从员工个人资料的地址行选用。日期维护、身份、修订和选用资格由 M01 负责。采用日期继续取服务端当次北京业务日。[316 模型规范](../architecture/316-object-and-configuration-models.md#selection-date) · [505 对象合同](../specs/m01/505-personal-profile-contract.md#profile-address-types)

| 受影响的环节 | 实施结果 |
| --- | --- |
| 配置详情 | 共享详情、状态、日期导航和表单。支持首次生效、预排停用、更正日期或撤销误停。选择时间轴上的日期显示该日资格，变更日志查看当时的资料与停用安排。 |
| 配置与旧数据 | 00062 保存单项半开区间。旧项从升级当日建立可核实的资格，旧停选继续生效，旧停用日留空。首日和停用日相同形成空区间。原修订和回执按原身份查回。 |
| 员工地址 | 候选按当前实例和办理日直接筛选当前项。新采用在原人员事务中持锁复核，停用或修订过期时保留草稿重选。更正其他字段保留原名、修订和采用日。 |
| 权限及接口 | 原配置读权和维护权分别核验，个人资料行权继续由原办理入口核验。新详情按项读取，确切修订按需读取。旧接口标志映射到即时维护，改名沿用原停用安排。 |
| 部署与资源 | 新数据库账本由 upgrader 迁移，再启动对应 API 与 Web。日期到达后按区间查询生效，配置项和员工资料无需定时改写。单项更正写当前项与一个不可变修订。 |

## 2 评审与复验

第一轮对照旧客户、旧回执和原选用合同，区分首日、可核实起点、停用日和操作时刻。第二轮从普通用户菜单和事务锁重新核对，覆盖首次与停用同日、未来停用当天的边界、撤销误停、保留原采用、同一提交重送及撤权。旧客户的实际 00061 请求摘要经 HTTP 重送与查回取得同一原回执，在原项上更正后仍能查看上一次停选。更正后的时间轴表示当前解释，原停用安排可通过同项的上一条不可变修订查回。

实库覆盖 00058 和 00061 升级、真实 PostgreSQL 与 HTTP 授权、并发与回滚。00061 的合成实例有四项和五份旧修订，迁移后旧修订原业务列、行版本与回执摘要保持一致。时间轴与原采用的独立预期见[数据库与 API 用例](../../tests/integration/personnel_address_type_test.go)、[旧库样本](../../internal/bootstrap/person_address_type_upgrade_integration_test.go)及[日期边界用例](../../internal/contexts/personnel/domain/address_type_period_test.go)。

## 3 浏览器、生成检查与现场交接

从正常菜单在 1440×900、1440×540 和原生 200% 对照同一构建的业务单元表单，三种条件均走完新增、取消、预排停用、日期轴、员工整页保存、门牌更正和撤回误停。名称输入实测为 14 px，标签为 13 px，输入区域高 32 px。误停更正后可从变更日志查回此前的停用日。专项使用真实 API、PostgreSQL 和 Chromium，住址的国家按合同使用手工原文。[浏览器用例](../../tests/e2e/personnel-address-types.spec.ts)

首轮预检发现三个 sqlc 包仍描述 00061 的字段，运行 `make generate` 后与干净副本逐文件一致。浏览器初轮把必填星号计入文本标签，复验又在页面切换时定位到同名列表表头。改为等候新增页面并按输入控件的可访问角色、名称定位，三项实操通过。运行脚本的一项 IPv6/IPv4 端口断言曾失败，单跑该组 20 项以及复跑 `make check` 均通过。升级前置两项与跨模块浏览器前置 11 项均实跑通过。修订测试期间的预检报告由候选一致性检查标为变化，最终提交单独核对。

个人资料固定环境为 `m01-profile-current-d`，Web 45317、API 45318、DB 48317。更新前按原卷备份完整数据库与固定构建，私有备份目录名为 `periods-before-62-6cuxafs7`。00062 升级前后按整组行值和条数比对，27 个人员来源、33 个办理终态、20 行资料内容、23 个配置修订、11 个配置身份及其头修订、配置未执行回执和人员授权七组相等。对账在新增本轮验收样本前完成。

固定 API 构建摘要前 16 位为 `bac43c3cb83a4cfb`，Web 入口为 `ba9387d5d8a23b72`。管理员在「设置 → 人员配置 → 地址类型」建立「预排停用地址（验收）」，查看 2030-01-01 的停用节点并查回上一次修订。原「宿舍地址（验收）」及其旧修订可读，管理员和 reader 在「人员」菜单复查「地址类型验收样本」的原住址，reader 直查配置详情返回 403。保留 45317 供用户验收，由 wt-dev-d 在下次更新或验收结束时复查。样本自 2030-01-01 起停止新选。[样本详情](http://127.0.0.1:45317/settings/personnel/address-types/aa7a2ee9-3ccf-4b33-b4e1-151a2bbc6270) · [员工名录](http://127.0.0.1:45317/personnel/employees)

## 4 容量与维护成本

沿用 317 的万名员工、二十份九栏样本，每条链路在 1 和 20 会话下各取 200 个样本。正式测量与本次浏览器、固定 Web 构建分时执行。8 组共 1600 个样本、3200 次 HTTP 请求，错误和超时均为零。以下为同一用例的 P95，单位为毫秒。此前主线样本保留作比较，各轮主机负载可有差异。[各轮容量明细](data/317-person-address-types/capacity.csv) · [测量用例](../../tests/integration/personnel_nine_sections_capacity_test.go)

| 链路 | 此前主线 20 会话 | 单区间 1 会话 | 单区间 20 会话 |
| --- | ---: | ---: | ---: |
| 九栏详情 | 310.87 | 29.51 | 234.76 |
| 保留原类型，更正、查回、重读 | 1383.20 | 101.46 | 954.62 |
| 地址行可选类型 | 153.25 | 20.78 | 85.79 |
| 改选类型，更正、查回、重读 | 1321.42 | 91.84 | 949.07 |

20 会话四条链路均在临时上限 1500 ms 内。候选查询直接过滤当前项，锁等待峰值为 0。两条整页写链路的锁等待峰值均为 11。管理员在详情通过一次保存安排停用或更正误停。到期后区间查询直接排除该项，历史员工行无需重写。

## 5 与薪酬主线合并后的复验

首个候选 `f36b873` 的质量、集成和浏览器检查全部通过。合入前默认分支更新到 `f7b47b9`，已包含 00059、00060 两项薪酬迁移。整合后的设置导航保留了薪酬配置、人员配置及地址类型子页面。API 和 Worker 在连续 00001 至 00062 上运行。升级器同时支持个人资料库补齐薪酬迁移、薪酬库补入地址类型和完整 00061 主线库增加区间。[首轮远程检查](https://github.com/jacksonlee411/CHNHCM-P/actions/runs/46120589635) · [迁移账本](../../db/migrations/README.md)

六种实库起点逐一升级两次，原账本逐行保留，第二次执行没有新增迁移行。覆盖已装 00061 或 00062 的旧个人资料库、两者在补完 00059 后的续跑、连续至 00060 的薪酬库及连续至 00061 的主线库。旧回执、地址候选、权限、保存与更正复验通过。三种视口也重新走完地址类型及员工整页流程。本机并行构建时，既有组织长时间轴取消测试首次耗时 1.08 秒，超过 1 秒预算。单独连续运行三次，以及重新运行完整 `make check` 均通过。[六种迁移路径](../../internal/bootstrap/t07_storage_admission_integration_test.go) · [地址类型旧修订与回执](../../internal/bootstrap/person_address_type_upgrade_integration_test.go)
