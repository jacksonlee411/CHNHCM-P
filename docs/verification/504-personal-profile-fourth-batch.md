## 4 九栏容量

每档在万人合成底库中使用预先选定的 20 人，每人七个集合各两条，另有基本信息和健康摘要。1 会话和 20 会话各从独立的同种底库开始。每条链路先预热 20 次，再计时 200 次。整页链路一次修改九栏，提交后按提交号查回再读当前详情。断言依据预置人员号、样本轮次和保留行，另验旧来源、遮罩及受限读者。第 190 个成功观测值为 P95。[容量用例](../../tests/integration/personnel_nine_sections_capacity_test.go) · [503 测量合同](../specs/m01/503-person-registration-design.md#m01-capacity)

## 7 多轮复评

仅授某人的账号遮罩读权时，原实现还要求银行名称读权，导致整栏消失。修正后，经办页面和单项 API 均可只返回固定遮罩，单行所有可读字段被拒时，条数随该行一并扣除。关闭明文后再次点开会重新核权。等候响应期间以及撤权后都不展示旧号码。

在 PostgreSQL 中锁住客户健康用途政策，再让详情请求等到主体健康读权到期。修复前该请求仍返回摘要。改为取得政策锁后取时，详情只返回仍获权的字段。另已核对主要标记含首尾空格时的切换及旧主写权，任何受影响行缺权都使整笔回滚。

同银行的账号冲突现定位到本次录入的行和字段，保留同页其他草稿。把账号改回原值可以直接按 Escape 返回。健康字段校验错误时，焦点移到摘要输入框。“更正资料”放在异步载入的入职操作之前，两个入口仍在详情控制栏。

首轮浏览器回归有两项失败，分别涉及延迟请求测试重复放行以及详情入口的位置变化。修正后，固定 Chromium 全部 29 项通过，含 22 项 504 场景和两项窄屏首单入职回归。相关 DB/API 回归及 `make check` 均通过。此次复用第 2 节的连续升级和第 4 节的万人容量实测。

4386 已更新到复评构建，清单 SHA-256 为 `f03d6ac9025e8ea9a0a088158a875a09219f9b119583db649cad65bf789a6802`。经办人从员工名录打开原样本，输入与乙账户相同的银行及号码，同时更改健康摘要。保存被拒后，焦点落在甲行账号上，修正输入后健康草稿仍在。取消后重读，整份资料及第 5 节的头版本一致。普通读者从同一入口查看，页面和 API 均隐藏银行与健康栏目。末轮未发现新增主要问题。
