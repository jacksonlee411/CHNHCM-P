## 3 多轮评审及实际结果

第一轮沿普通管理员保存企业通用单项计划，分别以零元、缺范围、重复编码、相同提交号和基于旧版再次保存办理。核对 PostgreSQL 中新政策与计划修订同时提交或同时回滚。单纯改名时原金额保留，显式清除受限金额整笔拒绝。首次漏填范围方式被请求解码器提前作为 400 拒绝，调整后由 X02 定位范围字段并返回 422。

第二轮办理 PRO-M、OPS-M、MGT-Y，按六月、七月、十月分别从计划重查制度。验证七月薪带撤去后当日适用与原采用可分别追溯。另一项单独反例在年标 180,000.04 元下核对精确百分比及半分舍入。正在使用薪标的计划须全部结束相应期间的引用。[共享与比例联验](../../internal/bootstrap/compensation_plan_integration_test.go)

第三轮从真实法律实体和职务系列验证各维度允许和排除，检查三月停用、四月恢复形成的期间缺口及授权收窄。首测误从职务系列回执读取记录身份，改由实际时间轴定位后通过。只获计划维护与薪标引用权的管理员可选 P4、P5 两个职级并保存，查看标准、原版和关联金额均按各自授权裁剪。未获引用权时，既有标准和不存在的身份得到相同拒绝。候选和保存统一核对精度等必需字段，表单仅列获权的来源维度。[范围与职级映射](../../internal/bootstrap/compensation_plan_integration_test.go) · [X02 匹配](../../internal/contexts/configuration/application/applicability_test.go)

第四轮用只获计划组成和固定额维护权的经办人更正津贴。发现更正不涉及薪标的津贴也重读了引用授权。已按生效期间、范围及实际费率映射判定何时重新采用标准。实库复验在撤去薪标引用权后能将津贴 300.00 更正为 325.00，保留基本工资的准确原采用，新增引用仍拒绝。

## 5 验证范围与首败

在 PostgreSQL 18.6 和真实 Go HTTP 会话上执行四个计划专项，分别覆盖企业通用及字段权限、共享薪标与原采用、指定范围与来源缺口、多职级及仅引用权限。四项均通过。薪标、计划、旧迁移升级与中断恢复另以 `make integration` 的受影响用例复验。范围、金额、角色的独立预期按 211 核对。[实库/API 用例](../../internal/bootstrap/compensation_plan_integration_test.go) · [薪标回归](../../internal/bootstrap/compensation_grade_rate_integration_test.go)

桌面和短屏均从实际菜单建单项津贴，并验证十月调整、行中取消、更正前后原件及返回搜索。原生 200% 用键盘提交组成并保存。计划并发时，第一页保留经办人输入的说明，重新读取另一名管理员保存的新名称；丢失响应后按原提交号返回同一修订。首轮五项中年计划用例超时，原因是驱动在已收起的候选菜单再次按 Escape，误关了组成项表单。改为等待候选菜单自行收起；固定环境另以查询账号实际验证年标原件和返回焦点。随后补验从尚未确认的组成草稿使用浏览器后退时可继续编辑，直接取消该行可以放弃其草稿。[浏览器用例](../../tests/e2e/compensation-plans210.spec.ts)

复验生产构建的五项 Chromium 场景全部通过，共 1.1 分钟。修订后的组成暂存、取消、离开保护和原件返回均用实际页面验证。固定库复查得到 2 份标准、3 个薪标生效段、3 份计划、4 个计划生效段、3 份显式范围版本。经本阶段多轮评审，已测范围内没有新增主要问题。

阶段检验使用 `make docs`、`make boundaries`、`make check`、真实 DB/API 分片及生产构建 Chromium。两类对象的联合容量、八组场景的逐项交接归 I3。固定环境供业务经办人继续验收，人工签收单独记录。

I1 合并请求的首次远程浏览器运行另有两个人事调动原件场景超时。取 I1 精确提交 `266496c` 的独立检出、独立生产构建和临时库，复跑「按岗位调入并更正原岗 1440×900」及「同日对调两个满编岗 1440×540」，两项均通过，共 38.6 秒；临时库、容器及网络已回收。远程结果以该提交的实际运行记录为准。[I1 运行记录](https://github.com/jacksonlee411/CHNHCM-P/actions/runs/46006996046)
