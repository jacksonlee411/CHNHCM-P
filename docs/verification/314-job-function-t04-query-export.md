## 2 业务操作与判据

| 验收 | 角色、路径与核对方法 |
| --- | --- |
| AC083 | 管理员从「设置 → 职务配置 → 职务」进入。三份职务分别为人力资源经理（管理类、人力资源）、人力资源专员（专业类、人力资源）、财务经理（管理类、财务）。桌面从对应表头、窄屏从更多操作进入，应用职类、追加系列、取消改筛选、只清除职类，命中 2、1、1、2。交集唯一成员为人力资源经理。从详情返回原行，在剩余两份职务之间前后切换。再在交集上全选，从菜单下载并逐列比较。 |
| AC088 | 旧库当前三份资料分别为真实未登记、已登记可见、已登记且因未来首条缺历史读权而受限。真实页面同时检查三行，查“未登记职类”仅命中 J01。API 将职类或未登记与系列取交集，复核固定选择和导出。已登记受限者入选时整次拒绝。单撤 Job 字段权后列表裁剪分类，查未登记返回 403。另从正常变更日志打开封存来源，撤职类历史读权后核对标签与日志差异。 |
| AC089 | 正常新建分别先选职类、先选系列，再保存。更正时单换一维，按封存来源核对另一维原采用。撤系列读取权仍可选择和保存合格职类。固定恢复端修改拟日期，在真实 API 已返回后延迟向页面传回旧响应，核对候选和其他输入。取消后以来源版本核对零写入。另在服务端已提交后断开保存响应，由页面用原号查回，核对一次写入、一次查回及两条日志（含新建）。 |
| AC093 导出 | 原版 API 捕获 J01、J02，排除 J02 后新增 J03，保存当时的八列文件、原会话和草稿修订。切换到候选版本，从原会话恢复同一草稿，实际点击页面导出。逐字节对照浏览器与 API 的新下载，逐列核对八列原件及新增的第九列。第四列为人力资源，第九列为空，唯一成员为 J01。撤去职类列权后重新导出返回 403。 |

## 4 评审与首次失败

- 复核过滤路径时发现，按裸 ID 比较可能通过未来首条推知已受限的采用。现在 Go 在同一查询快照按实际显示日核验历史权，列表、导航和选择共用该判断。未登记来自逐条校验过的旧依据。
- 复核候选时发现，搜索匹配为空或历史权撤回后，组件可能保留上次的候选名称。现在 Go 独立复核本维的已选项，搜索或翻页不改变核验范围，失去资格时不给出旧名。数据库/API 专项覆盖可选但搜索无结果、撤历史权及撤目录权。
- 第一次演练未先建仓外空目录，第二次临时 profile 仍在初始化、持有生命周期锁。按实际就绪状态顺序重试。首次升级后建目录返回 403，核对为原管理员尚无新目录动作。演练用本地初始化配置测试管理员，再显式授权所需职类字段。
- 首次桌面和窄屏撤权操作同时出现查询和原选择两条提示，测试把两条提示当成一个元素。复验按具体查询提示定位。固定恢复弹窗复验中等待子弹窗退出后再点外层取消，并等只读来源页呈现后核对历史名称。首次失败和复验均按各自运行记录。
- 固定时钟浏览器用例默认跳过。显式启动后，旧测试在 1984 年开始的企业创建 1900 年启用的职类，返回 409。将该用例的职类起日设为企业首日，再次运行通过，系列与职务页面都展示北京时间并保留原始时间。新建表单仍默认 1900-01-01。
- 文档检查首次指出验证报告缺少入口。补入总入口及验证索引并复查。
