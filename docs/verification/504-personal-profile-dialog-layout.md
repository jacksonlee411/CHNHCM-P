## 2 实测方法与结果

从七栏分别打开已有行，进入整页编辑后从「添加一行」和原行编辑入口打开另两种弹框。逐个读取标题、字段框、标签和值、正文滚动区及按钮的实际矩形，按显示位置重建行列。七栏有 21 个基本组合。再区分证件和凭证有期限或长期有效、电话或电子邮箱、三种教育记录，共 12 种字段排列，每种都测了查看、新增、编辑。有重复布局的预置行保留为独立样例。

| 浏览器条件 | 范围与观察 |
| --- | --- |
| 100% 的五个视口 | 40 个样例各测 1440×900、1440×540、390×844、320×900、320×256，共 200 组。桌面弹框最大宽 900，窄屏全屏。另对教育查看窗收窄并回查边界，599 宽时全屏单列，600 宽时弹框宽 536、居中双列。 |
| 原生 200%、400% | 在独立 X 显示器中启动有界面 Chromium，100% 内容校准为 1280×900，外框为 1280×987。用浏览器原生 Ctrl 加号放大、Ctrl+0 恢复。相同 40 个样例各测两档，外框固定，实际内容分别为 640×450 和 320×225，对应双列与全屏单列。 |
| 操作区与末字段 | 查看窗标题右上和底部右侧均可关闭。新增、编辑窗底部先「取消」后「应用」，窄屏的草稿提示在按钮上一行。320×256 编辑学习经历时，滚轮使正文从 0 滚至 646，末项完整可见。标题顶边和底栏顶边保持在 0、168，Tab 依次到达取消和应用。 |

首轮采集因新增按钮的可访问名称未被精确匹配而中断。调整到本栏的实际添加入口后，第二轮在改过渠道的草稿上遇到放弃确认。按正常流程选择「放弃本条修改」后重跑全组。最终对 280 组矩形逐项核对，505 的桌面左右配对、窄屏顺序、标题、操作顺序及可适用的动态字段均与实测相符。对勾选长期有效、切换教育记录类型后的布局另按相应字段排列校验。[实测样例与尺寸](data/504-personal-profile/dialog-layout.json) · [505 弹框对照表](../specs/m01/505-personal-profile-contract.md#profile-dialog-layout)

## 3 审阅结论与交付范围

Codex 主代理复核了两处容易误验的情形。相同的教育字段若调换左右位置，020 应失败。隐藏截止日期后，「长期有效」须移到末行左格。另按 505 保留字段授权、遮罩以及指定现用主要证件的能力，将指定或撤下主要证件安排在整页草稿的证件行。504 已排定四批分别验收本批弹框，第四批核齐 21 个组合及其适用变体。本次接受的是修订后的方案与合同。[020 产品验收条件](../specs/m01/505-personal-profile-contract.md#m01-ac-020) · [504 分批安排](../plans/504-personal-profile-extension.md#3-实施顺序与责任)

在内存副本中，故意交换「学位授予日期／最高学位」和「签发机关／签发日期」，两处均被字段位置比对发现。复算原审定稿及既有证据摘要通过。`make docs` 通过 137 项脚本测试和 431 份 Markdown 的仓库检查。用临时索引连同原有未跟踪文件检查本批 14 个文件的完整差异，空白检查通过。
