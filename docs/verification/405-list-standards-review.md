## 3 业务复验

| 入口与用例 | 本次实测 |
| --- | --- |
| 4496 管理员，Chromium 140.0.7339.186，1440×900 | 从正常菜单分别进入部门和人员，两页树宽均为 220 px，节点均为 28 px。人员名录有 6 份在任、3 份尚未生效，其中有 4 条在任主岗和 3 条未来主岗。按示例编号 P00000006 查得三份任职，职务均为客户服务专员，0、1、2 号岗位依次为「—」、服务值班岗、服务质检岗。分别隐藏和恢复职务、岗位时，另一列仍可见，查询编号保持。 |
| 4496 管理员及资料读者，1440×540 和原生 200% | 两个视口均从菜单操作。四级部门含下级为 3 份、直属为 1 份、含下级限兼岗为 2 份，均为 1 人。全选两行、排除一行和键盘返回均通过。短屏控制区高 64 px。原生放大后实测 640×450 CSS px，使用树抽屉与通用列筛选。读者从失效书签重查，得到 1 条档案行、0 份任职。[可复跑脚本](data/405-personnel-directory/verify.cjs) |
| 独立 PostgreSQL，Go 集成用例 | `TestPersonnelDirectorySelectionMembership` 通过。21 条匹配行跨页全选、排除和排序后数量正确，成员总数仍为 21 但更换一人时旧勾选归零。仅叶子有任职的五级链按祖先含下级查询得 1 条，直属为 0 条。收回上级关系读权后原祖先查询为 0，返回节点中也没有该祖先。[实库用例](../../internal/bootstrap/personnel_directory_selection_integration_test.go) |
| 临时环境，从人员、部门和业务单元菜单复验 | 7 项通过。按同号查人员的五级树用例核对直属 0 号、两个同级部门各自的 1、2 号、勾选与原行返回及资料读者。另验名录延迟响应与跨页选择、部门树选择与返回、部门捕获成员后再新增、业务单元搜索草稿与列显隐恢复。[人员用例](../../tests/e2e/first-hire.spec.ts) · [部门树](../../tests/e2e/department-tree300.spec.ts) · [部门固定选择](../../tests/e2e/department-selection-races.spec.ts) · [业务单元](../../tests/e2e/community-list.spec.ts) |
| 人员查询两种失败的恢复 | 在独立库登记合成人员，分别在申请查询引用和读取名录这两步向当前浏览器返回一次 503。两次失败时均没有旧行或零结果提示。再输入新草稿后点击重试，第一种重发原关键词，第二种按原引用重读并且新增引用数为零。两次都查回本人并保留新草稿。专项 1 项通过。[重试用例](../../tests/e2e/first-hire.spec.ts) |

首轮浏览器回归 5 项中 4 项通过。五级树用例在点击「含子部门」的同一时刻断言勾选状态，查询尚未返回，Playwright 报勾选状态未改变。在 4496 复现这一断言后，将用例修订为先等部门范围生效，正常点击，待查询返回再同时断言复选框和实际行。固定页再走直属、两个叶子和返回原行通过。临时 profile `p405-list-standards` 复跑上述 7 项全部通过。此次冒烟使用原有的未来任职数据覆盖即将生效的分支，固定环境另验当日在任的三份样本。
