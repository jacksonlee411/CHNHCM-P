# CHNHCM-214 员工薪酬页签与基本月薪实施验证

员工详情的「职务信息」和「薪酬」并列。人员名录一行对应一份任期。薪酬经办人和查询者从同一个任期进入，分别按个人工资、制度来源、历史和办理权限取数。[业务方案](../specs/m09/215-assignment-base-pay.md) · [技术合同](../specs/m09/216-assignment-base-pay-contract.md) · [方案复核](214-assignment-base-pay-design-review.md)

## 1 实库核定和权限

基线为 `a07582923dbd308870322c5913289cad72d99aae`。真实 PostgreSQL、生产 Go 路由、会话、权限、计划及薪标共同参与。两名登录会话在同一任期、同一基准上争办首次定薪，一笔成功，另一笔收到版本冲突。十一月试填 15,500、十二月试填 16,250、空额和三位小数均被拒绝。十一月原笔 12,100 更正到 12,000，十二月查见原个人额和新薪带，一月另立 13,000 的决定。十二月插入及撤去后，原笔与独立后继仍各自可查。

仅有指定兼岗读权的查询者打开主岗详情、原件及提交号均得到不可用。一个月薪决定生效后再变更其原日薪标，旧草稿保存遇到来源冲突。已办原件保留当时上限。退出之后查询旧任职得到无有效任职，再聘沿用 0 号但使用新任期，初始尚未定薪。另撤来源原件权仍可查获权个人金额；撤去个人读权后，原号和原件一并不可用。[实库 HTTP 用例](../../internal/bootstrap/compensation_award_integration_test.go)

主动查原号时，服务端用与写入相同的锁确认是否已执行。若服务端确认未办理，迟到的旧包被阻止，原申请者须凭确认身份重送同一规范化输入；同号异内容被拒绝。确认后的重复重送只产生一份原回执。一次小样本测量包含一份获权任期、两份合格计划、五个有效段，一会话连续十次查询用时 1.42 秒。竞争用例另以两会话执行。此处只记录该样本。
