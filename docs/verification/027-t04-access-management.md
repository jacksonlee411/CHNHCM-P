## 3 数据库、API 与历史

- **账号及受控恢复。** 并发两次相同引导只产生一份资格，另一内容不能复用该提交。开户后新主体未获业务许可。重置后两个原会话均为 401，原口令失效。停用、显式启用、交接及恢复均复查实际登录与历史中的原操作者。过期的接替请求不能替换现任。旧部署停用命令也保护现任管理员。在没有启动 API 的隔离库中运行实际 upgrader，应用库身份引导失败。部署库身份依次完成引导、恢复及交接。未换凭据的引导仍保留旧初始化的口令核对。
- **委派及共享版本。** 使用甲乙两 BU、独立管理上限和两个获管账号。根管理员的业务权为空。按动作、归属、业务目标、字段、用途和代理期限检查委派，全体受影响授予含待生效项。分别停用角色、范围、字段版本时有一个跨归属引用即拒绝。撤回可管理的单份继续保留重叠授权。发布新版本不扩权，显式采用只变更所选一份。
- **提交顺序及查回。** 在另一真实连接阻塞开户的实际写入，等委派期限届满才释放锁。收到 403，数据库没有生成账号。凭据重置另行委派，对权限超出上限的既有主体予以拒绝。回执依原操作者及当前管理权读取，仅返回办理状态和定位。原号尚未受理时，查明结果与迟到提交串行，防止二次执行。
- **存量升级。** 从公共 00058 的开发只读主体撤销部门读取。升级中途注入对象冲突，检查表、列和账本整体回滚。移走测试冲突，连续执行两次正常升级并重走初始化。对账逐行涵盖主体、凭据、策略守卫、策略版本、授予及修订、安全事件、有效授权，原部门权仍为空、BU 读权仍在。旧主体不自动取得管理资格，也不推断 BU 归属。[四组真实 DB/API 回归](../../internal/bootstrap/access_management_integration_test.go) · [Go 权限上限](../../internal/contexts/access/application/management.go)

## 4 多轮评审与复验

首轮从账号、角色和授权的正常菜单核对请求、可见字段和保存结果。第二轮用跨 BU 授予、两个数据库连接和部署身份核对越界、等待中失权及恢复。末轮回到正式构建，复验原失败输入、浏览器办理、隔离旧库升级和保留数据的 4627 实例。

| 问题及影响 | 整改与复验 |
| --- | --- |
| 接口形状校验把 RFC3339 截止时刻当对象。代理申请的日期格式正确，越界用例本应在核权后返回 403，却提前收到 400 | 按时间的 JSON 表示解析。复验有效代理、超过上限、未来生效引用及在锁等待中到期 |
| 新开户后读详情把空对象 ID 放进 UUID 数组，已受理操作的页面无法定位 | 仅查询当前可见的有效目标。通过实际浏览器在服务端保存后丢失响应，查回唯一账号 |
| 浏览器在短屏切页时可能输入仍在卸载的列表控件，原生缩放夹具也遇到 X 服务尚未就绪及 Playwright 上下文参数冲突 | 定位当前对象表单，对 X 服务就绪设超时，原生窗口采用无模拟视口。两种桌面视口和原生 200% 分别复验 |
| 旧库准入测试还原 00057 时，新管理表仍引用策略版本，无法复建原前置 | 仅在用例自建容器中按依赖移走后加结构，并把前置限定到 00057。国家迁移和准确账本两项前置复验通过 |
| 存储保护的初版把 BEFORE 触发器中尚未计算的生成列纳入比较，合法撤销管理职责被拒绝 | 逐项保护主体、职责、策略、期限及上限，仅放行首次撤销。通过独立受托账号和实际数据库事务复验 |
| 管理员可能在等锁时失权，或者将账号转入自己不能管理的归属。发布角色也可能改变建议策略 | 在事务结束前复核实际使用的委派期限，账号移交双向核权。原授予保留原策略定义，采用只允许选择同一策略系列。变更历史按当前权限显示原归属及新归属 |
| 两个真实数据库连接记录的时刻发生倒序，按时刻排列把早先的启用排在后续恢复前 | 同一实例管理写入已串行，按持久化回执先后展示各次变更，界面仍显示原始记录时刻 |
