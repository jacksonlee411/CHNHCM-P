## 2 列表与来源复验

| 办理场景 | 实测结果 |
| --- | --- |
| 管理员查薪标 | 表头和「更多操作 → 列筛选…」均能设置条件。币种与频率可组合，查询只读。限制上限读取权后，桌面列、列设置及缩放摘要都去除上限。 |
| 查询中又输入关键词 | 计划列表应用关键词和状态后，模拟查询暂时失败。重试沿用已应用条件，保留尚待提交的输入。取消筛选把焦点还给原按钮，分页沿用已应用条件。 |
| 月标与年标的来源 | 一月年计划改查六月三十日后立即点薪标，曾出现地址已更新、返回仍落一月。原开发版连续八次有七次复现。切换查看日或生效记录时先撤下原来源，收到所选日期的资料后显示链接。同样操作八次均返回六月三十日。快速切换列表查询也先撤下原结果。 |
| 短屏恢复全部隐藏的业务列 | 1440×540 下，原薪酬计划表格收缩，鼠标点不到网格内的「管理列」。管理入口移到共享列表控制区后，可恢复一列或全部列，搜索草稿、查询条件和原列宽均保留。同构建的业务单元表格保有选择列，能用同一按钮恢复其业务列。 |

第一轮开发版共 15 项，年计划原件返回、三计划联验、计划撤权、列表重试和短屏薪标办理五项失败。定位快速切换日期及查询结果的问题后，生产构建 15 项中 14 项通过，稳定开发版 5 项重点场景中 4 项通过，余下相同失败均为短屏「管理列」无法点击。修复后，生产构建分别复验薪酬计划与业务单元的列恢复，两项通过。独立开发环境从正常菜单复验同一条短屏计划用例，36.7 秒通过。两类薪酬页面在生产构建复跑全部 15 项，用时 4.9 分钟，覆盖 1440×900、1440×540、原生 200%、按日返回、撤权、原件及回执。[薪标页面用例](../../tests/e2e/compensation210.spec.ts) · [计划页面用例](../../tests/e2e/compensation-plans210.spec.ts) · [业务单元参考用例](../../tests/e2e/community-list.spec.ts)

薪标和计划的真实 PostgreSQL 与 Go HTTP 办理继续通过 `TestCompensationGradeRateLifecycle` 和 `TestCompensationPlanSharedRatesAndAdoptions`。同一候选的 `make check` 通过文档、边界、Go 测试及静态检查和前端类型检查。容量、独立原修订与重启的结果见原 I3 记录。[薪标实库用例](../../internal/bootstrap/compensation_grade_rate_integration_test.go) · [计划实库用例](../../internal/bootstrap/compensation_plan_integration_test.go)
