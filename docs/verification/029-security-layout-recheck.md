## 1 上一轮实际覆盖的范围

2026-11-28 在 wt-dev-a 固定入口 4627，以内置管理员从「设置 → 安全管理」进入三个菜单。上一轮交付了授权目录及逐份授予的查询、分页、换版和撤销。其控制区高度和首屏行数记录只能说明对应的授权场景。[上一轮验收](029-grant-management-experience.md)

| 页面 | 在原 4627 上复现的问题 | 本次处理 |
| --- | --- | --- |
| 账号、授权列表 | 显示名和登录名共用一列，账号状态是普通文本，独立「筛选」与参考页的列操作不同。 | 登录名进入详情，显示名单列，状态使用共享状态标签。列头和「更多操作 → 列筛选」打开同一筛选表单。「授权」仍分列账号状态和可见生效授予数。 |
| 角色列表及新建表单 | 角色与两类策略混列，标题前并排三个“发布”按钮。找范围策略前要经过 30 项业务动作和 API 说明入口。 | 主操作指向新建对象，其他获准对象进入更多操作，版本类型可筛选。名称后紧接范围和字段策略，动作按部门及部门编制分配两组排列。 |
| 账号、角色详情 | 账号停用与重置同级。账号和版本的日志接在资料尾部，需向下找。角色查看引用也要到资料末尾操作。 | 顶部保留身份、主操作和相邻对象导航。变更归属、启停进更多操作，「基本资料」「变更日志」分别可直达。有权的角色可直接切到「版本引用」，账号可从身份区打开授权。 |
| 授权详情 | 账号与授予的状态难以扫读，列表使用自制分页，职责逐块堆叠。 | 保留各份授予的入口、来源和期限，状态以共享标签呈现，子列表使用共同分页控件。管理职责按归属、到期和状态成行，明细在对应行下打开。 |
| 三个入口的变更日志 | 账号及角色按编号罗列，授权虽有对齐的文字但缺列头，原值、新值要逐条展开。 | 共用操作分组表格。记录时间、操作者、记录处理、变更内容和获准的原值、新值直接对照。提交编号、原始时刻和事由可在「来源明细」核对。操作者、处理动作和北京时间日期在服务端筛选后分页。 |

## 2 点按钮会发生什么

| 管理员的意图 | 入口及结果 |
| --- | --- |
| 建立角色或策略 | 「新建角色」「新建范围策略」「新建字段策略」打开对应表单。「保存」后该版本可供授予选择。 |
| 修改已有定义 | 「新增版本」带入所选版本资料。「保存」生成同一定义的新版本。既有授予继续引用原版本。 |
| 让某人取得或变更权限 | 在该账号的「业务授予」使用「授予权限」，或在具体授予使用「采用新版本」。实际可办范围由 Go 返回。 |

## 3 验证

以相同管理员、账号、角色及浏览器在更新前后访问。短屏为 1440×540、100%，普通桌面为 1440×900、100%。在短屏从「角色名称」输入框连续按 Tab，到「范围策略」由 32 次变为 1 次。授权列表的首行顶部在短屏两次都是 166 px；这个入口的改善体现在身份分列、状态和筛选操作。授予前后值较长时按行完整显示，短屏查看多次变更仍需向下滚动。

固定入口的首次逐页复核发现，「新建角色」日志能显示操作者及时间，却在变更内容、原值和新值三列都显示占位。Go 随后按事件保存的目标版本返回确切名称和版本号，启停根据对应的成功操作显示状态变化。重置凭据只显示操作及来源。核对一份已停用的 V1 和仍可用的 V2 时，V1 的建立记录仍指向 V1。[首轮角色日志原图](data/029-security-layout/first-role-log.png)

隔离实例中的安全管理员从普通菜单开户、新建角色，给经办人分别授予本职和代理权限。在 1440×900、1440×540 和原生 200% 下验证取消、提交、撤回一份授权、查日志及返回。按操作筛选的日志刷新后仍在原条件，从具体授予返回时焦点回到触发该次查看的原行。数据库/API 用例覆盖完整获权集合上的跨页日志、归属、版本及到期边界；测试以实际事件的北京时间日期核对记录，支持跨午夜运行。

固定环境沿用本树的 `x03-manual-a` 原卷，Web 4627、API 8627、数据库 54627。从正常菜单进入 [账号](http://127.0.0.1:4627/settings/security/accounts)、[角色](http://127.0.0.1:4627/settings/security/roles)、[授权](http://127.0.0.1:4627/settings/security/grants)。在账号或授权目录输入 `x03-t04-clerk` 可看同一经办人的本职、已撤代理和变更记录；在角色目录输入「T04 甲部门名录」可查相应版本。

本轮曾遇到同一条立即授予在读取时显示「待生效」。隔离数据库用例留存的本职开始时刻为 17:26:45.483963，程序在 17:26:44 已结束该次读取。浏览器另一次首败为期望两份生效、实见一份。目录计数用例改用明确已开始的本职，保留独立的将来授予。办理路径继续选「立即生效」，对待生效结果可用原条件再按「查询」，重新向 Go 读取当前状态。普通确认回执和历史记录保留原始时刻。

最终工作树通过 `make check`、7 个 X03 数据库/API 用例和 8 个 Chromium 用例。独立取出本次拟提交的产品代码后，TypeScript 和 access、bootstrap 的 Go 检查通过。固定 4627 包含工作树原有的 027/028 内容。三个样例更新前后的授予身份、绑定、期限、状态及事件、目标、回执摘要一致。视觉对照的两轮走查均未在固定库提交管理命令。远程 CI、生产环境与客户签收另计。
