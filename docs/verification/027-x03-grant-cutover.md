## 2 前向切换与原件查回

从基线 Git 树编译原 server、upgrader，使用仓内固定的 PostgreSQL 18.6 镜像安装至 00028。旧版受控初始化建立 admin、reader、空权限账号和停用账号。用旧版正常 API 创建甲、乙 BU，保留甲的原提交号并查回。升级前在库内留存逐份权限的比较集，停止旧 API，再执行新版 upgrader 两次。用同一旧会话和原提交号调用新版 `POST /api/v1/organization/submissions/{id}/resolve`。

- 逐份比较实例、主体、授予 ID、动作、范围种类、对象、读写字段及有效条件。两个方向均用 `EXCEPT ALL`，可检出身份遗漏、扩张和重复。旧模型授予没有起止时刻，迁入保持开放，缺失授予人及时间为空。账号停用、目录型岗位条件、空许可和此前撤过的默认动作分别核对。
- 在客户端再次使用会话前，对主体、凭据、会话、两笔 BU 的身份、历史、字典、结构及终态逐表比较内容摘要。重复迁移和再次初始化后摘要一致。原办理人按原身份读回同一业务来源及完整原响应。正文和会话材料留在隔离系统。
- 初次 251 份对账无差异，分别为 admin 171、停用账号 40、空账号 0、reader 40。扩展复验在甲乙各建一个部门，在甲部门建两岗，设置总额 10、岗位额度 2 和 3。首次把部门读字段收窄到仅编码，旧 API 因缺少部门名称返回 404。按实际入口补上名称字段后，旧库在目录可读时返回小计 5。撤去 reader 的岗位定义读和历史读两项后，仅直接指定岗可见，小计 2，未披露另一岗位或余量。此次剩 249 份（reader 38），双向差集仍均为 0。升级后原 reader 会话读回的部门核编响应完整一致。

## 3 受保护写入与授权竞争

使用现有 `POST /api/v1/business-units`，由真实 API 角色连接执行保存，独立管理连接控制事务先后。等待以 PostgreSQL 实际阻塞关系确认。检查 HTTP 结果、业务身份、来源及终态。重叠、到期与共享版本测试（原工作树 `internal/bootstrap/access027_integration_test.go`） · [业务先提交测试](../../tests/integration/bu_test.go)

| 条件 | 实际结果 |
| --- | --- |
| 同一对象有本职和代理两份完整授权 | 首次保存 201。撤代理后仍为 201。重复原授予请求只产生一条修订 |
| 业务先取共享守卫 | 撤权等待业务事务，业务先提交，原来源仍可查看。下一次保存 403 |
| 先撤尽授权 | 未提交的撤权事务阻塞保存。撤权提交后保存 403，目标 BU 和该提交的终态均为零 |
| 等待期间最后一份到期 | 业务连接在实际业务表上等待至截止时刻。释放后 403，事务未留下业务写入。后续独立保存同样 403 |
| 发布、采用、停用共享版本 | 发布只新增定义。采用者得到新版动作，旧版停用后原持有人被拒，采用者仍能保存。两个主体采用同一字段版本后，管理连接先停用该版本，等待中的保存及另一主体后续保存均为 403 |
| 一份角色包含 BU 和法人两个办理动作 | 明确以法人为用途的授予不能保存 BU（403）。相同版本、范围及字段另授 BU 用途后保存 201 |
| 新建普通账号 | 可从现有登录接口进入，授予数为 0，保存 403 |

使用本地 Docker 可单独复验两种提交顺序。两项测试均自行建立隔离数据库。

```bash
go test -tags=integration -count=1 -run '^TestAccess027AssignmentOrderAndExpiry$' ./internal/bootstrap
go test -tags=integration -count=1 -run '^TestBUCommitVisibilityAndRevocationOrdering$' ./tests/integration
```

## 5 接续与未覆盖项

T03 可接当前 `Guard.Decide`、`DecideReads`、`PlanReads/DecidePlan`。部门候选与办理入口已由 X03 裁决，固定选择与 CSV、多岗业务字段和可见小计仍依各自业务合同验收。T04 可在原管理事务先调用 `LockManagement`，按当前管理会话核对委派依据和待变动的目标，再使用发布、逐份授予／采用／撤销、版本停用端口。当前客户 API 数据库角色只可读取和锁定版本。T04 须纳入账号、角色和授权的管理动作及目标归属，接入管理 HTTP、跨账号委派上限、停用前对全部引用的管理资格检查、客户首位引导及恢复命令、管理页面和管理回执。T05 验证页面撤权后的实际启动和重新登录。真实客户管理员与恢复责任人由客户在开放前指定。完整容量目标沿 125 专项跟踪。本轮为本地验证，未执行远端 CI 或客户开放验收。
