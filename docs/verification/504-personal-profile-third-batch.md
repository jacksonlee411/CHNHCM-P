## 2 实库及权限

| 合同场景 | PostgreSQL 与 API 结果 |
| --- | --- |
| 014 三种教育行、两种凭证 | 一笔保存三行教育、两行凭证和曾用名。在读行无结束年月，学历行与学位行各有一个最高标记。切换最高学历后，原最高学位行的修订保持。相同学历事实只改标记仍判重，同名续发件可持有各自条目标识。截止早于起始、无取得事实设置最高、无效年月与状态都被拒绝。 |
| 016、019 当前授权 | 选择新的最高学历须能撤下旧行标记。学位授予改为已取得学历时撤回原学位字段写权，或有限期改为长期时撤回截止日期写权，两栏同笔修改均被拒绝。借另一人的条目标识移除时返回统一拒绝。普通详情固定遮罩证书编号，经办人可查看单项原值，只读者获得遮罩。 |
| 017 同笔终态 | 在写入 Outbox 前注入故障，人员头、来源数、条目数及事件数保持。原号查回为未执行。成功后由第二个会话查回并重送同一命令，仍为原回执。持旧来源的后续更正冲突。普通用途到期后重登，单项直达、当前集合及回执均无该行正文。 |
| 017 处置与恢复 | 合成保全只保留指定来源的教育行。实际 `pg_dump` 封存处置前资料，`pg_restore` 恢复至独立数据库后通过统一 upgrader 重施处置。原两行正文归零，产生两条处置凭据，原提交仍按原来源查回。 |
