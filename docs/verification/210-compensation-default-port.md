## 2 重新登录与持久化验证

上述九个业务对象及三次后续维护均由管理员在网页点「保存」完成。初始空库的两个本地账号按职责取得本次所需权限。管理员可维护，查询者从同一菜单查阅。查询者分别选择业务日，点击 BASIC 组成的标准链接，再返回计划，所选日期与原链接焦点均恢复。查询 `2027-01-01` 时，两份月计划的当日上限都是 16,000 元。查看保存时依据，专业计划的一月新段取得上限 16,000 元，运营计划原段仍指向 15,000 元。

逐笔读取原件和办理回执后，使用 `python3 scripts/local-bu.py down` 停止本次 Web、API 和 PostgreSQL，保留原数据卷。再用 `python3 scripts/local-bu.py up --fixed-web` 重新启动，`python3 scripts/local-bu.py verify` 核对实际端口和工作树归属。管理员和查询者分别使用新的浏览器会话重新登录，十二个按日计划页面结果、八份薪酬原修订、八份原回执及业务对象身份均与停机前一致。月薪核对当日、十一月末、十二月首日、十二月末和一月首日，年薪核对当日和一月首日。重启前后结果文件的 SHA-256 均为 `04730b3c45dafe3cb919dbde4ee27529cbc6233019011c6293745a46f3e67db5`。[对象、日期、原修订和回执实测值](data/210-default-port/after-restart.json)
