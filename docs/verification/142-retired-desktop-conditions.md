## 2 第一轮实施及反例

薪酬原型删除了高度小于等于 580 像素时的整页滚动规则，走查的默认桌面由两种高度收为 1440×900。人员名录脚本保留默认 `desktop` 与显式 `200`。012 的“本轮页面合同”、023 第 21、28、30 节和 121 的 R5 交接已分别标明原批次和现行条款。[薪酬原型](../specs/m09/prototype/compensation-configuration.html) · [薪酬走查](data/210-compensation-design/walkthrough.mjs) · [名录走查](data/405-personnel-directory/verify.cjs)

默认薪酬走查得到一组 1440×900 观测，遍历 192 个样例地址及来路组合。另一次加 `--native-zoom` 得到 1440×900、640×450 两组，脚本异常均为零。名录也在标准桌面完成了首轮经办与只读路径。

主动传入薪酬脚本未声明的 `--zoom400`，发现它会继续尝试启动浏览器。给名录脚本传 `desktop short`，则会采用第一个值并先创建输出目录。反例使用空的浏览器安装路径，两个进程均走到了浏览器启动，未打开旧尺寸页面。随后两个脚本都在启动前严格检查参数数量和值。

## 4 正式菜单、登记与收尾

使用同工作树固定生产构建和临时数据库补验 4 项正式 Chromium 用例。首轮 3 项通过，“重复建标返回原件、错误取消、仅目录角色及撤权后保存”在权限反例处缺少冒烟专用的 `access.subject_grant` 视图。向同一任务库安装仓库原有的冒烟权限夹具，原四项同组复跑，全部通过。覆盖薪标原生 200% 的菜单与保存、非法指导值返回 HTTP 422 并定位原字段、取消后原版本保持，以及人员名录的失败重试和跨页排除。[薪标用例](../../tests/e2e/compensation210.spec.ts) · [人员名录用例](../../tests/e2e/first-hire.spec.ts) · [冒烟权限夹具](../../tests/fixtures/access/policy.sql)

复查正式视口与独立场景入口，桌面为 1440×900、唯一原生倍率为 2。CI 发现 650 项，含重复前置分配 730 次，清单摘要与 012 的最后一轮一致。本轮核对了发现及分配，仅执行上述定向浏览器流程。在基线的 `docs/verification`、`docs/archive`、资产清单及工作流说明中，除本次维护的两个脚本外，其余 532 个原文件与 Git 版本逐字节一致。

归档后 `make check` 通过，覆盖 195 项 Python 测试、仓库文档与模块边界、运行时测试、Go 测试与静态检查、Web 类型检查及 `git diff --check`。归档计划与本报告共 40 处仓内链接逐一验证，三个受测源文件与机器记录中的 SHA-256 一致。

任务环境 `smoke-ui142-af9387e7` 使用 Web 46943、API 46431 和 DB 46359。退出后核对这三个端口均已释放，任务容器、网络和卷均已回收。页面改动限于仓内离线原型，持久环境继续使用原构建。本次结果为本地定向验证，远程 CI 及人工业务签收未执行。[归档计划及交接](../archive/plans/142-retired-desktop-conditions.md)
