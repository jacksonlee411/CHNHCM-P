## 1 基线、范围与结论

2026-11-04，固定工作树wt-dev-b，HEAD为`9ec5d53124f458d1ae44315633875cd5e154485d`，受测内容为既有未提交122实施及本次修复。实际输入摘要见本目录证据，不把HEAD等同于整个受测工作区。

本轮只处理实施复核发现的三个问题：成功日志读取收窄字段权限后仍保留旧基本资料；分页及应用筛选后焦点丢失；TL-373的固定两条/未来首条及同日新身份浏览器参数未充分落地。原报告中的汇总通过不能替代这些参数的主层执行，本记录补正该证据边界。其余既有结果保持原验证层次；不声明全M02、部门或生产验收，不作为独立评审或人工签收。

## 2 修复内容

### 2.1 权限收窄与详情缓存

日志仍按`bu.read ∩ bu.history.read`裁剪。响应新增`detailReadFields`：普通上下文来自当次bu.read，历史上下文取交集；同一Go授权守卫下产生，仅用于同页详情缓存失效判断，不是授权令牌或日志筛选目录。范围变化立即丢弃旧详情、隐藏页签、标题及能力，并重新读取详情。仅收窄历史权不误删普通资料中的合法字段；历史交集原已收窄时，再收窄普通权也可检测。

OpenAPI、Go公开DTO、生成客户端与013合同同步，未新增迁移、兼容字段或第二套业务算法。对象或历史权限整体拒绝仍走已有清理路径。

### 2.2 键盘连续操作

记录发起操作的控件及新请求是否已开始，待对应新结果或错误反馈出现后恢复焦点。翻页返回原分页按钮；按钮在边界禁用时回到列筛选，页大小返回选择框，应用/清除筛选回到触发控件或其新节点；失败转重试。用户等待期间主动移动焦点时保持其选择。

原“已保存”提示只随实际资料/保存结果变化聚焦，日志页码和筛选参数不再触发。关闭筛选对话框产生的旧路由渲染不再提前消耗焦点恢复，避免随后卸载表格又落到body。原件返回的条件、位置和链接焦点机制保持。

### 2.3 删除验收补齐

新增浏览器用例使用admin、reader两个不同认证主体；reader仅在独占临时环境中临时授予维护权，结束恢复。业务写入通过正常菜单和表单，H45容量及空changes参数使用真实公开API准备或补验。

| 样本 | 实际页面操作和独立核对 |
| --- | --- |
| S单条与同日新身份 | A/B交替创建、增加、更正和删除；前来源原件与删除来源墓碑均保持原业务修订/A摘要，删除日志属B。空changes不创建记录，正常新增得到不同ID；两旧链接再打开仍为原件。复制的前来源、墓碑及删除后URL撤历史权后均拒绝 |
| P固定两条 | A插入停用/恢复，B只更正恢复名称，A成对删除。实际逐一打开两条前来源链接及墓碑URL，摘要分别为P2/A与P3/B，保留各自原期间、分类和删除证据修订；删除后仅一条时间线记录；复制URL撤权拒绝 |
| F未来首条 | A创建未来首条并新增第二条，B删除第二条。删除后链接省略被删ID，NO_FACT仍显示首条派生修订/F3/B摘要；被删条两原件摘要均为F2/A。明确缺失ID无摘要；当前/历史缺日期权无日期、期间及肯定未来提示；撤历史权旧URL拒绝而合法当前摘要保留 |

F浏览器使用9998-11-10/9998-12-01以保持相对真实服务器日期为未来；数据库专项使用合同固定D=2026-11-04及2026-11-10/2026-12-01。两者明确分层，不把浏览器真实时钟冒称受控时钟。
