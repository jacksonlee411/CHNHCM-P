# CHNHCM-210 薪酬体系业务方案与页面原型走查

本次走查回答三个问题。薪酬专员能否用同一套配置表达月薪和年薪制度，能否看出一次调整从哪天生效，以及能否沿计划查回当初采用的金额依据。业务预期由 [211 薪酬体系方案](../specs/m09/211-compensation-configuration.md#design-cases)给出，操作入口见 [212 页面设计](../specs/m09/212-compensation-configuration-pages.md#prototype-walk)。本记录关联[实施路线图](../plans/210-compensation-configuration-roadmap.md)，元数据存于[登记表](../governance/registry.json)。

## 3 业务预期与实际结果

| 走查对象及操作 | 核对结果 |
| --- | --- |
| 从两个配置菜单分别办理两套制度 | 专业计划 BASIC 指向 P5 月薪带，岗位津贴显示 300.00 元/月。管理计划 BASIC 指向 P5 年定额 180,000.00 元，目标奖金显示基准和 12.50%。新建计划及标准以 1900-01-01 为首次默认值，填写样例改用职级已生效的 2027-01-01。组成行可增、重排、切换取值及整稿取消。[AC-001](../specs/m09/211-compensation-configuration.md#m09-ac-001) |
| 从专业、运营两份月薪计划独立查薪带 | PRO-M、OPS-M 的 BASIC 都打开同一月标。两条路径同样显示六月上限 15,000.00、七月上限 16,000.00，从各自发布依据仍能查回一月的 15,000.00。运营计划仅有基本工资。重复建标样例提示已有 P5 月标，可直接打开查看。[AC-005](../specs/m09/211-compensation-configuration.md#m09-ac-005) |
| 七月调整、误录更正、查当初依据 | 一月记录在日期轴显示至 6 月 30 日，上限 15,000.00。7 月 1 日的新段显示上限 16,000.00。另一套误录样例从原值 16,500.00 填为 16,000.00，日志保留同一生效日和两值。能从更正前原件返回日志，能由年薪计划发布原件打开当时年标并逐级返回。[AC-002](../specs/m09/211-compensation-configuration.md#m09-ac-002) · [AC-003](../specs/m09/211-compensation-configuration.md#m09-ac-003) |
| 单独复算数字，定位错误项 | 用 Python 十进制和四舍五入到分复算，180,000.00 × 12.50% 为 22,500.00。将基准改为 180,000.04 后，未舍入值为 22,500.005，结果为 22,500.01。按左含右开的两个日期区间核对，六月末和七月首日各只命中一条。例外页的指导值 17,000.00 超过 16,000.00 时，输入处显示可用范围，辅助技术也可读取。[AC-004](../specs/m09/211-compensation-configuration.md#m09-ac-004) |
| 查询、取消、角色和返回 | 用 `PRO-M` 筛出一条，穿过计划和标准返回时，焦点回到原引用，列表保留相同大小写的条件和一条结果。取消七月新增稿回到一月样例。只读薪酬详情无维护入口，仅有目录权的旧链接不显示金额或 P5。[AC-006](../specs/m09/211-compensation-configuration.md#m09-ac-006) · [交互保护](../specs/m09/212-compensation-configuration-pages.md) |

## 4 浏览器复验与首败

在 1440×900、1440×540 下以 100% 走查，再以原生 200% 重走相同的菜单、编辑、异常、历史返回和键盘路径，三次均通过。原生 200% 从内容视口 1280×900 开始，浏览器外框保持原尺寸，内容视口为 640×450。独立配置恢复 100% 后重新测得 1280×900。三次文档宽度均等于当时可用宽度，分别为 1440、1440、632 CSS 像素。脚本从首页遍历到 76 个可达页面及来路组合，未捕获页面脚本异常。[浏览器走查](data/210-compensation-design/walkthrough.mjs)

| 检查中的首败或差异 | 修正与复验方式 |
| --- | --- |
| 由日志打开一份旧标准后，返回可能落到另一条记录。从详情回列表时搜索条件被转为小写 | 给确切来源保留来路，分别保留筛选原文和匹配值。走完计划原件、标准原件和误录更正三个分支，再返回各自起点。 |
| 首轮原生 200% 检查以包含纵向滚动条的视口宽度比较正文，得到 632 与 640 | 将文档滚动宽度与可用宽度比较，同时独立核对视口。第二轮发现窗口装饰就绪较晚会得到 1280×848，改为按实测窗口和视口校准后再切换。 |
| 从未带片段的首页再选一次同名菜单，偶发重绘清除刚输入的筛选 | 统一初始地址。点击当前菜单仅关闭菜单并回到标题。脚本在每次进入目标页后检查其定位。 |
| 按误录反查时发现更正表单预填了目标值 | 改为先带出原上限 16,500.00，由经办人实际输入 16,000.00，再查看结果和旧修订。两套制度的首次新建也加入正常菜单走查。 |

## 5 验收边界与移交

用户于 2026-11-27 就同一职级、币种、频率和计量单位下的薪带明确选择「各计划共用同一薪带」。该选择已落实到 BR-002、AC-005 和两个菜单的原型。跨计划固定津贴是否联动、哪些发布需要复核仍由制度负责人审阅。职级内设薪档的客户可补一份逐档金额样例。[制度选项及反例](../specs/m09/211-compensation-configuration.md#policy-decisions)

原型展示预置结果。权限样例、日期选择和取消能验证页面表达，后续 I1 至 I3 仍须用真实 Go 命令、数据库、授权和菜单验证落库、撤去未来记录、撤权与缓存清理、重送、并发、引用失效和停用。AC-005、AC-007、AC-008 的完整业务结果以及其余各例的服务端保护均留待实施验收。客户制度、业务代表签收、生产构建及同构建页面对照也由相应阶段补录。[八组验收预期](../specs/m09/211-compensation-configuration.md#design-cases) · [实施及交接责任](../plans/210-compensation-configuration-roadmap.md)
