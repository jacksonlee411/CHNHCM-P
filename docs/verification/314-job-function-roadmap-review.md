## 2 发现与关闭依据

| 轮次与问题 | 修订与复验 |
| --- | --- |
| 一 · 旧来源的截取时点 | 第一稿要求固定旧来源，缺少在途写入和迁移中断的验证办法。T03 改为排空旧写入、按提交或回滚归属取样，在同一边界重试，切换后追溯创建须走新规则。源码中的头、封存来源、修订及终态各有存储位置，计划逐份核对并复验读索引重建。[存储事实](../../db/migrations/00017_staffing.sql) · [重建路径](../../internal/contexts/staffing/infra/postgres/rebuild.go) |
| 一 · 原写入地址可能提前报 400 | 现有写入先执行 HTTP 形状检查，应用随后才按提交锁检查旧终态。若在前一层对全部请求强制要求职类，合法旧请求到不了回执。T03 明确准入顺序，AC093 分别走原写入地址和查回地址，并核同号异载荷及缺值新号。[HTTP 写入](../../internal/bootstrap/staffing.go) · [应用终态](../../internal/contexts/staffing/application/commands.go) |
| 一 · 继承采用仍可能延长不合格期间 | 单移停用端、删除或改日均可能延长引用。修订后对各动作复核受影响启用段，同时保留合格的原采用。AC086 和 AC091 分别验证共有日期归类变化与纯移首日，再以有权、缺权和显式清空区分 403 与 400。[旧资料与按段判权](../specs/m03/308-job-foundation-contract.md#m03-br-031) |
| 二 · 企业后移起日的端口归属 | 第二稿将反向端口列给了 M02。终稿明确由 Staffing 提供最早首条，企业命令在同一事务读取。T02 包含已停用且无人引用的职类、竞争的两种先后及端口故障。[Staffing 实现](../../internal/contexts/staffing/infra/postgres/store.go) |
| 二 · 选中第二个条件、撤权或返回可能扩大结果 | 当前列表应用列条件会替换另一条件。T04 补齐分类与普通列切换、未登记与指定 ID 互斥、原条件失权后由用户显式移除，以及列表、导航、返回 URL 和固定选择的共同查询。第三轮复算交集成员和各步计数。[页面筛选](../../apps/web/src/features/staffing/List.tsx) · [查询合同](../specs/m03/308-job-foundation-contract.md#m03-br-032) |
| 二 · 旧选择失效后重建也可能得到九列 | 现有草稿与会话、业务日、有效期及查询条件关联。T04 要求用仍有效的原草稿、修订、入选和已排除成员重导，并加入新匹配职务验证成员身份。AC089 同时明确可用原号查回，断言对象是唯一业务写入。[选择及导出](../../internal/contexts/staffing/application/selection.go) |
| 二 · AC090 整行计数会阻塞或错关 314 | 终稿拆为“仅 308”“仅 313”“两者并存”。308 先就绪时，314 可凭本批证据关闭，移交联验给后就绪批次。313 先就绪时，314 的 T05 执行联验并引用 313 独验。三条分别记结果。[独立交付合同](../specs/m03/308-job-foundation-contract.md#m03-br-033) |
