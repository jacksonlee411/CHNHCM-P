## 2 实施前的独立文档评审

第一轮独立代理审查提出四项修改。未设置筛选时可以查询，筛选字段失权后可以清除条件。相同掩码或单侧到期时须保护隐藏事实。日志直达、失去历史权和原件不可读各有对应反馈。同标签返回须限定主体、会话和人员，并明确焦点去向。修订后首轮逐项复核通过。另一独立代理复核相同尾号、翻页间新增、不可读原件及空差异办理组，第二轮通过后开始实施。审定的 500、502、503 文件 SHA-256 前十二位依次为 `8a2d461c5ba0`、`7326229f5445`、`137df08afb13`。文档评审人员均为独立 Codex 代理。

## 3 实施与验收

人员使用职务同款可滚动页签和命名面板，共享表格组呈现办理时间、操作者、字段差异、原件链接及行内来源。人员日志使用独立查询合同，一次 PostgreSQL 语句沿真实前序链读取两侧，同次 HTTP 请求返回一页办理，Go 按读时资格处理遮罩及处置。原件及按需敏感差异继续按确切来源读取。[人员页面](../../apps/web/src/features/personnel/Detail.tsx) · [办理组](../../apps/web/src/features/personnel/ChangeLog.tsx) · [Go 查询](../../internal/contexts/personnel/infra/postgres/change_log.go)

- 两项独立 DB/API 专项核对 22 笔与第 23 笔新增、同刻及回拨、北京跨日、真实电话更正及同尾号、到期和处置。实现评审发现显式空分页值与空上界会当作缺省，修正后五个非法样例均返回 400，专项复跑 2/2。[独立样例](../../tests/integration/personnel_log_test.go)
- 前端类型检查首次发现响应页大小的类型宽于 20／50／100，已修订 OpenAPI 并重新生成客户端。首轮 Chromium 跨页与撤权专项通过。界面代码评审另发现重新打开资料可能使用旧字段、再次前进后退丢失焦点与位置、非法筛选不能就地清除。浏览器复验沿用真实请求及角色权限。[浏览器用例](../../tests/e2e/personnel.spec.ts)
- 最终独立源码复核确认，浏览器历史菜单直接跳过中间原件，也能恢复对应访问的页码、筛选和已获权链接焦点。主动切回个人资料时若历史权已撤去，重新授权后显示单页，焦点落在资料标题。对应的浏览器专项验证了这两条操作路径。
- 最终固定构建在 Chromium 通过 28 项。16 项人员场景包含 14 个角色与视口组合，以及同一人 22 笔办理、翻页间新增第 23 笔、撤权及迟到响应。12 项共享日志回归覆盖摘要、权限、筛选、分页及准确原件。经办与只读账号都从菜单走过 BU、职务、人员三页，在 1440×900、1440×540、390×844、320×900、320×256 和原生 200%（640×450）、400%（320×225）核对页签、日志组和焦点。页签最小高度 42px，顶部指示线 3px，选中边框与职务一致。检查使用浏览器的可访问角色、名称、状态及真实键盘操作，未做人工读屏朗读。[用例、视口实测和构建摘要](https://github.com/jacksonlee411/CHNHCM/blob/061d28105966bd10eb1e3b0032cf2976a6448de4/docs/verification/data/500-personnel-change-log/acceptance.json)
- 首次合跑的 28 项中有一项共享日志的原生缩放缺少系统测试依赖 Xvfb。补装后单项通过，最终固定构建 28/28 通过。Go 的人员专项在真实 PostgreSQL 和 HTTP 上通过九项业务用例，同时运行了匹配的 bootstrap 检查。此次未改迁移或登记命令，未重跑独立万笔容量与备份恢复试验。[人员业务用例](../../tests/integration/personnel_test.go) · [日志专项](../../tests/integration/personnel_log_test.go)
