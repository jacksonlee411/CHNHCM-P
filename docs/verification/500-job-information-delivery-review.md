## 4 阶段 1 首任期与地点办理

`00041` 把旧首任职及撤销后补办的任期关联到本人同一份 0 号。`00042` 把首次办理的日期、依据及原采用移入准确修订，保留首次经办人与登记时刻。旧入职及撤销分别构成可定位的来源。旧单只记地点身份时，按当天及当前权限读取地点名称。新办地点变更保存采用的地点来源、修订、前后值及用工用途依据。经办人从原笔更正时，Go 保存被替换的值及准确前版。每次发布的任职来源保存成员及非重叠的日状态，回执和待发事件绑定当次修订。[迁移](../../db/migrations/00042_job_information_sources.sql) · [Go 办理](../../internal/contexts/staffing/infra/postgres/job_information.go)

## 5 阶段 3 人事事务办理记录

本阶段先使用已开放的入职和地点更改。「人员 → 人事事务 → 办理记录」从 Go 集合接口取得获权事项。每一稳定办理身份一行，按首次登记时刻倒序。发生部门从该笔修订发布时的任职段取得。生效起止取业务日期，办理起止取北京时间的自然日。未来首单撤销后，原入职仍是一行，撤销依据沿原件联查。等阶段 2 开放调动后，再将实际调出、调入两侧接入相应筛选。[办理合同](../specs/m04/403-hire-technical-contract.md#personnel-action-query)

`00043` 为跨人查询新增独立范围授权。经办人与部门的筛选、选项和行内容分别核对应字段；名单与人员识别权在计数前取交集。原件另核原有读取权。初始化由一次性试件登记，已撤回的授权保持撤回。旧办理只保存原经办人身份时保留原标识，不补造姓名。[前向迁移](../../db/migrations/00043_employment_register.sql) · [查询](../../internal/contexts/staffing/infra/postgres/employment_register.go)

真实 PostgreSQL 与 API 使用两个部门的两名员工、两笔入职和一笔地点变更。原笔更正后仍是三笔，生效范围按 2027-05-01 只命中该地点变更，首次登记时刻与原件一致，按北京时间筛选命中正确。撤销第二名员工的未来首单只命中一笔已撤入职。收窄到第一人后只有两笔，移除经办人及部门披露字段后该两类候选为空，按未获权部门命中零笔。收回跨人查询并重新初始化后，集合接口拒绝，原修订仍可按已有原件权限读取。[业务试件](../../internal/bootstrap/job_information_integration_test.go)

从「人员 → 人事事务 → 办理记录」检索员工、按地点变更及生效日期筛选、从原笔更正，查看同一任职的同一修订并返回原筛选和办理行。五种 100% 视口及原生 200% 均通过。另从登记列表直接撤销未来入职，原通知、撤销依据、原行和已撤销状态均可复查。单个本地 Chromium 工作进程共 7 项，约 2.1 分钟。[菜单联验](../../tests/e2e/first-hire.spec.ts)
