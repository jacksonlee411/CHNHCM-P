## 3 复验与交接

复验时将 `CHNHCM_LOCAL_PROFILE` 指向已登记且运行中的自有临时 profile。以下三个参数分别指向 T01 仓外交接目录、00024 的 server／upgrader 目录及候选程序目录。脚本为每条路径建立独立分库。数据库和会话配置保存在仓外。

```sh
python3 -B docs/verification/data/314-job-function-t03/upgrade.py \
  --handoff "$T01_HANDOFF" --old "$T02_BIN" --new "$T03_BIN"
```

第一次从 Go 公共代理查找 sqlc 时返回 EOF。改用本地锁定的 sqlc v1.31.1 后生成成功，又使用本机模块缓存执行完整 `make generate`。首次编译集成测试发现一处旧建样辅助变量名错误，修正后编译并运行真实 DB/API 测试。最初的读索引重建辅助程序从验证目录直接导入 Staffing 存储，被模块边界检查拒绝。现已移到存储包的集成测试，从临时库脚本调用。同一职类正在被另一连接排他锁定时，无字段写权的显式回送也直接得到 403。一次并行复验因 profile 生命周期锁退出，随后按顺序重跑。评审加严了恢复端原采用、分类正反向资格、存量依据缺失和停写中断重试的断言。生成、编译、实际命令及回归范围见[本次验收清单](https://github.com/jacksonlee411/CHNHCM/blob/061d28105966bd10eb1e3b0032cf2976a6448de4/docs/verification/data/314-job-function-t03/results.json)。

补查旧职务的停用记录时，新增的 Go 反例复现了原样更正会替换停用原件的未登记依据。现按前序记录及其来源是否改变决定继承，在原前序和未登记事实不变时保留停用记录自己的切换依据。反例纳入领域测试和 00024 真实 API 建样后的升级复验。[无变化更正反例](../../internal/contexts/staffing/domain/function_test.go)

扩大到 307、309、310、312、314 的非容量后端回归后，首次运行在四个旧迁移用例的原表摘要断言处失败。差异定位到可重建的 `job_read.fact.functionEvidence`。复验逐项比较原列和原 JSON 字段，并另行断言新增指针等于原职务、来源、记录和修订。四项单独重跑均通过。同一选择范围又分三组复验，54 项通过，1 项按设计仅在显式开启写入剖析时执行。两项 308 日志回归也通过。旧停用记录无变化更正的最终修正另外通过原备份升级、双连接竞争、单元和构建检查。T03 的原备份检查逐行比较了 44 行原业务事实。

本轮在 `t03-314-dual-d` 临时 profile（Web Origin 55584、API 55585、DB 55586）及独立 Testcontainers 中验证。临时 profile 的进程、容器、网络、卷及仓外连接配置已回收。T04 接续两个候选、正常职务表单、组合筛选和九列 CSV，T05 以同一集成候选办理端到端签收。45300 继续供既有页面对照。
