# CHNHCM-025 全新实施与当前模型交付策略

登记信息：[registry.json](../governance/registry.json)。适用范围：全仓开发实施及M02下一批交付。依据用户2026-11-01明确决定“全新实施，不用考虑向后兼容”，承接[003](003-implementation-stages.md)、[024](024-timeline-implementation-simplification.md)及根目录[工作约定](../../AGENTS.md)。

## 1 背景与问题

当前只接通BU创建/查询，记录维护尚未实施。此前方案仍要求从00004升级、保留旧CREATE空元数据及摘要、并存两代事件格式，并通过停服排空及密码轮换隔离旧程序。这些要求把开发期实现当成已对外承诺的存量版本，增加了与本批用户任务无关的分支和验证。

用户明确取消这些向后兼容义务。已有代码可按业务价值复用或直接重构，已有通过报告只证明其受测基线；二者都不冻结下一批的内部模型和接口。

## 2 决策

### 2.1 只交付一套当前模型

领域、数据库、sqlc、OpenAPI、客户端和页面一起对齐当前合同。开发期允许整理未对外交付的迁移基线，在隔离空库安装当前结构；不要求保留旧字段、旧结果解码、旧事件形态或旧二进制运行。请求、诊断和事件各采用一个明确的当前格式标识，严格拒绝损坏或不符合当前合同的内容，不建设多版本转换层。

创建、单条维护和有限联合使用相同的资料、修订、影响及终态规则；单目标与多目标的必要字段差异由动作区分，不形成两代协议。记录身份只承载稳定归属，日期和业务分类由所选来源修订解释；首次登记信息从首份不可变修订追溯，不为旧表保留initial_effective_date或initial_kind。

### 2.2 保留当前业务历史与失败保护

同一当前模型内，旧sourceVersion、修订、原分类/日期、采用和已终结提交结果仍不可改写。原子提交、当前授权、显式结果查回、安全诊断及有界执行继续实施。取消旧软件版本兼容不影响用户查看既有业务历史，也不允许用当前头伪造原结果。

升级后只提供当前模型的读写入口。产品明确某项用途及其历史可丢弃时，前向迁移在同一事务中直接删除其专属数据和退役结构。共享表按用途及对象身份清理，逐项核对保留的来源、版本、事件和回执。2026-11-23 的岗位职能协作退役按此执行。[岗位合同](../specs/m03/312-position-contract.md) · [升级对账](../verification/315-department-quota-allocation.md#quota-start-gates)

开发/测试使用隔离的合成样本。本文不授权清空现有持久库、共享环境或历史证据；新实现优先使用新的任务数据库。已有报告、来源资产和本次修改前的024输入保留，不能用新模型的测试替换历史失败或宣称旧库升级已通过。

### 2.3 以第一批业务能力组织实施

[010](../plans/010-m02-scope-and-plan.md)保留T01—T08编号，调整依赖和交付组合：

1. 第一批合并推进T01、T02、T03：先实现Go最终候选模型，再接当前存储/接口，并从正常菜单完成资料新增和普通更正。候选内核从一开始接受显式有限项，单条维护转换为一项；无需先建设另一套单条规则再在T08重写。先实现新增/更正所需规则和共用不变量，删除/改日/分类分支随对应批次补齐；有限项结构不等于首批必须交付全部动作。T01的持久化断言随T02/T03验证，避免空等前置闭环。
2. 第二批T04交付停用、重新启用及完整启停守卫。
3. 第三批T05/T06/T08共用删除、改日和分类更新能力，交付单条入口及联合编辑、首条补全、分类纠错。建议按删除、改日、联合入口推进，但联合能力的依赖是已验证的共用操作和生命周期规则，不是所有单条页面先验收。
4. T07按实际范围汇总业务、故障和容量证据，未接入消费者与生产交付能力另列。

每批均保留预览、保存、审计/Outbox、查回、历史与正常入口证据。首先完成可用的资料维护批次，不设置旧库升级或旧CREATE协议适配的独立前置批次。

## 3 备选方案与取舍

| 方案 | 收益与成本 | 决定 |
| --- | --- | --- |
| 维持旧库和两代协议 | 保留开发样本的原地升级路径，但增加字段、解码和旧程序隔离工作 | 不采用；当前没有该兼容义务 |
| 同步更新当前实现与合成样本 | 可直接落实目标模型，需重新验证创建/查询和维护能力 | 采用 |
| 借重构放松历史、事务或授权 | 会改变已采纳的业务规则并失去可靠恢复 | 不采用 |

## 4 影响与验证

013以当前结构的空库安装、重复初始化、失败保持关闭及单一格式严格解码替代旧库升级方案；仅检查当前程序与当前存储是否匹配，不建立兼容矩阵、制品准入平台或密码轮换机制。以后存在真实客户交付需求时再制定升级/恢复方案。

011的AC029缩减为当前模型初始化与格式一致性；023保留全部257个编号，其中TL-241、242、246、247的旧版本专项退役，253例仍为当前待验。涉及旧格式的混合案例仅去除兼容参数，保留当前模型内的业务历史、权限、诊断和恢复断言；退役不算通过。

本次仅修改文档和策略，未修改运行代码、执行数据库迁移或重建数据。文档检查及证据保护见[修订验证](../verification/025-greenfield-implementation-policy.md)；下一步实现仍需真实Go、DB、API和正常菜单验证。
