# CHNHCM-018 生效记录与来源追溯决策

登记信息：[registry.json](../governance/registry.json)。适用范围：M02 BU 首批创建/查询实现、后续记录维护规格，以及 X01 共享历史查询合同。2026-10-31 用户确认取消 knownAt，并要求按分析方案完成调整；本文完整承接并替代 [016 原决策](016-m02-effective-record-history.md)。实际检查与限制见[本次验证](../verification/018-source-history-simplification.md)。

普通维护的日期入口由[123](123-current-maintenance-and-dated-query-boundary.md)部分调整：列表按服务端D，详情按具体记录；内部按日解析、确切来源和本决定的历史保护保持。

## 1 背景与问题

首批 BU 没有已接入的消费者必须按任意系统时刻还原业务事实。016 将该能力列为首批要求，013 因而引入逻辑解码、提交证据、复制槽、采集进度及恢复屏障。旧基线 1bf1ee6 的最终浏览器流程为 5/6，主机时钟回拨触发 CAPTURE_CLOCK_REGRESSED 并阻断新建；原结果保留在[首批报告](../verification/010-first-vertical-slice.md)。当前收益不足以承担这条运行依赖。

业务日期、审计时间和来源身份回答不同问题。保留旧内容及当次采用依据不需要任意时间戳查询。B&B 本地 a76db79 的 032、691、899 和 1402 区分有效日期与审计，不承诺统一的系统当时已知查询；此处只借鉴范围取舍，不移植其 DB Kernel 或事件回放平台，不作 Oracle 行为或法律结论。

## 2 决策

### 2.1 生效记录与确切来源

继续采用生效记录、不可变修订和确切来源版本。每个来源保存该次完整期间解释、成员及删除关系；未变化的不可变修订可以复用。普通更正保留记录身份及生效日；后续新增、插入、删除和停用保留各次期间边界及原件，不用审计摘要替代可读取内容。

| 输入或事实 | 唯一职责 |
| --- | --- |
| businessAt | 按本次查询可见的最新已提交资料解释指定业务日期 |
| sourceVersion＋businessAt | 精确读取指定不可变来源内该日的事实及完整记录轴；来源视图只读 |
| recordedAt | 服务端记录的审计时间；不是精确提交完成时间，也不是历史选择条件 |
| adoptedRef | 消费者对当次采用的确切来源或不可变快照的引用；实际采用归消费者 |

上述businessAt是按日解析值，内部读取可以显式传入。普通列表/详情HTTP按123仅由服务端确定D，不接受用户businessAt；所选记录与确切来源仍分别用selectedRecordId、sourceVersion定位。

knownAt 从现行产品合同退役，接口拒绝该参数，不更名为 recordedAt 截点，不保留时间近似、兼容解析或隐式最新回退。账期、结账事实、发布版本和资金交易时间按各域真实业务语义保留，不能据此恢复通用系统时间截点平台。X01 只保留小型协议；不统一各域存储、也不要求其他对象套用 BU 的完整期间模型。

### 2.2 一次保存与历史保护

Go 继续作为业务唯一权威。同一事务保存事实、修订、来源清单、业务分类及名称快照、成功日志、幂等结果、授权依据关联和必要 Outbox。提交成功即可读取，不依赖后台补齐提交证据；失败不留下部分成功。超时仍通过原 submissionId 查回确定结果，不能猜测失败后换标识重提。

同一 BU 的来源先后由 source_no 和前驱关系确定，后续修改在 BU 头锁内递增并持锁至提交。审计时间可以同刻或回退，保留原值，不用于版本先后、并发依据或区间选择。XID 不作为提交顺序；现有 xid8 仅用于同事务封存，拒绝后续事务向旧来源补插成员、修订、日志和 Outbox。应用角色仍不能修改或删除旧历史。跨域没有全局原子快照；消费者的采用清单解释其原结果。

历史、当前资料和提交结果均执行当前授权及字段裁剪。确切来源不存在明确报错，不返回最新版；业务日期无适用资料与来源不存在保持区分。并发校验仍针对同一 BU，编码唯一、企业范围及已接入引用保护独立执行。

### 2.3 页面与实施范围

保留设置 → 组织配置 → 业务单元、列表详情、生效记录、表单习惯、未保存保护和结果查回；通用查看日期按123取消。变更日志的“查看当次来源”及结果链接进入只读来源，返回当前资料后重新读取和授权。取消高级截点表单与提交证据提示；修订号、来源标识不是日常手工输入。

新业务选择操作原因；普通更正/改日/删除继承准确目标的原分类及名称快照并自动留痕，不另填处理原因。[022](022-joint-timeline-revision.md)为显式分类纠错开放例外，并允许同一BU有限联合修订与首条历史补全；旧来源仍引用原修订，普通处理默认继承。原“首批不增加已保存记录改日”限制已由[020决定](020-effective-record-delete-and-redate.md)部分替代：允许已生效删除和所有记录改日，首条仍禁止删除但允许改日。其余不增加整BU删除、恢复旧版、审批、工作台、完整消费者或事件溯源的边界保持。创建/查询之外的动作只修订规格，仍由010后续批次实施。

## 3 备选方案与取舍

| 方案 | 收益与成本 | 决定 |
| --- | --- | --- |
| 严格 knownAt 与提交捕获 | 任意系统截点还原，但增加复制槽、捕获、故障恢复和时钟条件 | 退役 |
| 用 recordedAt 近似 knownAt | 看似保留接口，实际混淆记录与提交可见性，仍需解释并发边界 | 不采用 |
| 生效记录＋不可变来源＋审计 | 保留当次内容、有效期、更正血缘与来源解释，普通事务即可完成 | 采用 |

本决定取消任意系统截点查询能力。已有精确来源内容与历史权限保护继续保留；不以减少时间字段为由退回覆盖旧内容。
