# CHNHCM-107 首条资料维护收敛到通用操作

登记信息：[registry.json](../governance/registry.json)。适用范围：M02首条日期/名称更正及随后普通资料新增。用户已明确采纳两次独立保存，要求取消专用入口和保留选择；长期规则由011—013维护。

当前范围补充：[109](../archive/plans/109-lifecycle-pair-maintenance.md)已按用户决定替代公开通用联合办理：仅保留插入停用与重新启用、删除停用与重新启用。旧任意项目、跨节点交换及多目标分类纠错退出；首条两步、单条组合更正及旧历史读取保持。以下原决定和评审过程保留时点含义，当前办理以011—013及109为准。

## 1 背景与问题

统一更正已能同时修改首条日期和名称，103新增/插入已按所选位置办理。原“补全首条历史”额外要求保留原日期资料的选择，并把两步强制组合一次保存，增加入口和表单分支。用户接受每步结果立即生效、第二步可单独取消或重办，因此不再要求该场景必须联合。

## 2 决策

首条前移及名称变化直接从更正记录办理，不展示“补全首条历史”“补齐首条历史”或“是否保留原日期资料”，不自动新增原日期节点。首条recordId和CREATE类型保持，日期不早于企业起点且仍最早，普通更正守卫全部保留。

原6月1日乙，可先更正为1月1日甲并保存；如果6月起确实应为乙，再选择1月记录，用新增记录或插入记录明确填写6月1日乙及资料变更原因，第二次保存。没有后继时显示新增记录，有后继时显示插入记录，日期继续受所选位置约束。原6月值不是独立保留开关，普通新增按所选资料带值，用户填写需要的真实差异。

每次成功各产生独立来源、日志、事件与提交结果；两次之间按第一步结果正常查询。第二步取消、无变化、拒绝、撤权或结果未明不回滚第一步；原结果按各自提交恢复。后继独立资料、停用继承及旧来源按既有规则解释，不抹除第一步或原6月修订。

首条仍使用两次独立普通办理；后续109已取消可自愿使用的通用联合，两个固定启停操作不能用于首条资料维护。107原批次验证和业务历史保持。

## 3 备选方案与取舍

| 方案 | 代价与业务语义 | 决定 |
| --- | --- | --- |
| 保留专用首条补全向导或迁入保留开关 | 仍需用户判断一项可由后续新增表达的选择，并维护专用分支 | 移除 |
| 更正后按需独立新增/插入 | 两次独立事实立即可查，第二步不影响第一步已保存结果 | 采用 |
| 显式联合请求 | 107原批次曾保留，109收窄后退出 | 当前不支持首条联合编排 |
