# CHNHCM-113 BU列表改用Community并保留既定规则

登记信息：[registry.json](../governance/registry.json)。适用范围：M02业务单元列表的组件选择、源码接入及受影响验证。依据用户“除了不引入pro，其他的规则按之前已经确定的执行”，沿用[110交互决定](110-bu-list-and-datagrid.md)、[012功能合同](../specs/m02/012-m02-functional-and-interaction-design.md#m02-ui-list-pro)和[013接线合同](../specs/m02/013-m02-technical-design.md#m02-tech-list-pro)；由[111计划](../plans/111-bu-list-experience-upgrade.md)实施。本文从[决策模板](../templates/decision.md)起草。

当前普通维护按[123](123-current-maintenance-and-dated-query-boundary.md)取消通用查看日期；列表日期由服务端D确定，详情按所选记录。此前时点的采纳/检查记录保留，本决定其余列表体验与技术边界继续有效。

## 1 背景与问题

2026-11-03，固定工作树wt-dev-b、基线`5748df9a5882865002df563fc0615b19ca312901`已接入Pro 8.29.3源码，完成基础列表接线及部分UI适配检查。业务列表当前允许无密钥挂载，官方许可水印及提示仍存在；真实Go/API/DB业务及完整视口验收尚未完成。历史结果分别由111的T01、T02、解除阻断和简化报告持有。

用户先撤销Pro选择，后指定CubeBox部门列表并明确“不再要求列拖动和固定”。当前Community源码、依赖和T02-A/B/C已接线，保留原生菜单/显隐/列宽/恢复及其余既定规则；实际类型/构建、组件和合成HTTP定向检查见[本轮报告](../verification/111-community-t01-t02.md)。该组件报告本身不等于真实业务；后续T03的真实Go/API/DB及七组条件已单独执行，见[新报告](../verification/111-community-t03.md)。旧Pro报告保持原基线。

## 2 决策

### 2.1 组件、来源与构建

采用`@mui/x-data-grid`的Community `DataGrid`。选择8.29.3及mui/mui-x固定提交`109f5a0c73075355f755352ad2849d52a01197b5`，与当前基础层一致，不因CubeBox使用8.27.0而自动降级，不升级React/MUI主版本。Community采用MIT许可，无DataGrid商业密钥配置要求；第三方许可原件与来源仍须保存。

未转译源码接入继续执行：本仓packages/mui-x-data-grid保存固定提交原字节运行TS/TSX，由Vite转译。原始运行输入归档及501项逐文件摘要、官方同版500份声明及声明归档，见[接入清单](../../packages/mui-x-data-grid/upstream.json)。TypeScript的types导出条件使用官方8.29.3声明，runtime/default入口仍为原始src；用于避开上游实现源码与本仓React声明的类型冲突，不引入发布包的编译JavaScript。React/MUI Core及基础依赖继续精确发布包，本仓构建自足；未导入整个上游构建工具或测试集。

Pro运行源码包、工作区引用、x-license、许可初始化/环境声明、专用releaseInfo插件及旧夹具路径已退出。当前仅Community运行入口，无Pro可选模式或Table回退。原Pro来源/许可证/报告保持，原接入摘要另按原字节保存在[112历史清单](../reference/112-datagrid-pro-upstream.json)。无水印/许可提示的实际组件检查见本轮报告，不通过CSS遮挡或console过滤实现。

构建自足、纯build与本地运行profile解耦、显式来源核对而非每次构建门禁等决定保持。原Pro来源归档、许可证、来源登记及验证原件继续作为历史资料保存，排除于运行构建；移除的是运行路径，不能删除或重新标为MIT的商业源码原件。

### 2.2 既定交互与响应式展示

当前功能规则唯一维护于012，技术约束唯一维护于013。下表限定本次选型变化的影响，不重新作业务裁决。

| 范围 | 继续执行的规则 | 本次技术替换 |
| --- | --- | --- |
| 控制区与导航 | 新建、标题、更多操作；日期/状态按需面板；设置→组织配置→业务单元入口 | 保留已完成布局；不恢复常驻筛选行或扩大模块导航 |
| 搜索 | 文本输入框＋查询按钮，A/D及面板局部草稿事件规则不变 | 不引入CubeBox客户端搜索引擎、实时搜索或新查询语义 |
| 表格与分页 | 桌面四列、现行服务端排序、GridPagination、默认20及20/50/100 | DataGridPro及Pro API类型换为Community；仅一套受控分页状态 |
| 名称与返回 | 仅名称真实链接，其他单元格/行不导航；当前授权重查后恢复对象、滚动与焦点 | 适配Community滚动/渲染API，保留慢行等待及用户操作优先 |
| 窄屏 | 低于900 CSS px名称主行＋编码/状态/日期次行；同一查询、分页、排序和选中身份 | 采用CubeBox式摘要列，按宽度切换列模型，退出Pro listView |
| 主题与表达 | CHNHCM保留较深的`#066b68`；日期按[026](026-date-display-and-input-format.md)统一YYYY-MM-DD，状态表达和字段读权继续 | 不恢复CubeBox较浅顶栏或借组件替换批量改文案/字体 |
| 业务及保护 | Go权威、授权裁剪、请求/会话代际、历史和未知提交恢复继续 | 不改OpenAPI、Go DTO、SQL、领域模型或生成客户端 |

摘要列只显示API已裁剪字段，保留名称链接的浏览器原生操作；不维护第二套手机查询。切换列模型时搜索D、A、分页及对象ID保持，桌面列偏好不隐去手机摘要；若组件需重挂载，按012恢复可用焦点和返回位置，不让搜索框重挂载丢输入。

### 2.3 纯展示列能力与后置边界

Community原生列菜单、显隐、列宽及“列设置…”恢复入口已接线，全部隐藏可恢复。列拖动/固定及额外顺序调整取消，不建设相关自研适配，默认顺序服从列定义。桌面普通列及summary列保持同一字段集合，媒体条件仅控制可见列；桌面显隐与宽度不被摘要布局或A/D变化覆盖。

列显隐与宽度只作用于当前获权结果及当前挂载期，A或D变化不重置这两类展示状态，不引入跨会话偏好、服务端列API或新的授权缓存。记录排序继续使用既有Go/API白名单；取消列拖动/固定不改变查询排序、权限或返回语义。

T04已比较Community单条件面板、按需应用及必要的自有条件UI，结论维持现行查询、列条件后置；后续单条件优先候选见110第2.4节，不能沿用“Pro原生多条件编辑器已可用”的假设。本次另行采纳单列条件（含状态同列多值）及应用/取消，按110第2.6节及011—013接线；原T04结论保持历史。完整Excel式候选、跨列组合、通用高级查询、收藏/分享增强、分组及114未采纳的其他导出继续后置；新增字段/操作符/组合须先补服务端合同。现有q/status不能冒充独立列条件，不能对当前页过滤后宣称全量结果。

### 2.4 CubeBox部门列表样板及采用边界

样板为用户指定的`http://localhost:4180/#/org/units`部门列表，带departments搜索条件及department_panel=1。桌面1440×900、手机390×844、日期和列菜单的实际观察、构建身份、九个关键文件摘要见[部门样板依据](../reference/113-department-list-template.json)。只采用通用体验，不将样板的部门对象、字段或原型引擎作为BU业务。

| 样板部分 | 当前采用 | 保留的CHNHCM差异 |
| --- | --- | --- |
| 三段控制区 | 左侧新建/标题/更多，中间搜索，右侧记录范围及分页 | 搜索仍为文本框＋查询；日期/状态面板及A/D保持 |
| 表格面板 | 浅色背景、白色面板、细边框、顶部圆角、紧凑行分隔 | 标题18px/600、字号14px及控制区12px/20px已相同；不盲目锁定截图行高 |
| Community表格与列设置 | 原生列菜单、显隐、列宽、恢复入口 | 列拖动/固定取消；表头只接现行服务端排序 |
| 分页与窄屏 | 紧凑范围，摘要列及响应式控制区 | 继续GridPagination和20/50/100，手机大小入口可达；名称主行＋元数据次行，无重复表头/标签 |
| 名称与主题导航 | 采用列表视觉层次及菜单/抽屉适配经验 | 仅真实名称链接进入，现有CHNHCM菜单及#066b68保持 |

部门树、含子部门/含无效、层级视图、负责人/路径/人数继续不纳入BU；多选工具条及导出不属于111原批。后续[114](114-bu-query-selection-and-export.md)仅采纳完整授权查询结果选择及CSV导出所选，由115另批实施，当前已实施，限定结果见115实施报告；不复制search JSON、department_panel、客户端切页或useDemo。手机样板在department_panel=1时先打开部门抽屉，这不是BU窄屏列表默认状态。不因样板含按钮、菜单或截图，就增加相应业务API或验收承诺。
