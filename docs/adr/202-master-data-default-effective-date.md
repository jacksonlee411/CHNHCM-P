# CHNHCM-202 配置与主数据默认生效日期

登记信息：[registry.json](../governance/registry.json)。适用范围：全项目配置数据、主数据及采用相同初始资料语义的对象首次新建。用户于2026-11-13明确：“配置数据、主数据等的默认生效日期为1900-01-01”。本决定将该项目规则与当前日期、后续业务变化日期及来源日期区分。

上游：[025全新实施](025-greenfield-implementation-policy.md)、[026日期格式](026-date-display-and-input-format.md)、[123普通维护日期](123-current-maintenance-and-dated-query-boundary.md)、[124对象接入](../guides/124-dated-object-admission-and-capacity.md)。

## 1 背景与问题

现有BU规格明确拒绝沿用CubeBox的1900默认值，部分创建流程使用服务端今日。用户本次确定新的项目规则，需要同步当前合同并列出产品适配任务。国家/地区及区划来源同时包含发布日、观察日及数据版次，这些日期也不能与初始默认日混用。

## 2 决定

### 2.1 默认日期与适用操作

配置数据、主数据首次新建的生效日期默认1900-01-01，包括企业初始资料、BU、部门，以及本批国家/地区、行政区划和地点。界面使用共享日期组件直接显示完整值，用户可修改；默认值由Go权威入口给出，不由浏览器当前日期或前端独立常量决定。

本规则针对尚无首条记录的对象初始化，不将已有对象新增变更、插入记录、停用、重新启用、改日和固定期间的日期统一改为1900。后续操作仍执行各自位置、生命周期及关系合同；更正表单保留原日期。员工入职、任职变动、薪资计算期间、打卡等业务事件不因含日期字段自动归为主数据初始化。

### 2.2 显式输入和业务资格

用户明确输入、导入文件明确提供或已有记录保存的日期必须保持；不因与默认值不同而自动改为1900。公开写API继续要求完整有效日期，缺失/null/非法日期仍按合同拒绝；Go创建上下文返回默认，表单或受控初始装载工具明确填入后再提交。不新增“缺日期就偷偷改1900”的协议。

默认不表示已通过资格。若实际企业、BU、上级或其它必需引用的有效期间不覆盖1900，应按业务字段返回准确拒绝，允许用户明确改为合法日期；不得静默改用今天、自动移动上级首条或清空关系。新隔离环境的企业初始化也按本规则默认1900；既有持久企业起日、业务历史和终态不自动更改。

### 2.3 默认与历史含义

1900-01-01表示初始化资料采用的默认生效起点，不证明国家、行政区划、企业或地点在该日真实成立。来源发布日、来源数据截止日、观察日、已核实的实际行政变更生效日分别保存；未知的实际行政日期保持未知，不用1900补造。

对于按当前来源包初始化的参考目录，目录在系统中的首条可从1900适用，但说明其证据覆盖的是指定来源版次，不宣称已还原1900以来行政沿革。用户明确提供的真实历史按独立来源导入，不由默认目录推断。

### 2.4 查询和运行时刻

服务端今日D、列表按今日查询、详情按所选记录、未来首条“未生效”、北京时间记录时刻均保持原语义。不得把默认日期作为服务器业务日、列表查看日或记录时刻，也不新增通用查看日期控件。

## 4 实施与验证

Go用一个常量/纯函数提供初始默认，各对象context、导入及初始化路径复用，defaultEffectiveDate与currentDate分别表达初始默认和今日。前端仅在首次创建或明确重置表单时取默认，不新建默认日期配置服务、注册器或策略平台。

1900是默认值，不是全项目最早合法日期。对象适配层提供真实最早允许日期，dated的创建、候选、改日、位置新增和启停窗口统一消费该边界；BU/部门/Location保留企业范围，地理参考对象使用既有日历范围。明确的1900以前日期只按该对象真实资格校验，不能因默认1900而额外拒绝。X01如复用日期值工具，也不放入完整对象生命周期。

200 G1须补验以下独立预期：

1. 现有企业初始化工具及BU/部门创建默认1900-01-01；本批新对象随各自切片接同一默认，直接提交完整日期。企业没有正常创建页面时不为本规则新建企业管理模块。
2. 用户改日、保存失败、辅助重读、跨午夜或返回表单不覆盖已输入值；明确重置表单恢复1900默认。满足真实资格的显式早期日期不被默认值拒绝。
3. 既有企业或上级晚于1900时拒绝不合法候选；明确改为合法日期后可保存，原依赖历史保持。
4. 同一已有对象追加/插入、停用/恢复、固定期间仍使用原操作规则；更正保留原日期。
5. 缺失或非法API日期拒绝；只读角色和无字段权用户不能借默认绕过权限。
6. 旧来源、原提交恢复、现有列表今日语义及记录时刻保持。

决定编制时仅完成合同同步；随后[200 G1实施](../verification/200-g1-default-date.md)已完成企业初始化及BU/部门接入，并记录上述范围的专项、完整清单分组及浏览器复验；国家/区划/地点随各自切片接入。

## 5 取舍与后续维护

统一初始默认可减少配置和主数据创建时的日期输入，但可能暴露已有依赖起日较晚的问题；准确拒绝及用户明确改日保留业务语义。相较直接改历史或放宽关系覆盖，本方案只调整缺省初始选择。

本决定依据用户明确项目规则登记采纳，文档与来源核对见[200报告](../verification/200-geography-plan.md)。后续对象如有不同的初始化语义，应明确其是否属于本规则范围并登记具体依据，不能因旧前端写死今天而自行豁免。

本次[共用能力评审](../verification/200-geography-design-review.md)只澄清默认值与下界、最小实现及各对象接入时序；用户1900规则和原历史保护均保持；评审当时未实施，后续产品结果由200 G1报告持有。
