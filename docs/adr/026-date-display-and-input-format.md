# CHNHCM-026 统一业务日期显示与输入格式

登记信息：[registry.json](../governance/registry.json)。适用范围：项目共享UI的完整业务日期、日期输入及记录时刻；当前接线覆盖M02已实现页面。上游为用户2026-11-03关于统一为YYYY-MM-DD的明确决定、[012交互规格](../specs/m02/012-m02-functional-and-interaction-design.md#m02-ui-date-display)、[013技术合同](../specs/m02/013-m02-technical-design.md)及[025](025-greenfield-implementation-policy.md)。

[123](123-current-maintenance-and-dated-query-boundary.md)取消普通维护中的查看日期及其草稿交互；本决定的日期格式、输入与时刻规则继续有效，原验证报告保留当时范围。

## 1 背景与问题

API与Go业务日已使用YYYY-MM-DD，共享businessDate却输出中文年月日，原生日期输入还依赖浏览器语言与操作系统显示。当前完整日期应统一一种格式，不增加格式配置或多套兼容显示。原生date输入的值与显示不同，见[浏览器参考](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/date#value)；仅修改显示函数或页面lang不能保证输入区统一。

## 2 决策

### 2.1 业务日期

所有面向用户的完整业务日期统一为`YYYY-MM-DD`，例如`2026-01-13`；年份四位，月日各两位。列表、详情、日期轴、日期菜单、业务表单、反馈、期间、历史来源及变更对照使用同一规则，日期轴不省略年份。缺失或无效格式保留明确不可用反馈，不以今天替代。

业务日仍为0001-01-01至9999-12-31的纯日期，不通过Date/UTC毫秒或用户浏览器时区改变业务日。前闭后开、不含当日、开放终点和过去/未来含义保持；Go继续拥有日期及业务不变量的最终校验。

M02 记录详情与单条删除、首条改日晚移的资料空档、成对删除产生的可见资料变化均展示至 Go 给出的最后适用日。有限段写作“YYYY-MM-DD 至 YYYY-MM-DD”，开放段写作“自 YYYY-MM-DD 起”。当前日期读权和读取投影约定见 [013](../specs/m02/013-m02-technical-design.md)。

### 2.2 日期输入

共享DateField显示和接受ISO文本，支持手输、粘贴、清空、必填、只读、禁用、焦点及错误定位；空输入占位YYYY-MM-DD，不重复附加中文回显或接口格式说明。

日历按钮调用原生选日并将结果写回ISO文本；原生输入不作为可见文本框，不新增日期库或手写业务日历。选日面板的年月导航、星期可继续本地化，它们不是另一种完整业务日期显示。输入完整性、日历有效性及服务端min/max只作辅助，不替代Go最终校验。[showPicker参考](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/showPicker)

真实编辑继续触发未保存保护，初始默认不触发；写入日期使用明确操作生效日，普通维护不保留查看日草稿。撤读权时清除可见文本、隐藏选日值及相关缓存；测试同步更新ISO负向断言，不能因仍检查旧中文日期造成假通过。

### 2.3 记录时刻与历史证据

记录时刻按Asia/Shanghai显示为`YYYY-MM-DD HH:mm:ss（北京时间 UTC+08:00）`，保留时分秒；来源说明中的原始时刻继续展示服务端原串及精度，不截断RFC3339证据。格式不改变排序、日期计算、权限、来源或审计内容。

## 3 备选方案与取舍

| 方案 | 局限与成本 | 决定 |
| --- | --- | --- |
| 只修改businessDate | 输入仍随浏览器本地化 | 不采用 |
| ISO文本加原生选日 | 复用MUI及浏览器；面板外观仍由浏览器决定 | 采用 |
| 新增格式设置、日期库或自建日历 | 当前只有一种确定格式，增加维护面 | 当前不采用 |

## 4 影响与验证

共享UI、M02表单/反馈/日志、日期轴布局及可访问名称、浏览器定位与负向断言、现行视口脚本同步更新。API、客户端、Go、数据库迁移、幂等结果和历史原件保持；未实现的导出不增加本轮范围，后续新增日期展示遵守本决定。

验证格式与跨午夜北京时间、两种locale输入、选日回填、闰日、0001/9999边界、无效/空值、只读/禁用和范围；正常菜单创建、更正、启停、删除、历史及撤权，另检查日期轴/窄屏。原026验证中的查看日草稿仅作当时证据，123后不再提供该功能。实际结果由[验证记录](../verification/026-date-display-and-input-format.md)持有，本文不代替实现验收。

## 5 适用与替代关系

替代012日期显示条款及100计划R06中完整日期使用中文年月日、原生日期输入中文回显的当前约定；100其余体验及业务边界继续有效。012持有交互，013持有纯日期/时刻边界，026持有项目格式决定。原验证报告、截图、日志和来源资产保持原结果，不批量替换历史，不保留两套当前显示。

## 6 待决事项

无格式待决。默认桌面Chromium，其他浏览器与原生选日面板视觉一致性不在本轮验收范围；生产、消费者及未实现模块不因格式统一计入完成。
