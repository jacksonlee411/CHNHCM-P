# CHNHCM-213 本阶段管理员维护与业务生效

2026-11-27，用户明确本项目现阶段的业务实施均采用管理员维护生效管理。此阶段决定适用于所有模块纳入实施的业务办理，包括配置、主数据和业务记录的维护。[项目阶段](003-implementation-stages.md) · [登记表](../governance/registry.json)

## 1 维护与生效

由具备对应对象、动作、字段及数据范围权限的管理员直接办理。「管理员」指实际获授该职责的人，现有业务角色可以按授权分别承担维护职责。新建、新增或插入生效记录、更正、停用、重新启用以及获准的撤去或删除，都由一名有权管理员一次提交。**现阶段所有这些动作均不采用人工复核工作流。** 页面和接口直接返回办理结果，不设送审、待复核、第二人批准或自动代批步骤。[授权合同](../specs/x03/028-local-account-and-authorization.md)

**按日维护的记录一次保存，按指定的生效日期采用。** 保存成功即形成业务记录并返回回执，没有另行“发布”的操作或“待发布”状态。提前保存的未来记录立即可在时间轴查看。生效日前，已有对象仍按当天有效的记录取值，首次新建且尚未到生效日的对象暂无适用记录。自指定日起自动采用新记录。原资料误录走同一记录的更正，保留原生效日和旧修订。其他业务动作按所属对象已定义的生效条件办理。[日期与历史](../specs/m02/120-dated-maintenance-technical-contract.md)

## 2 命令、页面与验收

| 业务情况 | 实施与验收要求 |
| --- | --- |
| 管理员在正常入口保存或确认业务动作 | Go 在提交事务内检查当前授权、目标版本、业务规则及适用的引用期间。成功即返回办理结果，页面定位到该记录。按日对象同时显示实际生效日。全程只需该管理员。 |
| 只读、失权、无效输入或版本冲突 | 只读者仅见获权资料。管理员打开表单后失权、输入不合法或依据过期时，给出可处理的反馈，拒绝本次写入。来源变化后按新依据重新核验。 |
| 更正、撤去、重送或取消 | 保留实际操作者、必要审计、准确修订、原采用和原办理回执。重送按原请求查回。放弃未保存输入不产生业务版本。 |

## 3 与既有合同的关系

目标架构描述了未来可选的人工核准能力。本决定明确当前实施阶段的选取范围。各域保留服务端核验和各自的业务事实，实施时不建立复核岗位、审批待办、审批状态或虚构的决定记录。系统在提交时检查权限、可用日期或依赖，以及管理员本人确认停用等有后果的动作，都在同次办理中完成。[领域核验与生效](../architecture/target/10-ddd-and-state-contracts.md#current-maintenance-effectivity) · [直接保存](101-direct-save-and-form-assistance.md) · [必要审计](128-authorization-evidence-removal.md)
