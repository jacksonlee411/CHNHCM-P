## 1 背景与问题

### 1.1 已确认的占用

781698次访问判定属于133301个请求；同一请求、主体、动作、决定、原因、策略号、提交身份和证据根完全相同的组中，有232576条额外事件，占判定事件29.75%。这是重复记录已持久化的输入和结论，不证明发生了重复业务提交，也不意味着所有阶段的重新判权都可以跳过。

119份列表投影证据中，118份各包含87344个目标、262031个意图及逐项结果。共享后的投影内容约17.32MB，当前存储主因仍是命令根与Intent；但列表在分页前组装全量判权材料的计算开销同样需要处理。不能据此宣称每个链接、每次页面刷新都会独立复制一棵完整组织树。

### 1.2 过度设计是怎样形成的

| 诱因 | 合同或实现事实 | 需要纠正的推导 |
| --- | --- | --- |
| 把“现在必须有权”扩大成“以后必须完整重演每次判权” | 原013第6.3节要求每次查询、预览、命令、重试和resolve保存完整输入、Grant及匹配结果 | 当前安全判定是必需能力；永久保存执行过程需要独立、明确的业务用途，不能自动成立 |

| 用另一领域的判权快照补齐业务终态 | `RecordedIntent`、`validateDecisionReference`及`Terminal.Decision`参与恢复和完整性检查 | 请求定位及原结果应由M02自有终态负责；不应先读取X03全过程才能解释自己的提交 |
| 先固定昂贵表示，再围绕其优化 | 126第3.4节保留完整快照语义，只共享和压缩；测试继续要求保存和还原完整过程 | 首先审查是否需要保存，再选择编码；压缩和更多索引不能使无消费者的数据成为必需 |
| 全量列表材料兼作证明材料 | 当前读投影为全部目标构造意图、结果和引用数组，再分页 | 应区分获得准确查询结果的计算与永久存证；精确总数不要求永久保存整批推导过程 |
| 容量反馈晚于合同固化 | 原55GiB成员/路径展开问题与本次授权过程问题都在大规模验证中显现 | 设计阶段必须列出数据消费者、保留理由、行数增长及实测成本；测试应验证业务目标，不维护无必要机制 |

以上为合同、源码和测量能够支持的因果分析，不推测个人动机。55GiB案例中的业务历史重复展开已经由126处理；本决定主要撤除其仍保留的授权过程档案。业务历史、准确来源和部门路径证据有真实消费者，不能与授权过程快照混为一类全部删除。

### 1.3 关联链接引出的计算与存储链路

2026-11-08用户追加指出详情页链接及由此产生的检验和存储同属过度设计。本次核对当前源码，确认删除范围应包括链接能力本身，不能仅取消其审计。追加检查见[关联跳转补充报告](../verification/128-reference-link-removal.md)。

| 层次 | 当前实现 | 归因与限制 |
| --- | --- | --- |
| 页面 | DepartmentRelations将管理BU、行政上级及路径祖先名称按canOpen渲染为Link，URL由稳定ID拼接 | 这些是关联快捷跳转；URL没有单独的数据库表，不能按链接数估算整棵树副本 |
| 预判 | projector.ref取得名称/编码的引用读权后，再发reference-link意图检查目标完整详情权；本请求按kind:id缓存 | 额外目标可打开判定只服务跳转，错误还可能沿投影返回；取消链接应同时取消该调用，不保留“为可能点击预备” |
| 批量 | listAuthorization为每个部门构造object/reference/reference-link三项，为每个BU构造两项 | 87343部门和1BU时共有262031项；仅去掉跳转项即少87344项，剩174687项。这是源码静态计数，不是已测吞吐或空间收益 |

生成历史编解码器确有BeforeRecord/AfterRecord引用的CanOpen编码分支，但正常写入先Persist、再populateResultItems；不能据此声称所有链接或全部投影都已写入历史。本次未单独测出跳转的毫秒数或字节数，不把全部907.66MB授权两表开销归于链接。

## 2 决策

### 2.1 授权计算不默认产生持久证据

X03继续由Go判断当前主体、会话、动作、对象范围、字段范围和引用权限；继续执行策略守卫、撤权并发控制及必要锁后复验。授权依赖不可用时仍不能返回受保护数据或完成写入。

普通列表、详情、历史读取、关系候选、预览、按钮能力、路径链接、选择/resolve，以及业务命令中的每次判权，均不再写完整授权过程或独立`access_decision`事件。普通成功读取产生的授权审计行数和授权内容字节数必须为零。会话有效期维护与真实登录事件单独计量，不把这条要求误解为HTTP GET完全没有数据库写入。

判定结果只在本请求所需生命周期内存在。可以共享本请求相同事实下的计算，不能跨请求缓存允许结论；锁后事实、策略或会话变化时必须重新核验。保留安全性所需的重复检查，去掉它们重复存档的副作用。

不保留原机制的开关、空实现、兼容列、兼容视图、双写或备用算法；不改名为“请求证明”“操作追踪”“诊断快照”继续保存。也不将同样正文转移到文件、对象存储、Outbox或无限增长的日志中。

### 2.2 只记录有明确用途的事实

| 事实与用途 | 保存位置及最小内容 | 不保存的内容 |
| --- | --- | --- |
| 谁实际修改了哪条业务记录；读取历史、日志和准确来源 | 继续使用M02来源/修订、操作摘要和结果；保留操作者身份快照、时间、动作、准确目标及结果 | 不另复制完整表单、整棵树或授权执行轨迹；不再为每次判权复制业务审计 |
| 本次提交是否成功；重试、查回和封闭本人未知提交 | M02自有终态保存提交身份、摘要、必要请求定位、原结果/安全拒绝；见第2.3节 | 历史授权事件ID、完整Grant及匹配数组 |
| 认证、会话撤销、账号/授权配置真实变更 | 复用X03安全事件；记录发生时间、实际操作者、事件动作、受影响主体/配置身份、请求关联、结果及原因；配置变更只保存实际变化所需事实 | 不在每次判权重复保存全部账号状态、所有Grant、算法及匹配过程 |
| 已有导出等明确需查证的敏感操作 | 以实际操作为单位记录必要事件；导出只需主体、时间、请求/导出关联、对象类型、字段名、行数及结果等摘要 | 不保存每个对象的Grant匹配过程、完整结果正文或完整目标清单 |
| 服务排障 | 复用有界运行日志和聚合指标；必要时短期、受控排查 | 不建立通用永久调试档案，不默认捕获请求正文、cookie、密码或完整权限快照 |

这张表是允许保留的用途边界，不要求为了填满表格新增尚未接入的安全管理或导出审计平台。已接入的必要事件复用既有设施；新增事件须指出实际消费者。普通按钮不可用、关系不可选等正常判定不能自动升级为安全事件。确需记录异常访问时以请求及安全事件为单位，不能按每个目标/字段/检查阶段逐项写入。

实际业务事实、终态、业务日志及Outbox保持原子性；必要安全配置变更与其最小事件保持原子性。删除完整判权证据写入后，也删除“证据写失败导致普通读取失败”的依赖。一般排障日志失败不阻断已合法授权的读取；这不放宽当前授权本身或业务原子提交要求。

### 2.3 业务终态自行解释原提交

删除`authorization_decision_id`、`Terminal.Decision`及`Guard.RecordedIntent`的业务依赖。四种终态accepted、rejected、no_change、not_applied仍按既有协议解释，不改成“查不到授权证据就是未提交”。

M02在严格解析请求后，只保存恢复确实使用的请求事实：实例/主体/提交身份、动作、摘要、原对象/记录/修订、预期来源，以及相关动作需要的锚点、声明字段和逐项定位。优先使用终态已有字段；缺少的锚点等补入对象自有强类型终态。字段须能指向具体恢复读取点，不引入通用原始请求JSON或另一套完整Intent档案。not_applied没有收到原正文时继续不补造原动作、摘要、目标或声明字段。

终态与业务来源/修订/操作项的归属、唯一性、完整性和封口在M02内验证；不再查询`access.security_event`证明一条业务终态有效。当前命令仍须通过X03判权，原结果查回仍须执行当前会话、本人提交身份及适用对象/字段读取规则；旧allow不能充当现在的许可。

删除与更正后的原结果、无变化ADD锚点、显式null/同值字段声明、固定启停的逐项结果、无正文resolve、迟到提交和COMMIT未知均须保留原语义。删除业务依赖不能通过丢弃这类事实实现。

### 2.5 类似放大机制的处理边界

列表必须分开考察筛选、权限、路径、精确计数/集合摘要与返回页装配。只为返回页和确有消费者的中间结果构造DTO；能安全提前筛选的条件提前使用。若精确总数或选择摘要确需遍历完整候选，使用紧凑的请求内计算，不再序列化成永久证明材料。存储查询只能提供事实和安全预筛选，Go保持业务和权限唯一权威。

不能先分页再漏判其他候选，却继续声称获得了准确获权总数、全选或完整CSV。完整集合选择、字段裁剪、来源一致性、祖先名称读权、撤权和全量导出失败时不输出部分CSV继续有效。计算整改与删除存储分别验收，后者成功不证明列表性能P1关闭。

部门字典表103.72MB，是后续审查点；占用本身不能证明哪些字段多余，也不能证明跨对象重复值都能无成本消除。固定字段/类型标识优先考察类型化编码与对象内复用；测量整行、索引、查找及解码成本，不能为少量节省新增全局可变字典和新的跨对象锁。

每条历史必须能定位到当时的准确资料/父边来源，父部门改名或调动不能改写旧来源。继续复用已经相同的业务内容，禁止恢复每版本完整展开成员/路径的旧布局，也不以当前组织树反算并替换旧历史。三份原始来源、历史原名及未建模扩展原值继续保留；不通过删验证来源或业务历史凑容量。

### 2.6 取消关联快捷跳转及其专属机制

详情“组织关系”中的管理业务单元、行政上级和部门路径祖先统一显示获权名称/编码或路径文本，不再提供关联跳转、可点击样式、跳转提示或替代的额外按钮。相同投影被列表、关系选择/筛选及结果恢复复用时，同步去掉仅为跳转计算的数据；不为这些调用保留一套未使用的链接能力。

删除reference-link意图/结果分支、额外bu.read/department.read预判、canOpen/CanOpen字段、相关缓存失效条件、路径与集合摘要中的跳转位，以及专属DTO/生成客户端/编解码分支和测试断言。详情已有Go生成的路径文本与分段日期，页面直接消费它们；取消仅为逐节点导航下发的nodes及DepartmentPathNode公开结构，不再为展示名称重复下发源/记录/修订/父边引用。领域内部确切路径来源仍按真实历史消费者处理，不因取消公开节点DTO再新建影子结构。

引用名称/编码的当前读权仍需核验，可读引用不要求目标完整详情权；编辑关系仍需稳定ID、字段写权、候选资格及保存时的关系不变量检查。历史路径真实性与原来源还原按业务历史合同保留；不能因去掉跳转就泄露无权名称，或把祖先关系合法性检查一并取消。每个保留字段必须指出其展示、维护或历史消费者，不以“原链接曾使用”作为保留理由。

正常菜单、列表打开本对象、返回列表/日志以及时间轴/准确业务来源定位有独立任务用途，本次保留。目标页面经正常入口打开时继续执行该请求的当前读权。取消的是提前为关联快捷跳转构造能力及证据，不在原详情预判另一个页面，也不新增“点击再鉴权”替代链接方案。

### 4.3 容量解释与复发约束
