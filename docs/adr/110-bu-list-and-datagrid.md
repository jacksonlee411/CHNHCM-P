## 1 背景与问题

起点为2026-11-03的wt-dev-b、`94dd06466ffc44ee233e600d99f3bb82218a143b`，当时工作区干净，共享DataGridPage实际使用MUI Table，控制区常驻日期、状态和排序，窄屏逐项展示字段标签。用户先采纳Pro及紧凑控制、现有搜索草稿、真实名称链接、紧凑分页和窄屏摘要；整行进入详情不采纳。随后改为未转译源码，并要求解除多余限制。

## 2 决策

### 2.1 基础改造与展示能力

| 内容 | 继续适用的决定 | 当前技术承接 |
| --- | --- | --- |
| 控制区 | 新建、标题、更多操作；保留文本框＋查询按钮；日期/状态按需面板及非默认摘要 | 保留已有布局、授权、面板局部草稿和焦点恢复 |
| 桌面列表 | 四列、仅现行表头排序；不恢复MUI Table | 113采用Community DataGrid，Go查询合同不变 |
| 窄屏 | 低于900 CSS px名称主行＋编码/状态/生效日期次行 | Community摘要列替代Pro listView；同一列表状态 |
| 分页 | GridPagination在控制区右侧；默认20及20/50/100，记录范围及空集表达 | Community原生分页；不另建分页状态机 |
| 纯展示列 | 原生菜单、显隐、列宽；更多操作的列设置可恢复全部隐藏 | 按用户补充裁决取消列拖动/固定及自研适配，采用113部门样板边界 |
| 查询功能 | 基础阶段现有q/status；T04评估完成，用户另采纳单列条件及应用/取消，见第2.6节 | 不因组件具备入口就开放无API合同的语义 |

常驻筛选行、行导航、多列排序、行编辑、114以外的导出、分组及未承接查询条件继续关闭。保留纯展示列能力不意味着增加服务端条件或业务写入。较深的`#066b68`主题、日期展示/输入按[026](026-date-display-and-input-format.md)统一YYYY-MM-DD，状态表达保持。

### 2.2 必须保留的合同

正常入口仍为设置 → 组织配置 → 业务单元。管理员按动作权限新建，查询者只读；仅名称真实链接进入详情，支持Enter、Ctrl/Cmd、中键、新标签和复制地址。其他单元格与行的点击均不进入详情。列表操作不写业务事实，详情维护及不可变历史保护保持。

搜索D、已应用条件A及完整事件规则由[012查询状态](../specs/m02/012-m02-functional-and-interaction-design.md#m02-ui-query-state)唯一维护。日期与状态面板使用独立局部草稿；应用时按012合并动作时D并回第一页，取消不改变A/D。分页、改大小、重试仍用A并保留D。保留直达、刷新、前进后退、详情对象导航及返回选择/滚动/焦点；不设固定帧数提前放弃慢行，不抢用户后续输入和焦点。

Go仍是查询语义与授权的权威，见[013查询接线](../specs/m02/013-m02-technical-design.md#m02-tech-list-pro)。组件模型不成为公开业务协议，不对当前页本地排序/过滤后宣称全量。解除多余限制不影响现行授权、历史、未知提交恢复及业务不变量。

### 2.3 列筛选评估与后置范围

评估交付物是方案比较及结论，基础实现不开放列条件。113撤销Pro原生多条件优先假设，改为比较Community单条件面板、按需应用适配及必要自有条件UI。编码/名称文字操作符、状态枚举、纯日期输入须明确，现有统一q不能冒充独立编码/名称条件，单值status不能冒充任意多值组合。

同列多值“或”、不同列“且”仍为后续建议，字段/操作符/空值/范围、A/D与API表示须在实现前定案。完整Excel式候选、搜索/勾选/数量/联动、新排序、多列排序、通用高级查询、收藏/分享增强、分组及114未采纳的其他导出继续后置，不从当前页推导全量候选。组件采购或替换均不等于上述能力已授权实施。

### 2.4 T04评估结论及方案比较

2026-11-03，111 T04的评估交付已完成；固定8.29.3源码、现行API/SQL和独立组件实验依据见[评估来源](../reference/111-column-filter-assessment.json)，执行与限制见[评估记录](../verification/111-column-filter-evaluation.md)。本批采用“维持现行查询，列条件后置”的结论；如另行采纳单条件筛选，优先评估复用公开GridFilterForm及输入器，由应用承接按需对话框和应用/取消。该候选路线不代表列条件已获产品实施授权。

| 方案 | 能复用或减少的工作 | 剩余差距与结论 |
| --- | --- | --- |
| 直接开放原生筛选面板 | 字段、操作符及输入控件 | 原生随编辑更新模型，无项目应用/取消；现有API无法表达多数列语义。本批不采用直接接线 |
| 公开GridFilterForm＋应用按需对话框 | 复用单条件字段/操作符/文字及枚举输入；无需重写供应商表单 | 应用持有局部草稿，主网格仅反映A；需白名单转换、Go查询、URL、授权及移动适配。作为另批单条件的优先候选 |
| 完全自建条件表单 | 可按业务定制所有输入 | 相对上一方案额外维护控件、操作符和键盘；仅复用不适配的输入/纯日期场景另行评估，不为本批先建通用查询器 |
| Excel式候选勾选与联动 | 可复用MUI基础控件 | 需要全授权结果的候选、计数、分页及联动合同，成本主要在服务端及业务语义；继续后置 |
| 保留现行搜索及日期/状态面板 | 使用已经过T03验证的合同和实现 | 无新增查询语义或重复入口；本批采用，不阻塞基础列表交付 |

Community的单条件限制针对filterModel.items数量；固定版本singleSelect的isAnyOf可在一个item内接收多个值，不能据此推导跨列多条件已支持。原生headerFilters属于Pro路线，不纳入当前Community方案，也不复制其源码或增设常驻筛选行。不能通过修改Community强制属性绕过限制。

独立实验已证明公开GridFilterForm可以仅编辑局部草稿，主网格的filterModel保留A，应用一次才推进A，取消/Escape不改A及搜索D；390px可按列重排。原生filterMode=server只停止客户端筛选计算，不会自动发送或实现Go查询。原生面板的输入可以复用，服务端合同和应用状态适配不能省略；不得把草稿直接放到主网格模型导致表头图标先于A变化。

### 2.5 服务端差距与后续准入

| 条件或语义 | 当前支持及具体差距 | 后续处理 |
| --- | --- | --- |
| 编码/名称包含、等于等 | q在获权编码或名称之间做字面包含；不是单列条件。例如编码AA与名称含AA的另一BU均可命中q=AA，独立编码条件应区分 | 明确字段及操作符白名单、大小写/归一化、字面字符、长度和拒绝规则，补当前Go及SQL合同后实施 |
| 单值/多值状态 | 当前status只接受all/active/inactive/not_effective；active与inactive集合不等于all，后者还包含未生效 | 现行单值继续使用原面板；多值需另定合同，不能拼逗号、重复参数或以all代替 |
| 生效日期及空值 | 普通列表用服务端D解析事实，不是effectiveDate范围；不可读字段的缺省也不等于业务空值 | 先明确比较列表已解析记录还是任一历史记录、纯日期边界及字段授权；列日期条件只比较展示记录的生效日期 |
| 条件组合与公开协议 | 当前没有通用条件或GridFilterModel参数，未知/重复查询参数拒绝；q/status在当前SQL中按既定组合处理 | 新字段/操作符/值类型/数量及组合逻辑须显式定义，组件模型只作内部输入，不成为公开协议 |
| Excel候选及数量 | 只有分页结果和一致总数，没有全量distinct候选服务；当前页不能代表全结果 | 如另行采纳，先定义获权范围、businessAt、候选搜索/分页/计数、是否排除本列条件的联动及过期响应保护 |

后续实现前，由Organization合同维护者明确字段读权/筛选权、无权字段参与策略及计数一致性，补011—013、OpenAPI、Go DTO、SQL和客户端；是否需要索引随实际查询评估，不预设迁移或缓存平台。按需面板保持应用时合并动作时搜索D并回第一页，取消不改A/D，分页/重试使用A；URL、返回及窄屏入口共用一套已应用状态，不新增手机查询引擎。候选移动入口为更多操作中的按需对话框，桌面可从列菜单打开同一编辑器；该入口仅为后续设计建议，本批不接线。

新增列条件及Excel候选的未来验收另定，不把本次7项组件实验计入TL-323—334或提升为业务通过。尚待业务采纳的操作符、空值/日期语义和组合写明为下一批合同问题；T04评估本身不再保持未完成。

### 2.6 后续采纳：单列条件与统一应用/取消

用户在T04评估后另行授权实施单列条件。当前规则由本节及011—013承接；第2.4节及原评估记录保留当批结论，不改写为当时已实施。

一份列表查询至多一个列条件：编码/名称支持contains、equals；状态支持is、isAnyOf（一个条件内多个状态为或）；生效日期支持is、before、after、onOrBefore、onOrAfter。列条件与现有q/status为且；更换列替换原列条件，不隐式累加。生效日期比较服务端D解析的列表展示记录（D早于首条时为明确标注的未来首条），不检索任意历史记录，也不改变列表解析日。无空值/否定、日期区间或多列组合。

桌面从列菜单“筛选…”、已应用图标或更多操作“列筛选…”打开同一按需对话框；窄屏从更多操作或摘要打开。复用公开GridFilterForm的列/操作符和枚举输入，文字及纯日期采用同步MUI输入，避免输入防抖未提交即应用或Date时区转换。草稿独立；仅应用（含清除后应用）合并动作时搜索D、推进A并回第一页；取消/Escape/点外部不改A/D、不请求，恢复触发控件焦点。主网格filterModel只投影A且filterMode=server；不展示原生即时面板。

服务端仅新增filterField/filterOperator/filterValue三个成组参数；状态集合使用明确的逗号枚举值，未知/重复/缺项/非法配对拒绝。Go校验，SQL按当前对象/字段读权排除无权行，再统一计数和分页；status沿用现行对象可读状态，不增加独立字段权。编码/名称同现行q执行trim＋不区分大小写的字面比较，最多400码点，不增加NFC转换；百分号/下划线/反斜杠不作通配。日期按纯日期校验，无客户时区转换。条件随URL、刷新/历史、详情对象导航和返回保留，查询不写业务事实/来源。具体技术合同见013，新增验收见023第22节。

跨列组合、完整Excel候选及计数联动、收藏/分享增强、分组及114未采纳的其他导出继续后置；不引入Pro、列拖动/固定、第二套查询引擎或新迁移。本次执行归111的T04-I增量，T04原评估保持其当批结论；当前单列增量及T05限定交付已完成，见[交付记录](../verification/111-community-t05-delivery.md)。
