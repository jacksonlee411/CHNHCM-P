# CHNHCM-123 基础资料维护取消通用查看日期与按日查询边界

2026-11-16：[306](../archive/2026/plans/306-department-path-simplification.md)精简路径展示，企业不隐式拼接，未生效/停用说明不进入路径内容。以下按日解析及历史来源规则保持。

登记信息：[registry.json](../governance/registry.json)。适用范围：当前BU、116规划中的部门及后续采用相同模式的基础资料维护。依据用户2026-11-04采纳的取消通用查看日期原则、未来对象列表补充及文档先行后实施指令；从[决策模板](../templates/decision.md)起草。业务、页面、技术合同由[011—013入口](../specs/README.md)持有，部门差异由118—121持有，实际检查与实施范围见[本批报告](../verification/123-current-maintenance.md)。

## 1 背景与问题

原BU列表/详情允许任意查看日期，详情身份区按该日期显示状态，基本资料按所选记录显示，可能同时出现启用和停用。列表、详情、返回、选择/导出还需要维护这项用户上下文。正常维护的任务是找对象、了解现状及维护具体生效记录；进入详情的定位可以由今日或明确记录确定，不能据此反推任意日期控件必需。

按日模型仍需要支持过去、今日、未来事实，业务办理需要明确生效日期，确切来源需要保留原件。这些能力与普通维护页的通用查看日期分别决策。部门路径会在本部门记录不变时因祖先变化而改变，须明确期间和来源，不能以隐藏的页面日期解决。

## 2 决策

### 2.1 普通列表与未来资料

普通列表取消查看日期控件、更多操作入口及URL继承；服务端每次读取按Asia/Shanghai确定D。默认全部状态，每对象一行：今日有适用记录时显示该记录的名称/状态/生效日期；未来更名、停用或恢复不提前覆盖今日资料。今日无适用资料但有未来首条时，显示首条名称、首次生效日期和未生效，不隐藏对象、不把未来首条当今日有效事实。名称搜索、排序、列筛选、选择与CSV使用同一展示投影及当前字段权限。

停用对象默认可查；用户选择启用、停用、未生效筛选时按D判定。未来记录不额外占一行；已有对象的未来安排从详情时间轴读取。本批不增加未来任务工作台或常驻未来变更统计。

### 2.2 详情及办理定位

普通对象入口默认选中D适用记录；未来首条对象默认选中首条。显式selectedRecordId优先，时间轴、保存/删除结果、未来记录及日志链接都按准确身份定位。明确目标不存在时反馈selectionMissing，不静默换条。来源历史按确切sourceVersion只读；返回当前来源保留合法记录身份并重读，不把旧版本令牌用于写入。

详情名称、状态、适用期间等资料统一表达所选记录，取消当日状态及查看日/所选记录对照说明。未来记录由服务端返回只读selectedRecordIsFuture供页面显示尚未生效；日期失读权时不返回肯定的未来提示。记录状态仍为启用/停用，尚未生效是相对D的时间提示。保存选中实际结果，不自动跳到今日。列表搜索、排序、分页及返回高亮独立保持；前后对象导航重新按同一筛选和当前服务端D读取。

新增、插入、更正、改日和启停继续使用明确操作生效日、目标记录及Go返回的范围/默认；Go校验完整受影响期间。取消通用查看日期不缩减追溯维护、未来安排、不可变来源、原采用及可靠提交。

### 2.3 协议、选择和跨日

普通列表/详情GET不接受businessAt；传入按未知查询参数拒绝，不保留隐藏任意日期路径。内部按日解析继续保留；普通HTTP响应中的businessAt只读，表示本次请求由Go确定的D。同次列表/详情的事实、currentDate及未来提示共用该D，不在响应组装中二次取日。选择/导出的query删除businessAt输入，服务端在同一请求事务读取D并解析完整集合；集合版本继续包含D、条件、授权和来源。跨日后旧选择返回M02_SELECTION_CHANGED，零CSV输出；客户端清空旧选择并重新查询，不自动将旧选择应用到新集合。文件名使用成功响应的服务端日期。

页面不把登录时/上下文首次加载的日期固定为永久查询日，不自行运算业务日历。OpenAPI、客户端和调用方同步改为唯一当前合同，按025不提供兼容字段或双格式。历史结果和数据库来源无需重建。

### 2.4 部门路径

列表/CSV按D显示路径；未来首条的安排路径按首日解析并由独立未生效状态字段解释，不能冒充今日有效父边。停用行继续按停用前一日及最新来源解析停用前路径，当前授权归属、有效父边/历史引用规则继续遵循117/120。

详情路径跟随所选记录的适用期间：启用记录按相关祖先/层级日期边界分段，单段直接显示，多段分别显示适用期间和路径；不增加用户日期输入，也不把记录首日的路径冒充整段不变。停用记录仍由Go按停用前一日解析，但路径内不重复显示停用说明或解析日期，状态与日期独立表达。显式旧sourceVersion按原封存path_evidence裁切对应记录期间；当前来源按关联对象最新来源计算。路径失读权时整条受限，不泄露分段数量/日期。具体投影由119/120持有，部门产品仍留116 R4/R5实施。

### 2.5 专项按日查询准入

只有明确角色需要判断某日的整体情况，今日资料、具体记录或业务期间不足，且日期不能从办理生效日、凭证或报告自动取得时，才提供局部日期查询。必须定义随日期变化的字段、来源/授权及下钻口径，使用统计日期、组织基准日等具体名称，不传播为全局或普通维护页日期。

某日组织树、在职名册、多个独立有效期组成的员工快照属于可评估任务；本决定不启动这些功能。历史报表/工资及审计原件按确切来源或结果版本读取，业务日期不能替代版本；未来有效资料不等同于规划方案。当前权限始终适用。

## 3 备选方案与取舍

| 方案 | 满足的需求与局限 | 决定 |
| --- | --- | --- |
| 普通列表/详情始终提供查看日期 | 可任意查询，但所有日常维护承担多时间口径与上下文复杂性 | 不采用 |
| 仅藏入更多操作 | 减少可见控件，隐含日期及冲突仍存在 | 不采用 |
| 普通维护取消，明确任务局部提供 | 日常维护更直接；任意时点整体查询须另定合同 | 采用 |

## 4 影响与验证

本批先修改并检查文档，再同步Go/HTTP/OpenAPI/客户端/UI及受影响测试。不修改按日区间、修订、来源、日志、Outbox及已有提交结果，不重建持久库。BU/部门独立表、Hierarchy唯一父边、现行权限及不兼容策略保持。共享界面删除无消费者的查看日期组件和样式。

验收至少覆盖今日有记录且有未来更名、今日停用而未来恢复、仅未来首条、全部/单一状态筛选、未来首条搜索/排序/CSV；详情默认/显式/保存/旧来源/删除原件/目标缺失；未来提示字段权限；导航返回；GET及选择/导出拒绝日期注入；跨日列表变化和旧选择零输出。领域历史边界通过Go或受控服务端时钟验证，不复活普通用户任意日期API。实际分层结果由本批报告登记，不把文档检查或旧报告当新产品通过。

011维护今日/记录业务语义，012维护入口与状态，013维护协议和集合，023维护当前案例；010与116承接实施和共用提炼交接。118—121同步部门路径/时间合同；122仍为未实施草案，其准确来源链接退出businessAt并沿用sourceVersion/selectedRecordId。旧阶段完成记录不重开，不据本批宣称部门、116 R1—R6、122或全M02完成。
