## 1 背景与问题

当前源码基线为`b82a1027c35b2591aa8a9b86f10246c25f5f3e09`。[131阶段交接](../verification/131-t04-capacity-and-handoff.md#41-本次t05阶段交接结论)保留万科87343部门的6400次请求：单会话3200次无HTTP失败，20会话3200次有2682次503，全部32个正向组均未达各自时延目标。普通列表双角色20会话400次零HTTP失败，路径400次、选择1200次全部失败，父候选另有1082/1200次失败。这是规定API波次的可用性失败，不是生产流量比例，也不证明数据库、Go或某一资源是唯一根因。

现有131已经删除每请求全企业完整性聚合及重复存储摘要重算，并实现普通列表按页投影。本方案针对仍存在的完整集合版本、父候选精确计数、全量预览及重复编排；不得把已经删除的工作重新列为当前缺陷。完整集合计算有一部分源自现行合同，必须先改变合同再改变实现。

整改原则为：每项检查说明保护的业务事实、责任层、实际依赖范围和执行时点。不能说明实际用途的计算优先删除；能由当前写入事务保证的不变量不在每次读取重复证明；用户尚未执行的消费动作不提前逐项演算。全量本身不等于过度：全选身份建立、完整导出、确有影响的期间和历史恢复仍有完整处理义务。

## 2 拟采用决定

### 2.1 必要保护及责任

| 事项 | 保留的责任 | 收敛方式 |
| --- | --- | --- |
| 日期、金额、状态和资格 | Go唯一权威；业务日、完整相关期间、未来边界和环路仍准确 | 同一份已固定事实和候选在请求内复用，前端不复制规则 |
| 当前授权 | 返回业务内容和执行动作时按当前主体、当前归属、字段及动作权核验；历史还需历史读权 | X03编译计划可在请求内复用；选择标识、游标和旧页面均不是授权票据 |
| 写入及历史 | 确切对象来源/记录修订、锁后最终候选、原子提交、幂等和原结果恢复 | 只加载受实际变化影响的依赖；持久化适配器不重新演算同一份已验证候选 |
| 存储 | PostgreSQL负责结构约束、事务、必要锁与历史保护；Go事务同步写查询事实 | 读取保留必要解码、归属及来源身份检查；离线存储诊断独立执行 |
| 出错 | 真正缺失的必需事实、SQL失败、取消、失权均不得返回假成功 | 保留首因、及时停止无效后续步骤；删除无业务作用的重试和重复确认 |

输入边界校验、业务校验和数据库结构约束各有责任，不按“出现两次”机械删除。预览结果不能替代保存时的新事实、新授权及最终检查。每次读请求也不承担整个企业、全部历史或全部权限组合的健康证明。

### 2.2 选择身份与资料内容分离

推荐语义是“选中这些对象，导出它们执行时的当前资料”。选择身份固定；未选对象变化、选中对象普通更名、排序及翻页不清空选择。用户改变搜索/筛选范围、离开列表、注销或服务端业务日改变时仍清空。

| 模式 | 建立及后续处理 | 明确变化的业务行为 |
| --- | --- | --- |
| 显式选择 | 只处理用户提交的ID和必要当前范围事实，不先求完整查询集合摘要；页面读取独立按页完成 | 未选对象变化不导致重选；所选资料普通变化不使身份选择失效 |
| 全查询选择 | 一次捕获点击时全部匹配且获权的ID，页面仍只接收本页内容和轻量选择标识；后续按ID集合和排除项处理 | 后来新增匹配对象不自动加入；未发生用户增删时，集合不因重新查询而漂移 |
| 选择计数 | 表示用户选择的身份数量；全选按固定成员数减合法排除数计算 | 不再把每次计数当作全体成员资料、读权和导出权均已重验的证明 |
| 导出 | 对最终ID集合在本次读取快照执行当前对象/字段/独立导出权及完整取数 | 资料以导出时为准；成员不存在或失去必要权限时整笔拒绝，不静默删行或输出部分文件 |

所选对象因资料变化不再符合当时的文字筛选，身份选择仍保留；筛选曾用于确定选择对象，不冻结它们的资料内容。转BU后仍有当前读权则可继续，失权则导出整笔拒绝。此项与现行“任一完整投影变化就重选”有意不同，须同步114、011—013、118—121和页面说明，不能只在后端换算法。

全选所需完整工作限定为身份集合及决定集合所必需的筛选事实；不为生成选择标识装配全体八列CSV、全体路径摘要或全部资料DTO。路径条件仍需完成准确匹配才能固定全选ID；这项完整扫描不能假称已消除。

本次推荐在现有PostgreSQL内保存有界、可过期的短期选择草稿，内容仅为实例/企业、主体/会话、对象种类、服务端业务日、查询身份、成员ID及必要的选择编辑状态；各对象保持独立存储归属。草稿不含名称、业务资料、历史快照或授权结论，不产生业务来源、操作日志或Outbox，不承诺刷新后恢复。到期、注销、显式清除和后台回收均释放资源；进程重启或清理造成不可用时返回重新选择，不恢复成实时全选。具体字节预算、TTL和单会话草稿上限在133-T00用87343成员/20会话实测后冻结；容量不足须明确拒绝，不截断成员。

新增草稿是为一次全选复用身份集合的最小状态，必须与反复全量重建比较总成本；不引入Redis、通用结果缓存或后台任务平台。前端增加轻量本页成员状态，防止全选后新出现的行被错误勾选；排序保持成员身份，取消排除须验证ID确属该草稿。旧`selectionVersion`全量投影哈希退出选择协议，草稿编辑版本仅处理用户选择动作的并发，不承担组织全局版本职责。

导出按钮的可用性改为当前入口级能力，明确DTO不承诺所有成员已通过最终导出验证；最终执行仍逐成员核验。选择汇总只返回该用户草稿的数量，不借此返回已失权成员的旧名称或字段。撤权后的已显示内容仍按现有会话及页面失权处理清理。

### 2.3 行政上级按合格候选逐批返回

取消父候选每次精确总数和总页数；保留无搜索直接展开、可见编码/名称搜索、稳定排序、翻页、独立已选标签及原草稿。响应采用`items + nextCursor + hasMore + selectedReference + applicable`，不保留假count或新旧双分页协议。页面呈现上一页/下一页或继续加载，不要求用户先搜索。

先按当前可见标签和Go生成的期间事实取一批保守候选，按本次实际窗口加载其必要祖先/BU及共同目标依赖；Go完成所有必需资格判断后收集一页及一个额外合格候选。只有确实找到额外合格项才能给出`hasMore=true`；只有穷尽剩余范围才能给出false。批内不合格项不占页面名额，不能先取20条再过滤出不足页并谎称结束；预算耗尽仍明确失败。

相关期间继续覆盖窗口前跨入记录和全部已登记未来边界；保存独立核验最终关系。对同一固定事实共享期间计算，处理到足够合格项后停止后续资格演算。低命中率或零结果仍可能遍历大量窄事实，须单列成本，不宣称算法固定为20条。

游标由服务端绑定查询、业务日、排序位置和维护目标的来源/拟变更上下文；它不授予权限。下一页位置以最后实际返回项为准，不能越过仅用于判定hasMore的额外合格项；该项仍须进入后续页并重新执行当前授权。每页是当前授权下的一次一致读取，不持有跨页面数据库事务；数据不变时无重复遗漏，并发改名/换父允许后续页反映新状态，刷新可重查。目标来源变化拒绝沿用旧维护上下文；业务日变化重新开始，游标失效不丢用户仍有权编辑的草稿。

### 2.4 路径查询与对象导航

普通列表继续以本页及必要闭包投影；精确count仅对窄查询事实计数，不带动全体路径、时间线或选择摘要。路径文字筛选保留当前获权文字匹配、停用前路径及未来首条路径语义，改为窄事实/关系读取和Go按需匹配；路径筛选页推荐与父候选一样采用游标，不在首屏强制计算精确总数。用户在路径结果点击全选时，才执行完整准确匹配并建立身份集合。

“某部门下的组织”可作为后续结构查询能力独立评审；本轮不把文字包含悄悄改为子孙关系，也不增加第二个复杂搜索产品。优先复用现有Go写入查询列和必要关系；如必须增加读取投影，须说明唯一写入责任、并发/日期更新和祖先变动的写入成本，不自动物化所有历史全路径。

详情上一条/下一条按当前查询、排序及对象锚点查找相邻获权对象，取消完整列表投影版本与精确全局位置的强依赖。2026-11-15用户要求恢复位置／匹配总数展示，由[302](../plans/302-detail-navigation.md)接续：普通导航从窄匹配事实一次返回位置及邻居；路径准确统计独立加载；详情仍独立可用。无关对象资料变化不阻断导航；锚点已删除、不再匹配或当前无权时返回安全提示并允许返回列表。详情本身读取成功不依赖辅助导航成功；原返回筛选、滚动及高亮继续保持。

### 2.5 预览、保存及能力表达

预览只读取本对象和实际变化所需依赖，移除部门`Snapshot(ctx, "", "")`的默认全企业加载。合法无变化、覆盖不变和关系/期间变化由Go依据准确来源与最终候选分类；不能凭前端字段名或“更名”动作标签跳过规则。能力表达只回答当前入口和字段是否可操作，不提前执行所有可能命令；保存继续承担最终业务决定。

BU按[129计划](../plans/129-bu-simplification-and-department-alignment.md)处理候选前全量依赖锁、请求内重复验证、预览冗余和类型转换。一次事务内使用明确的已验证候选传给存储，存储仍执行原子性和结构约束；同一批事实变化或换事务后必须重新验证。共同守卫是否可缩小按实际并发依赖证明，不能用取消守卫换时延。类型转换和包装删除属于后续低优先级工作，不抢占万科可用性整改。

继续直接保存和就地冲突反馈，不增加预览确认门槛。没有实际消费者的响应字段、重复计算和未实现入口一并删除生成源/客户端/测试依赖；原不可变来源、操作者事实、终态和恢复协议保持。

### 2.6 错误、事务与并发资源

读取业务拒绝和基础设施失败分开处理。SQL取消、连接失败、事务失效和请求取消直接结束失败路径并保留首因；仅健康事务中的合法业务拒绝可完成必要的会话活动更新。安全公共错误不泄露SQL或敏感值；服务端按请求关联保留错误类别和必要阶段，不恢复128已删除的完整判权档案。

先消除工作量，再依据测量决定是否为重型任务加独立、有界的准入；等待发生在业务连接外，计入原请求总预算，取消即退出，拒绝/超时均计入容量失败。调度不能把20会话验收降成更低并发，也不以自动重试制造成功样本。

单请求的一致事实和当前授权仍须保证。分批SQL不能因处于同一默认事务就假设共享快照；优先单语句流或明确生命周期的读取快照，任何多语句协议须验证并发写入、同会话活动和字典回收。不能把可变当前事实、旧字典ID或旧权限拼接。实现选择由133-T00的小范围原型冻结，不修改全局隔离级别或跨页面持锁。

## 3 备选方案与取舍

| 方案 | 价值及成本 | 本次建议 |

## 4 影响与验证

体验变化须实测正常菜单：选中更名后仍选中、全选后新对象不自动加入、跨页排除保持、候选无总数可连续找到目标、辅助导航失败不影响详情。业务保护覆盖当前撤权/转BU、字段裁剪、未来期间和环路、并发来源变化、历史读取与原提交恢复。导出按固定成员身份逐值核对当前资料，失败零文件。

容量按完整万科与合成两种形状分别测量。新的查询草稿、索引或读取投影须计入整库、峰值内存、WAL、正常写入和到期回收成本。原131失败保留，改变契约后的结果单列，不把旧规则测试删掉后的通过写成原合同容量通过。正式分母和原目标由[133验收](../plans/133-overdefensive-processing-remediation.md#r133-acceptance)映射回125。

### 7.2 草稿表示、额度与生命周期

采用每对象独立PG表组：元数据保存实例、企业、主体、会话、业务日、规范化查询、创建/到期时刻、修订和选择意图数；成员块按UUID排序，每块最多1024个完整UUID，附逐身份选择位。主键为草稿ID及块首UUID；本页成员定位不读取整份身份数组。UUID不是名称或历史快照，不保存当前读权、字段许可、业务资料或来源档案。

显式初建及每笔编辑上限1024项，沿用64KiB请求上界，超出时客户端分笔编辑；每笔带expectedRevision并原子返回新revision。完整草稿最多131072身份，超过上界明确拒绝整笔建立，不截断；当前87343全选必须完整成功。每会话每对象保留一份当前草稿，替换先完成新集合，再在同事务替换旧集合，失败保持旧选择。仅允许编辑已在固定成员中的排除位；显式追加按当前权核新身份。编辑、取消和建立按本人会话串行化，旧revision返回冲突，前端不静默覆盖新意图。

到期为建立后30分钟，resolve和翻页不延长；业务日改变、改变查询、离开列表、注销/换账号清空客户端选择并尽力取消本人草稿。服务器始终核会话和到期，客户端取消失败不延长可用期。服务端建立前按到期索引有界清理，每会话每对象一份、每实例每对象最多128份、每份逻辑身份及选择位预算3MiB；数量上限包含尚未清理的过期项，准入先清理过期而不能挤掉仍有效的其他会话草稿。20份完整万科草稿的原型物理上限96MiB、建立WAL160MiB；持续运行的表/TOAST/索引空间预算512MiB，T02须验证PG正常维护可回收复用，不在每次请求做全库大小扫描或VACUUM。

使用普通有日志表，正常DB重启可恢复未到期草稿；API冷启动清除其单实例短期草稿后接流量，缺失/到期返回重新选择，不自动重跑原查询。注销在会话撤销后清理，清理失败仍不能使旧会话可用。当前单API实例部署范围不预建多节点租约平台；扩展多实例时必须重新评审启动清理责任。任何草稿故障不影响真实来源和原提交结果查回。

导出保持完整核权和同次事实，成功前不发送文件：使用请求自有0600临时文件顺序暂存CSV，单份上限64MiB、20并发至少预留1280MiB暂存容量，取消/失败/发送结束均删除。先固定输出与授权成功，再发送响应；末项拒绝、依赖缺失或提交失败时零文件。额度耗尽是明确失败并计入容量分母，不新增异步任务、后台队列或分片下载。本预算是全规模原型约束，T02还须验证实际生成器的转义、公式防护、双角色及逐值一致，存储原型不能代替业务验收。

### 7.3 单请求游标与一致事实

采用现有READ COMMITTED事务内的单声明、只读、不可滚动PG游标；不全局改隔离级别。顺序为：当前认证及策略共享守卫→服务端业务日及查询上下文→声明唯一事实查询→分批FETCH并由Go判权/匹配/资格→关闭游标→必要会话活动→提交→返回已准备的响应。共享策略守卫从认证到提交保持，撤权仍按既有锁次序生效。

候选/目标来源/完整相关期间/BU/祖先/字典内容必须由同一个游标语句绑定；字典ID不能留待后续SQL解码，可变事实不能在批次间另查。固定目标不变材料只准备一次，祖先资格只在本请求共享。数据库只提供必要存储事实和关联，不承担日期资格、路径匹配或业务判断。游标每批候选上限64，Go取得pageSize+1个真正合格项即停止后续资格；数据库计划不得在首批前物化完整宽投影，T03/T04用SQL计划、解码/捕获数及首屏成本验收。

133-M1原决定为按规范化排序键和完整UUID作稳定比较、不计算全局位置；2026-11-15位置展示按302接续，取消全局版本的决定保持。路径筛选仍可能为得到相邻合格项扫描多条窄事实，零结果必须穷尽。任何必需依赖缺失直接失败，不能当作不合格继续。原型已证明协议的MVCC/锁性质，不表示最终完整关系捕获SQL的成本已经通过；后续产品仍须覆盖实际关系和权限并发。

外部nextCursor使用进程密钥HMAC认证的结构：版本、实例/企业/主体/会话绑定、业务日、规范化查询与排序、最后实际返回项的排序值及UUID、维护上下文摘要与确切目标来源。解析先限制长度，再验证签名/归属/日期/查询；拒绝篡改、错对象和跨主体使用。维护来源变化要求刷新上下文；服务重启使旧游标失效。排序位置使用最后返回项，额外合格项不被越过；后续页重新取得当前权和当前事实，不跨页持事务，也不携带可复用权限。签名仅保护输入绑定；不能替代当前授权。

### 7.4 首错及其余条目的交接

OD133-08仅允许明确4xx业务拒绝走健康事务的会话活动/提交路径。基础设施错误、5xx、SQL取消、连接及上下文失败直接返回原因并回滚；现有公共安全错误和写入提交不确定语义保持。查询捕获解码和路径投影将安全公共Fault与原始原因一并保留，不能把上下文取消误记为缺失依赖。诊断观察仅接入离线工具，按请求记录SQLSTATE/取消类别、阶段及工作量，不恢复128判权档案。
