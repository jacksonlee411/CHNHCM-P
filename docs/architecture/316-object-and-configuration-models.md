# CHNHCM-316 业务对象与配置数据建模规范

本规范供领域维护者、产品设计者和评审者在新增数据、扩大配置能力或提议迁移时使用。所属域的 Go 内核裁决业务，客户在自己的实例内维护配置。具体对象已有的办理、来源、授权和历史合同继续适用。文档元数据见[登记表](../governance/registry.json)，事实归属见[目录与领域边界](004-repository-layout.md)。

## 1 选模型时看业务后果

先用一句话说明“谁修改什么，修改后哪些办理可以产生不同结果”，再按下表选择。只把客户有理由独立维护的值交给管理员。模型粒度落实到具体事实，一张表单可以同时使用几种模型。

| 选择 | 适用条件与维护单位 | 项目中的判断依据 |
| --- | --- | --- |
| 业务对象或业务记录 | 业务需独立办理、定位和更正某个主体、关系或已发生事项。按该对象合同维护身份、关系、约束及所需历史。 | 企业、BU、部门、法律实体、企业地点、职务、职级、岗位和人员按各自的主体或关系维护。任职、调动和劳动合同按实际办理留存。将部门内一岗的一编调给另一岗须同日核对额度和总额，由 M03 同笔办理。[核编与调剂](../specs/m03/313-position-capacity-contract.md) |
| 受控参考对象 | 选择时须验证权威身份、期间关系或来源层级。所属域按目录任务开放必要维护能力。 | 国家／地区及行政区划要保留来源，地点引用区域时还要核对当日的父链。企业工作地点另有独立新建和维护流程。[三类对象的能力矩阵](../specs/m02/201-country-region-geo-area-and-location-maintenance-contract.md#m02-br-208) |
| 轻量配置项 | 客户可增减选项。改变某项只影响录入可选值、显示或统计分组，所有选项遵循同一种办理行为。维护单位为单项。 | 假设招聘部门只需统计报名来源，可维护“校园宣讲”“招聘会”。若同一字段还决定渠道佣金，应把费率与计算条件交给相应规则所有者。 |
| 规则配置 | 客户维护的单个参数或一组取值决定资格、状态转换、金额或必交资料。按最小共同生效单位发布强类型规则版本。 | 到岗日决定直接入职采用哪个证件要求版本。任职政策决定某段是否占编，实际发生的占编归办理域。目标域在执行时判定规则。[入职规则读取](../../internal/contexts/staffing/infra/postgres/hire_rule.go) · [任职政策](../specs/m04/401-direct-hire-requirements.md#m04-br-005) |
| 产品固定枚举 | 每个值对应 Go 中明确的行为，增加一种取值需要开发其业务处理。随代码维护可接受值及语义。 | 人员教育的“学习经历”“已取得学历”“学位授予”决定适用字段及最高标记资格。给下拉框加一个名称不足以支持新的教育记录类型。[教育合同](../specs/m01/505-personal-profile-contract.md) · [Go 校验](../../internal/contexts/personnel/domain/education.go) |

以调动为例，原因名称是定义的属性，原因可用于哪些调动类型由 M04 动作目录版本决定，员工因何从甲岗调往乙岗记在原调动办理中。若文字已随目录版本封存，沿用该定义及版本即可，另设词表会增加第二个写入者。[M04 动作目录](target/modules/m04.md) · [业务类型与记录操作](../specs/m04/506-job-information-records.md#m04-br-010)

## 2 轻量配置的最小数据合同

下表为逻辑结构。目录可直接在所属域的 Go 代码中声明。域内同形词表可共用配置项与修订的存储结构，管理员使用同一组维护控件。复杂业务参数使用各自的强类型字段或值对象。新增目录的成本应主要落在目录定义、权限与实际消费入口。

| 组成 | 应能定位的事实 | 写入约束 |
| --- | --- | --- |
| 配置目录 | 所属域、稳定目录键、用途、明确的实例或企业范围、日期口径 | 目录定义由所属域维护。普通管理员直接维护目录里的值。实例内共享和企业专用须在合同中明确。 |
| 当前配置项 | 稳定项 ID、目录与范围、业务编码、名称、排序、初始生效日、可选状态、当前修订 | 编码在同一实例、目录及明确的归属范围内唯一，由存储约束保护，并发新建相同编码最多成功一笔。归属键对实例共享也有明确值，创建后编码固定，停选仍占用该编码。改显示名称沿用 ID 和编码，实际含义改变时新增身份并停选旧项。 |
| 单项变更记录 | 项 ID、不可变修订、经办主体、记录时刻和实际变化 | 首建记录初值，此后按项记录差异或不可变版本，保证能按确切修订还原有权读取的原值。当前项与变更、需要保存的回执同事务提交，记录时刻按北京时间显示并保留原时刻。 |
| 业务单据中的采用 | 原单修订、所选项 ID 及确切修订、采用日、用途、当时使用的显示值或可按原引用取得的同等资料 | 消费域在办理中固定实际采用。跨域通过公开端口读取，租户、来源域和目录可由所属记录及类型明确绑定。原单修订承载已有的经办、业务日期等共同信息。 |

数据以客户实例隔离。目录在实例内明确采用实例共享还是企业专用范围。编码在不同归属范围可以相同，跨范围选择时以稳定身份区分。涉及共享与专用范围时显式声明适用规则，同名、空范围或有读权均不能推定默认值。适用范围、默认来源及访问授权分别判断。适用或默认需要共享策略时按 X02 合同解析，X03 提供当前授权，消费者在保存时重新核验。

调用者的实例由认证上下文确定。按编码查找也须绑定目录和范围。单域词表可直接从本域读取。已有跨域通知义务按对应合同接入，由来源域持有 Outbox，消费域持有 Inbox 和采用。[X02 适用与默认](target/modules/x02.md) · [一致性合同](target/03-consistency-contracts.md) · [日期显示](../adr/026-date-display-and-input-format.md)

## 3 办理日期与维护动作

**首次新建。** 配置与主数据的首次生效日由 Go 提供默认值 `1900-01-01`，管理员可显式修改，写请求传入实际确认日期并校验下界。后续变更和更正按本次动作确定日期。

**当前选用的词表。** 候选查询和保存各以服务端当次北京业务日判断。初始生效日已到、当前可选、范围适用且有权引用才能新选，即使补办的单据属于上月也适用此口径。未来首日在到日之前不可新选。改名、调整排序、停止选用、恢复选用只更新选中项。管理员在所属业务菜单直接保存，取消或无实质变化时零业务写入。停选之后恢复，仍沿用原身份并追加修订。查询者按授权查看，维护权单独授予。[首次默认日](../adr/202-master-data-default-effective-date.md) · [共享表单与未保存保护](../specs/m02/012-m02-functional-and-interaction-design.md#m02-ui-protection)

**按业务日选用的词表。** 若合同要求预排停止日、按旧日补办时还原可选项，或支持追溯更正适用期，源域维护生效期间。新采用在办理事务中按业务日解析当前来源，查原单则按原采用版本。数据库以 `daterange [start,end)` 存储有效段，并用排除约束或等效的并发约束防止同一项在同一范围、同一来源内的有效段重叠。该日无适用段时该项不可新选，字段可选时允许留空。更正追加来源修订，被采用过的旧版本仍可精确读取。只扩充该目录需要的期间能力，逐项决定是否需要改日、追溯或结构关系维护。[按日接入指南](../guides/124-dated-object-admission-and-capacity.md) · [按日与确切来源](target/10-ddd-and-state-contracts.md#61-历史查询能力与计算依赖)

**有业务后果的政策。** 单项政策可独立生效。多个取值必须共同解释时，所属域一次发布整组规则，保存不可变版本、适用键和有效期。Go 按业务日期、用途和范围解析合同要求的唯一版本。必需版本缺失或存在无法消解的冲突时，向经办人说明并阻止提交。发布只改变后续解析入口，已采用的业务结果按原版本查回，确需追溯时由消费域按自己的合同处置。[政策版本及采用](target/modules/x02.md) · [薪酬规则目标设计](target/modules/m10.md)

## 4 提交、更正与原件

1. **查询候选。** 按当前授权、目录、范围和日期返回合格项，列表只取当前任务需要的字段。管理列表可查获权的停选项。前端提交选中身份，是否同时提交所选版本按消费合同确定。服务端解析资格。
2. **选择后换版。** 普通统计词表只更名、所选身份仍合格时，保存锁内采用新修订。现行合同有两种不同约定。M02 地点地址可取仍合格的新来源。M01 人员住址所选项换版则须保留草稿重选。无关项变更不阻断保存。[地点保存守卫](../specs/m02/201-country-region-geo-area-and-location-maintenance-contract.md#m02-br-209) · [人员目录采用](../specs/m01/505-personal-profile-contract.md)
3. **保存与并发。** 两名管理员同时编辑同一项时以期望修订防止覆盖。实际采用与停选、撤权须有确定先后，来源守卫与消费写入共享短事务或采用对象合同已证明等价的提交机制。采用先完成则保留该笔，停选或撤权先完成则拒绝新的无资格采用。发生并发冲突时保留仍有权的草稿供重新核对。撤权时清理不可读候选和字段，迟到响应不得恢复它们。提交前故障回滚全部业务写入。
4. **重送与查回。** 保存已提交但响应丢失时按原提交身份查回。同键同内容取得原结果，同键不同内容拒绝。查回与原件均按当前授权投影。原身份、修订和提交结果须能在现有机制中定位。
5. **更正与读取。** 只改无关字段时沿用原采用日及原修订。改选其他身份或合同指定的采用依据变化时，重新核验并记录新采用。改业务日、范围或用途是否触发新采用，由消费合同明确。复核原单按确切采用读原名，统计按稳定身份归组。有权查当前目录不自动授予业务原件读权，失权时按现行字段与范围权限裁剪。必要来源缺失须明确不可用。当前词表可按项修订查证，不能从变更时刻推算历史业务日的可选集合。对未提供的按日查询应明确拒绝。[历史保护](../adr/025-greenfield-implementation-policy.md#single-current-implementation) · [原选择与新采用](../specs/m01/505-personal-profile-contract.md)

## 5 接入、验收与成本比较

新增目录时，在所属模块的需求或实现方案里写明维护者、正常菜单、消费者、选用日期、稳定身份、改名或停选对旧单的影响，以一个正常样本和一个会改变判断的反例说明模型选择。需求涉及首个跨域消费者时补齐公开端口和事务边界。轻量配置项默认提供新增、编辑、停选和恢复。高级时间线、批量导出、审批与缓存按实际需求单独决定。

| 实施时的验收输入 | 可独立核对的结果 |
| --- | --- |
| 同一合同下设两个不同目录，同一目录又在企业甲、乙各有同名项 | 限于自身范围的经办人只见、只选获权身份。即使某项在另一目录可见，提交给错误字段或企业也拒绝。原单无部分写入。 |
| 甲保存“招聘会”，管理员更名，乙随后保存“线下招聘会”。管理员停选，丙用早先打开的草稿提交 | 甲、乙各见原名，统计归同一 ID、共两笔。丙的新采用拒绝，更正甲单无关字段可沿用。恢复后新单可选同一 ID 的新修订。 |
| 两位管理员从同一修订改名，一笔成功后断线重送 | 只有一次变更。过期写返回冲突，同一次成功提交可查回原结果。 |
| 管理员在 2027-05-01 实际停选当前词表的某项，另一按日词表同日起停选。2027-05-02 补办 2027-04-30，其他资格、权限满足 | 当前词表拒绝新选。按日词表在 2027-04-30 允许，业务日改为 2027-05-01 则拒绝。 |
| 只读者尝试停选，已打开候选的经办人在保存前失去引用权 | 前者无法修改。后者不能新采用或读出失权标签。原已提交记录仍可由有权者按原引用核对。 |
| 同组规则同时改变允许原因和证件要求，保存时第二项无效 | 发布整笔失败，原版继续适用。有效新版本生效后，消费者只能取得整组同版规则。 |

首个试点宜选客户确有维护需求、只影响统计的新词表。候选优先按目录、实例和范围读当前项，只取有权的候选 ID、编码、名称及必要排序字段，以稳定 ID 打破排序并列，按需分页。核对执行计划和取数范围，普通候选无需回放历史。一次改名只写该项的当前值、修订及必要回执，原单和同目录其他项零改写。

实施前由消费域约定日常规模和目标。在相同输入、数据量、历史深度、并发、权限分布、硬件及冷暖条件下比较基线与候选，回读同一业务预期。分开记录候选查询和保存的端到端 P95、样本数、失败及超时、一次修改的写入行数，以及表和索引增长。维护成本记录实际操作步数，有第二个同形目录时再统计其专用代码和测试。没有可比基线就报告绝对值及是否达标，省去为对照而开发第二套产品。[容量口径](../guides/124-dated-object-admission-and-capacity.md)

## 6 存量与演进

出现按旧业务日选用的需求时，先评估给词表增加期间。出现计算、资格或原子组合时，明确参数的规则所有者。若条目本身开始有独立办理或持续关系，重新评估业务对象。已上线的能力由现行合同维护。提议将已上线的对象或配置改型时，由源域列出受影响的公开端口、存量实例和消费域，核对原身份、原修订、原采用、原回执、当前权限以及历史证据。只有当前来源的旧数据若缺少过去的有效期间，须标明可证实的起点与未知范围，不能用日志时刻或首次默认日补造旧资格。迁移方案须能验证这些事实并说明切换、失败恢复及旧入口退出方式。仅因页面位于“设置”或字段少，不构成存量迁移理由。[唯一事实与历史保护](../adr/025-greenfield-implementation-policy.md) · [当前切片登记](contexts.json)

首个目录由提出需求的模块在立项时选定并约定容量目标，实装后登记测量结果。本规范的评审对象限于选型与实施要求。
