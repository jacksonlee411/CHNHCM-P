# 中国大陆设计：政策、主体、时间与独立账本

本章将中国大陆特点落实到对象、接口和反例[D]，并保留来源稿列出的官方依据[O]。目标是让架构容纳并解释适用差异；设计文档不证明法定金额、全国城市参数或实际报送渠道已经验证。本仓来源采集、本地修订与核对边界见[来源说明](../../reference/README.md)。

组织角色与工作关系的实际核对仅覆盖 [009](../../adr/009-mainland-organization-terms.md) 及其[来源记录](../../reference/m02-terminology-sources.json)。其余政策和地区样本保持来源观察范围，本次文档修订未重新访问外链。对应领域维护者在其进入业务规格前，须按 [014](../../governance/014-document-management.md) 记录发布方、标题、链接、地区、有效期间、实际核对日期和适用解释；原记录缺失的信息保持待核，不以本次修订日期补写为核验日期。

## 1. 先确定上下文，再评估规则

同一个人的工作地点、用人单位、派遣接收用工单位、非劳动关联单位、扣缴义务人、社保参缴主体、公积金账户、付款主体及成本承担方可能不完全一致。目标通过明确关系和用途映射解析；不能从部门、Business Unit、人员类型或单一“公司”字段推断全部上下文。

用人单位不一概等于独立法人或合同签字公司；符合条件的分支机构按登记及资格依据表达，受委托签约另记代理事实。工作关系是上位系统概念，劳动关系起点与书面合同订立时间分别记录；具体角色及反例见[CHNHCM-009](../../adr/009-mainland-organization-terms.md)。[实施条例第三、四条](https://xzfg.moj.gov.cn/front/law/detail?LawID=284)、[劳动合同法第七、十条及派遣条款](https://fgk.chinatax.gov.cn/zcfgk/c100009/c5193025/content.html)

劳动合同法区分用人单位与劳动关系，并对派遣等情形另作规定；社保法分别规定单位登记、个人参保登记和征缴责任。本设计据此保留主体、登记和义务的独立身份，不将工资计算作为所有法定义务的起点。[劳动合同法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_0abfdd261c03417b949df19d869add8d.html)、[社会保险法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_e81d115419b4463ebb59ec46467fb136.html)

| 维度 | 目标表示 | 不能用来替代它的字段 |
| --- | --- | --- |
| 人员身份 | Person及证件事实 | 姓名、员工列表行、登录账号 |
| 关系性质 | EmploymentClassification及关系期间 | 国籍、绩效、一个“在职”布尔值 |
| 税收身份 | TaxIdentity及适用期间/证据 | 国籍或雇员/外部人员标签 |
| 用工责任 | LegalEmployer与实际用工方关系 | Business Unit或部门 |
| 扣缴责任 | WithholdingRegistration＋所得上下文 | 工资组或银行代发主体 |
| 参缴责任 | AgencyAccount＋Enrollment＋属地/险种/期间 | 工作地点或工资是否非零 |
| 工时与假期 | 制度适用、日历、资格、余额 | 一张通用工作日表 |
| 成本与资金 | CostAllocation、PaymentInstruction及主体用途 | 净工资或组织树节点 |

## 2. 政策对象与生效机制

来源 FSCR `d88c993d13d325b18943549f120c5f03e7864205` 的 `docs/china-hcm/04-china-localization.md` 记录了原型中的 payroll-legal-register 及不可变政策投影；原文保存在[离线来源包](../../reference/sources/china-hcm-d88c993.zip)，逐文件摘要见[基线](../../reference/baselines.json)。该描述是来源项目观察，CHNHCM 当前尚未实现这些政策能力。本目标保留规则来源、版本约束及不可变采用的设计方向，后续按业务规格实现和验证。

建议每个PolicyVersion至少包含：稳定规则ID、来源URL/文号、发布/取得时间、法律生效起止、地区及经办机构、适用对象与例外、参数/计算规则引用、依赖口径、核验状态、适用案例、替代/更正关系。核验状态区分“主题已核对”“某期间/参数已核验”“待确认”“不适用”；不能只留一个verified布尔值。

规则解析输入应含业务类型、地区、关系类型、责任主体、所属期/支付日、个人相关资格及明确采用版本。输出给出匹配依据、缺项、冲突和禁止原因；同优先级冲突不随机取值。企业增加待遇与法定最低/强制规则的组合按具体规则定义，不机械使用“更具体的配置覆盖上层”。

以下日期分别保存：

- 政策发布日和法律生效日：用于识别发布晚于生效的追溯影响。
- 所得/缴费归属期和实际支付/实缴日：用于不同账本的期间处理。
- 系统记录时间、来源取得时间和采用时间：保留审计与来源取得过程；原依据通过确切来源或采用版本解释，不按记录时间截点重建。
- 资格有效期、合同期和任职期：用于判断对象是否适用，而非直接决定税费结果。

## 3. 个税与工资之间的合同

工资薪金累计预扣及其后续特定人群调整说明：计算必须同时知道累计范围、资格条件和适用版本。不能把旧月度税额算法作为当前中国算法，也不能把一篇公告当成全部当前政策。[扣缴申报管理办法](https://www.chinatax.gov.cn/chinatax/n810341/n810765/n3359382/201812/c4182700/content.html)、[2020年第19号公告](https://fgk.chinatax.gov.cn/zcfgk/c100012/c5194953/content.html)

目标设计：

1. M10提供拟支付或已确认所得的来源与日期；M11拥有所得分类、税收身份、扣除事实、累计口径和税额评估。
2. 候选计算不更新正式累计；采用评估与累计入账分别服从明确合同。新Employment不能自动把同一税年累计清零，跨扣缴主体也不能无条件合并。
3. 定期工资、奖金、补发、离职结算、特殊所得、外籍及跨境事项分别选择适用规则；不由一个通用salary字段覆盖所有所得。
4. 预扣计算、企业扣缴申报、缴退税事实及个人年度汇算有不同对象和责任。申报接受不等于税款已到账。
5. 更正保留原评估与申报版本；跨年时列明税年、所属期、支付日及适用政策，未知项停止相关确认。

Oracle中国Payroll Relationship也有国家特定映射及再聘处理；这些是产品模型，并非中国法定扣缴口径的替代证据。China HCM用PayrollContext、计薪归属、独立税务累计和主体合同表达，不把Employment、PayrollRelationship和扣缴累计键当作同一个ID。[Oracle中国Payroll Relationship](https://docs.oracle.com/en/cloud/saas/human-resources/faach/payroll-relationships-for-china.html)

## 4. 社保与公积金的独立闭环

[M12架构](modules/m12.md)及[参缴账本ER](diagrams/e03-contribution-ledgers.svg)分别保留：

| 对象 | 核对问题 |
| --- | --- |
| 参缴资格与登记 | 谁在什么关系、属地、险种/公积金账户及期间下参缴？ |
| 期间义务 | 应缴依据是什么，单位和个人分别承担多少？ |
| 申报及逐项回执 | 哪些明细已被接受、拒绝或仍未知？ |
| 个人应收及扣收 | 个人承担通过工资还是其他方式收取，尚欠多少？ |
| 机构实缴/退款 | 哪个账户、哪笔资金对应哪些义务行？ |
| 补退与核销 | 更正关联哪份原义务、原申报和原资金事实？ |

本期无工资、工资不足代扣、补缴、跨地接续和退款都是架构反例。是否实际有参缴义务由资格和政策确定；不能仅凭“零工资”自动停缴，也不能仅凭“有工作关系”无条件生成所有险种义务。

## 5. 地区样本对设计的验证作用

以下只核对官方文件揭示的模型差异，不复制一套全国2026参数表。

| 样本 | 官方资料支持的差异 | 设计影响及核验边界 |
| --- | --- | --- |
| 北京 | 年度基数申报可按规则调取社保缴费工资；匹配与数据来源影响能否使用 | 基数不是孤立数字，要记录来源、匹配状态和不可直接覆盖的外部证据；尚未据此验证全部数值参数 |
| 上海 | 2026年度通知在8月发布，并规定自7月起的基数调整及新参加工作/新调入口径 | publishedAt与effectiveFrom分开；年度调整要能识别追溯影响及人员条件；不由自然年度自动推断规则 |
| 深圳 | 官方问答对2026年新入职人员当年基数调整单独说明 | 年度批量调整必须有人员条件，不对所有参缴者一刀切；经办规则与工资年度分开 |
| 广州 | 来源稿记录官方站点访问超时，检索仅得到可定位的转载线索 | 标为待核验；不采纳转载金额、不用其他城市或旧年度替代。模型保留地方期间内再次变更的能力 |

来源：[北京年度基数申报指引](https://gjj.beijing.gov.cn/web/zwfw5/386727/386730/386733/387178/index.html)、[上海2026年度通知](https://www.shanghai.gov.cn/gwk/affairs/content/0064%40f3d788ec72e9404ebcbf3d27fda98435)、[深圳2026年新入职人员问答](https://zjj.sz.gov.cn/hdjl/ywzs/content/post_12893632.html)。

这些样本说明模型必须按地区、适用对象和期间解析，并不建立全国城市覆盖率。广州资料缺口是政策核验待办，不影响已给出的地区版本机制；上线其具体规则前仍须补齐官方依据。

## 6. 工时、休假与退休

排班计划、实际工时、缺勤权益和计薪结果保持独立。法定年假资格和待遇有相应规定，不能用当前企业工龄一个字段覆盖所有资格或例外；目标记录资格依据、授予/消耗、政策期间及来源。地方假种、医疗期、加班和各类工时制度的具体参数列为逐项核验内容。[职工带薪年休假条例](https://xzfg.moj.gov.cn/front/law/detail?LawID=208)

弹性退休制度涉及选择、办理程序和关系/缴费安排。目标分别表示退休资格评估、选择/协议、实际办理结果、用工终结或延续和参缴变化；不能按一个固定年龄自动终结全部对象。[实施弹性退休制度暂行办法](https://www.mohrss.gov.cn/wap/zc/zcwj/202501/t20250101_533701.html)

## 7. 人员信息、供应商及数据出境边界

个人信息保护法规定不同处理依据、最少必要等要求。目标在X03记录处理目的/依据、敏感字段权限、导出和供应商传输范围、保留/删除规则及保全例外；人力资源管理不是所有资料均可任意收集的理由，也不能只加一个同意勾选框。[个人信息保护法](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)

向招聘、学习、福利供应商发送资料只交付必要字段；账号认证不自动授权导出。涉及跨境、敏感信息或自动化评价的场景保留专门判断接口，本轮不对具体客户处理活动作合法性结论。正式保留期限由数据类别、义务和用途确定，不在设计稿写一个全库统一年数。

## 8. 中国场景设计反例矩阵

以下为架构走查材料，并非运行通过证据或已验证法定金额。

| 场景 | 应当保留的边界 | 关联图/模块 |
| --- | --- | --- |
| 同名、离职后再聘 | 原Person不变，新关系/任职；历史工资不动 | E01/F01/F07、M01/M04 |
| 集团跨法人及异地调动 | 关系与主体交接、税累计和参缴分别判断 | E02/F02、M02/M11/M12 |
| 双关系与兼任 | 主选择不替代全部税费/权限范围 | E01、M04/X03 |
| 跨午夜班遇休假 | 班次归属日、实际时间、权益和计薪分开 | F03、M06—M08 |
| 月结重复采用 | 核对引用不重复产生金额 | F03、M07/M10 |
| 年中入职、同年再聘 | 关系时间与税务累计键分开 | F04、M11 |
| 跨年补发或更正 | 原税年/所得/支付及申报链各自存在 | F05、M10/M11 |
| 无工资但待处理参缴 | 独立资格和义务，个人承担可留应收 | E03/F06、M12 |
| 政策发布晚于生效 | 记录与生效分开，定位受影响采用 | E04、X01/X02 |
| 新入职排除年度统一调整 | 适用条件和原因可解释 | M12/X02 |
| 部分申报接受、部分付款未知 | 行级结果保留，查询与续办不重复执行 | E06/F06、X05 |
| 付款后换卡 | 新用途不改已发送账户快照 | E05、M01/M14 |
| 退休选择后继续工作 | 资格、关系、参缴和最终工资分别处理 | F07、M04/M12 |
| 学习完成但资格未确认 | 记录证据，不能自动授予岗位准入 | F08、M16/M18 |
| 经理跨范围查看旧评价 | 当前授权约束历史读取和搜索 | M17/M19/X03 |
| 成本更正遇已关账 | 原凭证保留，新期间差额/冲销可追溯 | F05、M15 |

后续落地应为适用场景提供独立输入、步骤、期望事实/金额、政策期间和官方依据；本章定义这些场景在目标架构中的责任与处理路径。
