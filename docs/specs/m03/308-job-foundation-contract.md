## 1 对象、角色与范围

<a id="m03-br-001"></a>
### 1.1 M03-BR-001 身份、分类及归属

JobFamily 是企业内的单层职务系列，Job 定义职责与任职要求。两者各有独立 UUID、编码、记录、修订和来源。每个 Job 资料记录必填一个同企业系列，一个系列可供多个 Job 使用。职类扩展增加与系列并列的工作性质分类，沿用同一个 Job 及原系列身份。三个对象均归企业共享。组织权限、岗位和人员任职由各自业务办理。企业身份取自已认证上下文。

职务管理员办理获权动作，查询者只读获权当前资料／历史；导出独立授权。原首批正常菜单为“设置 → 职务配置 → 职务系列／职务”，直接进入相应列表。职类扩展的菜单及候选见第14节。

可用职级、阶梯和岗位资格分别由[310 职级合同](310-grade-ladder-contract.md)及[312 岗位合同](312-position-contract.md)持有。[G2 实施记录](../../verification/309-grade-g2-implementation.md)与[岗位签收单](../../verification/311-position-definition-signoff.md)记录对应批次的结果。

补丁缺省保持，显式null／全空白清空可空文字，必填字段清空拒绝；字段应用完成后评价最终候选，顺序不影响结果。未知字段拒绝。创建必填字段缺少写权时不开放创建能力，服务端仍拒绝直调。字段错误保留其他仍获权输入。

名称规则采用[013名称合同](../m02/013-m02-technical-design.md)，代码通过T01核定中性纯文字准入位置，禁止导入organization/domain。职责与要求采用普通文字，不继承名称字符目录；所有展示按纯文本转义。

<a id="m03-br-003"></a>
### 2.2 M03-BR-003 操作及原因

CREATE固定原因NEW_JOB_FAMILY／NEW_JOB；CHANGE允许NAME_ADJUSTMENT、DESCRIPTION_ADJUSTMENT（系列）、RESPONSIBILITY_ADJUSTMENT／REQUIREMENT_ADJUSTMENT／FAMILY_REASSIGNMENT（职务）及OTHER_DATA_ADJUSTMENT；DEACTIVATE为FAMILY_CLOSURE／JOB_CLOSURE，REACTIVATE为FAMILY_RESUMPTION／JOB_RESUMPTION。Go按对象和类型核验目录，保存当时标签，目录变更不重解释旧源。更正名称、日期或分类可以组合提交；单独更原因不制造新分类采用。

## 3 按日维护与依赖资格

<a id="m03-br-004"></a>
### 3.1 M03-BR-004 时间线与完整操作

稳定记录身份、按日唯一、半开区间[start,end)、独立不可变修订；没有同日序号。支持新建、所选位置新增／插入、普通更正、原位置内改日、非首条记录删除、末条停用／恢复，以及两个固定启停期间操作；不开放任意多对象编排。首条CREATE不可删除，编码不可改成另一主体，误建身份通过停用处置，不提供物理删除或恢复已删记录。

CHANGE和恢复保存独立资料快照；停用继承最终前序资料，分类／删除／改日引起的隐式变化仍检查对应写权。插入早期资料不改写独立后继，历史原件、原记录日期和准确采用保持。普通列表取服务端今日D，未来首条可发现且显示未生效；详情按所选记录，不增加通用查看日期。业务时区沿现行Asia/Shanghai，前端不计算权威日期／能力。

首批采用[121共用规则矩阵](../m02/121-dated-object-admission-matrix.md#2-共用规则矩阵)的维护行为，不继承部门父边、树范围、BU授权、永久判权档案或M04同日动作。Staffing拥有自己的操作分类与对象资料，算法复用须满足第6节边界。

<a id="m03-br-005"></a>
### 3.2 M03-BR-005 企业日期下界

两个对象的首条日期不得早于所属企业首条日期；企业后来停用不影响目录维护和读取，不要求企业启用覆盖全部职务期间。企业更名不改职务来源。企业后移首条日期必须同时保护JobFamily／Job最早首条，含已停用对象；新建／前移首条与企业变更取得同一企业共享／排他守卫，在同一短事务内重读。

Staffing通过自己声明的端口取得企业身份和最小日期事实；最小上下文不授予企业详情／历史权限。Organization企业命令经公开反向端口查询Staffing真实最早日期，查询失败拒绝变更，不能当无引用；禁止直接扫描别域SQL。无Staffing实现的原产品不注册空成功端口，实际启用首批时必须同时接线。

<a id="m03-br-006"></a>
### 3.3 M03-BR-006 系列全期间覆盖

Job最终候选每个启用期间必须被当时所引用系列的启用期间完整覆盖，包含未来资料和未来恢复；停用期间只保留历史分类，不要求系列继续启用。系列停用、首条后移、删除或改日导致覆盖减少时，反向检查真实Job当前头全部受影响期间，不能只查今天仍启用的职务。失权引用仍参与内部资格校验，但错误不透露隐藏职务的身份或数量。

不满足时整笔拒绝。用户先逐项调整职务归属或结束相关期间，再维护系列；本批没有级联停用、批量迁移或自动换系列。单纯系列更名不扫描／重写其全部职务。职务删除分类变更后回退、恢复、固定期间删除导致启用区间延长，都重新校验最终全期间，不只核请求中显式变化的系列。

新建Job只有首条记录，其启用尾段为开放期间；有已排定停用且不能完整覆盖的系列不能成为该开放尾段的候选。服务端不得把系列截止日隐式变成Job停用日。已明确需要有限期间时，当前首批通过先建立合法开放期间、再显式维护Job停用与系列停用的顺序办理；对已有截止安排且不允许调整的系列，本批拒绝新建开放尾段，不提供隐藏的创建＋停用联合命令。此限制在候选无结果时准确说明，避免页面显示“可选”而保存必败。

<a id="m03-br-007"></a>
### 3.4 M03-BR-007 准确采用与名称展示

Job保留系列稳定身份及采用日、sourceVersion、recordId、revision。新建、切换系列、现有非停用记录改日、恢复按最终记录日新采用；新CHANGE／插入且系列相同继承最终前序采用，普通名称／职责／要求更正保留原采用。停用继承前序资料及证据。所有动作仍独立执行全期间资格检查，采用某日合格不能替代完整覆盖。

| 最终动作 | 准确采用的处理 |
| --- | --- |
| CREATE、换系列、新恢复／固定期间新恢复端 | 按最终记录日新采用 |
| 新CHANGE／插入，系列与最终前序相同 | 继承前序准确采用；插入仍检查新覆盖期间 |
| 普通名称／职责／要求更正，或仅更原因 | 系列不变则原采用保持 |
| 既有非停用记录改日或改变操作类型 | 按最终日重新采用；最终变停用则继承前序 |
| DEACTIVATE及所有最终停用记录 | 继承最终前序资料和采用，不另取停用日新源 |
| 固定期间仅改变停用端，既有恢复端日期／分类／系列不变 | 恢复端原采用保持；仍核最终全期间覆盖 |
| 删除普通／启停记录、删除固定期间 | 最终独立后继保持原采用，停用重继承前序；资料回退所继承的原采用保持，新增覆盖期间须合法 |

新采用与内部继承分开授权：删除导致系列ID隐式变化须有归属字段写权，但纯继承原证据不要求用户重新读取该历史标签；标签仍按当前权裁剪。若动作同时改变日期／类型而触发新采用，则须重新核系列引用权限。反向覆盖只检查各Job当前头的最终业务时间线，不以已被更正的归档来源阻止合法新维护；归档来源及其旧采用完整保留。

今日列表和普通所选记录展示按对应业务日及系列当前修订解析的名称，系列更名可改变当前展示但不生成Job新源。明确查看历史来源时显示Job封存的准确系列版本，不回退到最新名称；原采用身份在内部完整保留，展示依当前系列read/history.read及字段权裁剪。非今日名称或准确来源需要系列历史权；无权显示“受限”，不得泄露旧标签、系列数量或错误细节。

展示日期由Go明确返回：今日启用职务用D；未生效首条用首条日；已停用职务用该停用日的前一业务日。详情显式选择启用记录用该记录日，选择停用记录用其前一业务日；CSV与列表使用相同日期口径。没有该日系列资料时返回引用不可用，不能悄悄替换成今天或原采用名称。当前修订的按日展示与封存采用分开返回类型／标记，不给用户增加日常版本选择器。

## 4 页面、查询、选择与恢复

<a id="m03-br-008"></a>
### 4.1 M03-BR-008 页面及当前授权

系列列表列为编码、名称、英文名称、状态、生效日期；职务另加职务系列。说明、职责和要求在详情／表单直接呈现获权字段，可空不等于默认折叠。列表默认编码升序，无编码读权则UUID稳定排序；相同排序值以UUID打破平局，页大小20／50／100。关键词只搜索获权编码／名称／英文名称，支持上述获权列表列条件和排序；系列筛选使用稳定ID。显式无权条件／排序拒绝。

职务系列列是例外：首批只支持稳定ID筛选，不支持按系列名称搜索或排序，避免用隐藏引用标签排序泄漏信息。筛选须有job.jobFamilyId读权及所选系列当前read权，无权／不可用ID采用同一拒绝反馈；已有条件在撤权后清理并明确提示，不静默扩大结果。总数、导航位置和导出捕获都按同一获权条件计算；列表中的受限标签不成为搜索材料。

详情提供按日记录、记录摘要、操作日志、当前位置／匹配总数和前后导航，导航与列表同一完整条件。返回保留条件、排序、页大小和对象定位；导航辅助失败允许局部重试，不卸载仍可读详情。当前资料read与历史history.read分开，所有错误、摘要、预览、候选和CSV执行当前字段权。直接页面与直接HTTP遵循同一授权。

本对象当前头中的普通按日记录和所选记录摘要按read投影，选择过去的当前有效修订不自动要求本对象history.read；显式sourceVersion、删除前原件和changes日志要求本对象history.read。系列引用的非今日标签／准确旧采用仍独立执行第3.4节的系列历史权，不能用Job.read替代。未获本对象历史权时隐藏日志入口，普通记录维护按当前动作／字段权决定，不一并禁用。

系列候选由服务端根据拟动作／日期和当前记录确定所需覆盖期间，搜索、翻页与异步代次同表单关联。候选失败保留原身份和其他输入；改变日期、动作、对象或会话后旧响应不得覆盖。保存时再次授权和核验；无结果提供调整日期或系列的可理解反馈，不自动选第一项或清空原引用。

<a id="m03-br-009"></a>
### 4.2 M03-BR-009 固定选择与CSV

两个对象独立会话选择草稿，建立时捕获完整查询下当前获权UUID，分页／排序保留，条件集合变化重选。后续新匹配对象不加入，原成员不因不再匹配而消失；成员编辑带草稿修订，首次建立未知不能自动重新捕获。跨日、会话变更、过期按共用选择合同清理。

系列CSV固定六列：编码、名称、英文名称、说明、状态、生效日期。首批职务CSV固定八列：编码、名称、英文名称、职务系列、职责、任职要求、状态、生效日期。后续职类切片交付时按[第14.3节](#m03-br-032)追加一列。导出当前资料，按完整固定成员及当前授权验证后生成文件；实际入选成员／固定列读权缺失整笔拒绝，已排除成员失权不阻止其他导出。纯列表／详情允许字段裁剪；CSV不以空白冒充完整数据。保留UTF-8及既有公式注入、引号、换行处理。

<a id="m03-br-010"></a>
### 4.3 M03-BR-010 保存结果与异常恢复

保存直接提交；未保存取消不写业务事实。冲突提示重读并保留仍获权草稿；日期、系列或字段问题定位对应输入，不输出内部版本／锁标识。提交号按实例、主体、对象类型隔离，相同摘要重复不新增事实，变摘要拒绝；确认事务提交后才发布成功或确定拒绝。

响应未知使用原类型／主体／提交身份查回，查回与迟到提交共用锁；只有确认不存在且已安全关闭原身份才能报告未保存。超时、连接断开、解码失败或失权不能解释为未保存。当前页面有限一次自动确认与手动重试互斥；换账号清理受保护内容，未明提交的离开提示遵循现行301流程。数据库重启后终态和原来源仍可读取。

## 6 领域、存储、公开合同与事务

<a id="m03-br-011"></a>
### 6.1 M03-BR-011 领域归属及最小复用

JobFamily／Job归`internal/contexts/staffing`，各自拥有Data/Patch、候选、资料／分类规则和公开DTO，领域层不依赖organization、HTTP、SQL或前端。首批不创建M04空目录。现有M02 dated及submission有对象错误码、历史及授权依赖，禁止跨域导入或整包搬入foundation。

T01以两个实际域验证小型日期区间和纯文字准入的提炼，保持foundation仅有无业务状态的值／纯函数；业务时间线、操作目录、结果投影和授权留本域。提交确认可通过无业务类型的端口与设施实现复用，不能共享业务终态表或解码器。若采用新中性包须明确修改004及边界正反例，不能仅为通过构建放宽检查。前端仅提炼实际共用的展示／会话组件，所有能力和关系资格由Go返回。

<a id="m03-br-012"></a>
### 6.2 M03-BR-012 物理事实与API

在staffing schema中JobFamily／Job分别拥有身份、当前头、不可变记录修订／来源、可重建按日读索引、日志、提交终态、Outbox及选择草稿。固定类型标签和schema版本归Staffing，禁止借用M02对象类型码或复用BU／部门业务表。sqlc查询由staffing拥有；迁移在实施时核对main后追加，API／Worker不自行迁移。Go生成日期／状态投影，SQL只按明确参数查询，不另写一套业务状态机。

HTTP资源前缀分别为`/api/v1/job-families`、`/api/v1/jobs`。提供context、operation-reasons、列表／详情／changes／navigation、reference-context（Job）、preview、创建、records新增／correct／redate／delete、deactivate／reactivate、lifecycle-pairs的insert／maintain／delete、submissions/{id}/resolve、selection/start／resolve／cancel及export。公开类型独立为JobFamily／Job系列，所有写入携带提交号和预期来源，修改记录另含recordId／revision；前端只传稳定ID，不传可信名称／资格或伪造采用证据。OpenAPI是HTTP唯一生成源。

创建例外：尚无对象来源，提交号绑定规范化内容及目标类型，不要求虚构expectedSource；既有对象写入必须给expectedSource。业务提交结果至少包含类型、提交号、对象ID、确定outcome及获权的新来源／记录定位；未知返回恢复引用，不能填成功资料。选择草稿增删使用独立draftId／revision，不混用业务来源或终态；OpenAPI冻结时逐端点列明HTTP方法、动作字段与空值语义，T02接线前由T01验证类型反例。

事件随本域事实与终态同事务落库，包含对象／来源／动作稳定身份，不含永久逐次判权过程。源事件落库不宣称已投递；本批没有消费者Inbox或采用成功状态。审计操作者快照、不可变修订和当前授权继续保留。M03请求不得返回M02错误码；业务字段错误400、未认证401、无权403、当前版本／引用冲突409、暂时依赖失败503由Go分类，历史不存在与不可见按同一防泄露合同处理。

<a id="m03-br-013"></a>
### 6.3 M03-BR-013 共同守卫与失败原子性

企业首条校验使用Organization公开应用端口加入同一短事务；返回最小身份／日期值，不返回内部聚合或pgx事务到domain/public。组合根将本地事务作用域注入各域适配器。企业共享守卫与其维护排他守卫一致；反向最早日期由Staffing端口在同事务读取，不通过外部HTTP或异步事件补救。

Job写入与系列资格变化共用系列守卫，涉及原／新系列时按稳定ID排序；系列变更在锁内读取受影响Job来源和有效段。依赖发现与取得锁之间变化须锁内重新规划，按同一总预算退出，不能边持锁边无限重试。固定顺序为本类型提交锁、必要企业守卫、排序后系列守卫、职务对象锁；系列缩短资格只读取Job依赖不反向取得职务写锁，避免与职务先取系列的顺序相反。

每次Job写入取得最终可能受影响的原／新系列共享守卫，系列资格维护取得对应排他守卫；系列本身的对象版本写锁另保证其同对象串行。空引用集合也取得系列守卫，不靠已存在Job行锁防止幻影。所有写入统一按上述顺序，纯读取不取得写守卫；Job所属系列、企业及候选源在取得完整锁组后再次确认。

资格判定必须在共同锁取得之后看到此前已提交的依赖。首批写事务采用READ COMMITTED，在锁内重新读取当前头及其不可变资料，禁止复用锁外／旧事务快照中的依赖列表；每个实际依赖的源版本必须对应读到的头。依赖集合变化需回滚该次业务事务后按排序锁组重规划，不在持有较后锁时补取较前锁。确定结果前不发布临时回复，失败重规划不写拒绝终态。跨域端口必须使用同一物理事务／连接，无嵌套独立事务；T01实测这一性质，不从接口签名推定成立。

锁内重读来源与当前授权，构造最终候选并核所有实际字段变化，随后一次保存事实、准确采用、投影、日志、Outbox及终态。任何失败回滚业务写；确定拒绝终态仅在安全回滚后确认提交。取消、等待超时及未知COMMIT分别记录，不放宽预算或用重试掩盖错误。企业／系列／对象／提交锁均有可释放验证。

### 10.3 共用实现和日志读取边界

现有`packages/ui`外框、控件、主题和日期展示直接复用；`apps/web/src/shared`已有导航、离开保护和提交协议按现有接口复用。DatedPages及固定期间的对象流程仍有M02类型和API耦合，Staffing通过本域适配接线，不能整包导入Organization业务实现、用断言转换其DTO或另建第二套业务规则。实际中性提炼为[列筛选](../../../apps/web/src/shared/dated/ColumnFilter.tsx)及[日志展示](../../../apps/web/src/shared/dated/OperationLog.tsx)，两域均已接入；原M02消费者须同时回归。

原实现只返回来源列表与快照，未满足U09；现由[Staffing Go日志读取](../../../internal/contexts/staffing/application/changes.go)按准确前后修订及当前权限提供操作组、记录上下文、字段原／新值、直接／随期间变化、操作者、来源链接、分页数量及固定上界；前端不能从最新详情反算历史差异。日志每页20／50／100项操作，字段子行不拆页；列筛选沿012交互，一次一列，支持记录时间、操作者、记录处理、生效记录日、变更字段，谓词沿[013日志合同](../m02/013-m02-technical-design.md#m02-tech-operation-summary)的适用定义，字段目录改为本对象获权字段。

当前／历史日志分别绑定当前源或明确`contextSourceVersion`，服务端给出`throughSourceVersion`；分页、筛选及从原件返回保留该上界。原值／新值、记录上下文及来源明细均按当前字段权裁剪，不能泄露被裁剪字段名、数量或引用名称；日志读权不扩大Job对系列历史的引用权。OpenAPI、Staffing查询参数／DTO和对应测试随整改一同落实；不增加永久判权过程档案或业务数据迁移。初始合同批次仅确定要求的历史事实由原报告保留。

日志的`action`使用Staffing自己的CREATE／ADD／CORRECT／REDATE／DELETE／DEACTIVATE／REACTIVATE及INSERT_LIFECYCLE_PAIR／MAINTAIN_LIFECYCLE_PAIR／DELETE_LIFECYCLE_PAIR处理目录，不复制M02的REVISE_TIMELINE或已退出联合写入口，也不把CHANGE业务分类当记录处理。`changedField`采用M03资料字段及期间／状态／日期／分类的获权投影；错误码沿Staffing合同。筛选先授权再匹配，未知／重复／不完整参数拒绝，不能静默扩大结果；排序沿保存来源先后，不按客户端时钟或当前页面局部排序。

## 12 页面独立样本、场景与验收

### 12.1 样本与角色

以下是独立样本定义，执行结果另由验收报告持有。仅在自有隔离环境用真实API准备，受控日期样本采用D=2026-02-01；不改主机时钟，不向4380用户验收库写样本。各例从声明的前置独立开始，不串用其他案例已经更改的数据、筛选或选择。UUID、来源和记录身份记录为别名，期望的名称、日期、条数和权限来自本表，不能由被测页面或候选算法反算。自动运行可加唯一编码前缀隔离数据；普通浏览器采用真实业务日时，未来记录必须显式置于该日之后并记录映射，受控Clock的时刻及日期边界另行验证，不把实际已生效的2026-03-01冒充未来样本。

2026-11-17用户后续明确要求在4380实际执行页面及API场景并保留操作数据，本批按该授权在备份和原数据保护后新增独立样本，并留存所有来源及回执，见[现场验收第9节](../../verification/308-job-page-standard-implementation.md#m03-308-live-retained)。这是该次明确授权的例外；日常自动测试继续遵守上段隔离要求，不据此取得改写用户已有对象、调整授权或回收固定库的许可。

### 14.1 M03-BR-030 工作性质与专业领域

职类（JobFunction）回答“这份职务属于什么性质的工作”，如管理类、专业类、操作类。职务系列（JobFamily）继续回答“属于哪个专业领域”，如人力资源、财务、工程。CubeBox 称后者为“职种”。本产品沿用“职务系列”这一名称和已有身份。每个新职务各选一个同企业的职类和系列，两项分别维护，没有父子关系。更换一项只重选该项。管理类不会授予审批权或产生经理关系。子职能、子职种及晋升通道需各自的业务依据，不属于本次扩展。[CubeBox 与 Fusion 对照依据](../../verification/308-job-function-contract-review.md)

| 可验收的职务样本 | 职类 | 职务系列 |
| --- | --- | --- |
| 人力资源经理 | 管理类 | 人力资源 |
| 人力资源专员 | 专业类 | 人力资源 |
| 财务经理 | 管理类 | 财务 |

Staffing 唯一维护企业内的 JobFunction。每项职类有稳定 UUID、企业内同类型唯一且不可改的编码、必填名称、可选英文名及说明。字段长度、规范化、状态、独立修订和操作沿用第2、3节的系列规则。首建默认 `1900-01-01`，允许改日。职类、系列可使用相同编码。原因目录给职类独立的创建、关闭、恢复原因，资料变更可采用名称调整、说明调整或其他资料调整，Job 增加“职类调整”原因。原因与最终字段差异分别判定。样本目录由验收时显式建立。

职类首条受企业起日约束。Staffing 的最早日期公开端口把所有本企业职类首条纳入比较，含已停用和无人引用的职类。企业后移起日与职类新建或前移首条共用第3.2节的企业排他／共享守卫，在同一事务内复读。端口失败时企业命令拒绝提交。

### 14.2 M03-BR-031 职务归类、存量及原采用

Job 新增单值 `jobFunctionId`。服务端接收稳定 ID，对每次新采用保存职类身份、采用业务日、sourceVersion、recordId 和 revision，系列保有自身的准确采用。对于已登记的维度，必须有同企业的合格来源覆盖 Job **整个启用段**，含开放尾段、已排定的未来段和固定期间的恢复端。第3.4节逐维适用。新建或换类按目标日新采用。新增或插入启用资料，与前序同类时可继承其采用。更正名称、职责或仅更换另一维时保留本维原采用。已登记的启用记录改日或转为启用时，按最终日重取。停用段继承最终前序。固定期间仅改停用端时，原恢复端日期、分类均未动则保留其原采用。

| 办理情况 | 职类的确定结果 |
| --- | --- |
| 扩展交付后新建 Job，包括追溯新建 | 必填且无默认，合法的系列仍须单独选择。缺职类或显式传 null 均为字段错误 |
| 升级前已保存的 Job 记录，包括未来节点及已停用记录 | 保留逐条原件，获权读为“未登记职类”。不按职务名称、系列、职级或管理岗标识推算。盘点时发现旧系列混有管理／专业等值，由业务逐项确认，再按真实生效日期办理相应维度的变更 |
| 原未登记的启用记录维持原类型，更正文字、职级、系列或只改日 | 可省略职类，原记录保留未登记依据。改日后，系列等已登记维度按最终日重取，相邻期间的隐式职类变化按下文判权。若获权且有依据覆盖原日，可补录到该记录。后来才确定归类则从真实生效日新增 |
| 新增或插入启用资料、新恢复（含固定期间恢复端）、把原停用节点更正为启用 | 最终必须有一个职类。可沿用合格的已登记底稿身份，按第3.4节判定继承或新采用。可用底稿仍未登记时须显式选类，缺值不能提交。未动的独立后继即使落在未来也保留其原登记情况 |
| 停用、删除或改日使一段回退 | 按最终前序继承。回到有依据的未登记旧段时显示该事实。若改动导致某一段的职类身份隐式改变，办理人须有该字段写权。保留改动前原件 |

Job 命令显式提交 `jobFunctionId` 时，先核本动作的字段写权，即使提交的 ID 与底稿相同。缺权返回 403。具权者显式传 null 或空 ID 返回 400。省略时按上表确定底稿。Go 以操作前后全部生效边界分段比较。在两条时间线均有 Job 记录的日期，只要任何一段从未登记变为已登记、反向变化或变为另一职类，均须字段写权。首条纯改日只缩短原未登记段，或相邻期间仍同类，单凭改日无需职类写权。仍须有动作权及重取引用所需的权限。表单只提交主动修改的获权字段，直调 API 也执行同一规则。

升级用追加迁移，以切换前已提交的 Job、sourceVersion、recordId、revision 为旧未登记依据，覆盖现行头、未来记录、已删除记录的历史原件。切换时在同一写入边界确定旧来源集合并启用新规则，重试仍识别同一批原件。后续合法继承未登记时可追溯到对应原件。业务日期本身不能证明是存量。已登记采用残缺，或缺值却找不到旧依据，均报数据错误。核对原来源、日志、回执、已存在的岗位及真实下游采用，升级本身不产生业务修订。旧岗位按封存 Job 源及当前授权读当时分类。

### 14.3 M03-BR-032 正常菜单、查找和导出

从「设置 → 职务配置 → 职类」进入独立目录，路径 `/settings/staffing/job-functions`。参照已交付的“职务系列”完成列表、日期轴、新建、记录新增／插入、更正、改日、删除非首条、末端与固定期间启停、准确来源、日志及返回。新建取消零写，更正带原值，保存定位到生效记录。职务表单在系列旁直接呈现职类，包括固定期间弹窗的独立恢复资料。按动作、日期、记录和当前字段权取候选，失败保留其他获权输入。参照既有正常页面验收桌面、窄屏、键盘及原生缩放。[308 页面继承表](#m03-page-inheritance) · [121 接入矩阵](../m02/121-dated-object-admission-matrix.md#24-页面标准继承与m03接入映射)

打开新建表单就可先查任一维。候选只依赖本维的拟动作、记录、日期、所需覆盖段和权限。另一维尚未填写、变更或在既有记录上受限，都不影响本维已合格的候选。候选请求可带本维已选 ID。服务端用同一次试算返回其可用性，合格时同时返回获权名称。搜索和翻页只影响候选列表。保存时 Go 再验整个职务。固定恢复端使用自己的拟日期与底稿。变更日期后旧响应失效，保留另一维输入，重新校验并指出实际失效的字段。

职务列表和详情各自显示获权的职类、系列。稳定 ID 条件 `jobFunctionId`、`jobFamilyId` 同时应用时取交集。职类条件也可选 `jobFunctionMissing=true` 查询有来源依据的未登记，与指定职类 ID 互斥。按 ID 查须有本维字段读权及目标读取权，查未登记须有 Job 职类字段读权。已登记但目标受限的记录从不计入未登记。分类名称只在对应目录按权限搜索。职务关键词和排序沿用第4.1节。固定选择、导航和匹配数使用同一获权查询。已无权的条件须提示并拒绝执行，用户显式移除后重新查询。

职务列表对第10.2节 U02 的单列筛选作一项业务扩展。桌面从对应列、窄屏从筛选菜单进入，每次编辑一维。职类与系列各可保留一个已应用条件。应用或清除其中一维时保留另一维，取消保持原查询、计数和焦点上下文。应用普通列条件时替代这组分类，首次应用分类时替代原普通列条件，关键词沿用原规则。返回列表恢复当时两个获权条件。

新职类独立使用 `jobfunction` 动作、范围及实际字段读写权。Job 的两项分类字段分别判权。新采用查目标读取及所需字段，非今日采用或准确旧标签另查目标历史权。内部继承未变引用可保有原证据。主动提交和隐式变化均按第14.2节判权。详情、日志、候选、选择、错误及导出分别重验。无字段权时裁剪字段，有字段权但引用不可读时显示“受限”。普通显示按第3.4节业务日取名，明确查看准确来源时按原采用和当前权限取名。升级前成功但响应丢失的旧提交，先按原主体、类型、提交号和摘要查回终态，再按现权裁剪。原样重送沿用旧结果，异载荷重送按第4.3节拒绝，新提交号适用新规则。

职类目录 CSV 沿用系列的六列。自职类切片交付，Job 新生成的 CSV 在第4.2节既有八列末尾追加“职类”，共九列，职务系列仍在第四列。此规则接续 310 职级批次的八列约定。本人此前已下载的八列文件保持原件。用仍有效的旧固定选择再次导出，按原固定成员和届时授权生成九列。获权的真实未登记输出空单元格。任一入选成员的固定列或必要引用缺权时整次拒绝。

### 14.4 M03-BR-033 写入、反向保护与独立交付

新 `/api/v1/job-functions` 资源提供与第6.2节 JobFamily 对等的维护、查询、选择、导出和提交恢复入口。Job 增加字段、筛选、日志差异和独立的 `POST /api/v1/jobs/function-reference-context`。客户端按拟议动作／日期提交稳定身份，Go 在保存时重验全部受影响段。跨企业或不可见对象给相同受限反馈，错误不枚举隐藏依赖。未认证 401、缺权 403、输入字段不合法 400、版本或期间资格冲突 409、暂时依赖失败 503 依既有合同分类。OpenAPI、sqlc、X03 和页面随实现共同交付。

在同一 PostgreSQL 短事务中，沿用 310 的提交身份、必要企业守卫、Family、Grade、目标 Job 等锁序，在 Family 与 Grade 之间加入按 ID 排序的 JobFunction 守卫。312 的岗位及组织引用沿用各自的获取顺序。Job 写入取原／新全时间线涉及的职类共享守卫。职类收窄资格时取自身排他守卫，在锁内读取全部受影响的现行 Job 启用段，含隐藏和未来引用。由消费方共用守卫保护首次使用，反查无需再取 Job 写锁。覆盖减少会使任一 Job 失格时整笔拒绝，办理人可先显式重分类。锁内按 READ COMMITTED 重读，集合变化按原总预算回滚重规划。仅更名不重写 Job 或其采用。各命令把业务事实、准确来源、终态及本域 Outbox 同笔提交。

| 后续切片 | 可单独签收的结果 |
| --- | --- |
| 308 职类 | 成功通过目录与职务正常菜单维护、筛选和保存两维分类，并验证存量、双向守卫、权限与历史。使用已有企业、系列、Job 及必要的既有岗位回归样本，全程无需核编、招聘预留或任职占编数据 |
| 313 编制管理首批 | HR 可按有效部门核总额、按合法岗位定额，并在部门内调剂。岗位可继续引用升级前未登记职类的 Job。职类资料、归类完成率均不作为设额、改额或签收条件，职类变化也不改编制记录。[313 部门分配](313-position-capacity-contract.md#m03-br-040) |

实施可按任一次序集成。两项都准备好时加做相互隔离回归，各自的领域命令、授权与验收仍独立。按企业、职类分组查在岗人数、任职数或占编量时，分别由真实人员与编制管理模块按业务日、原采用与权限办理，不能由职类推定兼岗、编制或薪资。
