# CHNHCM-312 岗位定义与岗位层级对象接入合同

登记：[registry.json](../../governance/registry.json)。范围：[311分批计划](../../archive/plans/311-m03-positions.md)。上游：[310职务资格](310-grade-ladder-contract.md#m03-br-017)、[层级与汇报](../../architecture/target/10-ddd-and-state-contracts.md)、[120期间协议](../m02/120-dated-maintenance-technical-contract.md)。

## 1 岗位资料与身份

Position表示一个席位，不表示任职或有多少可招聘名额。“空缺”在本批指无需任何人员即可存在，不设置可手改的空缺标志。编码在企业岗位内唯一、创建后不可改；职务编码不是岗位编码。名称必填，英文名可选。首次日期默认1900-01-01，可显式改，不早于企业首日。JobFamily与阶梯都不是岗位引用。

| 字段 | 首版决定 | 可选范围 |
| --- | --- | --- |
| 所属部门 departmentId | 必填，唯一归属 | 同企业可读且覆盖岗位整个启用段的M02部门；不是上级岗位或人员经理 |
| 职务 jobId | 必填，一个职务可定义多个岗位 | 同企业且全段启用的Job，不隐式采用其系列或第一项职级 |
| 工作地点 locationId | 必填，明确席位的组织地点 | 同企业且全段启用的M02地点；不用文本地址代替 |
| 职级 gradeId | 可空，不设默认；空表示本岗位未指定 | 非空时Grade全段启用，且段内每份生效Job记录均含该Grade；Job空集合只允许空职级 |

## 2 按日维护与引用保护

编制后台接入后，岗位改隶、启停和日期更正须按最终归属复核受影响部门的分配，岗位首日后移须保护已有核编日期。岗位入口复用 M03 的额度校验，岗位定义继续持有所属部门。[313 核编日期与部门分配](313-position-capacity-contract.md#m03-br-026)

采用[121共用矩阵](../m02/121-dated-object-admission-matrix.md#2-共用规则矩阵)。一日一条、稳定记录ID、独立修订，DB业务区间为`[start,end)`；开放段不人为截窗。同日更正不新增生效节点。新建、未来追加／插入、更正、原位置改日、非首条删除、停用／恢复及成对维护按[308日期与页面合同](308-job-foundation-contract.md)；停用继承资料，不要求其停用期间引用仍启用，恢复重新核验。更正带入原值，未传保留；显式null可清职级，不可清必填引用。独立后继不被覆盖。

候选在拟定的起点、下一节点及拟职务上下文计算，不在浏览器过滤今天的名单。Go按岗位段与引用边界逐段核对；保存对最终时间线重算（包括前序延长、删除回退及恢复）。不可用时报首个冲突业务日及可见字段；不暴露其他岗位标识。反向改变Job的职级集合或启用期间、收窄部门／地点／职级资格，同一事务在共同守卫下按最终现行岗位用段检查。非资格更名不阻塞，也不重写岗位；有冲突先显式换引用、清职级或结束使用，不级联改历史。失败不写业务头、修订或Outbox，可靠提交保留确定的拒绝回执。

当前展示按查询日，精确来源按当时采用的业务日、来源、记录、修订及名称。重新选择、改采用日或恢复时重新采用；纯名称更正不换采用。业务日与北京时间记录时刻分开。岗位与源对象均须当前授权；精确来源另需历史权，不以组织或岗位树授予访问。核对受影响的启用段：即使未手改外键，停用、恢复、改日等改变引用使用期间，也须有权读取对应边界上的新旧引用；不能用停用绕过撤权。独立且未受影响的后继不因此重新采用。

## 3 层级发布合同（第二批）

日常查询、安排和解除上级统一使用管理汇报。查询日用于定位结构；安排时可改生效日，发布前可取消。最新结构列出查询日启用的岗位；指定版本按发布时封存的岗位来源清单及日期取名称与有效状态。两者都允许尚无上级的岗位。

每个企业只有一个管理汇报结构，hierarchyId 固定。发布命令携带期望发布版本、拟生效日期、子岗位与上级（撤边明确指定）；未发布编辑不改变已发布结构。发布后保留包含全部有效期边的不可变快照、版本号、操作者、时间与Outbox；一次业务命令一个幂等结果。查询以 businessAt 及可选 sourceVersion 定位，管理汇报省略版本读最新发布版；显式旧版不可编辑。没有上级表示根或未挂接，不构造虚拟岗位。

同一企业只有一条管理汇报发布版本链，但允许多个无上级的真实岗位。安排未来换上级时，旧边截至生效日前一天，新边从生效日起算；如已有独立后继，新边仅持续至下一次安排。保留旧发布快照，不修改其原有的结束日。撤边后从该日起没有上级，不解释为删除岗位或终止任职。读指定版本时不存在的结构不回退到最新版本。

Go对所有受影响边的开始／结束、父子启停及邻接链边界分段验证：端点同企业且全段有效、同一天每个子岗位最多一个管理上级、不得自指或沿链成环。单独验证未来安排。取得本企业的管理汇报写锁并固定顺序锁受影响岗位，锁后重读最新发布头再验；岗位变更与发布共用守卫，若将破坏已发布现行边则拒绝。拒绝或取消不改版本及边。HR按结构日期查看管理汇报，在岗位详情保存上级安排，并可查看只读历史版本；本批无自动发布到M04、无实际经理关系变动。

### 3.1 管理汇报的唯一入口

岗位详情与上下级页面直接展示管理上级和直属下级。发布历史只列本企业的管理汇报版本，旧版按当次封存的岗位及查询日读取。页面地址、Go合同、存储根及新发布事件均无用途字段。API 的固定路径为 `/api/v1/position-hierarchies/reporting`，结构查询和调整分别使用其 `/structure` 与 `/publish` 子路径。查回原提交按提交号定位，不接收查询参数或请求正文；无效查回在写入任何回执前拒绝。带用途的旧页面地址显示「页面不存在」。[139方案](../../archive/plans/139-position-workspace.md)按本节办理，其初稿及311原批次的双用途条款只适用于原批次。

从含双用途的受支持版本升级时，保留管理汇报的身份和已发布历史。按 2026-11-23 的产品决定，直接移除职能协作根及其专属版本、节点、边、发布事件和回执。事务失败时原库状态可重试。[升级副本逐项对账](../../verification/315-department-quota-allocation.md#quota-start-gates)

## 6 岗位工作区接续

[139方案](../../archive/plans/139-position-workspace.md)合并了岗位菜单，并统一了岗位详情。根据 HR 的页面复核，入口采用以下约定，取代原方案第 2 节的并列视图。

- 「职务配置 → 岗位」直接打开标准岗位列表。桌面左侧按部门筛选，右侧展示岗位，窄屏使用部门抽屉。控制区沿用公共列表的标题、获权操作、搜索和分页。
- 有岗位关系读取权限时，列表「更多操作 → 查看岗位上下级」打开独立页面，可直接按日期浏览获权范围内的管理汇报关系，或查看发布历史。「返回列表」恢复进入时已应用的部门范围、搜索、排序和页码。
- 查看单个岗位的上级和直属下级，直接打开「岗位详情 → 岗位关系」。从关系图点岗位也进入同一详情，返回时恢复关系图的位置。

岗位列表的今日部门范围与岗位层级的结构日、历史版本分别处理。部门范围不限制已授权的跨部门上级。在当前岗位的“更多操作 → 调整上级”办理，顶部“保存／取消”；成功按拟日定位，取消恢复原位置。只读旧结构按封存清单定位岗位源，再以结构日在该源内选记录，不能用层级版本号读取岗位资料。当前关系需层级读权及岗位必要字段权，非今日或封存资料还需岗位历史权，指定层级版本另需层级历史权；写入再验调整权。
