## 2 候选、查日与准确采用

1. Go 按同一业务日验证任职、可用计划、该版范围、基本工资组成及薪标。该版计划的全部组成中须恰有一项性质为 `BASIC`。该项采用 `GRADE_RATE` 取值，口径为 `CNY / MONTH / PER_MONTH`、两位小数，且对实际职级命中有效的 `RANGE` 薪带。客户可自定项编码或名称，核定按稳定的组成项 ID 保存采用。计划候选分页在筛完权限和资格后计算。跨页有多份合格计划时要求明确选择。[组成表示](../../../internal/contexts/compensation/domain/plan.go) · [币种与计量口径](../../../internal/contexts/compensation/domain/rate.go)
2. `businessAt` 是此次解析的业务日。`sourceVersion` 定位该源已公布的资料版本。`adoptedRef` 记录本笔实际采用的来源身份、来源版本、选中记录及修订和采用业务日。封存任职及必要组织/职务来源、计划段、范围版本、组成项和薪标修订，以及个人金额及口径。计划自身原先保存时引用的薪标和这次个人核定采用的薪标可不同。11 月计划未换段而 12 月标准已经换段时，12 月定薪须采用 12 月薪标。[首期按日及原采用](211-compensation-configuration.md#m09-br-006) · [共享日期与引用](../m02/120-dated-maintenance-technical-contract.md)
3. 首次、调薪及重新选择依据，以**本次决定的生效日**重核上述条件。只对采用日判断金额及当日资格。未来的薪带换版不会把原约定自动切段。查询某日取该任职覆盖当日的个人有效核定，再分别解析当日该计划、范围、标准及可见津贴。计划已不适用或来源停用时按权提示当日依据需核对，原核定仍可按身份查。任职本身已结束时，只在实际任期内解释个人有效额。
4. 更正带入原业务原因和原采用。只更正说明时沿用原采用。改金额、计划或组成须重新核验**原生效日**的有效来源及薪带。原日来源追溯更正导致资格或金额依据变化时，指出可披露的变化，重读后由经办人按有效依据重新提交。原日已无合法依据时拒绝该金额更正，误建按撤去办理。制度后来正常换版且起日晚于原日，仍按原日判断。真实工资决定的后续变化走后继核定。所有旧版可按现权查回。

## 3 核定身份、期间和历史

| 事实或投影 | 身份及约束 |
| --- | --- |
| 个人薪酬核定 `CompensationAward` | `awardId` 识别一次真实决定，保留所属客户、`personId`、实际任期 `assignmentId`、基本工资性质、计划与组成身份。真实调薪取得新的 `awardId`。同一决定更正或撤去追加不可变 `awardRevision`。办理者、记录时刻、原因、采用和前后修订与原笔关联。 |
| 任期个人基本工资有效段 | 同一客户、实际任期和个人基本月薪在同日最多一笔有效核定。唯一性覆盖更换计划、组成或职级的情况。以独立决定的起日和相邻后继推导 `daterange [start,end)`，有后继时显示含在内的末日，并与 M04 实际任期求交。无任职或首笔前可为空。已知的个人后继决定独立保留自身采用。不使用同日序号。 |
| 修订、采用与回执 | 当前有效段是可重建的投影。补插或撤去仅改变相关段，旧核定、旧修订、采用、原回执及当时成功的结果身份保留。对同一工作关系的两份任职、离职与再聘的新任期使用不同的任期身份。相邻生效段从独立核定推导，补录早于已排定首笔的决定也据此处理。按原回执读取其原修订，即使该笔已更正或撤去。 |

核定事实、修订、采用、按日投影、幂等结果和源域 Outbox 归 M09，在本域落库。当前段须有防重叠约束及按任期和起日的索引，原件可按核定及修订唯一定位。金额使用十进制定点与明确口径，Go 拒绝超精度输入。有效日与记录时刻分存，界面按 [026](../../adr/026-date-display-and-input-format.md) 以北京时间 YYYY-MM-DD HH:mm:ss 显示并保留原始时刻。迁移 00061 由 upgrader 执行。已有任职初始无个人核定，保留首期计划、薪标及其全部历史。[历史保护](../../adr/025-greenfield-implementation-policy.md)

## 4 读写、并发及结果恢复

以下公开入口及客户端类型由同一份 OpenAPI 描述。路径以 `/api/v1/compensation` 为前缀，使用当前会话，写入沿用 CSRF 防护和 `Idempotency-Key`。

| 操作 | 请求、响应及失败合同 |
| --- | --- |
| 页签准入 `GET /assignments/{assignmentId}/base-pay/access` | 按任期和当前权限返回是否可进入；不返回金额和核定数。 |
| 办理准备 `GET /assignments/{assignmentId}/base-pay/context` | 任职身份、拟生效日、可选的计划身份和候选页码。返回可办动作、获权原值、按日候选及依据版本。多份由经办人选定。候选响应区分无合格计划、必要事实待补、读取失败。候选和总数均按现权生成。 |
| 按日详情 `GET /assignments/{assignmentId}/base-pay` 及原件 `GET /awards/{awardId}/revisions/{revision}` | 单一实际任期、工资查询日返回任期状态、该日个人额、当日制度和所选核定引用。原件显式用核定身份与修订读取，个人历史权及每个来源的当前权限分别检查。任职不可披露时统一反馈不可用。 |
| 单笔办理 `POST /assignments/{assignmentId}/base-pay` | `ConfirmAward` 写入口接收明确动作、实际任职、金额或实际有变动的字段、生效日、计划及组成、必要原因、幂等键、期望任期薪资版本及采用版本。更正和撤去另传目标准确核定及修订。成功返回此次核定、修订、日期、回执与返回位置。字段省略沿用适用原值，受保护字段显式清空或越权写整笔拒绝。 |
| 原号查回 `GET /award-receipts/{submissionId}` | 同客户、原提交者和操作命名空间下按原请求身份查回，经现权投影。相同键、同一规范化业务输入重送只返回原结果。同键异内容拒绝。超过响应预算或断线先查原号，处理中或暂不可查时保留原号。主动确认使用 `POST /award-receipts/{submissionId}/resolve`。服务端在该号守卫下核实未办理后，原申请者凭返回的确认码，以同号重送相同输入。 |

组合根将 M04 任期和所需来源的版本守卫、X03 执行授权及 M09 写事务接在同一次办理内。按一致顺序锁定任期工资时间轴和确有依赖的来源，或使用与源域写入互斥的版本校验。读快照后再无条件写入不能保证资格。首次尚无核定时也按实际任期和基本工资用途串行。先按原键识别已确定的结果，再对新请求重读受理时的权限、时间轴、来源与金额。首次、调薪或更换依据时提交经办人在表单确认的具体计划和组成，多份可选而尚未选择时拒绝保存。仅更正说明或撤去时按准确的原笔处理。成功提交一份仍合法的选定计划，只核本次采用所依赖的来源。其他计划并发新增在下次取候选时反映。[办理时的校验范围](../../adr/132-query-and-validation-boundary.md#21-必要保护及责任)

同一旧时间轴或原笔修订最多一笔并发写入成功。旧版冲突返回可重读的最新获权资料。业务拒绝、来源变化、数据库回滚均不得留下半份核定、变更投影或成功回执。写成功时核定及必要的相邻投影、原采用、操作者、原号结果和事实事件同笔提交。使用旧号恢复成功结果时，先核原提交者的当前读取权限，直接返回该次修订的授权投影。事件限必要身份和版本，个人金额通过获权入口读取。此期下游尚无工资域采用，后续的下发和工资期运算按 [M09 与 M10 边界](../../architecture/target/10-ddd-and-state-contracts.md#212-薪酬口径转换与期间分摊) 接续。

## 5 权限、恢复与实施验证

员工详情按当前任职范围与个人薪酬授权决定「薪酬」页签是否可见，已有核定笔数不参与判定。直达页签、切换任期和恢复浏览器历史均重核。当前任职范围与个人薪酬授权同时约束今日、过去、未来、原件和回执。撤去已误建的原笔时核处置权、原修订、实际任期身份和相邻投影。即使原日的来源已撤回，仍能按权处置原笔。未授权看工资时，金额、差额、可倒算的百分比、受限存在性及对应链接一起裁剪。撤去来源原件读权与撤去个人金额读权分别验证。来源变更仅提示当前经办所需的实质影响，现阶段由一名获权管理员直接办理。[历史授权](../m02/012-m02-functional-and-interaction-design.md#m02-ui-history-access) · [213 管理员直接办理](../../adr/213-administrator-maintenance-and-effectivity.md)

| 验证层次 | 可复现的输入和独立断言 |
| --- | --- |
| Go 与实库/API | 取 [215 的金额边界](215-assignment-base-pay.md#m09-ac-010) 及[插入、撤去预期](215-assignment-base-pay.md#m09-ac-012)。用两条连接竞争首次、同日改计划、改个人额与上游撤回职级。按提交顺序核对只有合法串行结果，撤回后对原采用可溯源。 |
| 来源、撤权与故障恢复 | 先保存一月核定，再分别更正计划、薪标、原任职及权限。原号返回原修订的获权字段。旧编辑、原件、错误、历史和迟到响应按现权检查。模拟提交前失败及提交后丢响应，逐笔比对事实数与回执。[权限反例](215-assignment-base-pay.md#m09-ac-013) · [并发反例](215-assignment-base-pay.md#m09-ac-014) |
| 页面与恢复验收 | 同一生产构建从两角色的正常菜单核查日期、两个金额口径、来源、焦点和取消。固定环境更新前后比对首期原件，以及新增核定的各版和回执。不在用户环境注入故障。实际结果由对应阶段报告记录。[实施出口](../../archive/plans/214-assignment-base-pay-rollout.md#2-实施顺序与出口) |
