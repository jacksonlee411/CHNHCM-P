# CHNHCM-211 薪酬体系配置业务方案

薪酬制度维护人可以按计划查到它适用于哪些任职、约定报酬由哪些部分组成，也可以按职级查到标准从哪一天起生效。首期覆盖「设置 → 薪酬配置」中的薪酬计划与职级薪酬标准。**同一客户内，职级、币种、约定频率和计量单位相同时，各计划共用同一薪带。** 个人核定、薪酬下发及工资期运算由后续专项承接。[M09 对象归属](../../architecture/target/modules/m09.md) · [业务用语](../../architecture/target/17-terminology-glossary.md#term-m09-compensationplan) · [登记表](../../governance/registry.json)

## 2 配置对象与字段

<a id="m09-br-001"></a>

### 2.1 M09-BR-001 薪酬计划及组成项

| 维护内容 | 输入与约定 |
| --- | --- |
| 计划身份 | 计划编码在同一客户内唯一，新建时确定。名称必填、说明可选。同名计划按编码和范围区分。按生效日期维护名称、范围和完整组成。 |
| 适用对象 | 明确选择企业通用或指定范围。首批样例以法律实体和职务系列确定范围。职级引用指向 M03 的实际对象。计划保存所采用的范围版本和适用期间。 |
| 薪酬组成 | 至少一项，每项有稳定身份和名称，项编码在本计划内唯一。可表达基本工资、津贴补贴、绩效工资、奖金等性质。选择约定频率、币种、计量单位及取值方式。组成项、行次、范围随同一份计划保存或取消。 |
| 金额取值 | **固定额**由计划持有数值。**职级标准**按可选职级逐项关联标准身份，金额在标准中维护。**目标比例**选择同计划中的基准项，记录比例和舍入口径。页面只要求本种方式实际需要的输入。 |
| 组成项的关系 | 固定额和职级标准独立约定。仅使用目标比例时填写它依赖的基准项和舍入规则。总额分摊、预算分配及实际奖金核定留给后续专项。 |

同名组成项可出现在不同计划。首期固定津贴由各计划独立维护，金额调整在所属计划增加生效记录，仅影响该计划。凡按职级薪带取值，计划只选择共用标准，下限、指导值、上限统一在该标准维护。M10 维护工资项目、计薪规则与工资输入，后续通过公开合同映射计划条款。[首期取舍](#policy-decisions) · [工资项目归属](../../architecture/target/modules/m10.md)

### 2.2 M09-BR-002 职级薪酬标准

| 维护内容 | 输入与约定 |
| --- | --- |
| 职级及身份 | 从当前有权使用的 M03 职级中选择。按客户内职级、币种、约定频率及相配的计量单位定位标准，有一个稳定身份及逐段生效记录。同一日同一口径仅有一份有效薪带。计划或组织范围用于决定计划适用对象，不能据此另建或覆盖同口径薪带。P5 月额与年额可分别存在。 |
| 标准形式 | 首期采用定额或连续薪带。定额填写一个金额。薪带填写下限、上限，可另填指导值。必须满足下限 ≤ 指导值 ≤ 上限，未设指导值时只比较上下限。指导值是区间内的参考金额，职级内不设一档、二档等离散薪档。 |
| 金额、频率和单位 | 金额采用精确十进制，显式填零与未填分别处理。定额、薪带和目标比例均为非负。币种、约定频率（月、年、小时、一次性）及对应单位清楚成组，例如人民币元/月、元/年、元/小时、元/次。不同口径单列。 |
| 有效与保留 | 首条、新增、插入、更正、停用、重新启用均定位具体记录。在同一标准内，每个业务日只可命中一段。切换币种或频率时选择另一标准，原标准和原引用可查。 |

<a id="m09-br-003"></a>

### 2.3 M09-BR-003 比例、精度与金额解释

目标比例须列明基准项、单位、频率、币种及舍入规则。基准项在该计划中必须存在且覆盖所指期间，拒绝自引、循环和隐含币种或频率转换。引用薪带时展示区间，待个人实际选值后才有个人金额。下限、指导值均不能冒充已选值。比例是目标约定，考核结果和实发金额由后续业务形成。

例如，月度目标奖金约定为同计划基本月薪的 10%，BASIC 采用连续薪带。基准身份、口径和期间合法即可保存，显示「基本月薪 × 10%」，个人金额留空。若改用已确定的年定额 180,000.00 元和 12.50%，则可给出年目标参考额 22,500.00 元。组成项改名或重排后仍引用同一项。移除基准须在同一草稿内重选基准或移除依赖项。

本方案为两套人民币制度选用金额两位小数、比例最多四位小数（以百分数录入），由 Go 按十进制运算，目标金额最终一步四舍五入到分。输入超出本制度金额精度时指明字段，让经办人核对。其他币种、小时单价的额外精度及舍入由对应口径明确。样例中的月额和年额有各自的标准，评审时按原单位比较。[精确金额合同](../../architecture/target/03-consistency-contracts.md) · [核算换算与期间分摊归属](../../architecture/target/10-ddd-and-state-contracts.md#212-薪酬口径转换与期间分摊)

## 3 适用、生效与历史

<a id="m09-br-004"></a>

### 3.1 M09-BR-004 范围选择及准确引用

指定范围时，同一维度中命中任一允许项即满足该维度，已启用维度须同时满足，显式排除优先。空条件、未知组织、失效职级或缺少适用版本均须指出缺项。计划底稿可以保留未保存输入。管理员在计划表单一次保存。Go 在事务内核验当前授权、计划组成及本次变更所依赖的来源和期间。变更范围时通过 X02 端口同时保存新范围版本和 M09 的采用，任何一方失败均回滚。沿用范围时保留其版本。默认推荐与当前经办人的可见范围分别判定。

一条按职级取值的组成项须列明它支持的职级和各自唯一标准。应覆盖整段拟生效期间。条件相同的重复标准、漏配的职级和期间空档在保存时定位到相应行。多个计划可并存。本期由经办人明确选择要维护的计划，涉及个人应采用哪一份计划时，再由个人核定合同确定。

企业通用计划可以只有一行人民币固定津贴。此时显式保存企业通用范围与该项金额，职级和薪标均可空。企业通用计划也可按职级取值，此时在对应组成行选制度覆盖的职级及标准。例如基本工资覆盖 P4 和 P5，分别选两份共用月标，后来新建的 P6 不会自动取得任一金额。对实际引用按有效段交界核验完整期间，薪标在七月连续换版可直接沿用。若拟用期为一月至六月，三月整月停用，即使一月和六月均有效也须指出三月缺口。开放结束日覆盖至已知未来边界及末段。[校验范围](../../adr/132-query-and-validation-boundary.md)

<a id="m09-br-005"></a>

### 3.2 M09-BR-005 制度变更、误录更正与停用

企业从新日期调整薪带，用「新增记录」或「插入记录」建立新生效段，上段截至新起日的前一日。制度原文未变而金额抄错，用「更正记录」在同一记录上生成新修订，保留旧修订及依据。新建主数据由 Go 提供默认日 `1900-01-01`，经办人可以改成制度实际日期。所选职级或组织从更晚日期才有效时，就地指出合法期间。后续调整按所选记录的位置确定日期。[日期格式](../../adr/026-date-display-and-input-format.md) · [首次新建默认日](../../adr/202-master-data-default-effective-date.md)

已保存的未来调整被取消时，由有处置权者选择准确的未来记录，核对撤去该段后恢复适用的资料，再删除该记录并保留原修订。首条误建且已有引用时保留对象，按期间停用。只改金额就在原标准新增生效段。确需停用标准时，所有仍会采用它的计划须在停用日起结束相应引用或结束适用，遗漏任何一份仍会造成缺口。仅告知经办人有权看到的影响。源域后来更正或停用职级时，原依据仍可追溯。从受影响日期起，保存依赖它的变更或再次采用时重新核对来源。

<a id="m09-br-006"></a>

### 3.3 M09-BR-006 查看当期、原件及原采用

普通列表使用服务端北京时间当日。详情选时间轴节点看该记录适用的资料，日志选一笔办理看其确切来源修订，原计划的标准引用指向该版计划保存时采用的依据。计划记录标准身份及当时的采用日、来源和修订。后续按指定业务日解释标准时沿同一身份取该日适用额，清楚标明所选日期。薪标换版后仍按原引用查回旧计划的采用证据。数据库按 `[start,end)` 表示日期段，业务页面展示首日和含在内的末日。生效日期与记录时刻分存，后者按北京时间显示。[日常维护及历史定位](../../adr/123-current-maintenance-and-dated-query-boundary.md) · [按日记录与原采用](../m02/120-dated-maintenance-technical-contract.md)

<a id="m09-br-007"></a>

### 3.4 M09-BR-007 谁可以维护配置及查看金额

管理员按权限新建计划或薪标、调整计划组成、新增或插入生效记录、更正、停用、重新启用或撤去记录。一次保存或确认即完成本次办理并返回回执。未来版本可提前保存，自指定生效日起采用，无需第二人复核。目标架构中的 `PublishPlan`、`PublishRate` 分别对应保存薪酬计划、保存职级薪标的写入命令，同一次办理完成写入和授权校验，没有另行“发布”的步骤或权限。[M09 写入命令](../../architecture/target/modules/m09.md)

服务端在提交时核验对象、数据范围、变动字段、办理动作及必要来源，同一管理员可按获授权限兼管薪标和计划。[项目实施规则](../../adr/213-administrator-maintenance-and-effectivity.md)

仅有 M03 目录权不能据此得知薪标是否存在。有薪标引用权且有计划相应维护权，可选用获权的标准名称、频率和单位。显示金额、计算结果及可反推金额的差异按字段授权。只改获权的计划名称时，未提交的受限金额由服务端沿用，显式清空金额仍须金额写权。撤权后重新读取当前资料、历史及原回执均按现权裁剪。只读者经菜单、返回列表或旧编辑地址均无写入口。[字段与来源权限](../../adr/128-authorization-evidence-removal.md)

取消未保存表单产生零条业务记录。保存结果以原请求身份查回。同键同内容重送只返回同一办理结果，同键不同内容拒绝。两名管理员基于相同修订修改时只允许一份基于旧修订的写入成功。对一份计划，组成项、引用、来源和回执同笔提交。来源失效时提示管理员更新依据并重新提交。

## 4 两套可以逐项录入的制度

合成企业「甲公司」明确选用法律实体甲。职务系列「专业」「管理」「运营」及职级 P5 均自 `2027-01-01` 起有效。下表按两套完整制度录入，币种均为人民币。再用一份仅含基本工资的运营计划核对跨计划共享。

| 配置 | PRO-M 专业人员月薪计划 | MGT-Y 管理人员年薪计划 |
| --- | --- | --- |
| 范围及起日 | 实体甲、专业系列、P5，自 `2027-01-01` 起 | 实体甲、管理系列、P5，自 `2027-01-01` 起 |
| 基本工资 BASIC | 引用 P5 月薪薪带，10,000.00–15,000.00 元/月，指导值 12,500.00 | 引用 P5 年薪定额，180,000.00 元/年 |
| 第二项 | 岗位津贴 ALLOW，计划固定 300.00 元/月 | 目标绩效奖金 BONUS，以 BASIC 的年额为基准，目标比例 12.50%，目标参考额 22,500.00 元/年 |
| 后续调整 | 自 `2027-07-01` 起改为 11,000.00–16,000.00 元/月，指导值 13,500.00，津贴仍为 300.00 | 同期年薪定额和目标比例沿用原制度 |

共享对照计划 OPS-M 适用于实体甲、运营系列、P5，自 `2027-01-01` 起生效。它只有 BASIC 一项，选择 PRO-M 已使用的 P5 人民币月薪标准。薪酬专员只需在这份月标上增加七月记录。两计划按七月首日查到相同的 11,000.00–16,000.00 元/月，按六月末仍查到 10,000.00–15,000.00，各自原件仍指向一月修订。PRO-M 的 300.00 元津贴只出现在该计划。MGT-Y 继续按年定额解释。[共享规则与重复建标反例](#policy-decisions)

## 6 首期范围与行业对照

| 制度问题 | 首期口径 | 业务处理及评审责任 |
| --- | --- | --- |
| 各计划共用同一薪带 | **2026-11-27 用户已确认。** 同一客户、职级、币种、频率和计量单位下，每个业务日共用一份标准。 | 经办人从各计划选同一标准。金额变更在标准上维护一次。M09 负责拒绝重叠标准，计划所属组织或系列不构成例外。[共享验收](#m09-ac-005) |
| 固定津贴 | 归各计划所有，按该计划的生效日期调整。 | 跨计划联调延后。出现企业统一津贴政策，明确要求一次调整影响多份计划时，再评估共享津贴标准及各计划的采用规则。 |
| 管理员维护与生效 | 获权管理员直接保存，按生效日管理。所有动作均无双人复核。 | 按对象、字段、办理动作和管理范围核验，并记录实际操作者、版本和生效日。[项目阶段规范](../../adr/213-administrator-maintenance-and-effectivity.md) |
| 职级内薪档 | 首期直接配置定额或连续薪带，可填指导值。 | 离散薪档及自动晋档延后。客户正式制度明确同一职级各档金额及适用条件时，再设计档次、档额与生效期间。M03 的职级阶梯表达职级之间的顺序。[职级与阶梯](../m03/310-grade-ladder-contract.md) |

重复建标可用两法人作反例。同一客户已有 P5 人民币月标 10,000–15,000 元，另一法人试图在相同业务日新增 P5 人民币月标 12,000–18,000 元。保存时应指出已有标准，获权经办人可打开或选用它。若企业决定所有相关计划从七月统一调整，则在原标准增加七月生效记录，各计划按日读取，仍可查到每份计划原先采用的标准版本。

固定津贴另用独立副本验收。假设 PRO-M 与 OPS-M 各有同名岗位津贴，分别为 300 元/月和 200 元/月。管理员把 PRO-M 从 2027-10-01 起调到 350 元/月，PRO-M 的九月仍为 300 元，OPS-M 的九月和十月均为 200 元。两计划引用的 P5 月薪带继续共用。这组预期补充 AC-002 的按日调整与 AC-005 的跨计划影响。

Fusion 的职级费率可记录区间、定额、币种及频率，也允许同一职级出现在多份费率中。本项目按已确认的客户口径收敛为同日同口径共享一份标准，区间内指导值由制度选填。PeopleSoft 的费率代码支持固定额和百分比，薪档及预算矩阵均可按需设置。两套产品支持这些表达方式。本项目的津贴归属、单人维护及共享范围以本方案的业务决定为准。[Oracle 与 PeopleSoft 官方依据](../../reference/README.md#compensation-configuration-benchmark) · [实施路线图](../../plans/210-compensation-configuration-roadmap.md)
