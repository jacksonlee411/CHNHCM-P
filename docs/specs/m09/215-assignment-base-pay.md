# CHNHCM-215 员工基本工资核定业务与页面方案

一名薪酬经办人在一份任职上确定基本月薪，能回答“这一天个人约定多少、当时按什么标准定的、后来哪次办理改了金额”。本期采用人民币、月额、职级连续薪带。计划内固定津贴按权限展示制度依据。个人津贴、年薪、奖金授予及工资期计算另行立项。[登记表](../../governance/registry.json) · [实施计划](../../archive/plans/214-assignment-base-pay-rollout.md) · [办理技术合同](216-assignment-base-pay-contract.md)

## 1 经办人、任职与计划

<a id="m09-br-008"></a>
### 1.1 M09-BR-008 按一份实际任期办理

薪酬管理员从「人员 → 人员名录」选主岗或兼岗，在员工详情选择与「职务信息」并列的「薪酬」页签，直接查看或办理这份任期的个人基本工资。页面显示获权的员工、雇用记录编号、主兼岗、工作关系及任期。查旧任期可从其获权任职历史进入同一页。查询者用同一入口读获权金额，有历史权时可读原笔。仅有薪标维护权或人员资料读权的角色，按其原有授权查阅相应资料。

Go 按经办人选定的生效日取 M04 的实际任期、工作关系雇主、职务及**个人实际职级**。M03 提供该职务所属系列与职级身份，M02 提供用到的法律实体来源。按岗位管理也取该任期实际采用的任职安排。已结束的任职可在有效期间内按权回查。再聘沿用雇用记录编号时选择新的实际任期。主岗、兼岗和再聘各自定薪。旧任期缺记职级时，经办人可请任职维护者依原任用资料从真实日期补记，再重读。[任职与实际职级](../m04/506-job-information-records.md#m04-br-013) · [任职页](../m04/507-job-information-tab.md#job-tab-layout)

<a id="m09-br-009"></a>
### 1.2 M09-BR-009 怎样选到可用于基本工资的计划

1. 先找生效日有效且经办人有权采用的计划。X02 按计划该版的企业通用或指定范围、允许及排除，与实际雇主、职务系列和职级匹配。按启用的维度取得事实。未知的必需维度提示补齐，权限遮蔽时只返回获准披露的信息。[首期范围](211-compensation-configuration.md#m09-br-004)
2. 本期每份可选计划须能**唯一确定一项基本工资**。按组成性质识别，引用稳定的组成项身份，支持该任职职级、人民币月额和有效连续薪带。计划仅有津贴、按年约定、采用定额，或有多项基本工资需拆分的，仍可按权查看制度。个人月薪经办人改选符合本期口径的计划。指导值只作参考。
3. 命中一份可带入，表单显示将采用的计划。命中多份则留空，由经办人明确选一份。保存即确认页面上这份计划，未选时须先选计划。没有合格计划时，获权者可查看相关制度或调整日期。变更日期或计划后按新组合重新取依据，已填金额留给经办人核对。由服务端验证保存时的选择。[适用范围与默认来源](../../architecture/target/modules/x02.md)

## 2 基本工资何时生效

<a id="m09-br-010"></a>
### 2.1 M09-BR-010 个人约定与制度金额

首次定薪从决定载明的生效日起采用。首条之前任职有效的日期显示「尚未定薪」。同一任职在每个业务日最多有一个有效的人民币基本月薪金额，变更计划也沿该任职同一条时间轴。金额在生效日的薪带上下限内，含两端。按精确十进制录到分，超精度就地报错，空值须补录，显式零按所用薪带判断。企业主数据的首次日期规则仅用于相应主数据。[金额口径](211-compensation-configuration.md#m09-br-002) · [日期规则](../../adr/202-master-data-default-effective-date.md#21-默认日期与适用操作)

按日查看分别列「个人基本工资」「当日制度」，选定一笔办理可查看「核定时依据」。薪带变宽、收窄、计划范围变化或一月固定津贴调整后，继续按原核定取个人金额。获权查看原计划时按该计划解释当日制度。当日已不适用则标明原因。尚未定薪或已撤去唯一核定时，可以选日期查候选依据。若原额已低于当日下限，能看到金额与当日标准的差异，由有权经办人判断是否办理调薪。任职已结束或未来首聘被撤销，则相应日期显示无有效任职。可从原核定查回当时采用的依据。发起新的核定须在选定日期重新核验。

<a id="m09-br-011"></a>
### 2.2 M09-BR-011 新决定、误录与撤去

| 经办情况 | 如何办理 | 成功后能核对什么 |
| --- | --- | --- |
| 首次定薪或真实调薪 | 首次填写决定生效日、计划及个人金额。此后在时间轴选「调薪」，带入前段获权资料，直接改成新决定的值。可提前保存，也可在两笔之间插入独立决定。若已有未来首笔，能在实际任期内补录更早的真实决定，原笔的身份、原件及起日保留。 | 一次保存返回原号回执。每个新决定有自己的核定身份。前段截至新起日前一天，已排定的后继仍从其原日起取独立约定。仅重复原金额、计划和组成而没有实质变更时提示无变化。 |
| 同日再输一笔或抄错金额 | 生效日已有核定时定位原笔。两份决定对同日给出不同金额时，拒绝叠加，须由业务查明哪份有效。若已办决定确已取消，可按其依据撤去后办理有效的决定。事实抄错用「更正」，带入该笔原值及依据，可直接修改有权字段。 | 同一核定身份、同一生效日追加修订，旧金额、操作者、原采用和原回执可查，独立后继保持。若承接的来源在原日已追溯变更，按 [216 来源校验](216-assignment-base-pay-contract.md#pay-adoption) 处理。 |
| 未来安排取消或整笔误建 | 获撤去权者选准确原笔，看撤去后该日起会恢复哪笔或出现「尚未定薪」，一次确认。错人、错任期、错生效日按原笔撤去后在正确位置另办。真实发生的回调另办新决定。 | 撤去有独立处置依据，原件和回执可按权查回。前一笔恢复至下一份独立决定或任期结束。唯一一笔撤去后可重新首次定薪。 |
| 放弃输入、结果未明或失权 | 未提交时可取消。有改动离开才提示保留或放弃。已提交后断线可按原申请号查结果。 | 取消产生零笔业务事实。重送相同请求只得到同一回执。重读和恢复按此刻权限裁剪，受限金额从草稿、错误与差异中清除。 |

## 3 经办页面与字段

「薪酬」与「职务信息」共享详情页头及所选实际任期。从名录进入已定位任职，从本人详情有多份获权任职时先明确目标。主岗、兼岗均按当前任职及个人薪酬权限显示页签。已获权且尚无核定时显示「尚未定薪」，有办理权者可首次定薪。顶部沿用人员环境和对象控制区，正文依次为业务日及个人基本工资、当日制度、按日核定记录。查看日初次取进入时明确的任职业务日，否则用服务端今日。允许在**本任职**填写「工资查询日」查两个核定日之间的薪带及个人额。任职名录仍按原目录规则查询。原件只读，从原件退回所选日期或原日志行。[按日专项查询](../../adr/123-current-maintenance-and-dated-query-boundary.md#25-专项按日查询准入) · [日期与原件](211-compensation-configuration.md#m09-br-006)

## 4 验收场景与独立预期
