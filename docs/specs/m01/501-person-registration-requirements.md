# CHNHCM-501 人员登记与名录业务规格

人事专员可以先登记一个尚无工作关系的人，重登后按姓名、现号或旧号找回。个人资料的主责是 Personnel。入职、岗位、工资和登录账号有各自的办理依据。首批交付范围来自 [500 路线图](../../plans/500-personnel-roadmap.md)，人员、工作关系及任职的取舍见[目标映射](../../architecture/target/07-concept-mapping.md)和[M01 合同](../../architecture/target/modules/m01.md)。[登记表](../../governance/registry.json)

## 1 谁使用哪些资料

一个客户实例是一处编号与登记核对边界。X03 按当前主体、动作、对象、字段、用途与期限逐份匹配完整授权，显式拒绝优先。下表是职责任务，同一人可取得多项明确授权。客户的登录角色名称本身不授予这些权限。[X03 合同](../../architecture/target/modules/x03.md)

| 办理人及用途 | 对象范围 | 允许做什么 |
| --- | --- | --- |
| 登记经办人，为「人员登记核对」办理 | 明确授予本客户登记权及可录入的字段 | 可凭姓名登记。经授权可录入主要证件、联系方式或引用真实单人登记单。需改资料、看历史或改人员编号时另按该项授权办理。本人、录入人、创建人均无自动读取特权。 |
| 资料维护人／名录查询者，为「人员资料维护」或「人员名录查阅」办理 | 明确授予实例人员范围或列明的 Person 身份集合，对尚未任职者同样适用 | 在获权人员内查找，按字段授权看资料。维护人只能编辑具有原值读取及写入权的字段。只读者可按另授历史权查相应来源。 |
| 改号经办人，为「编号纠错或制度迁移」办理 | 明确获权的人员及可执行的改号决定 | 在原人上核对原号、拟用新号、原因及客户决定文号后保存。材料载有截止日时带入，明确为长期有效时可空，具体受当前改号政策约束。 |
| 只有部门／任职授权的负责人 | 本批无 M01 人员核对或名录范围 | 正常菜单、直接链接、查询结果数和操作回执均不能用来发现该范围外的人员。 |

经办人录入姓名后可以直接办理登记。需要按姓名找人时，可主动在员工名录查询有权查看的档案。只有登记权的人可以办理并取得最少结果。只获核对权的人不能新建档案。查阅来源材料和读写主要证件分别授权。

## 2 首批字段与保留

<a id="m01-fields"></a>

| 字段、用途 | 基数、输入与默认 | 读取、脱敏与写入 | 保留类别 |
| --- | --- | --- | --- |
| 姓名，用于显示和查询 | 每人 1 个现用显示姓名，必填，默认空。按原有顺序录入，保留有意义的空格及文字，不拆分姓、名，姓名不参与人员判重 | 有名录基本读权且姓名、现号均可读才列行。登记人录入，具姓名维护权者可更正。只用获权姓名参与检索及排序 | 身份资料及其准确来源 |
| 主要证件，用于识别同一人的重复档案 | 每人至多一份现用主要证件。独立登记可暂缺，填写时类型和号码须成对。同一客户实例内，两人不能持有同一规范化的非空现用证号。类型、签发地、部门、在职状态均不划分号码范围。正式入职按相应业务要求补齐 | 登记时按字段权录入，补录、更正或换证从原人资料办理。员工名录不展示证件。当前及历史按当下字段、用途与期限读取，普通详情默认不展示完整号码 | 身份资料 |
| 登记来源，用于查回办过的真实单据 | 手工登记可无单据。有真实单人材料时可引用实际类型与单号，同一张单的重复办理见第 3 节。不得以身份证件号、电话或邮箱充当材料号 | 只在获权的确切办理来源按需查看。更正原引用仍须有本人资料更正及材料核对权，保留原件和旧绑定 | 核对证据 |
| 人员编号，日常识别及历史查找 | 每人 1 个现号、0 至多条旧号。登记时由 Go 分配，默认 P 加 8 位十进制流水，起于 P00000001。编辑资料时只读。改号才接受指定新号 | 名录基本读权可见现号。按旧号精确查询时有编号读取权且可见原人才显示「历史编号」及现号。完整改号链另需历史权 | 永久编号占位及最少归属 |
| 联系方式，供获权人事联系本人 | 0 至多条，各有稳定资料项身份。类型限电话、电子邮箱，一项一值。默认无条目，添加时类型和值均必填。同一类型可有多条，无“第一条即主联系方式”规则 | 默认不出现在员工名录。详情可分别获完整或遮罩读权。电话仅显示末 4 位，邮箱只显示首个本地字符及掩码，不显示域名。完全无权时不返回项目、数量及有无标记。经办人须具有相应类型的完整读取和写入权。更换类型须同时有原类型及新类型的权限 | 联系资料，含旧值 |
| 办理依据与操作者，用于核实更正、查回及解释改号 | 来源版本、办理人、记录时刻由系统生成。改号还必有原因和决定引用，不为普通联系方式更正增设原因 | 当前详情的最小操作摘要按资料读权裁剪。日志、准确来源及敏感差异另验历史权与当下字段权。号码、联系方式正文均不进通用日志或事件 | 最小办理证据 |

<a id="m01-retention"></a>

保留按类执行。普通使用只在客户为本用途启用的期限内。首批按 X03 发布的客户用途、政策版本及期限保存依据。登记时固定起算点和各类截止，后续确有新用途须由相应经办人记录依据并核实新的适用范围。查询、纠错、反复登录不会自动续期。时间边界以截止当日北京时间 00:00 起算，到点即停止普通投影和对应搜索。未配置有效政策时，登记入口提示联系管理员并拒绝保存。

主要证件采用身份资料的保留政策。以后补录时从首次获准收集该项起算，普通更正、换证均不自动续期。普通读取到期按权限收缩，只要仍有依据持有现用证件，同号继续排他。号码更正、换证或撤回误录成功时原号退出占用；旧来源仍按原期限、用途与保全读取。现用证件已按政策处置时也释放其占用。

身份资料和核对证据可在普通用途结束后依批准的证据期限受限保存。登记身份和核对材料的普通及证据期限分别从首次获准登记起算。联系资料按该项获准收集时固定相应期限，修改同一项不会重置起算点。普通用途截止后，有证据读取授权者从确切来源进入，普通名录和旧号查询不泄露已退出范围的人。联系方式停止使用后从当前联系入口撤下，旧联系方式只有在证据期限、历史用途和字段授权同时满足时可读。到期且无保全的私人载荷由 Personnel 按政策处置，条目标记处理事实。保全只限指定对象、类别及期间，专门的保全读权与普通历史读权分开。处置动作须有已到期及无保全的依据，记录类别、时间与结果。缺少依据时停止普通投影并保持受限保存。有合法保存义务、争议保全或仍需重现的原采用时按其范围保护原件。可处置私人载荷失去读取资格后返回「资料已按保留政策处置」，不回填现值。原业务来源身份、修订关系、必要审计、已执行幂等结果、永久编号占位及下游原采用受保护。合成验收政策及到期、解除保全的预期见[保留样本](#m01-ac-009)。此处规定产品行为，客户为实际用途提供政策参数。

## 3 登记、更正与改号

| 规则 | 办理条件与结果 |
| --- | --- |
| <a id="m01-br-001"></a>M01-BR-001 独立登记 | 从「人员 → 员工 → 登记人员」输入姓名即可保存，生成 Person、人员编号和首份来源。联系方式、证件及真实单据均可省略。取消无业务写入。没有证件和共同来源时，两次独立提交可能登记出同一个人的两份档案。 |
| <a id="m01-br-002"></a>M01-BR-002 主要证件号码防重 | 同一客户的人员档案只按现用主要证件号码判断人员是否重复。新建档案、补填或更换证件时，号码已在他人名下就不能保存，即使姓名、证件类型不同，或原人已离职、超出经办人的可见范围。本人沿用原证号可更正其他资料。独立登记暂缺号码时可以保存。登记不按姓名查重，不提示同名，也无须确认。电话和邮箱可重复。离职员工再聘从原档办理。 |
| <a id="m01-br-003"></a>M01-BR-003 编号 | 对输入编号去首尾 ASCII 空格、英文字母大写。同一客户的现号与全部旧号永久唯一。只接受 1 至 32 位 ASCII 字母、数字及中间的连字符，首尾是字母或数字。旧号不能重新分配。改号只因既有错误或编号制度迁移，绑定客户、personId、原来源、前后号、原因与有效决定，提交后即生效。首批从本人改号页由获相应决定权及执行权的人事专员对照客户依据，一次保存，同时形成 M01 的决定。不得以一段自由文字替代授权或批准。再查原件仍得原号。 |
| <a id="m01-br-004"></a>M01-BR-004 资料更正 | 姓名、主要证件、联系方式按获权任务更正。按原人和期望修订写入，未触碰项保留原值。补证、换证或撤回误录均保留原 personId、人员编号和准确旧来源。抢占新号失败时原证件、占用和其他资料都保持；无变化不新增业务修订。联系方式可显式移除某一项。 |
| <a id="m01-br-005"></a>M01-BR-005 可见范围 | 对普通名录先按实例、人员范围、用途和可公开字段形成集合，再查询、去重、计数、排序、分页。详情、旧号解析、日志和回执皆重验当前权。一个可见人员不表示其任一任职可见。 |
| <a id="m01-br-006"></a>M01-BR-006 查回原办理结果 | 同一笔保存因网络中断而原样重试，返回原办理结果。同一提交号改了内容则拒绝。如果是有编号的单人登记单，系统按材料类型和单号识别这张单。内容与原单一致，有权限的人可以查回上次结果。内容有变更须核对原单。普通手工登记可以不填单号。即使换了一张登记单，主要证件号码已在另一份档案中使用也不能另建。 |

## 4 T01 独立验收条件

场景沿用[登记与编号](../../plans/500-personnel-roadmap.md#m01-scn-001)和[个人资料与权限](../../plans/500-personnel-roadmap.md#m01-scn-002)。下列均为合成样本的产品预期。实际业务办理、界面行为及服务端验证分别见[页面规格](502-person-directory-interactions.md)和[技术合同](503-person-registration-design.md)。

| 验收条件 | 给定、操作与预期 |
| --- | --- |
| <a id="m01-ac-001"></a>M01-AC-001 尚无任职 | 经办人先取消空表，再仅填「样本青」保存。前者零写，后者得到一人、一现号、一首来源，证件与材料均空，工作关系与任职均为零。重登后按编号找回。再仅填同一姓名登记另一人，可直接保存为两份档案。录入、离开姓名栏和保存均无同名提示。 |
| <a id="m01-ac-002"></a>M01-AC-002 按主要证件号码判断重复 | 按[三种登记情况](#m01-registration-examples)核对档案和办理结果。同名异证可分别登记，即使电话和邮箱也相同。改用另一姓名或证件类型录入已登记的号码，也须拒绝。同一客户内同时登记同一号码，只新增一份档案、一个人员编号、一份登记来源和一条登记事件。不同客户的档案各自检查。 |
| <a id="m01-ac-003"></a>M01-AC-003 受限读者 | 查询者只获甲本人及姓名/现号，在员工名录按姓名搜索只见甲，位置 1/1。甲的电话权不能与乙的基本读权拼出乙的电话；只有部门权、已撤权或另一客户，持链接、旧号或回执也不能发现目标。旧材料权不能读证件。登记遇到无权核对的占号时拒绝，页面、API 与回执均不含占用者姓名、编号、标识、证号尾数或链接。 |
| <a id="m01-ac-004"></a>M01-AC-004 资料项修订 | 在姓名档上补证、沿用原证改姓名、换新证，均指向原人；旧来源仍可按权查当时值。换到他人号码时原证与同笔其他修改全部保持。更正或移除一条联系方式保留另一条，改姓名保留隐去项；两连接基于同一旧修订改同项仅一笔成功。电话改成只可遮罩读的邮箱须整笔拒绝。 |
| <a id="m01-ac-005"></a>M01-AC-005 改号 | 从 P00000001 改成「 r-01 」，当前显示 R-01。用原号仍定位同一人并标历史编号，登记原件仍显示 P00000001。决定依据已到截止日、占用旧号、两人竞争同一新号分别拒绝、拒绝、至多一人成功。未来或回溯生效改号均拒绝。 |
| <a id="m01-ac-006"></a>M01-AC-006 历史与撤权 | 旧来源保存时的姓名/编号与两条联系资料可按当前权分别解释。撤去电话字段权后，即使已开旧来源、日志、回执或浏览器后退，均不出现电话、尾号或能推定该字段的子行。只撤写权时仍可查当前获权结果。 |
| <a id="m01-ac-007"></a>M01-AC-007 重送与失联 | 登记保存丢回包后按原号查回，再原样重送，人员、号码、事件各一份。沿用同一提交号改填姓名被拒。若查明原请求未执行，迟到原命令不能再入账。重启后查原办理，重新根据当前权返回。 |
| <a id="m01-ac-008"></a>M01-AC-008 正常菜单与返回 | 在员工名录主动按姓名搜索，从结果页的页末进入、跨页切人、查看原件、退出并返回，核对条件、位置、焦点。登记人和只读者各过七种尺寸／缩放，按自己权限走完全程。验收明细见[逐页对照](502-person-directory-interactions.md#m01-page-map)。 |
| <a id="m01-ac-009"></a>M01-AC-009 保留到期 | 合成政策下普通使用截止 2027-04-01，身份及核对／联系证据截止 2027-05-01。3 月 31 日可按权查看，4 月 1 日普通名录、回执和旧号查询不得借此发现本人，依法持有的现用证号仍阻止同号新增。5 月 1 日只保全指定来源的核对材料，其他到期载荷依政策处置；处置现用证件后才释放相应占用。保全经办人仅能从确切来源取指定材料，不能顺带读证号、姓名或联系方式，普通读者也看不到保全标记。解除保全后过期材料可处置。旧人员编号永久不可复用。 |
| <a id="m01-ac-010"></a>M01-AC-010 目录容量 | 真实 HTTP 用 1 万名合成人员，分别验全范围及受限范围。姓名、现号和旧号检索须先裁剪再计数分页。每组运行次数、计时、原件保护及分位目标按[容量合同](503-person-registration-design.md#m01-capacity)。 |
