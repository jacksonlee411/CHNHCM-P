## 2 输入、授权及访问集合

<a id="m01-registration-access"></a>

姓名保留录入顺序，拒绝控制符和换行后去首尾空格并按 NFC 规范，1 至 200 个 Unicode 码点，至少一个文字字母（含汉字）。该表示用于显示和员工名录中的姓名片段搜索。新建档案时不检索同名人员，姓名不进入人员判重条件。

主要证件可整体省略，填写时接受类型和号码一对值。类型用于校验和解释（居民身份证、护照或其他身份证件）。Go 拒绝控制字符，去首尾空白，拒绝空号码，将 ASCII 小写字母转大写（含末位 x），保留前导零和内部字符。所有类型用同一文本比较值判重。居民身份证按其号码格式校验，其他证件不套用居民身份证格式。类型、签发地和姓名不参与排他。

来源引用独立可选。同一客户的单人材料按实际类型、单号定位，单号沿用去首尾空格和 ASCII 字母大写，保留前导零。可直接引用实际签发的单号，无需补造字母前缀或连字符。无单据则不创建绑定。旧来源的类型、规范号与原始登记摘要继续用于跨提交重送。多人单据逐行接入由实际来源业务确定，本期不以整张多人单标识个人。

电话接受可选的一处起首加号及 5 至 15 位数字，输入时允许数字间空格或连字符，保存去掉分隔符。邮箱接受单一地址，首批限 ASCII，左右各有内容、仅一个 @、域含点且没有空白或控制符，域转小写、本地部分保留，最长 254 字符。类型及值成对校验。只含空白的已有值报字段错误，移除须显式指定该项。上述是首批输入合同，不把电话、邮箱或姓名推算为唯一人员身份。

X03 按完整授予评估 `register`、`verify`、`read`、`correct`、`renumber`、`renumber.decide`、`history.read` 与各字段、用途和范围。建立新登记按客户级登记授权核对。已存在人的一般读写使用该人范围。可见人员必须同时具有可展示的姓名及现号。遮罩和完整读取分级，遮罩权限不得升级为能按原值搜索、排序或写入。命令先验证每个显式输入字段与项目操作均获权，再做无变化比较。发送隐去字段，即使猜中原值也给同一拒绝。授权范围和类型先进入 SQL 查询及当前来源资格，再投影、计数、分页。不会先拉全量在 Web 端过滤。普通名录、当前详情、现/旧号、导航及普通回执使用同一人员可见集合。普通历史须额外具备历史读取及字段资格。已结束普通用途的证据／保全读取单独按该主体的历史或保全用途匹配该人、准确来源和指定类别，可只返回依据而没有姓名，不把证据对象并回名录。对隐藏与不存在对象返回相同的不可用结果，不给另一个人的字段、超出范围的查询结果数或位置。

登记入口与保存都以 `register` 对姓名及实际提交字段的授权判断。只获登记和姓名录入权即可仅填姓名登记。X03 分开授予主要证件和单据来源，旧材料的普通、历史、证据及保全授权均不扩及证件。冲突后的原人入口须同时具备对该人和证件的核对资格及基本读权。否则仅返回统一不可办理提示，无目标标识、证件尾数或可推断占用人的元数据。查回、重送按查询当时的权限重新裁剪冲突结果。

## 3 公开命令与查询

<a id="m01-ports"></a>

T01 在 `/api/v1/persons` 下登记下列操作。请求身份来自受保护会话，写请求沿用 CSRF。下表的字段是领域语义，OpenAPI 是实施时唯一 DTO 定义。状态码按项目约定区分无会话 401、功能不可用 403、对象不可发现 404、字段错误 400、版本或冲突 409、暂时不可用 503。[现有 API](../../../api/openapi.yaml)

| HTTP 操作及领域动作 | 输入、结果及失败保护 |
| --- | --- |
| `POST /queries`，`GET /`，`GET /{personId}/navigation` | 接受姓名片段或现/旧号搜索，默认按现号、可按姓名排序，再以 personId 稳定排序。返回与会话绑定、30 分钟无活动后到期的不透明查询引用。分页支持 20/50/100，默认 20。按同一当前查询返回可见总数、位置、前后及页码。引用绑定实例、登录会话和主体，失效、跨登录或到期时不返回关键词、旧总数及成员。普通列表可不带引用。关键词对获权姓名做 NFC 文本包含，对规范化的现/旧号做精确匹配，两路取并按 personId 去重。仅以旧号命中该人时标历史编号，精确解析号码的领域查询只匹配号码。查询正文只进受控短期会话，读取时重新鉴权。搜索不接受邮箱/联系方式条件。 |
| `POST /` RegisterPerson | 必传姓名和提交号。主要证件、联系方式、真实单据引用均为可选。人员查重仅按非空现用主要证件号码，直接调用 API 与页面保存执行同一规则。 |
| `GET /{personId}`，`POST /{personId}/corrections` CorrectProfile | 更正以原 personId、期望来源和实际修改字段提交。证件字段缺省保持原值。只有显式修改证件才要求完整证件读写权，完整对象表示补录或替换，显式 null 表示撤回误录，半填拒绝。原人同号允许，归一化后无变化则 no_change。联系项按 itemId、expectedRevision 和具体操作更正，跨类型须有原新类型完整读写权。来源纠错另验该人及材料权，新引用已属他人则整笔拒绝，旧绑定及原办理保留。 |
| `POST /{personId}/renumber` RenumberPerson | 原号、期望来源、新号、原因（纠错／制度迁移）、客户决定文号及有效截止日、提交号。经办人对照单人决定材料。Go 按当前时刻检查权限、原头及材料期限。若有截止日期按北京时间该日 00:00 截止。长期有效且本地政策允许时截止可空。获 renumber.decide 及 renumber 执行权者同屏办理，M01 同事务将核实人、依据、截止、客户、personId、前后号、原版本、原因和政策版本固定为决定与结果。无需外部工作流。 |
| `POST /{personId}/changes`，`GET /{personId}/sources/{sourceVersion}` | 列表的基本摘要、日志及准确来源有不同读取资格。显式来源即使正好为当前头也验历史权。每个字段按当前范围及保留状态投影，记录时刻保留原值并按北京时间展示。历史不返回可执行命令。 |
| `POST /submissions/{submissionId}/resolve` | 只允许同客户、原主体确认为自己发出的提交。客户端沿原提交身份查回，服务端返回按当前权限投影的终态/待确认。原人已不可见时不给标识、前后号、载荷或旧错误详情。 |

实施时从 OpenAPI、Go 路由和客户端移除 `POST /api/v1/persons/candidates` 及登记确认字段 `confirmedCandidates`，同时删除登记写入时按姓名检索并核对候选的逻辑。登记页不调用名录查询代查重。员工名录的主动搜索沿用 `POST /queries`。

### 3.1 人员办理日志读取

<a id="m01-change-query"></a>

`POST /api/v1/persons/{id}/changes` 是只读分页查询，条件由请求正文传递。默认第 1 页、每页 20 笔，支持 50 和 100。首次 Go 从该人当前头固定 `throughSourceVersion`；后续翻页、筛选、同标签返回沿该来源及其前序链读取，刷新日志重取上界。按来源链从新至旧排序，相同时刻或时钟回拨仍保持真实先后。显式上界须属于当前实例及此人，错误来源不给其他人的信息。一次查询返回本人当前获权的操作组、办理总数、页码、页大小、上界和可筛选的字段。翻到空末页时返回合法页及其数据。

Go 在同次一致读取中裁剪历史和字段权，按投影筛选，再按办理计数及分页。日期支持等于、早于、晚于及包含边界，按北京时间日历日；操作者按办理时留存账号包含或相等；动作和变更字段支持等于或任一。字段条件须在本次获权目录内。未指定条件或显式清除时读取全部获权办理。半填条件、无效日期、未知列或操作符及不支持的分页输入返回字段错误。未知及无权的变更字段值都返回同一无内容的字段错误（字段定位 filterValue），不回显字段、总数或旧结果。页面据此清除失效条件并重读。操作者条件、姓名、证号及联系方式正文不进入地址、持久浏览器存储或通用请求日志。

每个操作组返回实际动作、操作者、时刻、当次和前一来源以及由确切前后版本比较的获权差异。联系方式按项标识匹配，同次多个同类型项可区分。列表只传展示所需的遮罩和业务状态，证件与材料正文均不进入日志；新增项旧值标记未登记，真实移除标记已移除。对无权、已过期或已处置的一侧不能推断新增或移除；无法给出合规前后对照时省略该子行，保留获权办理摘要。仅有遮罩权时以两侧获权显示值判断差异，同掩码不暴露原值改变；完整历史权可在同掩码真实变更上看到遮罩摘要并按需查看。用于计数、筛选、展开入口的差异遵从同一可见投影；无可展示的差异不暴露隐藏字段名称或数量。精确的 `GET /{id}/changes/{version}` 仅在显式查看差异时按当前授权读取。继续使用现有的来源保留与专项原件读取资格。日志初次打开与翻页各用一个分页请求，不逐组取原件或差异补表；过期权限、切人或切换主体后的旧响应不回填。

统一名录在同一授权读取中返回 `canListAssignments` 和可见部门路径。`department` 配合 `directOnly` 区分直属与含子部门。勾选请求用 `all` 表达全选或逐项选择，`ids` 分别为排除或选中行。Go 依当前人员及任职修订、业务日、会话和已应用条件核对范围，返回版本、确认数量及变动标志。排序和页码保留选择。匹配集合变化或传入已不可见行时清空。

## 4 事务、竞争与恢复

<a id="m01-recovery"></a>

Go 先识别已经办过的提交或单据。只有确需新增或更改证号时才判断人员是否重复，唯一依据为现用主要证件号码。每一项先验证本次操作所需权限；原终态查回按当前读权投影。

1. 原提交号按客户、主体和人员命令空间识别。动作、目标、期望版本和规范化输入相同返回原终态，改内容拒绝。普通手工登记以这个提交号保证一次分配人员编号。升级前的提交仍由原主体按原提交号查回；迁移不能覆盖原终态或把拒绝改成待执行。
2. 新提交确有单据引用时，核对同客户、同类型、同规范化单号的原办理。同据且原始业务内容相同，来源用途仍有效且具原人基本读权及来源核对权者可取原办理，否则仅提示不可办理。同据换内容拒绝。只在已按类型和单号找到同一张单后，才比较原始登记内容（包括姓名、实际证件和联系方式），以确认是否原样重送。旧单据当时未收集证件，按未提供证件时的原语义与既存摘要比对，不拿新字段默认值或已更正的现值重算旧绑定。仅经纠错绑定、无原登记摘要的引用，也应拒绝再建并由获权者核对原件。普通手工登记跳过此步。
3. 确需写入非空主要证号时，在整个客户实例内检查现用归属。已属另一人则拒绝新增或更正，即使登记内容完全相同也不能作为另一提交的成功回执。证号未填写只省略证号占用；没有来源的不同提交不按姓名或其他资料自动归并。

Go 在短事务内重验权限、期望来源与提交身份。PostgreSQL 对现用非空证号强制 `(客户实例, 规范化号码)` 唯一，每人至多一个现用占用。唯一性覆盖看不见、已离职及普通投影已截止但仍合法持有现用证件的人员。换证同一事务更换占用，失败保留原占用和原头；历史来源里的旧号码不参与唯一索引。登记事务不按姓名查人或加锁。数据库不可用则写入失败。

登记在同一事务中保存 Person、人员编号占位、首来源、实际证件或来源引用、必要操作记录、Outbox 及终态。分配器跳过已作现号或旧号的人员编号，8 位空间无号可用时回滚。改人员编号继续使用永久占位，同人同号不新增来源，他人占用的新号不返回占用者。拒绝时不留下人员、占用或事件，允许按原提交号查回拒绝。

证件载荷按确切来源和期限读取。当前及历史详情默认只对有字段权者返回类型和固定掩码。显式请求完整证件才返回获权原值，查看历史另验该来源的历史或专项资格。编辑器按完整读写权取原值。不在名录、通用日志、Outbox、URL、浏览器持久存储或持久化错误详情传递证号正文。只获单据证据或保全权不能查看证件或其尾数。现用证件依政策处置时，同一事务退出载荷及对应占用；处置旧来源只能针对该来源，不得释放新证号。

查回和原请求串行守卫同一提交号。原保存已提交时返回原终态。查回先取得守卫并确认未受理时固定 `not_applied`，迟到原命令不得再执行。结果未知时保留同号。已确定未执行或拒绝后，用户修正输入再办理使用新提交号。只失去写权仍可按当前读权查原结果；无读权者得不到原对象及业务字段。取消草稿零写，no_change 不产生新来源或事件。只读查询失败不走写回执协议。两个主体相同提交号相互隔离。注销再以原主体登录可按实例及原提交号查回，先前查询引用则随原会话失效。

保留按 [501 字段表](501-person-registration-requirements.md#m01-retention) 区分普通、限目的证据、保全及到期处置。不可变来源的事实标识和载荷分开，普通投影、历史、索引及回执都按读时政策收缩。到期先阻止普通读，再按客户、资料类别、准确来源核实保全及仍有效的保存义务。处置前在同一受保护事务重验期限／保全版本。保全先成立则封存，处置已合法完成则后来的保全不能恢复已处置正文。私密值从活动载荷／检索索引退出，日志、来源与回执只给获权的处理说明及必要身份。定向重跑按来源和处置依据幂等。备份随客户保留计划受限保存。人员编号的永久占位、已完成命令的判重和最小审计不依赖私人正文可读取。旧快照恢复上线前重新应用已生效的处置，不能恢复已失效的展示资格。

## 5 容量与测量

<a id="m01-capacity"></a>

使用自有隔离客户。基础载入 `i=1..10000`，现号为 P 加八位 i，每 50 人同名「同名样本」，其余姓名唯一。受限主体只获 i 除以 4 余 0 或 1 的人，且有姓名与现号读权。每 5 人中第 5 人有两条联系资料。每 100 人中第 100 人有一个 LEG- 加八位 i 的旧号及 20 份留存资料修订，现号排序不变。名录预期为 10000／5000，同名命中 200／100，页大小 20 时同名有 10／5 页。受限同名的第 20、21 位为 i=2000、2100，第五页首末为 8100、10000，旧号 LEG-00000100 只得 i=100。核对跨页、无结果以及超范围直达。此规模用于验收，不是产品上限。

| 真实 HTTP 链路 | 计时、独立答案与目标 |
| --- | --- |
| 全范围名录、受限同名末页、按旧号精确查找、当前详情 | 单会话各 P95 ≤300ms。旧号定位同一人并标明历史号。名单、计数、末页与来源外部复算，不能用服务端所报总数生成预期。 |
| 准确旧来源、更正一条联系方式并取回执 | 单会话各 P95 ≤500ms。原件读取按历史权，更正后另一项及旧来源保持。分开记录保存到确认的端到端耗时。 |
| 上述六项的 20 个同时活动会话 | 每项 P95 ≤500ms。1 和 20 会话各链路先预热 20 次，再每组完成 200 次，合计 2400 次计时操作。所有尝试纳入错误率和总耗时，成功耗时另列 P50/P95/P99，意外错误目标为 0。P95 取排序后第 190 个（200 次全部成功时）。重试另记。 |

每条链路按办理起点至完整结果计时（如需创建查询引用，计入该次检索）。真实登录与 CSRF，读取组从固定快照开始。每个写入组从同一快照的独立副本起步，使用原有的 i=100、200、…、2000 共 20 人，按会话独占并带前次真实返回修订，不另造人员。写组结束后核对样本旧原件、全部旧号及回执。2400 是计时办理数，多请求链路另报实际 HTTP 次数。记录测试构建、冷启动、预热、并发、数据库配置、机器、锁等待及意外错误。目标延迟借鉴[既有合同的计时口径](../../archive/plans/200-geography-and-location-roadmap.md#43-验证规模与计时口径)，本批独立实测，超目标的组单列实测值与责任，不回填“达标”。
