# CHNHCM-502 人员登记与名录页面交互规格

「人员」默认进入获权的「员工」。登记人从名录发起登记，资料维护人从本人详情更正资料，只读者沿相同路径查阅获权内容。501、503 的按人去重和名录容量约定用于人员档案查询。接入 M04 后，日常员工列表按任职行筛选和分页。T04 在「人员」下增加同级的「人事事务」，跨员工查询办理记录。仅获此项列表权限的用户从「人员」直接进入「办理记录」。页面按 Go 返回的可办操作、可见字段及办理结果展示。[字段范围](501-person-registration-requirements.md#m01-fields) · [人员公开接口](503-person-registration-design.md#m01-ports) · [办理记录入口](../m04/507-job-information-tab.md#personnel-action-register) · [登记表](../../governance/registry.json)

## 2 从菜单完成的办理

<a id="m01-page-register"></a>

1. 从「人员 → 员工 → 登记人员」打开空表。姓名必填，人员编号显示「自动分配」。有权录入主要证件时，直接显示可留空的类型和号码，两项都空即省略。首条联系方式也可留空。获准引用纸质人事登记单的经办人可在同一表单填一行「登记单号（选填）」，类型由该字段确定；有来源的办理可直接带入实际引用。普通登记无需选择材料类型或填写单号。
2. 填写姓名后可继续填写其他资料，也可直接点「保存」。输入或修改姓名、移出姓名栏、保存时均不自动查找同名人员。表单中没有同名名单、提醒或确认步骤。需要查人时，经办人可在员工名录中主动按姓名搜索。
3. 成功后有基本读权则打开实际人员档案，否则仅显示获权结果。证号冲突时保留仍可见输入，焦点落在错误摘要并指向号码字段。只有能核对该人的主要证件且能打开档案者，才提供原人入口；其余只提示「无法按此证件办理，请联系人事核对」，不返回可定位占用者的信息。同一张有单号的登记单按原内容再次办理时，具备相应查阅权限的经办人看到原办理结果及原人员编号。
4. 「更正资料」带入可编辑原值，支持在原人上补证、更正或换证，电话与邮箱仍可逐项新增、修改和移除。证件只填一项时定位缺项。未编辑的字段从请求中省略。在个人资料的查看和更正摘要中，获权的证号均用固定遮罩。无证号读权时隐藏号码，证件类型、签发机关等仍按各自授权展示。具备完整号码读权可在单项明细按需查看，更正号码还需写权；提交时只传实际修改的值。电话遮罩用星号和末四位，邮箱用首个本地字符和固定星号。来源单据只在获权的准确来源按需查看；需纠正引用时针对该件从当前资料办理，旧原件只读。无变化不新增修订，保存冲突保留获权输入，取消沿用草稿保护。
5. 「更多操作 → 改号」显示当前号码、空的新号、原因、客户决定文号及有效截止日。截止字段直接可填，按材料及当前政策校验。明确长期有效且政策允许时留空，有日期使用 YYYY-MM-DD 与[共享日期输入](../../../packages/ui/src/components/DateField.tsx)。获改号决定和执行两项授权的人事专员在原表单核实材料，一次保存。失效或版本变更时只在有关字段反馈。无需复制 Person、调整业务日期或逐处修改下游。失败回到原表单并定位新号或依据。完整历史按字段权展开，旧依据显示当时号码。

撤回误录按实际入口办理。仅呈现 T01 单份主要证件字段时，清空已带入的类型和号码后保存；在 505 多条证件栏目中，对目标行选择「移除」再保存。仅撤下「主要」标记可把原件保留为补充证件。空白新表、未知原值及只清除一项都不提交移除。服务器拒绝变更时保留原证件与原占用。[505 主要证件](505-personal-profile-contract.md#profile-items-and-access)

## 3 查询、返回与异常

<a id="m01-page-query"></a>

搜索草稿仅在输入框，查询／Enter 才应用并回第 1 页。清空草稿后仍须应用才替换已有条件。翻页、排序及重试只用已应用条件。姓名及编号属个人识别信息，URL 仅带实例会话内的不透明查询引用及非敏感页码、排序，浏览器刷新或后退按同一查询重新授权恢复。查询引用过期、主体变更或条件字段失权时清除旧结果，给出重查入口。名录不将搜索正文写入地址、持久草稿或通用请求日志。这是对 012 已应用查询的隐私适配，保留草稿/应用、刷新、前后导航和返回行为。

可见姓名和现号作为此名录的最少识别组合。只读或遮罩字段只呈现获权投影。完全失去人员读权时清空详情、列表行、数量、历史、展开子行、回执、焦点标签及恢复内容。只失去一个字段时清该字段及受影响的筛选/历史，保留仍可读的当前资料。普通人员链接的未知对象与范围外对象使用相同不可用反馈。限目的证据或保全经办人可从其持有的准确办理来源引用直达只读原件，页头只显示当下获权的定位字段，退出返回相应用途的原入口。该引用本身不授予名录、姓名或其他字段权。有效空结果可调整条件，读取失败可重试，保存结果未知可确认上次办理。请求未到、已提交丢回包和迟到响应分别从原提交身份恢复。[可靠提交](503-person-registration-design.md#m01-recovery)

### 3.1 个人资料与变更日志

<a id="m01-change-log"></a>

「人员 → 员工」的任职行默认打开所选任职的「职务信息」。0 号主岗详情按「个人资料、职务信息、变更日志」排列获权面板，正号兼岗详情仅有「职务信息」。M01 的资料及日志按各自授权，M04 按实际任职或办理授权。在同一员工菜单保留获权的「人员档案」入口，按人查找、登记及补件，适用于尚未任职或仅有档案权限的人员资料任务。从档案入口仍默认「个人资料」，可办首次入职时进入本人原表单。只有个人资料可见时直接展示正文。多个页签中仅一个选中，各与其命名面板双向关联。方向键移动焦点，Enter／空格激活，切换后焦点仍在页签。个人资料与任职分别保存，切换时先保护当前实际改动。[职务信息页签布局](../m04/507-job-information-tab.md#job-tab-layout) · [个人资料整页保存](505-personal-profile-contract.md#profile-maintenance)

人员日志读取局部加载或重试。有权的日志地址刷新、后退仍选中日志。失去其历史权时从旧日志回到获权个人资料并聚焦标题，职务面板按其自身授权处理。显式原件按该来源独立授权，不可读时提供不可用反馈和退出入口。

- 桌面按记录时间、操作者、办理动作、变更字段、原值、新值、查看排列。每笔登记、更正或改号各占一组，共用一次时间、办理人和入口；多条联系方式按实际项显示。一笔含多项修改时直接展示所有获权主要差异。姓名、人员编号使用当次获权前后值；联系方式默认按既有遮罩显示，获完整历史字段读权者可按需查看该笔敏感差异。主要证件仅显示已登记、已更换或已撤回等结果，完整证号仅按既有原件规则查看。单据正文仅在获权原件查看。记录时刻按北京时区显示并保留原值。窄屏按同一办理组纵排且保留字段标签。
- 日志更多操作提供共享列筛选和刷新。支持办理日期（北京时间）、操作者、办理动作、获权变更字段；一次应用一列，取消不发请求，应用或清除回第一页。每页 20／50／100 笔，按办理计数，子行随组。区分没有记录、筛选无结果、加载及暂时失败。筛选内容与查看的敏感值仅在当前授权范围内使用。
- 「查看当次资料」是确切来源链接，可复制并在新标签打开。每组一个「来源明细」在相邻行展开该次来源、可用的前一来源和原始时刻，收起还焦。同标签退出原件或后退时恢复原日志上界、筛选、页码、页大小、滚动位置和触发链接焦点，再返回名录时恢复名录位置。返回位置、操作者条件仅保留在当前标签内存并绑定实例、登录会话、主体和人员。恢复状态已失效时，以当前权限重读日志第一页，焦点落到日志标题；触发链接不可见时同样聚焦标题。新标签不改原页。字段撤权后清除旧值、受影响条件和展开内容，历史失权清空日志，对象失权清空详情。证据或保全用途直达原件沿用原入口。
- 经办人和只读者按第 4 节矩阵从菜单实操。准备超过 20 笔的同一人记录，至少一次同时修改两项，验跨页、取消与应用、并发新增后的原页、打开原件与返回。仅有个人资料读权时核对单面板，字段或历史权收窄时核对日志、计数、子行、焦点和迟到响应。另验 M04 任职权与 M01 历史权分别授予。共用改动在同构建核验 BU 与职务消费者。

## 4 产品候选的页面验收

T01 登记和名录按 501 的专项目标从正常菜单验证。经办人和只读者各走五种常规视口及原生 200%、400%，共 14 组。记录所测角色、实际倍率、内容尺寸和办理结果。[501 正常菜单与返回](501-person-registration-requirements.md#m01-ac-008) · [已交付职务页面记录](../../verification/308-job-page-standard-implementation.md)

后续个人资料正文改动按 012 的视口规则验收。经办人走查看、更正和整页保存或取消，只读者走同一行的查看与返回，受限角色核对字段、摘要和可见条数。旧档与整页办理按 505 的 018 专项验收。逐批弹框的三种状态、字段变体及共用弹框首次接入或布局变化时的专项缩放按 020 验收。[012 视口与缩放](../m02/012-m02-functional-and-interaction-design.md#m02-ui-viewport-matrix) · [505 旧档与页面](505-personal-profile-contract.md#m01-ac-018) · [505 弹框验收](505-personal-profile-contract.md#m01-ac-020)

- 名录中预先登记一位王伟。经办人再录入一位身份证号不同的王伟，从输入姓名、移出姓名栏到保存，全程无同名提醒、名单或确认。核对登记页也未发起按姓名查人的请求，再从员工名录主动搜索，获权者可见两份档案。另验仅填姓名能保存、改填另一姓名也不能使用已登记的证号、只填证件类型时定位缺项，以及从原档补证和换证。有权限的人照原内容再录一次已办过的同一张登记单，应能看到原办理结果。用滚轮、Tab、Shift+Tab、Enter/Escape 到达末字段、错误、保存/取消、离开弹窗与历史退出。取消后核对零写，丢响应查回只得一个办理。只读者检查跨页定位、可读原件、退出及无写入口，对写 API 另验拒绝。
- 用受限读者、仅部门权限、撤字段权及变更登录主体做专项。直接 URL、证号冲突反馈、回执和浏览器后退与菜单一致。重现详情仍可读而辅助导航失败的情形。焦点恢复到当前获权行，行已不可见时落到列表标题／可操作回退点，不能代替用户重新选择。
- 逐项记录实际图面与完成动作，不用截图代替操作。实现若提炼共用布局、表单或恢复协议，补验 BU 与职务的实际消费者。[本次修订评审](../../verification/500-registration-without-name-prompts.md)与[原 T00 评审](../../verification/500-t00-personnel-specifications.md)分别保存。
