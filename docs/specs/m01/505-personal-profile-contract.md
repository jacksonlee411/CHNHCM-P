# CHNHCM-505 M01 个人资料九栏目维护合同

## 1 谁在什么入口办理

人事资料维护人从「人员 → 人员 → 个人资料」打开已登记的档案，查看获权栏目，进入「更正资料」维护当前人员的资料。仅登记、尚无任职的人也可办理。资料属于客户实例内的 `personId`。从人员档案或 0 号主岗按权打开同一份资料，离职再聘亦沿用。正号兼岗详情只展示该任职的职务信息。人员编号沿用 T01，改号有独立办理依据。只读者从同一入口查看，登记权本身不授予扩展资料的读写权。[实施方案](../../archive/plans/504-personal-profile-extension.md) · [M01 身份与资料](../../architecture/target/modules/m01.md) · [文档登记](../../governance/registry.json)

本合同规定九栏资料的当前查看、更正及保存。参考页的「查看个人信息变更」和「导出个人资料」均在范围外，含对应查询、文件生成及下载。501–503 已交付的登记、改号、办理原件及日志继续按原范围和原权限提供。新栏目正文、差异、栏目名称及数量不加入这些历史响应。办理仍保留准确来源和恢复依据。[T01 原件及日志合同](503-person-registration-design.md#m01-change-query)

## 2 九栏字段与办理规则

<a id="profile-nine-sections"></a>

两个单组是基本信息和健康信息。其余七栏各有零至多条可独立更正、移除的记录。表中列出新行成立所需的最少字段，其余可按授权留空。新建人员仍只要求姓名。既有空值显示未填写，空集合允许直接离开。无栏目读权时隐藏栏目和数量。[4180 栏目与明细字段](https://github.com/jacksonlee411/CHNHCM/blob/061d28105966bd10eb1e3b0032cf2976a6448de4/docs/verification/data/504-personal-profile/reference.json) · [弹框布局](#profile-dialog-layout) · [首批字段与原规则](501-person-registration-requirements.md#m01-fields)

普通资料录入、更正和设置主要或最高标记，由获权经办人填写相应业务字段后直接保存。页面和 API 均无需证明附件、材料编号、更正理由或另行审批。已有真实登记单时可按 501 选填引用，改人员编号时才走专属的决定依据。身份证件号码是证件行的必填业务字段，资格证书编号按下表选填。办理人、时间、资料修订及适用的用途政策由系统记录。[501 登记与改号](501-person-registration-requirements.md#m01-br-003)

| 栏目 | 资料、基数与输入 | 业务约束 |
| --- | --- | --- |
| 基本信息 | 工号（现有人员编号，只读）、姓名、曾用名、英文名、出生日期、性别、婚姻状况、国籍、民族、籍贯、出生地、户籍类别、户口性质、政治面貌。每人一组。 | 姓名取现有 Person 显示姓名，改姓名后名录按原身份找回。出生日期按资料录入，国籍独立于住址或证件签发地。新增项目均可空。 |
| 身份证件 | 每行必填证件类型、证件号码，可填证件姓名、签发国家/地区、签发机关、签发日期、到期日期、长期有效。允许多种证件，至多一份现用主要证件。 | 现行主要证件在同一集合内维护。证号规范及登记判重沿用 503。本人当期同一规范号只保存一行。更换、指定主要、撤回见第 3 节。 |
| 地址 | 每行必填地址类型、国家/地区、详细地址，可填省/州、地址地区（市、区县等）、邮政编码、主要地址。 | 同人最多一条主要地址。行政区划按国家和上级选择，境外可按当地地址层次记载。邮政编码保留前导零，人员住址与企业工作地点分别维护。 |
| 联系方式 | 每行必填联系渠道（电话或电子邮箱）、号码或邮箱，可填联系用途及主要联系方式。 | 沿用既有联系项及电话、邮箱的规范化。每个渠道各至多一条主要记录，同渠道可以有多条。旧项的联系用途和主要标记由经办人按事实补录。 |
| 家庭成员与紧急联系人 | 每行必填联系人姓名、与员工关系，可填出生日期、工作单位、职务、电话、电子邮箱、紧急联系人标记。 | 可以登记多名家庭成员和多名紧急联系人。勾选紧急联系人时至少提供一项可用的电话或电子邮箱。联系人是该人的关系记录，可凭已核实身份另作关联，单凭姓名不匹配人员。 |
| 教育经历 | 教育记录类型分为学习经历、已取得学历、学位授予。维护学校/授予院校、所学专业、学历、学位、学习形式、教育途径、入学年月、毕业/结束年月、学位授予日期、教育完成状态、最高学历、最高学位。 | 三类均需记录类型及学校。学习经历支持在读及缺结束年月。已取得学历需填学历，学位授予需填学位。最高学历、最高学位各至多一条，须分别有已取得学历、已授学位的事实，可以来自不同记录。 |
| 专业技术职称、职业资格与技能等级证书 | 每行必填凭证类别及职称/资格名称，可填等级、专业方向、证书编号、颁发机构、签发日期、有效起始日期、有效截止日期、长期有效。类别包含职称、职业资格、职业技能等级、执业许可与专业认证。 | 一人可持多份凭证，同名续发件保留各自身份。此处保存凭证资料。用于判断岗位准入时由 M16 核验资格与依据。 |
| 银行账户 | 每行必填银行名称、户名、银行账号、币种，可填开户支行、主要账户。 | 每个账户有独立的账户身份及所属人，同人最多一条主要账户。它表示档案中的首选。工资支付用途、有效分配和付款快照由 M14 维护。 |
| 健康信息 | 每人零或一份健康状况简述，可清空，默认无值。 | 仅按客户明确启用的健康资料用途收集。空值不推断为健康。此栏只承载摘要。 |

教育行根据类型显示适用字段。学习经历录学习形式、教育途径、起止年月及完成状态。其中学历可在已毕业且已填学历时标为最高，学位只填实际已授的学位。已取得学历行录实际学历、院校、专业、毕业年月及适用的学习形式和途径。学位授予行录学位、授予院校、专业及已知的授予日期。后两类分别提供本类的最高标记。在读学段的预期学历或拟获学位均不取得标记。改类型时直接显示会清除的原有字段，整笔核实这些字段的写权。

所填日期须为真实日历日期。证件到期不得早于签发，凭证截止不得早于有效起始，已知毕业/结束年月不得早于入学年月。长期有效与有限截止互斥，选择长期仍保留已填的签发或起始日。未知截止可留空，与明确长期分别保存。业务日期用 YYYY-MM-DD，年月只存 YYYY-MM，缺失的日或月不补造。资料修订以来源定位，证件期限是证件本身的属性。按日对象的 1900 首建默认及通用时间轴不适用于这些个人资料。[026 日期输入](../../adr/026-date-display-and-input-format.md) · [121 页面接入边界](../m02/121-dated-object-admission-matrix.md)

国家/地区及已有覆盖的行政区划经 M02 公开端口选用。国籍、签发地和住址分别选择。保存时按北京业务日重验本笔新选项及其依赖，如地区上下级、支行所属银行，固定标识、采用日、版本及名称。所选项换版时保留草稿供重选，无关目录项的变化不阻断保存。历史地名、未收录的地区、学校、专业、颁发机构及支行可直接按原文填写，系统从录入方式区分手工原文与目录引用，无需另填出处。保留先前选项时沿用原采用，即使其后来停用也可更正其他字段。候选查询故障或撤权时清理不可读选项并提示，失效的目录选择不得自动转存为手工原文。人事选项由 Go 按联系渠道、用途、亲属关系、教育类型等语义校验。独立目录建设按所属计划执行。[组织目录](../../architecture/target/modules/m02.md) · [资格与支付归属](../../plans/500-personnel-roadmap.md)

## 3 多条记录与敏感资料

<a id="profile-items-and-access"></a>

- **主要证件。** 允许零或一份现用主要证件。登记时填写的主要证件就是同一资料行，补充证件只归在本人档内。保存时同客户现用主要证号排他，换主要证件须在一笔办理中释放旧占用并取得新占用。升为主要时如已被占用，原主要标记、补充行和同笔其他资料均保持提交前状态。更换主要可保留旧件为补充件。撤回误录可明确移除。证件到期不自动释放仍有依据保留的现用号。跨人登记不以补充证件、姓名或联系方式判重。[501 防重](501-person-registration-requirements.md#m01-br-002) · [503 证号与处置](503-person-registration-design.md#m01-recovery)
- **主要与最高标记。** 新增行不自动取得标记。明确选中一条时，同组旧标记在同笔中撤去。移除或取消已标记行可留下零条。主要地址、电话、邮箱、账户和两个最高标记只在当前可使用的同组记录中生效。当一条记录退出普通使用时，旧来源保留当时标记。现用主要证号的占用另按上述身份资料规则核验。最高学历与最高学位分别维护。学位授予行可只有学位，学习经历可只登记在读。资料未表明取得学历或学位时不得标为相应最高。完全相同的教育记录按同人、记录类型及全部业务字段（标记除外）判重。不同授予事实可并存。
- **账户身份。** 账户归属由本域核对，账号按文本保留前导零，比较时去掉展示空格并统一 ASCII 字母大小写。本人在同一银行登记同一规范账号只得一条，币种或主要标记不额外创建身份。更正资料产生新修订，更换真实账户登记新账户身份。移除从当前资料退出，历史采用仍指向原身份和版本。提交账户与其他栏目时由 Personnel 协调本域账户根与 Person，不向 M14 发起付款或改分配。[个人银行账户](../../architecture/target/modules/m01.md) · [支付用途](../../architecture/target/modules/m14.md)
- **读写与遮罩。** X03 按客户、主体、人员范围、动作、栏目/字段、用途及期限匹配完整授予。查看身份和联系资料、第三方家庭资料、教育凭证、账户、健康各有所需用途。健康、账户、证号不得由普通档案读写权推得。证号、银行账号默认固定遮罩，电话和邮箱沿用 501。显式完整读权限供单项查看，编辑受限值须有原值完整读权和写权。服务端对显式字段、移除整行、切换类型及受影响的旧标记逐项核权。旧标记仍在当前集合但无权修改时，整笔拒绝。返回拒绝时不给出隐藏行、占用者、尾号、数量或原因细节。只读、无权及遮罩项均不以空值或掩码回写。[503 当前授权](503-person-registration-design.md#m01-registration-access)
- **用途和保留。** 客户启用某组资料时由 X03 给出用途、政策版本、普通及必要证据的期限，Personnel 按项和类别在首次获准收集时固定依据与起算点。更正同一项不重置时钟。新增字段不继承旧登录角色的授权。进入当前档案仍需 501 的姓名及现号读权，再按字段投影。只有专项保全权者沿原确切来源受限读取。健康政策未启用或已到期时，普通详情、弹窗和查回隐藏该栏，直接新增或更正健康资料被拒。具有处置依据的正文退出活动存储和查找索引，保留最少办理证明、必要保全及原采用。重试、备份恢复遵守已生效的处置。证号、健康摘要、账户及家庭资料正文不进入技术日志、Outbox、URL 或浏览器持久缓存。[501 保留合同](501-person-registration-requirements.md#m01-retention)

## 4 页面、保存与恢复

<a id="profile-maintenance"></a>

沿用当前人员详情的路由、页签、控制区与返回上下文。经办人在「个人资料」从上到下看获权栏目，点击「更正资料」后按原值直接修改可写字段。基本信息之外的栏目各占整行。多条记录使用 012 的详情正文布局。表格溢出只在表内滚动，明细内可到达全部获权字段。详情底部沿用当前资料的办理人和北京时间摘要。[502 人员详情](502-person-directory-interactions.md#m01-page-map) · [012 详情正文](../m02/012-m02-functional-and-interaction-design.md#m02-ui-detail-sections)

基本信息的查看与更正采用相同顺序。内容视口宽 900 CSS 像素起分两列，左列依次为工号、姓名、曾用名、英文名、出生日期、性别、婚姻状况，右列从国籍到政治面貌。低于 900 时先左列后右列排成一列。每行左侧为标签，右侧为值或输入，长英文名可换行，下一字段随内容下移。可见空值显示次要文字「未填写」，姓名及行内必填输入同时带有共享星号和可访问的必填状态。

身份证件和联系方式的标题旁显示当前获权的条数。可见空栏显示「0 条」和「暂无记录」，更正时有添加权者可「添加一行」。600 CSS 像素起使用浅色表头，低于 600 时，首行放记录标题和获权的「主要」标记，其下显示已填写且获权的摘要。两种宽度使用相同的记录入口。[首批实页对照](../../verification/504-personal-profile-first-batch.md#profile-summary-layout)

| 栏目 | 打开明细的标题 | 摘要与操作 |
| --- | --- | --- |
| 身份证件 | 证件类型，如「护照」 | 查看及更正的摘要均按读权显示固定证号遮罩。签发国家/地区、到期日分别按权显示；明确登记长期时才显示「长期有效」。完整号码按单项授权在该行明细中查看。更正时按权提供「设为主要」「撤下主要」或「移除」。 |
| 联系方式 | 本次获权显示的电话号码或邮箱，沿用其遮罩 | 显示联系渠道和获权的用途。电话、邮箱分别标示主要项。更正时可在该行明细修改主要标记、在行上按权移除。 |

「个人资料」面板的九栏共用一份 M01 草稿，职务信息按 M04 办理分别保存。添加、编辑、移除一条个人资料都只改该草稿，明细内「应用」回到原行，「取消」放弃本次行编辑。顶部「保存」一次提交实际变化，「取消」放弃整页。无改动可直接关闭，关闭明细、切人、切页签、返回或刷新会丢弃实际输入时只作一次离开提示。确认放弃或刷新后读取已保存资料。保存中的明细一并校验，错误聚焦对应栏目、行和字段。失败保留仍获权输入，撤权时清除受限正文、选项、数量及草稿，迟到响应不得回填。保存成功定位原人和修改栏目，返回名录恢复原筛选、页码、滚动及焦点。[012 动作](../m02/012-m02-functional-and-interaction-design.md#m02-ui-actions) · [502 查询和返回](502-person-directory-interactions.md#m01-page-query)

复用 `GET /api/v1/persons/{id}`、`POST /api/v1/persons/{id}/corrections` 及 503 的提交查回入口。Go 核对原人、期望人员来源版本、提交号、显式字段变更和条目操作。已有行按稳定条目标识及期望修订更新或移除，新增行在请求内可区分并在成功后取得稳定身份。遗漏字段、未加载的行都保留。移除只使该项退出当前集合，原修订及按政策持有的来源仍在。银行行另核所属人、账户身份及修订。

复用 503 的人员更正事务与提交查回。Go 重验当前授权、原来源、受影响条目和本笔新选目录项。PostgreSQL 按客户、人员和相应分组约束唯一占用与标记，将修订、办理来源、回执及事件同笔保存。任一项失败整笔回滚，无变化零新修订，同一旧版本的并发更正至多一笔成功。重送、迟到请求及回执按 503 的幂等和当前读权处理。[503 命令与恢复](503-person-registration-design.md#m01-recovery) · [现有更正入口](../../../internal/contexts/personnel/public/service.go)

### 4.1 七类记录的查看、新增与编辑弹框

<a id="profile-dialog-layout"></a>

从已保存资料的记录打开查看弹框。在「更正资料」中，从本栏「添加一行」打开新增弹框，从已有行打开编辑弹框并带入原值。三种弹框都留在当前个人资料页。标题在左，显示栏目名和「记录详情」「新增记录」或「编辑记录」，右上均有可用键盘操作的关闭按钮。查看态右下为「关闭」。新增、编辑态底栏左侧提示应用后还需在页顶保存，右侧依次为「取消」「应用」。桌面放大后底栏空间不足时，提示和按钮可以分行。应用后回到对应的草稿行，取消后回到触发入口。关闭有改动的弹框沿用本页草稿的离开保护。[4180 弹框实测](../../verification/data/504-personal-profile/dialog-layout.json)

验收 018 的正文时，从「人员」名录打开同一人的「个人资料」页签。在共享桌面视口核对基本信息两列、长名换行及证件、联系摘要。经办人应用新增行、移除已有行并取消整页，条数和标记应恢复。只读者从记录标题按 Enter 打开并用 Escape 返回原行，页面没有写动作列。有电话和邮箱各一条的样本，对仅可读电话且不可读用途的角色应显示「1 条」、电话标题及渠道，同时隐藏邮箱和用途。证件签发地失去读权时，表头和摘要一起移除。

验收 020 的弹框时，各栏从正常菜单打开上述组合及适用变体，在共享桌面视口核对字段左右配对、标题与按钮，放大后核对字段阅读顺序。直接读取仓内 CubeBox 基准作为预期，一个业务用例可以同时验操作和布局。[字段与布局基准](../../verification/data/504-personal-profile/dialog-layout.json)

共用弹框首次接入或布局改变时，选实际查看窗和可编辑长表单，按 012 的桌面视口与关键流程原生缩放验证宽度、间距、底栏、滚动与键盘行为。选例覆盖实际出现的长标题、错误换行和末项，记录真实倍率与内容尺寸。后续栏目的栅格、底栏、滚动实现和样式相同时，可以共用这部分结果。新出现专属布局、控件或受限字段改变重排、发现差异时，对受影响的状态和尺寸补验。验收记录能定位所测组合、预期、实际结果及差异即可。[012 视口与缩放](../m02/012-m02-functional-and-interaction-design.md#m02-ui-viewport-matrix)

只读者打开获权明细、以「关闭」或 Escape 返回原行，且看不到新增和编辑入口。经办人用滚轮和 Tab、Shift+Tab 到达末字段和底部操作。新行「应用」后在草稿中能找到，编辑原行后「取消」或在关闭提示中选择放弃，原值仍在。字段报错时保留输入并可定位错误。用受限角色另验隐藏、遮罩、焦点和草稿清理。字段错位、错序、操作不可达或底栏遮住末项应逐项记失败，未实测的产品组合保留待验。
