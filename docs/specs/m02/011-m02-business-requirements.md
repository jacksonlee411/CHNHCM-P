## 1 业务目标与边界

列表体验按[113](../../adr/113-bu-list-community-adoption.md)、110剩余交互及[111](../../archive/plans/111-bu-list-experience-upgrade.md)接入Community，本轮T01/T02有实际组件及合成HTTP定向检查，T03真实业务与七组条件另见[本轮报告](../../verification/111-community-t03.md)。编码/名称q、单值状态、服务端D、排序、授权及历史规则保持，不新增BR/SCN/AC或接口。列拖动/固定取消；列条件等未采纳时不增加业务承诺。上述“不新增BR/SCN/AC或接口”仅指111基础批次；后续114/115另采纳SCN018、BR022/023及AC032/033，选择/导出已由115接线，实际证据另见本轮实施报告。

### 1.1 用户目标

组织管理员从“**设置 → 组织配置 → 业务单元**”直接进入列表，维护单客户实例、一个企业上下文下的多个 BU。保存成功形成可追溯的组织事实；列表按服务端D区分未生效、启用和停用，能解释更正、改日、删除及来源版本。查询者在授权范围内查看同一份事实。

本批连接正常页面与新 Go 权威内核，保留列表详情、表单、日期维护、来源解释、返回上下文和未保存保护。菜单分组不形成新的设置首页或工作台；BU 仍由 Organization 上下文的组织对象根维护，不因菜单名称或通用页面而改变事实归属。

### 1.2 首批动作与限制

| 动作 | 本稿细化的首批规则 | 规则位置 |
| --- | --- | --- |
| 新建并保存 BU | 创建稳定身份及首条启用资料；首条可以从企业有效范围内的过去、当日或未来日期开始，记录时间始终为实际保存时间 | [创建](#m02-br-004) |
| 新增记录／插入记录 | 允许过去、当天及未来登记；生效日严格晚于首条、位于企业范围且未占用，只能在启用期间追加或插入 | [新增与插入](#m02-br-005) |
| 更正记录 | 在同一入口按各修改面权限更正名称、原位置内日期及显式业务分类，保留身份、编码和旧修订；不能借更正补办真实业务变更 | [更正](#m02-br-006) |

| 停用 BU | 操作类型为停用，明确生效日期和操作原因；首批采用冲突拒绝规则，不自动取消或改写后续未来资料 | [停用](#m02-br-008)、[分类与原因](#m02-br-016) |
| 重新启用 BU | 在目标日期前处于停用状态时，新增独立重新启用记录并确认完整资料，保留此前停用期间；允许重复启停 | [重新启用与完整时间线](#m02-br-018) |

010 原批次暂缓申请/撤回申请/审批/独立人工发布、工作台、其他组织对象完整维护、组织树及上级BU、复杂适用与默认配置、真实消费域、通用投递平台、批量导入导出与生产交付。后续[114](../../adr/114-bu-query-selection-and-export.md)仅采纳本BU列表完整授权结果选择与CSV导出所选，由[115](../../archive/plans/115-bu-query-selection-and-export.md)另批实施；不改变010原完成证据，其余暂缓范围保持。

## 2 角色、前置与术语

### 2.1 角色与办理前置

| 角色 | 允许的业务职责 | 前置与边界 |
| --- | --- | --- |
| 组织管理员 | 在被授予的企业/对象范围内创建、查询、新增过去/当天/未来生效记录、更正、改日、删除、停用和重新启用 | 每个动作都需要对应授权；名称为管理员不等于拥有全部权限，Go 在提交时重新判断 |
| 组织资料查询者 | 读取授权范围内列表、详情及最小操作摘要；另有历史权时读取日志/来源版本 | 无写权；基本读取不推导历史读取权，只读身份经直接接口也不能保存 |
| 初始化执行者 | 通过受控初始化建立本批唯一企业上下文及所需身份/授权准备 | 013 定义可复现初始化方式；不新增企业维护页面、不借初始化绕过 BU 命令 |
| 业务验收者 | 根据第 5 节独立预期核对事实与页面 | 实际人员由 Organization lead 指派；本稿不虚构人员或审批角色 |

进入办理前必须存在真实企业身份、有效的认证身份与当前授权，且本批存储可用。本批受控企业上下文的业务起点已生效、终点开放，不提供企业有效范围修改；有有限终点的企业不作为本批创建上下文，不能只校验首日而留下超出企业范围的开放 BU 期间。企业初始化缺失或上下文有歧义时明确阻断创建，不自动选第一条企业或创建匿名企业。X03 提供授权事实，M02 消费其决策并保护自身事实；无人员、岗位或组织树不自动获得权限。

### 2.2 对象与最小业务资料

以下是业务含义与可变性；具体控件、长度提示、DTO、表结构及约束实现分别由 012/013 承接。

| 资料 | 必要性及来源 | 可变性与含义 |
| --- | --- | --- |
| 稳定 BU 标识、对象类型 | 保存时由新内核形成；类型固定 BU | 不由名称、编码或 URL 临时生成；维护不能变成部门或法律实体 |
| 所属企业 | 来自当前受控企业上下文，界面可核对 | 本批不可改挂企业；提交时验证真实身份及日期资格 |
| BU 编码 | 新建必填，管理员输入 | 1—40 个 ASCII 字符；首位字母或数字，其余字母/数字/下划线/连字符；去首尾空白后忽略大小写判重；保存后不改、不重用 |
| 中文名称 | 新建及资料变更必填，去首尾空白后非空 | 可按日变更或纠错；允许同名，不承担身份或唯一约束 |
| 英文名称 | 可选，空值明确表示未提供 | 展示可回落中文并标明语言选择，不生成虚假的英文事实 |
| 操作类型 | 新建、资料变更、停用、重新启用；由当前办理入口限定并清楚展示 | 表达业务变化；更正/改日/删除不是独立业务类型，更正记录按分类权限编辑或只读，未显式修改时继承原类型；Go核验允许组合 |
| 操作原因 | 新建、资料变更、停用、重新启用从所属类型的固定选项明确选择 | 未显式修改分类的更正及单独改日/删除由服务端继承准确目标最新已接受修订的原业务分类和名称快照；更正表单原值带入单组类型/原因字段，不另列只读摘要；显式分类纠错按[BR021](#m02-br-021)输入新分类，见[分类规则](#m02-br-016) |
| 记录处理 | 新建、新增、更正、改日、删除；由用户选择的入口确定，服务端核验 | 表达怎样登记或处理事实；详情保留当前便捷入口，不强制再建一套处理方式选择器；取消编辑不属写入 |
| 生效日期 | 新建、资料变更、停用、重新启用及改日时明确选择；更正记录初始显示原日，获权时原位置内调整；删除只读原日 | 真实日历日期；停用类型的生效日期就是其停用日期，不另设字段；已保存记录经更正记录内的日期修改追加修订，不原地覆盖；由具体操作和Go默认确定 |
| 状态 | 创建为启用，自生效日适用；停用及重新启用由独立动作形成 | 普通字段表单不提供 active 开关，不借更正重新启用 |
| 记录标识、来源版本、记录时间及操作者 | 服务端记录 | 只读；业务日期、记录时间及版本是不同信息，不能互相代替 |

本批取消独立“办理依据”字段，也不以备注、补充说明或自由文本“操作原因”重新引入。操作原因仅使用第 4.16 节的受控选项；不新增配置页面或通用操作引擎。

首批不增加上级 BU、用人单位、付款主体、地区、复杂适用条件等字段。相关概念由既有术语及所属领域持有；BU 身份本身不证明用人、付款或税费责任。

### 2.3 日期、记录与查询用语

本批业务时区为 `Asia/Shanghai`。下文 D 表示服务端处理本次命令时的当前日期；跨午夜重新校验，不信任浏览器日期。业务日采用 `YYYY-MM-DD`，区间为前闭后开 `[start,end)`；没有后继时终点开放。

本节采用的首选中文、别名与概念边界统一登记在 [17 术语表](../../architecture/target/17-terminology-glossary.md#domain-x01)。“生效日期”表示业务事实开始适用的日期，所有相关表单和记录详情使用同一名称；“本次”仅在说明文字中限定当前操作。停用属于操作类型，“停用日期”仅解释该类型记录的生效日期，不再单列输入、存储字段或术语。“生效记录”和“未生效”按 M02 场景说明使用；普通维护取消“查看日期”，不升级为所有领域的同义词或新聚合；英文协议身份保持不变，具体控件由 012 定义。术语选用保持；本轮采纳与实施范围以 010 和登记表为准。

| 用语及术语登记 | 本稿约定 |
| --- | --- |
| [当前日期 Current Date](../../architecture/target/17-terminology-glossary.md#term-x01-business-today) D | 服务端按指定业务时区计算的当天日期，用于默认查询、办理日期说明及当前状态判断；用户调整操作生效日期不改变当前日期 |
| 服务端实际查询日期 businessAt | 响应中的业务日，由Go按服务端D解析；普通列表/详情不接受此输入。具体生效记录和确切来源另行定位 |
| [记录标识](../../architecture/target/17-terminology-glossary.md#term-x01-record-identifier) | 区分同一 BU 的各条生效记录；普通更正及改日保留它，新增记录形成新标识，与 BU 稳定标识分别维护 |
| 所选记录 | 用户明确选择的记录标识及其当前修订版本，可能不同于今日适用记录 |
| [生效日期](../../architecture/target/17-terminology-glossary.md#term-x01-business-effective-time) | 业务事实开始适用的日期；新建、资料变更、停用和重新启用时明确选择，保存后仍使用同一名称。停用时提示“自该日起停用”；更正记录默认原日期，获权日期修改使用原位置内范围并保留原值；删除只定位原记录，不输入新的生效日期 |
| [操作类型 Operation Type](../../architecture/target/17-terminology-glossary.md#term-x01-operation-type) | 表达真实业务变化；本批为新建、资料变更、停用、重新启用，具体分类及状态规则归 M02 |
| [操作原因 Operation Reason](../../architecture/target/17-terminology-glossary.md#term-x01-operation-reason) | 解释原业务变化为何发生，从属于相应操作类型；新业务选择原因，普通更正/改日/删除继承目标分类，不另设处理原因 |
| [记录处理 Record Action](../../architecture/target/17-terminology-glossary.md#term-x01-record-action) | 表达新建、新增、更正、改日、删除；与操作类型分开，停用及重新启用通过新增相应记录表达，普通更正/改日/删除不伪造新的业务变化 |
| [重新启用 Business Unit Reactivation](../../architecture/target/17-terminology-glossary.md#term-m02-business-unit-reactivation) | 保留停用期间并新增恢复业务，沿用BU身份及编码，保存独立资料快照；与删除停用及改日分别办理 |
| [删除记录 Record Deletion](../../architecture/target/17-terminology-glossary.md#term-x01-future-slice-deletion) | 页面使用“删除此记录”，处理符合条件的非首条记录，含已生效记录；从当前记录集合移除并衔接期间，保留历史原件和删除关系，不增加并列的撤销动作 |
| [修订版本 Revision](../../architecture/target/17-terminology-glossary.md#term-x01-revision) | 记录的修订版本；普通更正保留日期，改日追加保存新日期的修订；两者保留记录标识，不能用它替代来源版本或业务日期 |
| [当前已记录信息](../../architecture/target/17-terminology-glossary.md#term-x01-current-recorded-information) | 按本次查询可见的最新已提交记录解释所选业务日期；可包含已登记的历史和未来资料，不等于今日有效事实 |
| [来源版本 sourceVersion](../../architecture/target/17-terminology-glossary.md#term-x01-source-version) | 一次已提交 BU 来源事实的确切不可变版本，能解释该版的记录、期间、删除及修订；具体封装由 013 定义 |
| [已采用版本引用 adoptedRef](../../architecture/target/17-terminology-glossary.md#term-x01-adopted-reference) | 定位消费者当次采用的确切来源版本或不可变快照；采用事实由消费者维护。本批消费者未接入，该参数不在当前API白名单，按未知参数统一拒绝，不能伪造采用或回退最新 |
| [提交标识](../../architecture/target/17-terminology-glossary.md#term-x01-submission-identifier) | 识别同一次提交并绑定主体、范围、动作及内容；同次重试沿用，与操作者身份、BU 标识和记录标识分别维护 |

“未生效”是服务端D早于首条业务记录的读取结果，登记见[生效记录的场景说明](../../architecture/target/17-terminology-glossary.md#term-x01-dated-slice)，不表示待审批；“已保存”是提交结果，不代表未来日期已经到达。“停用记录”只表达停止可用的事实，名称等资料沿前一适用资料读取，不另带一次更名。类型、原因及记录处理采用第 4.16 节的合法组合，取消编辑不写入上述事实。X01 仅共享用语与小型值协议，M02 的目录和状态守卫由 M02 拥有，M04 人事业务类型/原因及办理记录保持原领域归属。

## 3 业务流程

所有写流程均遵守当前授权、版本、日期、引用和事务规则；以下省略的拒绝项由第 4 节统一约束。步骤中“确认影响”是管理员提交前核对，不建立申请、审批或发布状态。

## 4 业务规则

<a id="m02-br-001"></a>
### 4.1 M02-BR-001 稳定身份、企业归属与编码

一个 BU 归属本批唯一企业，维护时稳定标识、类型和企业归属不变。编码按“客户实例＋企业＋BU 类型＋忽略 ASCII 大小写的编码”唯一；输入首尾空白清除，展示可保留录入大小写。已保存编码永久保留在本批身份记录中，停用或删除记录不释放编码。不同编码允许同名，名称不能用于关联或判断同一对象。并发创建同编码必须至多一个成功。

<a id="m02-br-002"></a>
### 4.2 M02-BR-002 必填资料与状态操作

组织名称是正式主数据文本：允许多语言文字、生僻及扩展汉字、数字和技术设计明确列举的名称标点；至少包含一个文字或数字。禁止emoji及组合序列、目录外装饰图形、控制/换行/制表字符，以及不符合文字上下文的不可见字符。中文/英文为语言字段，不强制汉字或ASCII字符集；BU不按企业登记名称办理法定名称审核。新输入先校验原文本，裁剪首尾空格、做NFC，再按200码点上限判断；英文可为空。仅处理显式输入，不清洗未声明继承字段、后继独立快照、旧来源或原终态，已有不合规名称可通过有权的普通更正处理。具体码位、文字上下文及外部依据由013第2.3节持有，验证见[名称规则复测](../../verification/011-organization-name-policy.md)。用户批准的127历史验证按[来源绑定及原名保留规则](../../archive/plans/127-vanke-full-history-verification.md#7-已批准的历史导入规则)执行，仅在隔离导入工具中接线；不改变日常新输入规则，不预建兼容平台。

新建、资料变更要求完整中文名称、生效日期及操作原因；重新启用须确认完整资料快照及业务原因，可在字段权限内调整名称；停用只填日期及原因，名称继承前序明确资料。英文名称可选，类型/原因与记录处理见[分类规则](#m02-br-016)。普通更正/改日/删除继承原分类，不输入处理原因；改日另输入新日期。

状态只能由CREATE、CHANGE、DEACTIVATE、REACTIVATE及合法记录修订后的时间线解析，普通表单无active开关。无实际内容变化的普通新增/更正及同值改日返回无变更，不产生新业务版本；重新启用即使名称相同也有停用→启用的实际变化，不能据名称相同返回无变更；重复启用或重复停用属于非法转换。

<a id="m02-br-003"></a>
### 4.3 M02-BR-003 日期、区间及三种定位

日期必须是真实日历日期，且落在所属企业有效范围内。按用户2026-11-13确定的[202项目规则](../../adr/202-master-data-default-effective-date.md)，主数据首次新建默认1900-01-01，用户可明确修改；这替代原“不使用1900默认值”条款。默认不覆盖显式日期、不放宽企业及关系资格，现有产品适配及分批回归见[200 G1报告](../../verification/200-g1-default-date.md)，原验证结果保持。首条之后记录日期严格递增、当前集合每个日期最多一条记录；同日再次真实业务变化不通过增加同日序号解决。

新资料记录重算相邻区间边界，已有记录通过[改日](#m02-br-017)追加新日期修订，不能原地覆盖旧日；记录删除也只通过新修订表达恢复区间。显示的结束日若使用含末日形式，012/013 必须与 `[start,end)` 明确转换。服务端D、所选记录及操作生效日期分别解释；停用沿用同一日期字段；不能把选中记录日期无条件当作操作日期。新增及改日统一允许过去/当天/未来；D用于默认读取与办理说明，不作为排除某一类日期的门槛。提交时仍重验当前来源、企业范围、日期占用、首条及完整时间线；删除不以是否未来判定。读取历史仍使用当前授权。

<a id="m02-br-004"></a>
### 4.4 M02-BR-004 创建及首条保护

企业身份与有效范围须可核验；首条生效日可早于、等于或晚于 D，但不得早于企业的业务起点或超出其有效范围。过去日期只是本次登记的业务起点，记录时间如实保存；不伪造过去已有登记。

保存原子建立身份与首条启用资料，不允许无首条身份或创建时直接停用。首条记录本批不删除，未来首条也适用；允许普通字段纠错及按BR017改日，首条身份保留且新日期必须仍最早。首条之前为NO_FACT（无适用事实），不等于停用。首条后移可能使今日未生效，只改日期时前移延长该首条明确资料；更早内容不同可按BR020同次明确改名，后续资料按需另次新增/插入，不合并两次提交。整对象作废、误建身份/误编码处置另属后续范围，不提供物理删除、改编码重用或直接改库的办理路径。

<a id="m02-br-005"></a>
### 4.5 M02-BR-005 记录新增、插入与追溯登记

普通单条新增以当前来源的所选记录作为位置左边界L，R为同一来源紧邻后一条当前记录；无R时所选记录才是最新一条，按最大生效日期判断，不按最后登记/更正时刻、当前日期或今日事实判断。新增与插入仍是ADD处理及CHANGE业务类型，不另建分类。历史来源只读；当前已删除记录不能作为新增位置；首条之前不同资料仍通过BR020补全。

| 位置 | 页面入口 | 默认生效日期 | 日期资格 |
| --- | --- | --- | --- |
| 所选为最新一条，无R | 新增记录 | 服务端业务当前日D与L的次日取较晚者 | 严格晚于L，并满足企业范围及启用前提；允许合法过去/当天/未来日期 |
| 所选有紧邻后继R | 插入记录 | L的次日，仅在其合法时带出 | L＜生效日期＜R，并满足企业范围及启用前提 |
| 所选位置无合法可用日期 | 不进入编辑 | 不生成非法默认 | 无可插入日期只禁用插入记录，不增加原因说明、提示气泡或弹窗，不打开全灰日历；无合法追加日期也不得办理 |

默认仅在合法时带出；若公式默认不合法但仍存在合法日期，保留可选范围供用户明确选择，不另猜业务日或跳到其他位置；只有没有合法可用日期时才不可办理。次日和前一日按真实业务日历计算，覆盖月末、跨年及闰日，不以24小时毫秒运算代替。相邻为6月1日/10月1日时可选6月2日至9月30日；相邻为6月1日/6月2日时无可插入日期；相隔两天时仅中间一日可选。日期空档不代表启用：所选停用段内不能用CHANGE隐式恢复；当前BU停用但选定此前合法启用段时仍可插入资料，重新启用后也可新增。授权不足仍隐藏入口，不因禁用文案简化取消服务端错误和守卫。

中文名称、英文名称等当前模型可继承业务资料从所选记录自动带出，只显示有读权的字段、只允许修改有写权的字段；BU编码及企业信息保持只读。操作类型不复制，普通新增/插入固定资料变更；操作原因初始为空，由用户明确选择本次CHANGE目录原因。记录/修订/登记时间等由系统生成。实际保存从该位置的准确前序合并用户明确变化，形成独立完整快照，不以今日资料或其他来源替代，不复制前条CREATE/DEACTIVATE/REACTIVATE分类或原因。

初始带值及自动辅助不算用户修改；实际编辑后保护输入，恢复初始值可直接退出，自动加载不覆盖手工输入。未编辑字段保持继承语义；仅日期或原因不同、业务资料与前序相同则无实际变化，不新增空记录或业务版本，明确反馈没有修改内容。后继普通资料和重新启用的独立快照保持；随后停用继承随前序重新解析，遇到独立快照停止传播。旧来源、原采用和已存结果保持。

过去补登记仍新增独立记录身份，recordedAt如实记录保存时间；全部影响按BR011核验。准备上下文不承诺可保存：Go在原守卫内重验来源、所选记录、紧邻关系、权限、日期及完整候选；过期依据拒绝，不自动改到其他位置。未接受请求跨午夜时日期仍可合法，保留用户日期，不强制换成新D默认；已接受精确重试返回原内容及原结果。

<a id="m02-br-006"></a>
### 4.6 M02-BR-006 普通字段更正

当前来源尚未删除的首条、资料变更、停用及重新启用均从“更正记录”办理。名称、日期、业务分类是独立授权的修改面，可一项或组合提交；只办一条仅要求实际修改面的权限。编码、企业及recordId不变，无另设更正原因。仅改名称时保持日期及分类；日期变化按BR017，显式分类变化按BR021。一次提交共用完整候选、引用及事务，一次成功来源，禁止串行部分保存。

日期初始为目标原日；名称取所选记录在准确来源的自身资料，分类默认原类型/原因，直接显示及原因候选加载不算修改。不实际编辑的字段不回传；恢复原值可直接取消，同值命令不新建业务版本。保存及冲突重读保留真实草稿，未编辑字段随最新来源更新；撤读权清除输入/缓存，撤写权保留可读草稿供核对并允许明确移除。

名称更正只影响所选明确资料及随后继承它的停用资料，不覆盖后继普通或重新启用独立快照。最终仍为停用时名称不可编辑；显式转换为明确资料后可修改。转停用前已有名称草稿须明确选择移除或保留当前输入，不能静默丢弃。旧来源只读，返回当前并重核后才可保存。

<a id="m02-br-007"></a>
### 4.7 M02-BR-007 记录删除及期间衔接

统一采用“删除记录／删除此记录”，不另设撤销功能。允许删除当前来源尚未删除的非首条普通资料、停用或重新启用记录，含过去/当天/未来。首条无论唯一/有后继、未来/已生效均禁止删除；不删除BU身份、不释放编码、不提供恢复已删除记录。

先构造移除目标后的完整候选时间线，必须满足[BR018](#m02-br-018)：普通记录删除使前序资料延续并重算停用继承；后继独立快照保持。删除停用若使后继重新启用失去停用前提则拒绝。删除重新启用若使后续CHANGE落入停用期间，或使后续DEACTIVATE成为重复停用则拒绝。无后继依赖的末尾重新启用可删除，前一停用期间延长，可能使今日停用；合法末尾停用删除则可能使今日启用。两者均由自动辅助说明必要状态影响，直接确认删除，不能伪造新的相反业务动作。

不级联删除依赖记录、不隐式把REACTIVATE改成CHANGE；单条请求若留下关联错误则拒绝，需共同修订时由BR019显式提交全部关联项，只验证最终候选，不提交非法中间状态。提交执行对应目标类别权限、准确修订/来源及全影响期间引用守卫；不可因已生效、跨午夜或未接入消费者单独拒绝，真实冲突/必要依赖故障/覆盖未知仍拒绝。

从目标继承原分类和名称快照，无处理原因；以删除修订、关系及完整新来源保存，旧原件/日期/状态及消费者原采用保持。实际处理时间不倒填。删除后同日新增是新recordId，须重新满足对应新增规则；精确重试返回原删除结果，不重复执行。

<a id="m02-br-008"></a>
### 4.8 M02-BR-008 停用与启停期间

停用是DEACTIVATE业务类型，通过ADD在当前来源末尾新增停用记录。须选中按最大生效日期确定的末条，且该条生效后为ACTIVE；非末条不提供单条停用或重新启用入口，不能忽略所选位置追加到别处。生效日期允许过去/当天/未来，但须晚于末条、在企业范围且未占用。默认日期取服务端今天与末条次日的较晚者，日期上下界和资料默认由Go准备。操作原因留空待选，初始默认不构成未保存修改。保存时重验锚点、当前来源、完整时间线及引用；判断末条生效后状态，不以今日或今日状态代替。可有多次停用，每次必须由前次合法重新启用恢复ACTIVE，不允许重复停用。

停用只表达状态，自该日起至下一条合法REACTIVATE之前为INACTIVE；其名称继承前序普通资料或重新启用的明确快照，不另登记更名。期间为[start,end)，最后启用日是停用日前一天；未来停用不提前改变今日状态，不需要到日再次写库。新引用须满足所引用日期的有效资格，历史只读仍可授权查询。

例如只有12月1日更名、拟补11月1日停用，会使更名落入停用期间，整笔拒绝。若存在合法启停链，后一次重新启用之后的资料不能仅因晚于较早停用而被拒绝。不得自动删后继、自动生成重新启用或覆盖后继状态。已有停用日期错误按BR017修订，错误记录按BR007删除；能独立合法处理的记录可另次办理，每次独立提交，不承诺跨请求回滚；可通过BR019专用操作同时插入停用和重新启用，使最终后继合法。

<a id="m02-br-009"></a>
### 4.9 M02-BR-009 列表、历史与确切来源版本

列表默认按服务端D、全部状态，仅枚举有当前读取权限的BU，每BU一行。今日已有资料时只显示今日名称/状态/生效日期；未来更名或恢复不提前覆盖今日资料。服务端D早于首条时，可展示身份、明确标注的未来首条名称/日期及“未生效”，但按日事实查询仍返回无适用事实，不能将未来首条冒充当日有效记录；名称检索若命中该未来展示名称也须标明未生效。停用对象默认可查，使用状态筛选时按服务端D判定。

单列筛选增量：管理员/查询者从同一正常菜单，对编码、名称、状态或展示记录生效日期设置一个条件，明确应用才查询，取消不改变原列表及搜索草稿。编码/名称支持字面包含/等于，状态单值或同列多值或，日期等于/严格前后/含边界前后；与现有关键词和状态按且组合。更换列替换原条件，清除后应用移除条件。字段、操作符和值的具体合同见013，交互见012。生效日期比较服务端D解析的展示记录，未来首条仍标明未生效；不是任一历史记录命中。不可读编码/名称/日期不参与相应筛选，不从数量泄露其值；仅对象可见时状态沿用现行表达。全获权结果的筛选、总数及页码纠正一致，URL/返回保留已应用条件，查询不产生业务写入。完整Excel候选及跨列组合后置。

历史查询保留各次完整有效区间、内容、替代/删除关系和确切来源身份。日常查询按服务端D与当前已记录信息；具体历史记录按selectedRecordId及确切sourceVersion读取；旧版已删除内容可作为受限历史证据读取，并标出历史属性，不表示现在仍可用。默认读取当前来源；不接受 knownAt 或记录时间截点。不存在版本、未知参数（包括adoptedRef）、未接入消费者、无法读取的证据分别给出结果，不统一当空值或最新值。

变更日志只读，解释谁在何时以何种操作类型、操作原因及记录处理改变了哪些事实；本次普通更正/改日/删除动作与目标原业务分类分别呈现，分类表示被处理的业务事实，不表示另办一次该业务；日志不替代完整历史读取。来源历史及旧版本视图不提供直接办理，返回当前版本后重新检查可办动作。

<a id="m02-br-010"></a>
### 4.10 M02-BR-010 当前授权与信息边界

每次读取和写入按当前身份、企业/对象范围、动作及字段权限判断。已存结果的查回/同内容重放按本人提交归属、当前对象/历史及字段读取权授权，撤销原写权不阻断读取；无终态且将执行业务的重试仍须完整当前写权。历史allow、旧页面或知道标识均不是当前许可。查询者不能通过直接调用写接口产生新事实。预览和按钮仅反映当时判断，提交重新核验；固定两条操作分别核验各自类别权限，分类改型需原/新类别专用权。普通资料权不自动包含生命周期权；首条及停用/重新启用记录维护按013的目标类别授权。

授权服务/必要决策不可用时不放行；权限被收回后不继续展示缓存中的受限正文。无权对象不泄露名称、计数、历史及冲突引用详情；有办理权但看不到依赖详情时可说明存在受限依赖，不以泄露详情换取可操作性。

按128，X03负责每次受保护访问的当前主体、目标、动作及字段判定，不永久保存完整输入、Grant集合和匹配过程。成功业务保存保留M02自有来源、操作者和原结果，不依赖X03历史判定；必要安全事件只记录真实事件所需最小事实。新访问及原结果查回仍核验当前权限，不新增授权审计平台或业务表单步骤。

<a id="m02-br-011"></a>
### 4.11 M02-BR-011 实际引用范围与共同守卫

013列出实际BU引用写入口、日期/来源及共同守卫。本版只有企业归属、BU内部记录和来源约束；M03/M04尚未接入，不制造恒为空服务证明全域无引用。

| 引用类别 | 修改时的规则 |
| --- | --- |
| 不可变来源、adoptedRef、审计或原业务快照 | 保持原身份、版本及答案；仅存在这些历史证据不阻断当前来源修订，不自动重新采用或重算 |
| 要求某日或一段期间BU有效/启用的真实业务引用 | 按其公开准入合同验证原新来源全部差异区间，含过去、今日、未来、首条NO_FACT及多次启停边界；不满足则拒绝，由消费者显式处理后再核验 |
| 已声明必要依赖不可用、版本失配或覆盖未知 | 拒绝受影响写入，不能把未知当无引用；根本未接入的消费者不按依赖故障处理 |

固定启停期间办理以最终候选与原来源的全部差异区间核验引用，不把未提交的中间区间当作事实。预览后的新引用与新增/更正/删除/改日/停用/重新启用/固定启停期间办理共享守卫，冲突不能双方提交后异步修复。未来计划引用也按其实际日期核验，不只查D或目标新日。引用的字段冻结要求由所属消费者公开合同明确，不能以“引用”一词一概封锁全部名称纠错。

重新启用只恢复BU相应业务期间的资格，不自动恢复任职、岗位、权限、默认设置或原采用。消费者接入前补齐引用准入、同事务竞争及该域验收；替身只证明合同分支，未接入范围不能计跨域保护通过。

<a id="m02-br-012"></a>
### 4.12 M02-BR-012 同次提交、重试与结果未知

固定启停期间办理的提交标识绑定完整项集合、各项目标/版本及显式分类变化；项顺序不表示执行顺序，013规定规范化摘要。整笔只返回一个终态，不按项分别重试。每次保存具有稳定提交标识并绑定调用主体、作用域、记录处理、目标记录/版本、生效日期及完整业务内容；新建、资料变更、停用、重新启用还绑定本次提交的业务类型和原因。更正记录未编辑分类时不提交分类，仅日期API及删除继承原分类，由服务端从准确目标修订继承并固化，目标或修订变化不能只换令牌继续提交。同标识同内容的重试返回原已提交结果，不再新增身份、记录、来源版本、成功审计或事件；同标识不同内容明确拒绝。更改输入、确认了新的事实版本或另办动作时使用新的提交标识，不能修改旧请求的含义。

提交超时或连接中断不能直接认定失败：先按原提交标识查询或重试，未查明时显示待确认，不以新标识重建对象。回读或重试仍检查当前授权，无权时不返回原敏感内容。实际事务回滚与已提交但响应丢失分开处理；幂等不是允许旧版本覆盖新事实。

一个尝试已回滚，不代表相同提交身份最终未保存；精确重试与显式查回以已持久化的唯一终态为准。可恢复拒绝在原提交锁内保存，整笔事务结束后不另起事务补写拒绝；事务失效、取消或COMMIT未知保持待确认。原拒绝保存安全的项/字段定位及原请求依据，刷新失去正文、项重排或来源推进后仍解释原拒绝，不重验当前资料、不持久恢复表单值。当前读取权限收窄时保护受限诊断；仅撤写权不阻断原终态，结果暂不可读时保留提交引用。

<a id="m02-br-013"></a>
### 4.13 M02-BR-013 并发冲突与重新核对

固定启停期间办理只使用一个基准来源；任一目标修订或当前来源失效，全部拒绝并保留仍有权查看的输入。两个独立命令基于同一 BU 版本修改时，成功者推进版本；后提交者若依据已失效则整笔拒绝。不得仅刷新版本令牌、自动覆盖他人字段或将两份全表单直接合并。页面保留仍有权查看的输入，展示最新事实与冲突，管理员重新核对后才能另次提交。

不同 BU 的无关更改不因全局 DemoState 摘要变化而互相阻断；真正共享的编码唯一性、企业或引用条件仍须共同守卫。同日新增、同编码创建及删除与引用竞争均有明确胜负和拒绝结果，不能双方成功后再异步修补。

<a id="m02-br-014"></a>
### 4.14 M02-BR-014 成功事实、审计及源事件的原子保存

固定启停期间办理只生成一个完整新来源、一份汇总成功审计和一个Outbox事件，逐项前后目标及派生期间变化可追溯；任何一项失败全部回滚。一次成功写入的 BU 事实、修订/完整期间、操作类型/原因代码与名称快照、记录处理、成功审计、必要源事件/Outbox 及幂等结果必须一致提交；失败回滚不留下部分成功业务事实。拒绝或技术失败的诊断可独立留存，但不得伪装成功审计或新来源版本。服务重启后仍可按同一身份和确切版本查询。

业务拒绝、技术故障、取消或执行超限均不得遗留新记录身份或部分时间线；失败诊断只有按提交协议确定持久化才可对外称为终态。技术时限不改变业务合法性，也不允许将一笔固定配对请求拆成多笔部分成功。程序和存储不匹配时关闭业务接入，保留原事实及待确认提交，恢复匹配后再读取；不能用缺失结果或格式无法解析证明未保存。

本批只交付源事件落库、保留和核验查询，不处理真实投递/Inbox/采用，不建设投递监控页面。无消费者时如实标识未接入/未投递；保存、日期生效、通知到达和消费者采用是不同事实。已保留的旧来源版本及删除关系不能为腾出事件队列而删除；本批不提供历史清理操作。

### 4.15 M02-BR-015 保存定位、返回与取消编辑

固定启停期间办理保存后定位结果汇总和用户选中的实际变更项，支持逐项跳转，不伪造单一目标。保存后定位实际保存记录或明确的删除结果；改日按同一记录身份定位新日期，旧来源链接仍使用原日期；未来资料不能自动跳回今日而让用户误以为保存丢失。列表到详情保留筛选、排序、页码、页大小和选中对象；返回恢复原条件，若数据变化导致原页已不存在则回到有效页并说明，不能空白卡死或悄悄清空条件。

### 4.17 M02-BR-017 已保存记录改日

生效日期在“更正记录”内编辑，默认目标原日，可与获权名称/分类一次保存。以前一条P和后一条N在基准来源的原位置为界：P＜新日期＜N，原日期允许保留；首条下界为企业有效起点，末条上界开放。没有其他合法日期时日期只读，其他获权字段仍可办理。手填和直接调用均由Go重新验证，不允许借普通更正跨节点或交换顺序。

### 4.18 M02-BR-018 重新启用与完整时间线不变量

每次写入从当前来源构造完整候选集合，按日期扫描：

| 前状态 | 记录业务类型 | 后状态及资料 |
| --- | --- | --- |
| NO_FACT | CREATE，仅固定首条 | ACTIVE；保存首条完整资料 |
| ACTIVE | CHANGE | ACTIVE；保存本段明确资料 |
| ACTIVE | DEACTIVATE | INACTIVE；继承最近明确资料 |
| INACTIVE | REACTIVATE | ACTIVE；确认并保存独立完整资料快照 |

其他转换均拒绝，NO_FACT只用于首条之前的读取，不持久化为停用。每个业务日最多一条记录，多次启停严格交替；同日停用再启用、重复停用/启用、停用期间CHANGE均拒绝。任何新增、字段更正、删除或改日都须通过该不变量和全期间引用校验，不使用当前active布尔值作为全部判断。

重新启用沿用BU身份/编码/首条，形成新的recordId，业务类型REACTIVATE、记录处理ADD；日期允许过去/当天/未来，目标日期前必须INACTIVE。今日启用但已排未来停用时，仍可在其后安排未来重新启用。单条重新启用仅在选中当前末条且该条生效后为INACTIVE时开放，绑定该末条并限制日期晚于末条；默认日同BR008。表单进入即从末条停用所继承的准确资料带出名称，允许确认或按字段权限调整；同日所需名称变化合并在重新启用内，不另加同日CHANGE。保存后该快照独立，之后更正前序资料不会自动覆盖；更正恢复记录自身名称仍按BR006办理。

完整时间线验证不等于允许级联修复；单条请求引发后继非法即拒绝并说明准确依赖。显式分类纠错及有限固定启停期间办理由BR019—021补充，同日序号和消费者自动恢复仍不在范围。删除和改日的分类继承及历史保护仍按BR007/BR017；重新启用不作为删除停用的别名。

### 4.19 M02-BR-019 固定启停期间维护

只提供“插入停用与重新启用”和“删除停用与重新启用”。插入以所选当前记录为左界L、紧邻后继为右界R，所选后须启用；两新日满足L＜S＜A＜R，无R仍受企业范围及日期类型上界约束。默认空档最早两个合法日；不足两个合法日只禁用入口，不加说明。原因分别选择且初始为空，类型由Go固定，不提供类型和名称编辑。停用继承前序，恢复按停用前资料保存独立快照，名称相同也保存真实状态变化。

删除按当前来源相邻DEACTIVATE/REACTIVATE配对，不要求原本同次创建、不增加配对编号；可从任一条进入，缺完整配对不提供入口，合法单条删除照常。确认仅列两条日期/类型及实际可读资料变化，不提供保留名称、转换分类或补建资料开关。删除衔接期间并正常重算停用继承，可能产生派生修订；后继独立快照及旧来源保持。真实资料变更须另次普通办理，不承诺两次间回滚或隐藏中间结果。

Go分别核验插入所需停用/恢复权，删除所需两类别删除权，以及完整来源、准确目标/修订、日期、全候选和真实引用；不增加通用入口权。固定两条同一事务、一个来源/日志汇总/事件和提交结果，失败无部分事实，未知结果按原身份恢复。

通用联合页面、任意items写请求及对应公开预览退出。单条名称/日期/分类组合更正、首条两步维护继续；非法单条正常拒绝，不自动加入关联项或提供隐藏通用入口。过去的通用来源、原件、日志与既存终态继续按当前读权查询；退出能力的案例保留编号并注明退役。

### 4.20 M02-BR-020 首条资料维护与起点保护

首条前移及名称变化直接按BR006/BR017更正记录处理，保留first_record_id与CREATE类型，日期不得早于企业起点且必须仍最早；旧落点随原首条移走，不自动在原日期复制资料，不询问是否保留原日期资料。原6月1日B可一次更正为1月1日A。

### 4.21 M02-BR-021 显式业务分类纠错

业务分类在“更正记录”内只呈现一组“操作类型/操作原因”，默认保留原值；固定类型及无修改权但有读权的字段只读，无读权的字段不显示，不额外列原分类或使用原/新字段标签。由用户明确选择修改，不根据名称或日期自动匹配分类。单条使用CORRECT，多目标关联纠错退出，非法单条不再转通用办理，不增加业务操作类型。首条只能在CREATE内更正原因；非首条可在CHANGE、DEACTIVATE、REACTIVATE之间更正类型及对应原因。只对同一条与日期/名称组合更正，不同时修改其他记录；保留目标recordId，最终时间线和原/新类别权限均须通过。

新分类代码及名称快照由Go按当前适用目录校验并固化，旧分类及名称留在旧修订；未更改分类仍继承准确目标，不因旧原因下架阻断。未明确修改分类时名称/日期更正仍不回传分类；删除禁止提交分类，不新增处理原因、备注或说明字段。显式提交同一分类也不刷新已保存名称快照；只有真实代码变化才形成分类差异。

有效类型从所选不可变修订读取，记录的初始kind不再决定后来修订的解释。最终DEACTIVATE只继承最终前序资料，不接受同时提交名称变化；原DEACTIVATE改为CHANGE/REACTIVATE时默认取原目标在基准来源的解析资料，允许明确调整后保存独立快照。无论是否跨类型，未指定后继普通/重新启用字段都不传播；分类纠错不能借类型变化释放编码、修改首条指针或绕过字段和日期权限。

<a id="m02-br-022"></a>
### 4.22 M02-BR-022 完整授权查询结果选择

选择全集U为当前实例和企业中，按服务端D、q、status及单列条件解析，并依当前主体对象和字段读权过滤的完整列表结果。分页和排序不改变U；U的每个成员是一个稳定BU身份，不是生效记录、来源或历史修订。查询沿用BR009/010，不能因全选扩大字段搜索权、绕过授权或将分页上限作为全选总量上限。

逐项选择集合为显式ID集合；全部结果选择集合为U减去显式排除ID。两者均可跨页；点击表头全选直接选U，取消全选清空全部选择，部分选择时表头为半选。排除行重新勾选后从排除集合移除；U为空时全选不可用。数量以服务端对同一授权集合的核对结果为准，不能从当前页勾选数量推断全局数量。

翻页、改页大小、仅改变排序、列显隐/宽度和响应式布局保留选择；应用后的实际查询谓词变更清空。保持012的A/D合同：排序若同时应用了不同搜索草稿，就属于谓词变更；仅编辑或取消草稿不清空。离开、刷新、历史导航重新进入、退出/换账号清空；新标签打开名称链接保留原标签选择。详情返回高亮与勾选集合独立。

同一谓词下，成员、来源资料或读取授权发生变化也不能静默更新旧选择。以服务端集合版本发现变化后，清除旧选择和数量，重新读取当前授权列表，提示“列表已变化，请重新选择”；用户明确重选后才可继续。请求失败不保留旧数量冒充核对成功；无权时清除受限结果，旧响应不得恢复选择。集合版本不是读取旧快照或获取权限的凭证。

<a id="m02-br-023"></a>
### 4.23 M02-BR-023 导出所选与字段保护

首个选择消费动作仅为CSV“导出所选”；全选后使用同一动作导出全部查询结果，不增加重复的导出当前结果入口。选择仅需bu.read；导出必须逐对象同时具备当前bu.read和独立bu.export，选中全部可读结果不能缩减成可导出子集。缺任一所选对象导出权整次安全拒绝，不提供失权对象身份或部分文件。固定角色名、创建或维护权不代替导出授权。

CSV固定为编码、名称、状态、生效日期四列，值与该businessAt下当前获权列表投影一致；无权字段为空，不导出隐藏在DTO、详情、历史或缓存中的值。列显隐属于展示偏好，不授予读权，也不改变固定导出字段集合。日期按026的YYYY-MM-DD，状态包含启用、停用、未生效；不输出内部ID、版本、原因、负责人、人数或其他域字段。

导出前在同一一致读取中重新核对查询、集合版本、所选数量、对象/字段读权及bu.export；来源资料变化即使成员和数量不变也拒绝旧版本，要求重选。校验和完整生成失败不输出CSV，不以截断、跳过失权行或部分成功代替全量。内容按013转义及中和电子表格公式。选择与导出不写组织业务事实、来源、事件/Outbox、原采用或命令幂等结果；已有安全审计职责保持。

<a id="m02-br-034"></a>
### 4.24 M02-BR-034 记录级操作摘要与身份归因

基本资料底部默认显示所选生效记录的**当前展示业务资料修订**对应操作者及形成时刻。日常查询取当前修订，来源模式取该来源成员引用的修订；不得用整个BU的最新操作者、最新日志、页面打开时刻或当前登录者替代。另一条未来记录被维护而本条修订未变时摘要不变；派生期间修订归因实际形成该修订的操作，并在日志中区分直接/派生变化。删除前来源＋原记录和删除来源＋被删记录两类原件入口，均显示删除前业务修订的摘要；后者的删除证据定位仍保留，不能把删除者显示为原资料操作者。固定两条删除逐项取各自原修订，不能统一取删除前来源的操作者；删除者属于删除操作。

摘要是否显示由有无所选记录决定，不由今日是否有适用事实决定。按123默认选中未来首条时，仍展示该记录的资料和摘要；日期获权时显示尚未生效。确实没有所选记录则不编造摘要，显式记录缺失不自动换到首条或今日记录。字段失权不会将已有记录变为空记录，也不能据摘要泄露受限日期。

新成功操作从X03权威身份取得主体标识、姓名（可空）、账号及主体类别，并与来源事实原子封存最小身份快照。名称、账号后续变更或停用不改历史；必要身份读取失败整次写入失败，合法主体没有可选姓名不构成失败。旧封口来源仅有主体标识时，如实显示“操作者标识”，不得从当前账号资料补造历史姓名或账号。前端无权提交或覆盖身份。具体字段及缺失表达见[013](013-m02-technical-design.md#m02-tech-operation-summary)。

基本读取权允许读取这一最小操作摘要，不以`bu.history.read`或写权为前置；姓名/账号展示指操作身份，不意味着可以查询人员档案或其他操作历史。对象失权立即清除摘要；字段部分可读仍可读摘要，但不得由摘要夹带受限业务字段。记录时间按026显示北京时间并保留原始时刻。无变化、取消、失败和任何只读查询不改变摘要或生成成功日志。

<a id="m02-br-035"></a>
### 4.25 M02-BR-035 操作分组日志、筛选及确切查看

有当前对象读权和历史读取权的人员，按一次已保存操作阅读一组日志，直接看到记录时间、操作者、记录处理、涉及记录及获权字段前后值。多字段、多记录和固定启停两条均不能拆成多次成功保存；分页和总数按操作计，完整子项跟随操作。显示保存时分类名称，不用当前目录标签覆盖历史；新增的旧值为“未登记”，合法空英文名为“未提供”，无字段读权则省略该字段，三者不能混用。

日志同时返回操作前/后准确修订的获权记录上下文，包含展示生效记录和保存时分类所需的未变化字段；不能只返回差异再由前端逐行补查或借用当前资料。上下文中字段存在不等于发生变化，不计入字段筛选或差异数。

筛选复用当前表格单列条件及应用/取消/清除交互。Go先对当前对象/字段权限裁剪，再按013的字段目录、单列谓词和稳定来源上界计算全部操作的匹配、总数及页；不在已加载页内过滤，不因隐藏字段命中或差异条数泄露受限事实。命中一个子项后保留该操作的全部可读子项，不能拆散一次保存。并发新增只在当前日志刷新后纳入新上界，每次读取仍重新授权，旧上界不是授权令牌。

当前日志与指定来源下的历史日志须在请求中明确区分；历史上下文来源限定日志范围，分页上界不能越过它。刷新历史日志仍停留该上下文，只有明确返回当前资料才解除历史范围；前后导航须同时保留原上下文和分页上界，不能仅保留页码。

基本资料和日志正文取消大块“来源说明”。基本资料保留最小操作摘要；日志“查看”列提供当次资料、删除前原件、删除后版本及行内来源明细。普通资料定位该次准确来源及记录；删除前原件定位前来源/原记录，删除后版本定位删除后来源的时间线及服务端D默认记录，不携带被删记录ID，不能仍显示被删原件。删除后来源今日无适用事实但存在未来首条时，仍展示该首条、准确摘要及获权的尚未生效提示，不能误显示无资料。来源明细只补充标识、原始时刻和前后关系，不把主要前后值藏进展开区。多目标操作按项提供准确原件链接，来源明细每项操作只提供一次。

所有来源链接和直达API按当前历史/对象/字段权限检查；不存在、跨BU、跨实例或失权来源不替换最新结果、不恢复旧缓存。链接支持新标签打开；返回保留页面上下文。只读历史模式及返回当前资料仍遵守BR009/010/015，不增加恢复旧版本、恢复删除或删除审计能力。

### 5.3 M02-AC-002 创建身份与输入拒绝

### 5.4 M02-AC-003 过去、当天及未来新增与边界保持

给定首条为 11 月 1 日名称 A，自 12 月 1 日起已登记名称 C。在独立样本中分别令提交时 D 为 11 月 10 日、11 月 15 日和 11 月 20 日，选择11月1日记录为插入位置，新增 11 月 15 日名称 B：分别为未来插入、当天新增和过去补登记，三者均允许。新来源查询 11 月 14 日为 A、11 月 15 日至 11 月 30 日为 B、12 月 1 日为 C，C 的记录标识和内容不变；旧 sourceVersion 查询 11 月 20 日仍为 A。记录时间保留真实保存时间。保存后选中B，服务端D期保持，分别提示未来生效、当天生效或过去补登记，保留原列表条件。

再以 D＝11 月 20 日、首条 11 月 1 日 A、后继 11 月 18 日 C 的独立样本补登记 11 月 15 日 B：新来源仅在 11 月 15—17 日返回 B，今日仍为 C；没有后继时，过去追加 B 的区间开放至末尾，今日读取 B。不得自动覆盖后继或把补登记日期当作记录时间。旧来源、原采用引用或快照及消费者业务结果保持；当前无真实消费者，消费者保护不得用替身计为已通过。

重复已占日期、首条当日或之前、企业范围外、停用期间、启停日期同日占用、过期来源及实际引用冲突均拒绝；拒绝时保留仍有权查看的输入且无新业务版本。无实际变化返回无变更。新增的过去记录可按独立规则删除或改日，首条保护保持；普通更正保留原身份及旧来源，日期/分类未编辑时保持原值，显式变化按BR006/017/021；当前只读或无新增授权的主体不能借历史日期越权。

另以受控日期验证跨午夜：预览时 D＝11 月 14 日、生效日为11月15日，未接受的请求在等待后 D 已到11月15日，其他依据仍合法则允许；日期场景按实际接受时说明，另以11月16日验证过去日期仍允许；已在11月14日成功接受的提交，在11月15日或以后精确重试仍返回原结果，只保留一次事实和原办理说明，不按重试日期改成补登记。

### 5.5 M02-AC-004 更正保留原日和历史

在 T1 已有 11 月 15 日名称 B 的记录，T2 把错字更正为 B2；记录标识及生效日不变，按当前已记录信息查询该区间返回 B2，T1 的 sourceVersion 仍读 B，12 月 1 日独立记录 C 不被更正。改编码或直接改状态时整笔拒绝；日期/分类显式变化可按AC031及各面权限同笔办理。旧来源版本视图不能直接保存。

原业务类型为资料变更、原业务原因为名称变更；T2 的记录处理为更正，无更正原因输入也能保存，分类与名称快照由目标最新修订继承。日志显示更正、操作者、时间、目标及前后差异；T1 原件保持。更正请求以顶层类型、原因或另设处理原因回传时拒绝，包括照抄只读原分类。

### 5.6 M02-AC-005 删除已生效及未来记录与首条保护

对A→11月15日B→12月1日C的独立样本，分别在D＝11月10日、11月15日、11月20日和12月10日删除B，均应允许：新来源11月20日返回A、12月1日仍为C，旧来源仍读B，后继身份及内容不变。原首条无论唯一/有后继、未来/已生效均拒绝删除，编码不释放；跨午夜不单独改变删除资格。

删除只读展示目标日期和原业务分类，不输入类型、原因或处理原因；继承最新修订快照。额外字段、已删除目标、旧修订、越权、真实引用冲突及必要依赖故障拒绝，无部分事实。删除后同日新增使用新身份并遵守新增日期规则；旧结果精确重试仍返回原删除结果，不能重复删除或改写原件。

<a id="m02-ac-006"></a>
### 5.7 M02-AC-006 停用冲突与停用记录处理

### 5.14 M02-AC-013 分类、原因与历史解释

另一会话先更正目标后，旧删除、改日或更正请求必须因目标版本过期而拒绝，重新读取并核对后才能重新办理；若目标分类证据缺失则明确拒绝，不以当前选项补造。全部场景仍执行当前授权和现行日期、引用守卫；本节当前执行参数见T05/T06/T08、104/105/107及对应补验，未接消费者另保留边界。

先实际建立1月CREATE A→3月CHANGE B→5月停用B→7月重新启用B，再更正首条为B，取得合法基准T1；此时1月、3月资料已同值，既有3月记录仍保留。删除3月记录得到T2：1—4月启用B、5—6月停用B、7月起启用B。业务值差异为空，但首条期间延长、3月删除、5月停用继承关系变化必须留证；停用日期/区间/名称不变仍追加新修订，指向最终首条的新修订。7月独立恢复修订可复用；T1停用仍指原3月修订。不能因字段同值复用失配的停用修订。

以T1另作独立分支，仅把3月记录改到4月：其身份不变但修订变化，5月停用也必须改指最终4月准确修订，业务值差异仍为空；直接改日、前序区间及停用继承变化分别列入结构影响。上述删除/改日各以当前单条入口复验，均为accepted并产生一个事件，不误判整笔no_change。

固定插入/删除的状态变化、资料变化和必要派生影响同样核对准确区间与结构引用；首条仅改合法原因允许数据差异为空、分类结构差异非空。旧通用来源可能含不相邻资料变化区间，其原事件仍按原件解析；不为构造新分离区间提供多条编排写入。真实消费者未接，不冒充跨域引用验收。

### 5.26 M02-AC-025 失败不得遗留记录身份或部分时间线

有权管理员从“设置 → 组织配置 → 业务单元 → BU详情”联合补入3月资料并更正6月资料，原来源为“1月首条A→6月B→10月C”，最终候选合法。在已为3月分配并写入新记录身份、但尚未完成来源时注入一次业务409，拒绝后当前头、全部旧来源及身份集合均与办理前一致；不能只比较列表看不见新记录就计通过。分别在来源、修订/成员、逐项明细、审计、事件、结果及头指针写入阶段注入技术失败或取消，也不得留下半份业务事实。

### 5.27 M02-AC-026 回滚、重试和查回竞争的唯一结果

同一固定配对请求建立A/B两次传输及一次显式resolve，以屏障验证三个顺序。第一组A遇可恢复业务拒绝，仅回滚业务savepoint，在原外层提交锁内保存rejected；B及resolve等待该锁，提交后均回原拒绝。第二组A发生技术故障、整笔事务确认回滚，只返回待确认；B原身份原内容重新授权并成功，随后resolve读accepted。第三组A整笔回滚后resolve先封闭not_applied，迟到B不能执行业务。A在后两组均不另开事务补拒绝。

每组只有一个终态，成功组只有一份来源/事件。迟到的未知反馈不覆盖已确认状态。另验原拒绝COMMIT失败、B异内容、resolve撤读取权或存储超时，分别保持待确认、拒绝错配、保护受限信息；只按实际持久终态给出确定响应。引用替身只证明合同，不计真实消费者验收。

### 5.28 M02-AC-027 拒绝诊断在失去正文后保持

查回按当前对象/历史/字段读权裁剪；撤写权仍可读取，撤对象或历史读权安全拒绝。缺失/损坏结果保持引用并安全失败，不猜未提交。旧通用诊断按原件只读核验，不作为新编排入口。

### 5.29 M02-AC-028 长时间线、执行超限和取消

对长当前时间线只更正一个字段，请求正文仍小于预算；分别使候选扫描超时、多条SQL各未超局部上限但累计超限、等待锁时取消。按013测量从取消发起到本地计算停止的最大延迟及独立清理时间，观察DB锁释放和连接回收。排序先采用标准实现，按实测预算判断，不以采用自定义排序作为通过条件。规则与技术注入在主要层执行，正常菜单代表反馈按023补充验证；无部分事实，不拆笔或跳过后继校验，断网时仅报告可观察的清理状态。

## 7 R129关系影响分类

在原动作、字段、来源、修订、日期和分类检查成立后，BU候选的完整启用覆盖不变，可不遍历与变化无关的部门资格；不能仅凭请求名称、今日状态或记录数量认定。覆盖变化继续检查所有当前和未来依赖，未知或缺失事实不当作无依赖。无变化合法提交没有新业务来源，非法或过期输入仍拒绝。原因唯一默认及保存后本地清理边界遵循117和012，不改变历史原因与原提交终态。
