## 1 业务目标与边界

管理员从应用菜单→部门进入列表，直接创建、查询和维护部门；查询者在当前授权下读取当前/历史资料。复用BU现行按日维护、来源与可靠提交规则，同时交付必填单值BU归属、最小行政上级与部门路径。BU与部门业务表组独立；不支持同一部门跨BU使用、组织树工作台、整树搬迁、负责人/人数、审批、英文名称及M03/M04真实消费者。

编制后台接入时，M02 向 M03 提供企业内部门身份及有效期。部门首日后移和启停经公开端口核对受影响的额度日期与分配。部门核定总额与岗位定额均由 M03 维护。[313 日期与归属](../m03/313-position-capacity-contract.md#m03-br-026)

## 2 角色、前置与术语

企业组织管理员可按明确授权维护全企业范围；BU组织维护者只处理所授BU内部门，跨BU归属须有原、新BU授权及专门归属调整权。查询、历史、审计、引用和导出分别授予；角色名本身不放权。R0合同及检查由本工作树主代理承担，后续同一工作树实施/验证维护角色负责；具体人工验收者未指派，不虚构人工批准。

企业受控上下文、当前身份和当前模型存储是前置。代码、日期、来源及分类用语沿[011术语](011-m02-business-requirements.md)和117；完整日期为YYYY-MM-DD。当前“状态”含义保持；“未生效”是服务端D早于首条的读取结果。上级边归Hierarchy，部门路径是从真实根部门到本部门的派生名称路径，不隐式拼接企业名称。

## 3 业务流程

<a id="m02-scn-019"></a>
### 3.1 M02-SCN-019 创建根部门与下级部门

获权管理员从部门列表新建，在已启用BU下建立根部门“组织效能中心”，再在同BU建立“组织发展部”并选前者为上级。填写名称/编码、生效日期与新设组织原因，简称可空；根部门上级默认企业。每次保存形成各自身份、固定首条及不可变来源；详情分别显示“高谷集团 / 组织效能中心”和“高谷集团 / 组织效能中心 / 组织发展部”。企业及BU头不因部门创建推进。编码冲突、无权、日期不覆盖或不合格上级整笔拒绝，不留孤立关系。

<a id="m02-scn-020"></a>
### 3.2 M02-SCN-020 同日资料更改与修订

管理员从详情选位置新增/插入，一次修改名称、简称、BU或上级等获权面，选适用原因，形成当日唯一部门事件。该日已有事件则不允许再新增；更正原事件形成新修订、旧来源可读。停用资料继承、恢复独立快照及固定启停两条均沿共用语义；不能以同日第二事件或自由状态开关绕过。

<a id="m02-scn-021"></a>
### 3.3 M02-SCN-021 变更归属BU与上级

有原/新范围及归属调整权的管理员，从新增记录或更正记录修改归属，编码和部门身份不变。新BU必须在相应启用期间启用；上级须同新BU，根部门可直接归企业。若现有下级仍在旧BU且需要当前关系，整笔拒绝；先逐个合法调整下级或上级，再办理本对象，不自动迁移人员或整树。保存后按实际记录定位，保留原来源和原路径。

仅有停用下级不自动阻断父部门后续转BU，但须检查其所有未来启用安排。子部门C于2026-06-01停用、无后续恢复时，原父P可从2026-07-01合法转BU；C仍保留原关系供历史读取。C以后恢复时原上级若已不同BU，表单保留默认关系并明确不合格，由用户选择合格上级/企业根或经授权转BU，不静默搬迁。

<a id="m02-scn-022"></a>
### 3.4 M02-SCN-022 查看当前及旧来源路径

查询者从正常列表进入子部门，按所选记录适用期间及来源读取分段路径。祖先更名/合法改上级后，当前路径相应变化；子部门源头、修订及业务事件数不变。按子部门确切旧来源查看时，显示当次已知的封存路径证据，不用今天祖先名称覆盖。任一必要路径名称失读权时整条路径受限，不能截断伪装为根部门，也不泄露受限节点。

当前资料在停用期间仍显示“部门路径”，取对应停用日前一日并使用各对象最新来源。例如先安排2026-08-01停用，随后祖先安排2026-07-01更名，停用后当前详情按2026-07-31读取新名称；最初停用来源仍显示当时已知名称。对停用前历史的合法更正可更新当前路径解释，旧来源不变；首条前没有今日有效路径，可展示首日安排路径，未生效信息由独立状态字段表达。

<a id="m02-scn-023"></a>
### 3.5 M02-SCN-023 启停及BU反向资格

管理员按当前能力办理部门单条或固定启停；BU管理员从BU入口停用、更正、改日或删除相关记录。双方检查全部受影响期间及最终候选：启用部门要求启用BU和启用行政上级。部门和BU可同日停用，停用部门的历史BU引用不阻断；删除部门停用记录若使其在BU停用期恢复启用则拒绝。任意一条非法整笔不保存，旧采用保持。

<a id="m02-scn-024"></a>
### 3.6 M02-SCN-024 权限、引用与导出

查询者只能读取所授部门及字段；引用选择仅给BU/上级的最小获权名称和编码，不据此开放完整详情。列表跨页选择及导出只消费当前授权结果，导出另需专门权。撤权、归属调整或祖先变更使选择依据失效时重新核对；不得从缓存/路径/CSV泄露旧授权内容。

<a id="m02-scn-025"></a>
### 3.7 M02-SCN-025 未明结果、重试与查回

保存丢响应后保留对象类型命名空间中的最小引用；刷新、重开或原内容重试均查原提交。BU和部门相同文本submissionId互不读取、封闭或跳转；各写自己终态表。仅撤写权仍可读取获权原结果；失读权清正文但保留引用。无终态的显式resolve在同一锁下封闭，迟到原请求不能再成功。

执行日为2026-11-04、仅获BU_A范围相应创建/读取/历史读取权的管理员，从部门菜单新建2027-01-01生效部门。创建后凭首条BU_A判定当前权限，可进入详情及查回原提交，今日仍未生效且没有有效父边。首条只改日不改变同一BU的授权归属；首条BU纠错为BU_B须先核原/新范围与归属权，成功后立即按BU_B授权。已有部门未来从A转B则在转入日才按B范围判断，所选记录或旧来源不能提前获得权限。

<a id="m02-scn-026"></a>
### 3.8 M02-SCN-026 日期段循环及并发维护

管理员试图让A归B、B又归A，或两个操作分别造成未来某段循环，Go按全部日期边界拒绝。并发更名、改上级、换BU与BU停用按同一守卫及锁序重读；覆盖无既有下级到新增下级/引用的竞争。任一事务失败不得留下半条关系或不一致路径证据。

## 4 业务规则

<a id="m02-br-024"></a>
### 4.1 M02-BR-024 身份与唯一管理归属

部门稳定身份、首条身份与编码不随BU或名称变化。编码沿BU相同字符准入及规范化比较规则，在实例/企业内部门身份集合唯一，同名允许；创建后本批不办理编码纠错或回收。有效部门资料含且仅含一个真实管理BU，一个BU允许多个部门。不得增加同部门跨BU使用标记或集合。

<a id="m02-br-025"></a>
### 4.2 M02-BR-025 共用按日及生命周期

日期、首条、位置新增/插入、统一更正、分类删除、原相邻位置改日、继承及恢复独立快照引用011现行规则，范围以109为准。同对象同日最多一条当前事件；普通更正不创造第二事件，修订/审计不计同日业务事件。更正不传播后继独立资料，停用继承准确前序资料及修订；恢复确认完整独立资料。首条不能删除，之前无事实。

<a id="m02-br-026"></a>
### 4.3 M02-BR-026 资料及分类

主名称必填，简称选填并与名称采用相同NFC/安全字符/长度及显式清空规则；简称不作为身份或唯一键。英文名/英文简称、负责人及人数不纳入。目标目录由117唯一持有，显示数据更改而技术码仍CHANGE；新增CHANGE调整上级或BU时用变更归属组织原因。普通更正/改日/删除按准确目标继承原分类，首条归属纠错保持CREATE及原原因；恢复可调整获权完整资料，仍为REACTIVATE及恢复原因。显式分类纠错另核类别/字段权，旧分类名称不被新目录改写。

<a id="m02-br-027"></a>
### 4.4 M02-BR-027 全期间资格

对最终候选中每段启用资料验证企业、BU及行政上级的存在和启用覆盖，覆盖过去/当天/未来及原、新差异段。停用资料保留的关系只是历史资料；重新启用须重检。新建开放启用部门若遇BU或上级已安排未来永久停用，因无法完整覆盖而拒绝，不自动缩短部门期间或改动对方安排。必要依赖或覆盖未知拒绝受影响写入，禁止用空服务声称无引用。旧封存证据不因存在一概阻断，也不自动更新。

停用、恢复、删除/改日停用记录及固定两条先形成合法生命周期，再计算最终父边和双向资格；任一非法整笔拒绝，不留部分业务事实。停用后移须检查延长的启用期，前移须检查减少的覆盖是否仍被下级依赖；删除停用记录如果留下无停用前提的恢复，沿共用规则拒绝，不自动删除恢复。父部门资格维护检查全部启用下级期间，包括当前停用但已有未来恢复的安排。

<a id="m02-br-028"></a>
### 4.5 M02-BR-028 行政关系及路径

Hierarchy拥有有效父边，每部门在每个启用日恰有一个行政上级，停用期间及首条前无有效父边；根部门直接归企业，有效父子同企业且同BU。未来有效区间可提前保存；所有日期段均拒绝自指、循环或缺少上级启用事实。停用资料继承准确历史成员引用，该引用保持可追溯，但不要求旧成员继续覆盖停用期间。恢复在完整资料确认后建立新的有效父边，不把旧引用直接当作合格证明。

父边在停用日S结束，恢复日R重新开始，停用区间为[S,R)。关系期间/成员引用重算形成必要的派生修订，但不覆盖后继独立资料、不新增同日事件、不产生另一次用户办理。路径由Go解析真实祖先部门/本部门名称并用` / `连接；不是可编辑字段或浏览器算法，读取口径由BR029规定。

<a id="m02-br-029"></a>
### 4.6 M02-BR-029 路径来源与修订

本部门上级变更作为本次唯一事件的一部分，与本部门Hierarchy关系来源原子保存；部门修订只采用不可变关系引用，不维护第二份当前父边。关系来源只包含本部门关系时间线；同BU无关部门调整不推进本部门关系来源，不要求用户提供整树版本或因此重新确认。祖先更名/改上级只改变派生当前路径，不改写后代来源/记录或增加后代事件。部门源保存按日期段的路径证据及确切祖先/层级引用，旧源始终读原证据；当前路径解析依赖的来源另行返回，不冒充本部门头已改变。

未显式指定来源的列表读取：启用按服务端D、未来首条按首日解析；停用按对应停用日前一日解析“停用前路径”，两者均采用一致快照内各对象的最新来源。停用日之后生效的祖先变化不带入停用前路径，停用前历史的合法更正可以更新当前解释。显式指定任一来源（包括仍为当前头的来源）时，按该来源封存的路径证据读取；停用区间证据含其停用前解析日。首条前无今日事实，可显示未来首条安排路径，状态字段独立表达未生效。详情对启用记录按适用期间及祖先变化分段返回路径，停用记录仍显示停用前路径；不能以首日路径冒充整段。路径权限受限与无事实分开表达。

<a id="m02-br-030"></a>
### 4.7 M02-BR-030 操作与字段授权

当前主体、动作、部门范围、字段和导出分别判断，且每份Grant完整匹配。普通资料权不含启停、删除、改日、分类或归属调整权。归属BU/上级调整要求变更字段权及原、新管理范围；企业直属只表示行政上级位置，仍须有唯一管理BU。历史和恢复都执行当前读取授权，旧来源不扩大权限。

BU范围使用服务端执行日D和当前来源确定：覆盖D的资料给出BU，停用时保留该BU；D早于首条则取当前来源固定首条最新修订的BU。该归属只用于提交X03判定，不让未来业务资料提前生效，也不新增可维护字段。所选记录/旧来源/创建者不能替代；未来转入不提前授权，未生效首条BU更正则立即改变授权归属。停用BU可作稳定范围标识，企业/单部门授予仍按各自明确范围判断。

131的Q131-C01明确：A转B生效当天，仅A范围者失去本部门的当前及旧A来源读取范围；具B范围和相应动作权者可以读取该部门旧A历史，并不获得A中其他部门的权限。history.read、reference.read、export与基本read仍独立；当前归属赋予历史的范围，不自动赋予历史或导出动作。路径内容可以按停用前日或真实未来首条日解析，祖先的访问范围仍按同一次请求D决定。

创建准入须同时满足目标范围的create、保存后read和查回所需history.read，分别核验完整Grant；读取字段仍按各动作裁剪。任何新增/更正/删除/改日若实际替换某期间BU或父对象，须追加归属调整权、对应字段权和原/新范围；只有引用版本变化或纯启停关闭/重开同一关系不追加归属调整权。每次请求及查回均重新判定当前授权，真实撤权/转出后不保留创建者例外。

<a id="m02-br-031"></a>
### 4.8 M02-BR-031 引用与路径裁剪

引用BU或上级的最低读取只含稳定引用、编码、名称及需要的资格摘要；关联名称统一为文本，不提供快捷跳转，也不为此要求或预判目标完整详情权。路径按独立字段和必要祖先引用读取裁剪；若任一必要名称不可读，整条路径返回受限，不输出节点数量或部分串。不可读原关系不能当空值覆盖；提交重检全部声明字段权及关系资格。

<a id="m02-br-032"></a>
### 4.9 M02-BR-032 原子提交与恢复

沿013的内容绑定、来源并发、savepoint、提交确认、未知结果及原身份恢复语义。类型命名空间、路由与锁键按120固定；部门、层级及本次技术结果原子提交。失败零部分事实，no_change不产生业务源/日志/事件。不同对象终态不混表；原BU摘要及已存结果不重写。

### 4.10 M02-BR-033 查询、选择及CSV

### 7.2 M02-BR-037 树范围与固定身份选择
