## 1 场景与功能映射

### 1.1 页面原则及范围

管理员从“设置 → 组织配置 → 业务单元”直接进入列表，在详情办理已有对象。新建、资料变更、停用和重新启用维护业务日期、资料和适用的操作原因；更正核对字段差异，改日核对原日/新日和期间，删除核对目标与影响，不填写另一套处理原因。普通表单类型由入口或目标记录确定，记录处理由操作确定。[022](../../adr/022-joint-timeline-revision.md)原先新增联合修订及首条历史补全；首条专用入口现由107取消，单条分类在更正记录内办理；分类只呈现一组“操作类型/操作原因”，默认原值；有修改权可编辑，固定类型或仅有读权只读，无读权不显示，不另列原分类对照。保留主题、顶栏、列表详情、表单、日期维护、来源解释、未保存保护及返回上下文。

方案 B 的历史能力在后台完整保存。日常页面只有一条按生效日期排列的记录时间轴，更正不增加时间轴节点，改日移动同一记录节点；变更日志及其中的来源历史链接承接修订和确切来源解释。没有“选择一个修订才能编辑”的步骤，也不要求用户输入并发校验值。

本文不设计工作台、设置门户、申请/撤回申请、审批、人工发布、持久草稿、原因配置页面、批量导入、114范围以外的导出、组织报表或消费者采用管理。查看旧来源事实也不产生恢复旧版或重新发布动作。

## 2 导航与页面结构

<a id="m02-ui-navigation"></a>
### 2.1 正常入口与返回上下文

“设置”和“组织配置”仅是导航分组，末级“业务单元”直接打开列表。现有组织管理占位入口由该路径承接，不并行建设第二套 BU 维护入口。菜单名称不改变 Organization 上下文的事实归属。

列表打开详情时保存筛选、排序、页码、页大小、返回定位对象及可恢复的列表滚动位置。返回时恢复原条件；对象不再匹配筛选时直接显示当前查询结果，不追加对象缺失提示或“查看原对象”入口，不擅改筛选。页码失效时返回有效页，由分页控件显示实际位置。记录间导航只使用当前授权范围的列表上下文，范围已变则重新读取，不沿用旧对象集合绕过授权。

返回定位与勾选独立。用户主动查询（包括原条件重复查询）、翻页、改页大小、排序或应用筛选时结束旧定位，同时清除旧定位提示；新操作结果不再提醒上次查看的对象。只输入未应用草稿或取消筛选不结束定位。此收敛适用于BU与部门；跨页勾选仍按各自选择合同处理，真实读取失败及无权反馈保持。同步前验证见[原批记录](../../verification/133-list-return-notice.md)，最新main对齐与补验见[同步记录](../../verification/133-list-return-main-sync.md)。

对象标识、所选记录和只读历史查询模式须能通过受控页面地址恢复；查询文本和返回参数不能作为授权或写入依据。日期/记录不存在时显示明确说明，返回地址只允许本应用合法路径。无列表上下文的直达链接返回 BU 默认列表；不会返回未知外部地址。

<a id="m02-ui-link-return"></a>
对象名称必须使用有实际 `href` 的受控链接，支持键盘 Enter、Ctrl/Cmd 点击、中键、新标签及复制地址。链接携带已应用条件，不携带[尚未应用的搜索草稿](#m02-ui-query-state)；修饰键操作不得被普通点击处理强制改为当前标签导航。页面标题分别表达业务单元列表、新建和获授权的对象详情；未加载、未知对象、退出或权限拒绝时使用通用标题，不残留旧名称。

110列表目标中仅名称链接进入详情；整行及其他单元格点击不得导航，DataGrid的聚焦或选中不能隐式转为打开详情。

| 返回情形 | 查询与位置 | 焦点结果 |
| --- | --- | --- |
| 同标签返回列表或浏览器后退，选中对象仍在当前结果中 | 按当前授权重读已应用条件，恢复选中对象及可恢复的滚动位置 | 目标名称链接获得焦点且可见；两条返回路径分别验证 |
| 列表读取成功，但目标不在当前页/筛选、已移除或无读取权限 | 保留合法条件，正常显示获权结果或空列表，不改筛选找回对象，不恢复旧受限行；不追加对象缺失提示及查看原对象入口 | 聚焦可程序定位的列表标题，不落到 `body` |
| 列表读取失败 | 保留合法条件，显示实际读取错误和重试入口，不把失败解释为空结果 | 聚焦错误区域 |
| 新标签或复制链接进入详情后返回 | 合法 `back` 重建条件；有可见目标则定位，没有可用滚动记录只保证目标进入视口 | 有目标则聚焦名称链接；无列表上下文时用默认列表和标题，不虚构对象序号 |
| 在原标签用修饰键打开链接 | 原标签输入、选择及滚动保持，新标签不继承搜索草稿 | 遵循浏览器原生焦点行为，应用不额外抢焦点 |

返回定位只在当前授权查询完成后、且属于返回导航时执行；普通查询、翻页或迟到响应不得抢走正在输入的焦点。布局改为文档滚动时读取和恢复实际滚动容器，不能继续把原正文节点的 `scrollTop` 当作页面位置。链接改造必须同步应用导航适配及既有返回回归，保留焦点和滚动断言。

### 2.2 页面层次

```text
设置 → 组织配置 → 业务单元列表
                    ├─ 新建 → 保存 → 新 BU 详情
                    └─ 打开 BU 详情
                         ├─ 基本资料：身份、今日事实、生效记录
                         │    ├─ 新增记录／插入记录 → 同页表单
                         │    ├─ 更正记录 → 名称、日期及按权限直接显示的操作类型/原因
                         │    ├─ 停用业务单元 → 简短确认表单
                         │    ├─ 重新启用业务单元 → 资料与日期确认表单
                         │    ├─ 联合修订时间线 → 明确项并整体保存
                         │    └─ 删除此记录 → 简短确认表单
                         └─ 变更日志 → 操作明细 → 查看当次来源（只读）
```

详情沿用来源的页头、身份区、资料区、日期导航和日志分区。新建使用同一详情表单布局；新增、更正和重新启用在详情内进入编辑态；改日、停用和删除用短表单完成影响核对与一次确认，不增加向导、申请单或中间办理页面。

详情采用CubeBox的统一“更多操作”方式：对象标识旁放置带“更多操作”提示和可访问名称的⋮按钮；浏览态控制栏保留“新增记录／插入记录”主按钮，普通更正等次级维护收在同一菜单，不另在正文重复。菜单以“所选记录：生效日期”明确目标，不设置查看日期分组或入口。无动作权隐藏相应写入项；没有可用项时隐藏更多操作按钮，只读主体和只读来源按权限选择时间轴记录。业务资格与字段权限由服务端返回，不能根据前端今日状态推导。

当前开放新增、普通更正、停用/重新启用、分类删除、改日及有限联合。启停放在更多操作的业务单元分组；更正记录、删除及两项专用启停入口归入所选记录分组，单条分类在更正记录内办理，非法单条拒绝；只有固定启停对可一次处理两条；未实施动作不显示占位。新增不要求再复制一份菜单入口。两个返回入口的区分与新增继续暂缓，本批不增加页面“返回今天”或“返回查看日适用记录”，不改造既有历史只读/退出保护。

编辑态控制栏使用同一份表单状态显示“保存、取消编辑”；保存直接提交，由Go核验。从变更日志进入新增或更正时显示基本资料及编辑表单；取消恢复原页签，保存后定位基本资料中的实际记录。更多操作和对象导航暂时不可用，日期轴在编辑态收起，变更日志页签禁用，返回/退出保留未保存保护。取消完成后焦点回到更多操作，保存按原结果定位。

### 2.4 共享体验基线与布局修订

<a id="m02-ui-expression"></a>
页面设计必须避免过度表达。默认只展示完成当前任务所需的字段、选择和结果；内部机制、正常系统保证及可自动处理的提交意图不得成为常驻说明或额外确认。错误和风险在实际相关的情境出现，复杂业务影响按需查看，不用技术解释代替清楚的操作。

[019迁移](../../archive/plans/019-cubebox-experience-migration.md)将公共展示放入`packages/ui`，将路由、会话、列表返回及服务端查询适配放入`apps/web`。顶栏主体64px，控制区固定在其下，正文在独立区域滚动；桌面详情居中、最大宽1260px，窄屏改为单列。桌面采用应用菜单及设置内组织配置/基础资料下拉，窄屏使用导航抽屉；按[303](../../archive/plans/303-department-primary-navigation.md)，一级应用按部门、设置排列，部门直接进入列表，部门全部页面按路由归属且无重复子菜单；关闭与尺寸切换恢复触发按钮焦点。

按110，列表目标控制区为新建/标题/更多操作、现有搜索组合和紧凑分页；状态筛选按需打开，非默认条件显示简短摘要，不保留常驻日期/状态/排序行。桌面由支持的表头执行服务端排序，窄屏用Community摘要列展示名称/元数据，保留选中反馈；具体见[列表目标](#m02-ui-list-pro)。详情按[302](../../archive/plans/302-detail-navigation.md)在原查询及当前授权范围内显示“当前位置 / 匹配总数”、前后对象及跨页导航；窄屏保留数字，普通切换不等待列表重读；移动前重新核对当前授权范围；辅助导航暂时失败或位置失效时显示“暂时无法切换记录”并提供局部重试，保留当前可读详情；仅详情自身无权时清空受限内容。直达链接没有列表上下文时不伪造对象总数。

<a id="m02-ui-object-form"></a>
BU对象表单必须采用同一公共紧凑样式，适用于新建业务单元及详情内新增记录／插入记录、普通更正；后续维护动作接线时沿用，不另设一套外观。标签位于字段左侧，标签13px，输入及只读值14px，字段旁帮助/错误12px；普通文本及选择输入区32px、下划线边框，复选框文案14px并沿用small密度。原生日期控件以同一浏览器中新建表单的实际尺寸为对照，保留原生编辑能力。桌面按“基本资料/记录信息”两列，窄屏上下排列。文本、日期、原因选择器、复选框、只读分类、帮助和错误均使用同一表单上下文，不能仅复用同名输入组件却回退到浮动标签或描边样式。

进入详情编辑后，主体只呈现一份字段区域，保留所选记录原日期的只读定位；分类只呈现一组“操作类型/操作原因”，带入原值，按权限编辑或只读，不另列“原操作类型/原操作原因”或使用“新操作类型/新操作原因”标签；用户直接编辑名称，不显示“明确修改”勾选。页面自动记录用户编辑，未编辑字段的保留/继承及英文清空语义按013协议处理，不要求用户理解或选择提交字段。错误摘要能定位字段，字段旁保留服务端错误；日期输入使用共享ISO文本及选日按钮，不附加重复中文回显。保存/取消放在既有控制区；离开保护保留继续编辑和放弃。

普通编辑页不常驻展示“后继独立快照”“不填写更正原因”“旧来源/原采用保持”等保证，也不提示用户“只提交明确修改字段”。必要的默认及状态影响自动带出，不展示完整拟保存时间线；不默认铺开办理校验日、区间内部表示、逐项期间调整或未接入模块说明。无变化只提示“没有修改内容”，必要的未保存、冲突、权限及结果待确认反馈继续保留。

验收须在同一环境对照新建、记录新增及普通更正的实际字段字号、高度、标签位置及选择器密度，并验证桌面两列和放大后字段及操作可达。菜单可用、保存成功或截图已采集不能单独证明表单外观一致；实现接线见[013](013-m02-technical-design.md#m02-tech-object-form)。

019原实现把来源说明折叠在基本资料内；122目标改为[底部操作摘要及日志行内来源明细](#m02-ui-operation-summary)，变更日志仍在独立页签。来源历史显式标为只读并提供返回当前资料。日期轴只展示API给出的记录；当前按123移除通用查看日期，旧019图面仅作原批次证据。多节点/空集合的公共组件验证不代表本批已有新增记录、更正、删除或停用业务。实际图面、键盘与浏览器证据见[019验证](../../verification/019-cubebox-experience-migration.md)。

019/100的原实施基线和下列通用布局保护分别保留；113的Community替换目标尚待111实施，当前Pro接线不等于新目标已完成。100的七组结果见[页面优化验证](../../verification/100-ui-experience-improvement.md)，不能用旧Table或Pro通过覆盖新的Community摘要列及列适配。

1. 桌面保留顶栏、控制区和正文分区。可用宽度不足或放大后必须优先保证正文与操作可达；次要筛选可折叠，但仍显示已应用条件摘要。宽度不足时允许顶栏、控制区进入文档流并由页面滚动，不能靠隐藏溢出、缩小点击区域或零高正文维持固定外观。
2. 登录字段及按钮、列表数据、表单末项、错误和弹窗动作均须可通过正常滚轮与键盘到达。历史状态采用[历史短条](#m02-ui-history)的特殊保留方式；不得以常驻完整控制区再次遮住正文。
3. 详情/新建保留一个主要身份标题，控制区只留办理与返回所需的简明身份。无实际切换意义的单页签不占独立导航行；去除重复标题时保留区域结构、字段关联标签及可访问名称。在标准桌面记录首屏信息与操作路径，编码、名称、状态及日期不能被删减。

| 打开与返回 | 记录标题可用 Tab 到达，焦点清晰可见，可访问名称包含动作和当前可读的记录标识。用 Enter 打开，关闭或用 Escape 退出后，焦点回到仍可见的原入口。有实际修改时沿用离开保护。整页保存失败时保留仍获权的输入，字段错误可定位到对应栏目、记录和输入。 |

### 3.1 列表

#### 3.1.1 搜索草稿与已应用条件

已应用条件 `A` 包含 URL 中的关键词、状态、单列条件、排序、页码和页大小；未显式给出的默认值仍按既有服务端合同解析。输入框文本 `D` 是当前列表内存中的搜索草稿，不写入 URL、localStorage、sessionStorage 或持久业务草稿。`D` 与已应用关键词不同时，显示“输入已修改，点击查询后生效”，必要时给出已应用关键词摘要。`A` 表示已经发起的查询，不保证该次读取成功；失败不能把旧结果标为本次最新。

部门列表清空已有关键词的交互按[119第3节](119-department-functional-design.md#3-页面与字段)：立即移除已应用关键词并重查，其他筛选保留；该动作不作为未应用的空草稿。BU及非空关键词输入继续遵循下表。

| 事件 | 输入框 `D` | URL、请求与恢复 |
| --- | --- | --- |
| 首次进入、直达或刷新 | 从目标 URL 关键词初始化，缺省为空 | 按 `A` 重新授权查询，不把自动填充或存储中的旧输入当作已应用条件 |
| 修改或清空输入，尚未查询 | 保留输入，包括空字符串 | `A` 不变，不触发请求；清空输入不等于已清除筛选 |
| 查询/回车、表头或窄屏摘要排序，或应用状态/列条件（含清除） | 使用动作发生时的 `D`；等待期间可继续输入 | 原子应用整组条件，页码回 1，空关键词移除 `q`；后续新输入继续标为未应用。日期不完整时保留并提示完成输入，不请求不完整日期 |
| 编辑状态/列条件面板，尚未应用；或取消面板 | 面板局部草稿与 `D` 独立，取消不重置 `D` | `A`不变、不请求；应用时才执行上一行。今天使用服务端当前日期并按应用动作处理 |
| 上/下一页或更改页大小 | 保留 `D` | 沿用已应用关键词，只改页码/大小；改大小回 1，不把草稿重置为旧 `q` |
| 当前查询失败或重试 | 保留 `D` | URL 不变，重试使用 `A`，不偷偷应用草稿；失败与未应用提示分别表达 |
| 较早请求或旧会话响应迟到 | 不回写之后输入的 `D` | 只有当前会话且匹配当前请求的响应可更新结果；不改当前地址、不带回旧数据、不夺取焦点 |
| 同标签进入详情、新建或离开列表 | 丢弃未应用 `D`，不增加离开确认 | 链接/返回地址仅携带 `A`，另保留选中标识和展示位置；不自动提交草稿，不与表单未保存保护混用 |
| 返回列表或浏览器前进/后退进入列表地址 | 按目标 URL 重建 `D`，即使组件没有卸载也执行 | 按目标 `A` 重新授权查询；区别于用户点击分页按钮，返回焦点遵守[导航合同](#m02-ui-link-return) |
| 新标签或复制名称链接 | 原标签 `D` 保持；新标签无该草稿 | 链接及合法返回地址来自 `A`；新标签返回时按其 URL 初始化 |
| 退出、换账号或权限拒绝 | 清除受限输入及草稿 | 清空受限结果、数量和身份，后续读取重新授权；普通网络失败不冒充权限拒绝 |

#### 3.1.2 加载、分页与焦点

发起查询时保留稳定的分页控制结构和可理解的加载状态；不得为保持结构留下越权数据或数量。触发控件仍可聚焦时保留焦点；控件确实消失或不能再操作时，将焦点移到相关结果状态、错误或列表标题。键盘翻页、改页大小、空结果和失败重试后不落到 `body`，结果数/页码变化可被状态反馈感知。普通查询响应不得覆盖之后输入的搜索词，也不得以列表返回定位抢焦点。

#### 3.1.3 Community列表及控制区目标

新建按钮、业务单元标题和带可访问名称“更多操作”的⋮按钮按此顺序排列。搜索保留文本输入框加查询按钮，仅调容器宽度、间距与紧凑外观；不改为实时搜索、Quick Filter、候选提示或条件标签。无创建权时维持既有不可办表达及服务端拒绝，不因按钮摆放放宽权限。

已有列表列对应的条件从该列表头的「列操作 → 筛选…」进入，复用单列筛选的应用、取消、清除及焦点返回合同。窄屏摘要可从相应字段值直接调整同一列条件。保留通用的「列筛选…」入口，列表顶部和「更多操作」菜单均不另设对象专用筛选控件。新查询条件按列的读权提供，选用引用字段时显示获权名称。关联集合的范围提示与返回入口按对象合同呈现。

列表更多操作包含状态筛选、列筛选；桌面提供列设置，窄屏提供排序。状态默认全部，含启用、停用、未生效。编辑只改局部草稿，应用回第一页，取消/Escape不应用；关闭后恢复实际触发控件焦点。没有查看日期入口或弹窗。

状态不为全部或存在已应用列条件时显示相应摘要和调整入口；不显示日期摘要。摘要反映A，桌面表头/窄屏排序入口表达当前排序。

桌面显示编码、名称、状态、生效日期。只开放编码升序、名称升序/降序；名称清除排序回编码升序，编码不提供降序，状态/日期及多列排序关闭。Community原生列菜单、显隐、列宽及全部隐藏恢复继续采用，仅作用于已授权结果的本地展示；A/D变化保持显隐和宽度。用户已取消列拖动和固定，不提供自研拖动/固定或额外列顺序调整，默认顺序服从列定义。窄屏摘要使用同一排序白名单。单列条件按3.1.5承接；编辑、分组及完整Excel候选继续后置；导出所选另按3.1.6及114/115承接，已按115接线，实际验收范围见实施报告，不增加常驻筛选行。T04原评估见[110](../../adr/110-bu-list-and-datagrid.md#bu-list-filter-assessment)，本次采纳由110第2.6节承接。

分页复用GridPagination并放在控制区右侧，页大小20/50/100，窄屏保留大小入口并允许控制区换行；结果表达为记录范围/授权结果总数，如1–20 / 73、21–40 / 73、空结果0–0 / 0。范围使用服务端实际page/pageSize/count；加载中/失败不得显示旧结果数冒充当前数量，也不把未就绪当作0条成功。控制结构及焦点保持稳定，页码失效遵循已有说明。默认控制区保持紧凑；宽度不足时可换行及进入文档流，优先可达，不为固定高度裁切正文。

#### 3.1.4 窄屏摘要列及返回定位

低于900 CSS px使用同一Community DataGrid的摘要列：名称为主行真实链接，编码、状态及生效日期为次行。媒体条件只切换列展示，查询、分页、排序和选中身份保持；不维护另一套手机Table/卡片查询状态，600—899px同样不重复表头及逐项标签。桌面列偏好不得隐藏摘要列，切换期间D和焦点保持；不再使用Pro listView。长名称/编码可换行，状态与未生效标记可辨，纯日期沿用中文格式。无权字段不得在摘要、title或可访问文字泄露；名称不可读沿用通用“查看详情”及当前授权，不伪造名称。

桌面与窄屏摘要均按对象ID恢复选择，包括原列表URL尚无选中对象参数时的首次浏览器后退；只记录当前历史条目的点击对象和位置。返回时先重取当前授权结果，利用组件滚动/定位能力让虚拟行渲染后聚焦名称真实链接，不能持有已卸载DOM或把选中样式当作焦点恢复。等待按实际行渲染事件继续，不设置固定帧数的提前放弃；自动行高后续测量仍保持已恢复目标可见；用户已经输入、滚动或转移焦点时立即停止恢复，不抢焦点。对象/页码/权限失效沿用[返回合同](#m02-ui-link-return)；缩放和尺寸切换不丢搜索草稿，关闭受影响面板并将焦点移至可用触发控件。按第 6.2 节适用的视口与倍率补验。

#### 3.1.5 单列条件与统一应用/取消

同一个对话框由桌面列菜单“筛选…”、已应用条件图标、更多操作“列筛选…”或已应用摘要打开。按列菜单打开时默认该列；同列带出A，不同列初始化该列空条件，未应用前原A仍有效。更多操作带出原条件，无条件默认编码。列、条件、值按需显示：编码/名称为包含/等于文字，状态为等于单选或“属于任一”多选，日期为等于/早于/晚于/不晚于/不早于的纯日期输入。

只有一个条件行，不显示新增分组/逻辑组合。应用合并动作时搜索D并回第一页；“清除条件”只清空局部草稿，仍须应用才生效，可取消清除。空文字/空集合不能应用；有效性与权限以Go结果为准。取消/Escape/外部关闭不改A/D和图标，不查询、不写历史。面板关闭恢复触发控件，触发控件消失回更多操作；跨900px断点关闭草稿并回更多操作。可用宽度不足时字段垂直排列，动作可到达；溢出时允许对话框内容滚动，焦点不出模态。

已应用条件以紧凑可编辑摘要显示，主网格图标仅来自A。筛选的空结果、失败/重试、迟到响应及撤权沿用3.1.1/3.1.2；当前结果失败不得保留旧正文/数量。刷新、前进后退、详情对象上/下一个及返回使用完整A，不丢列条件；其他单元格不进入详情，名称链接能力保持。Excel候选勾选、跨列组合、空值/否定与日期范围后置。

#### 3.1.6 完整查询结果选择与导出工具条

按[114](../../adr/114-bu-query-selection-and-export.md)和[选择规则](011-m02-business-requirements.md#m02-br-022)新增目标交互，由[115](../../archive/plans/115-bu-query-selection-and-export.md)实施。勾选列、全量选择核对和导出已接线，实际分层范围见[115实施报告](../../verification/115-query-selection-implementation.md)；原文档采纳不作为产品证据。全集是当前条件/服务端D下全部获权BU，跨所有分页，不是当前页或一个BU的历史记录。

桌面最左增加Community勾选列，宽度沿用原生50px，不参与排序、筛选、列显隐设置或导出。行勾选只选择，不导航；名称仍是真实链接，其他单元格不导航。表头可访问名称为“全选查询结果／取消全选查询结果”，未选、半选、全选分别按全局已核对数量0、介于0与totalCount、等于totalCount判断；空结果禁用，不能因为本页全勾就显示全选。半选需向辅助技术表达mixed，不能只显示横线图标。

| 事件 | 页面结果及保护 |
| --- | --- |
| 表头从未选或半选勾选 | 一次选中完整授权结果；137条/20条每页显示“已选择137项”，不再追加“选择全部137条”第二步 |
| 表头取消或点击取消选择 | 清空全部跨页选择；恢复原搜索草稿D，不查询、不更改A、不要求确认 |
| 行勾选、取消、Space或Shift连续选择 | 只增减对应行；全选模式下取消即加入排除集合；Shift仅作用于当前已加载页的可选择连续行，不推测未加载页区间 |
| 翻页、改大小、仅排序 | 保留完整选择；新页按全局状态投影勾选；加载期间停止消费动作，成功且集合版本相同后恢复 |
| 应用搜索/状态/列条件 | 按3.1.1的A/D执行；实际谓词改变即清空，面板编辑/取消不清空；排序同时应用不同D时同样清空 |
| 列设置、尺寸或缩放变化 | 保留A/D及全局选择，按对象恢复实际焦点，不重复初始化选择 |
| 成员/来源/读权版本变化或读取失败 | 清空旧选择/数量；变化时提示“列表已变化，请重新选择”，按当前授权重新读取；失败可重试但不恢复旧勾选 |
| 离开、刷新、历史导航再进入、退出/换账号 | 清空勾选；现有selected返回定位独立恢复；新标签打开名称不清空原标签 |

有选择或正在核对选择时，在原控制区中间切换为紧凑工具条：“已选择N项、取消选择、导出所选”。核对未完成只显示“正在核对选择…”，停止导出，不把前端估算当作确认数量；取消始终可用且使旧核对响应失效。网格内Ctrl/Cmd+A执行与表头相同的完整结果全选；搜索或面板输入内保留原生文本全选，不拦截为行选择。不额外增加常驻说明。搜索草稿由现有列表状态持有，切换工具条不丢D、不会偷偷应用；已有未应用提示仍按3.1.1保留。清空后若原取消按钮消失，焦点移到仍可用的原行勾选框，否则搜索输入；不能落到body。表头/行选择本身不抢搜索或返回恢复的焦点。

低于900px继续同一DataGrid摘要列加勾选列；窄屏提供仅含必要全选控件的紧凑选择头，不恢复桌面四列标题。当前隐藏整个表头的CSS需适配，不能令全选入口消失；四类元数据继续摘要展示，桌面放大时工具条可换行，清空、导出及页大小均可达。桌面列设置不得隐藏勾选或摘要列，尺寸切换保持焦点及选择。

仅当服务端核对selectedCount大于0且canExport=true时可执行导出。只读者能选择，缺导出权时工具条保留禁用动作并按需给简短权限原因；不自动缩小选择。点击导出不增加确认，沿当前A中的合法排序请求CSV，不能应用D。等待中禁用重复导出，保留取消选择和独立请求身份；取消选择/切换查询/离开会中止当前下载请求，后到响应不得创建下载。完整响应成功且仍属当前会话/选择代际时才触发浏览器下载，显示“已导出N项”；失败不报成功且不生成半份文件，版本变化清空选择，权限拒绝清除受限内容；普通网络错误可按同一当前选择重试，但须服务端重验。

### 3.2 详情与生效时间轴

对象的只读属性进入基本资料字段，长值允许换行。对象合同已开放的关联集合有明确入口、集合范围和返回位置；首屏优先展示本对象，按需要进入集合。层级目录可从列表行进入直接下级。详情关联跳转沿用[128](../../adr/128-authorization-evidence-removal.md)的适用边界。

身份区展示编码、所选记录名称及所属企业；取消当日状态。记录区展示所选记录的生效日期、适用期间、状态、资料和原业务分类。普通入口默认今日适用记录，今日尚无资料时选择未来首条；显式selectedRecordId优先。未来记录仅按服务端selectedRecordIsFuture显示“尚未生效”；不与记录启用/停用状态混用，不另列查看日对照说明。

当前已记录信息下的时间轴每个生效日最多一个节点，删除记录从当前有效集合移除，原件可在变更日志或历史查询读取。更正后保留同一节点和记录标识；改日保留recordId并移动该节点，按新日期重排，不同时显示新旧日期为两条当前记录；按122目标，基本资料常显所选修订操作者/时间，修订/来源标识在有历史权的日志来源明细内展开，修订不另成一条业务时间轴。时间轴区分新建、数据更改、停用、重新启用，每轮停用区间及恢复起点由服务端返回。显示名称及停用继承资料由服务端解析，不由前端拼接不同来源版本。

适用期间展示为“2026-11-15 至 2026-11-30”，对应服务端 `[2026-11-15,2026-12-01)`；开放终点显示“自 2026-12-01 起”。结束日转换仅是展示，不提交第二套区间。停用的生效日期仍为 12 月 1 日，最后启用日为 11 月 30 日；“最后启用日”只作说明，不提供额外输入。规则见[日期](011-m02-business-requirements.md#m02-br-003)。

<a id="m02-ui-position-addition"></a>
普通资料新增以当前所选记录为位置基准，不是全时间线任意日期的入口。服务端返回位置、默认及可用范围：所选为最大生效日期记录时按钮/表单标题为新增记录，默认max(服务端D,所选日期次日)；所选有后继时为插入记录，默认所选次日且仅允许其与紧邻后一条之间。下界/上界按Go结果限制选择与手输；操作日期由Go根据所选位置及D默认，用户可修改合法默认。无可插入日期时按钮仅禁用，不增加原因文字、tooltip、弹窗或全灰日期选择器；普通服务端非法输入反馈及权限/历史保护保持。

进入即自动带出获权的名称等资料，不复制分类/原因：操作类型只读固定数据更改，操作原因初始为空待选。默认及自动刷新不标记已修改，未编辑直接取消无确认，真实修改与原提交未知仍保护；已编辑字段不被自动默认覆盖，恢复初始值可直接退出。切换位置先处理真实未保存输入；详情、保存定位及返回上下文继续区分当前日期与所选记录。按钮和表单标题简化不改变生效日期/适用期间字段及ADD/CHANGE语义。首条维护按107复用普通更正及另次新增/插入。单条启停只在选中末条时按该条生效后状态开放一个合法入口，恢复进入即带出获权名称；原因留空，日期默认及上下界由Go返回。非末条的启用空档仍通过固定成对插入办理；不自动换位置。初始默认不标记修改，真实编辑、离开与未知结果仍保护。业务拒绝自动就地展示并阻止确认，改正输入后重验；不恢复手动预览，网络辅助失败仍可由保存事务校验。

<a id="m02-ui-date-display"></a>
按[026日期格式决定](../../adr/026-date-display-and-input-format.md)，完整业务日期的显示与输入统一为YYYY-MM-DD，例如2026-01-13；年份四位、月日补零，日期轴也保留完整年份。API沿用同一格式，不通过时区换算改变业务日。共享日期输入支持手输、粘贴、清空及原生选日按钮，文本框始终呈现ISO；空输入占位YYYY-MM-DD，不重复附加中文回显。选日面板的年月导航和星期可继续本地化，输入辅助不复制Go业务资格校验。生效日和记录时刻分别标注。

记录时刻按 `Asia/Shanghai` 展示为 `YYYY-MM-DD HH:mm:ss（北京时间 UTC+08:00）`；来源展开区保留服务端原始时刻及其精度供核对。显示到秒不改变原时刻或日志排序，不根据显示文字重新拼时间。无效或缺失时刻显示明确不可用，不以当前时间代替。

详情更多操作不提供查看日期。共享RecordControl及列表控制区不保留通用日期槽或无消费者弹窗。记录切换使用时间轴，返回/前后导航只携带必要查询与记录定位。明确记录或来源读取临时失败时清理旧正文并可按原定位重试，不自动改读今日记录。

不增加查看日期标签行。来源历史独立以只读来源提示表达；未来提示只说明所选记录尚未生效，操作能力仍由Go返回。

### 3.4 变更日志与来源历史

本节按[122](../../archive/plans/122-bu-operation-summary-and-change-log.md)持有当前合同，页面已接线，实际参数和检查见[实施报告](../../verification/122-operation-summary-implementation.md)。基本资料消费Go的operationSummary；日志消费确切前后上下文和差异，前端不从当前详情或当前账户补造。

<a id="m02-ui-operation-summary"></a>
#### 3.4.1 基本资料操作摘要

在业务字段底部使用普通次级文字常显一行；保留既有顶部控制区和操作入口，如页面有底部动作区则摘要位于其上方。无卡片标题、说明大段或展开开关，长姓名/账号和窄屏允许自然换行。保持可读对比度、可选择复制，身份不默认链接到人员档案。示意中的姓名和时刻均为合成数据：

```text
中文名称    华东业务单元
英文名称    East China BU
生效日期    2026-01-01
……其他获权业务字段……
操作者：李明（liming）　操作时间：2026-11-03 14:32:18
```

取值严格遵守[BR034](011-m02-business-requirements.md#m02-br-034)。标签使用“操作者”“操作时间”，含义为当前展示修订的最近一次形成操作，不另放一个整个BU“最新修改人”。历史模式、删除前原件及未来首条仍按所选准确修订显示；没有选中记录时无摘要。姓名账号齐备显示`姓名（账号）`；仅有账号显示账号；旧证据只有主体标识时标签改为“操作者标识”。服务主体有类别提示，不伪装成人员；禁止以当前用户替代。时刻按026显示北京时间，原始精度在有权阅读的来源明细中保留。

删除结果入口或复制地址按“删除来源＋被删记录ID”打开时，仍显示已删除原件、原资料和原期间，底部摘要显示删除前业务资料修订的操作者/时间；删除者在日志的删除操作中读取。页面直接消费Go返回的operationSummary，不把selectedRecord的删除证据修订或顶层来源元数据拼入摘要；不新增第二块常驻元数据解释。

未来首条默认选中后，基本资料和摘要常显，即使viewFact为空、result为M02_NO_FACT也不渲染“无资料”空态；获权的selectedRecordIsFuture用于尚未生效提示，前端不比较日期推断。日期失读权时移除日期及未来提示，合法摘要仍显示。selectedRecord为空才无摘要；显式目标不存在显示selectionMissing，不静默改选。

基本读取者无需历史权限即可见摘要；无历史权不提供日志页签、来源展开及原件链接，直接URL仍由Go拒绝。字段读权部分收窄不独立隐藏合法最小摘要，对象读权撤销则整体清空。

“生效记录”和保存时分类使用日志响应的beforeContext/afterContext，普通记录优先使用后上下文，删除使用前上下文；日期变化的原→新值由diffs表达。仅更正中文名称时也能展示该次记录的生效日期及未变化的分类，不发起逐行原件补查、不借用当前详情。上下文字段不自动生成差异行，字段权限裁剪也覆盖上下文中的日期、期间、名称及分类标签。

日志请求将当前详情历史模式的sourceVersion传为contextSourceVersion，当前模式省略；首次由服务端返回throughSourceVersion，后续分页/筛选带回。刷新历史日志保留上下文、重新取该上下文上界，刷新当前日志才重新取最新头；切换历史来源或返回当前时重置页码和旧上界。恢复原日志必须恢复原上下文及上界，迟到响应不得替换新上下文，具体请求与错误由013持有。

正文基本资料和日志中的大块“来源说明”取消。来源明细是按钮，使用`aria-expanded`和内容关联，收起焦点回按钮；其他查看项是支持复制地址、新标签打开的链接，不用按钮模拟URL。多目标各自定位，整组来源明细只保留一处。展开不改变页数和筛选，折叠不隐藏主要差异。历史进入/返回保持所选记录、列表上下文，以及同标签日志的已应用条件、页码、页大小、滚动和触发链接焦点；新标签不改原页。权限失败清除受限原件和链接缓存，不回退最新资料。

<a id="m02-ui-history-access"></a>
#### 3.4.4 历史模式与权限保护

记录自动辅助成功或业务拒绝响应发现字段读权收窄时，立即按服务端读字段清除默认、输入、所选原件、父详情及日志的受限缓存，保留仍可读输入；重读当前资料后重新带出必要辅助，用户核对后直接保存。该保护覆盖来源冲突与字段撤权同时发生，迟到响应不能恢复旧缓存。日期不可读时隐藏期间，不能将裁剪后的空终点显示为开放期间。删除依赖拒绝显示整体错误，不跳转到不存在的日期输入。失去历史权清空日志、展开和原件缓存并回基本资料；仍有正常资料读权的摘要可以重新读取。失去对象读权清空整个详情。

历史状态与“返回当前资料”入口组成紧凑短条，桌面位于常驻控制区；切换页签或滚动正文时两者保持可见。放大后若正文随文档滚动，完整顶栏、身份和日期可以滚动离开，历史短条仍贴靠可见页面顶部且不覆盖正文；长解释放在正文中。不得仅靠正文开头的提示、颜色或地址参数表达历史模式。返回当前资料必须清除来源参数、重新读取当前事实和可办动作；等待或失败时不能提前显示可编辑的当前资料。历史源不存在不回退最新，历史没有写入入口。

只保留以下两种读取方式，不要求手工输入内部版本标识：

| 查询方式 | 输入及定位 | 明确展示的结果 | 写入边界 |
| --- | --- | --- | --- |
| 日常查询：当前已记录信息 | 无日期输入；服务端D | 该日按当前已提交资料解析的事实 | 可按服务端可办动作进入维护 |
| 来源版本 | 从操作/原提交结果链接带入确切版本；selectedRecordId用于准确定位，未指定时按服务端D默认 | 当次保存版本的完整记录集合及所选记录；无匹配仍说明该版本存在 | 不可保存；版本不存在/不可用不替换为最新 |

不再提供已知信息截点输入或来源历史模式选择。API 拒绝 knownAt 参数；旧页面链接明确显示该方式已停用并提供“返回当前资料”，不能静默丢弃参数后显示最新版。

指定来源不存在时清空旧资料并明确报错。已解析到来源、但服务端D早于该版首日时，可以展示该来源的未来首条并标明未生效，不能用当前首条替代。反例见[完整历史验收](011-m02-business-requirements.md#m02-ac-008)。

历史面板里的时间轴只解释该来源版本下的记录集合，不能与当前集合混合。被删除资料在旧来源版本中可以读取；已改日记录在旧来源仍使用该版原日期、期间及首条起点，明确标为历史事实；没有“恢复这一版”按钮。退出时使用“返回当前资料”，清除历史条件、重新读取当前资料，重新确定所选记录与可办动作；不得仅换版本令牌继续提交旧表单。

来源版本是读取依据，不等于消费者采用。本批无 adoptedRef 查询输入或采用管理入口；链接或接口携带该未知参数时统一拒绝，页面可返回当前资料，不保留501占位，不伪造已采用结果。历史查询及失败区别见[011 历史规则](011-m02-business-requirements.md#m02-br-009)。

## 4 状态与操作

<a id="m02-ui-actions"></a>
### 4.1 可办动作与保存定位

现阶段各模块的业务维护页由有权管理员直接保存或确认相应动作，成功后定位到实际办理的记录。未来生效标识显示生效时间，全流程无人工复核入口或待审批状态。[项目阶段规范](../../adr/213-administrator-maintenance-and-effectivity.md)

动作能力、限制原因、字段可读/可写由服务端按当前身份及事实返回。无相应授权时不显示可写入口；有权但业务条件不允许时可禁用并解释原因；无可插入日期为用户确认的例外，仅禁用插入记录，不提供额外原因表达。来源历史一律只读。按钮状态仅供交互，保存时仍须 Go 重新核验。

| 入口与可观察条件 | 表单及核对 | 成功后的页面定位 | 拒绝或保护 |
| --- | --- | --- | --- |
| 列表 → 新建；有创建权限且企业就绪 | 最小字段，操作类型新建；核对生效日和原因后保存 | 新BU详情选中实际首条，状态来自该记录；未来首条显示尚未生效及首日 | 输入错误留在表单；无首条的身份不能算成功 |
| 当前详情选择记录 → 新增记录／插入记录 | 先按所选位置带出获权资料及日期，类型固定数据更改、原因留空；用户修改后直接保存，范围按所选与紧邻后继及企业/状态约束 | 选中实际保存记录；日期场景及登记时刻按服务端结果，保留列表返回条件；同值无新记录 | 无可插入日期仅禁用按钮且无原因说明；日期越界、占用、停用段及过期来源正常拒绝；初始带值不触发离开确认，手工输入不被加载覆盖 |
| 所选记录 → 更正记录 | 名称与原日同页，操作类型和原因仅一组，标签不加原/新，按权限直接显示并保留原值；按各修改面权限编辑，一次直接保存，无更正原因 | 保留同一recordId；日志按实际名称/日期/分类差异展示 | 初始带值/原因候选加载不算修改；同值无新版本；撤权、冲突与恢复保持 |
| 所选非首条普通/停用/重新启用记录 → 删除此记录 | 包含已生效目标；日期和原分类只读；展示全受影响期间、状态与引用，无删除原因；删除合法末尾停用明确提示可能恢复今日启用，删除末尾重新启用明确提示停用延长及今日状态；有依赖则展示拒绝原因；按钮“确认删除” | 显示“已删除”；按目标原日期定位新来源适用资料，展示实际状态变化，原件入口只读 | 首条、已删除目标、旧版本、非法后继及引用冲突拒绝；不级联删除或转换关联记录；不因跨午夜单独拒绝，不提供撤销或恢复已删除记录 |
| 更正记录 → 生效日期 | 默认原日，范围由Go返回：前条次日起至后条前日，首条下界企业起点，末条开放；仅原日可选时只读 | 保留记录身份，日志可查原日→新日 | 手填越界/占用/完整启停或引用非法整笔拒绝；跨节点拒绝，保留输入供核对 |

| 更正记录内操作类型/原因 | 直接编辑操作类型/原因，不增加原因说明字段；转停用已有名称修改须明确移除或保留输入，转明确资料默认目标自身解析资料 | 一次CORRECT、新修订与旧分类来源 | 首条只改CREATE原因；非首条不改CREATE；原/新类别权及最终时间线均重验，不增加关联操作入口 |
| 任一未提交表单 → 取消编辑 | 用户实际修改时选择继续编辑或放弃；仅初始带值直接取消 | 回到原详情/列表及选中记录 | 不要求操作原因，不写修订或成功日志 |

保存确认结果显示“已保存”及相应生效日期，不显示批准、发布完成或已采用。未来记录已保存与今日已生效分别解释；新增及普通更正保持所选记录；改日、停用、重新启用按各动作合同定位，仅影响详情，原列表条件继续保留。[保存定位规则](011-m02-business-requirements.md#m02-br-015)为业务依据。

过去补登记使用相应业务入口：资料变更用“新增记录／插入记录”，停用及重新启用使用各自表单；类型和原因按对应目录选择，不增加处理原因、审批或新状态。自动辅助按动作展示实际结果及相关业务影响，当前新增/普通更正遵循2.4的简洁展示；权限受限的依赖只显示安全摘要，不常驻解释旧来源、原采用或内部期间算法。保存后可从变更日志核对实际登记时间和来源，旧来源只读；日期场景由服务端返回。列表返回后可能不再匹配原筛选，沿用已有结果解释和返回保护。

改日自动辅助由服务端基于当前来源计算；新日期变动后重取自动辅助，禁止沿用旧影响结果。首条后移明确显示新增的无适用事实期间，停用/重新启用前移、后移和删除显示变化前后的启用/停用区间、今日状态及后继依赖；普通记录跨过其他资料时拒绝，不搬动其他日期。首条删除入口不可办但改日独立授权；旧来源下两者均不可写。首条移到未来须直说今日将显示未生效；仅改日期时延长原资料；更早不同资料可同页明确改名，按普通更正保存。需要原日期起另一份资料时，用户再独立新增/插入，不出现保留选项，不强制联合。删除停用导致后继重新启用失去前提、删除重新启用导致后继资料落入停用期时，显示依赖拒绝，不提供自动级联处理。范围选择见[020决定](../../adr/020-effective-record-delete-and-redate.md)及[021决定](../../adr/021-bu-lifecycle-and-record-maintenance.md)，规则见[011改日](011-m02-business-requirements.md#m02-br-017)。

例如服务端D＝2026-10-31，新建2026-11-10首条后选中该条，基本资料状态为该记录的启用，并显示尚未生效；列表显示首条名称、11月10日和未生效。无需切换查看日期；11月10日后列表由服务端自动解析为启用。

### 4.2 提交和错误反馈

| 页面状态或服务端结果 | 页面反馈 | 允许的下一步 |
| --- | --- | --- |
| 提交中 | 保存按钮禁用、显示保存中，保持表单上下文 | 同一次提交不重复创建请求身份 |
| 字段错误或确定未提交的业务拒绝 | 表单顶部摘要＋字段就地错误；保留仍有权查看的输入 | 修正后重新核对并另次提交 |
| 非法转换或关联记录依赖 | 展示目标日期前状态及有权查看的受影响记录/期间；说明单条操作无法保持合法时间线 | 保留输入供重新核对；不推荐绕过守卫串行修改、不提供自动删除关联记录；仅补入完整停用期间或删除整段误登记可另次使用固定专用操作；其他依赖修复拒绝 |
| 无实际变化 | “没有修改内容” | 返回详情或继续调整输入 |
| 版本冲突 | “资料已变化，请重新核对”；展示获授权的最新事实与本次输入 | 用户明确核对后重新进入当前办理；不能自动合并全表单或只更新令牌 |
| 超时/连接中断，结果未知 | 原请求结束后自动确认一次；仍未知显示“暂时无法确认保存结果”及“查看保存结果” | 本页仍有原内容时可“重试保存”；确认与重试互斥，结果明确前不创建另一笔操作 |
| 原提交已成功 | 展示原保存结果并定位原对象/记录；若已有后续变更，另标明当前事实已变化 | 查看原结果只读，返回当前后重新办理 |
| 当前对象/历史读权失效 | 说明权限不足并清除受限正文及重试包，保留待确认引用 | 返回有权入口；不显示旧敏感结果 |
| 仅办理或字段写权失效 | 仍可按当前读权查回已存终态，禁止新的越权保存 | 查看原结果；未持久化请求的重试仍须写权 |
| 字段读权收窄 | 清理对应正文及诊断，展示获权字段和安全终态 | 可确认结果，不为显示受限字段要求恢复写权 |
| 必要依赖不可用 | 明确本次未能完成校验；若提交结果未知仍按待确认处理 | 依赖恢复后重新读取、核验；不能以空引用替身放行 |
| 自动辅助执行超限 | 提示辅助暂不可用并清旧辅助；保留有权输入，必要默认读取失败提供重试 | 必要上下文失败可重试；可选辅助失败不阻断直接命令校验，不沿用旧默认或拆分自动提交 |
| 结果暂不可读、服务初始化未就绪 | 不把技术故障显示为未保存，不用旧缓存冒充新结果 | 保留待确认引用；恢复服务且重新授权后查回，已有确定结果不被迟到错误覆盖 |
| 无日期适用事实、来源版本不存在、证据不可用、能力不支持 | 在当前授权允许的范围内分别说明 | 调整查询或返回当前资料；不静默回退最新；无权时不泄露对象/版本是否存在 |

提交标识是后台交互协议，不是要求用户填写的字段；页面保留可用于结果恢复的最小引用，不持久保存表单正文。刷新或重新进入后的结果查回与授权处理由 013 给出可实现协议。关闭待确认表单不删除已提交事实，重新进入必须先处理未明结果，不能把关闭当成确定失败。

字段拒绝指向对应字段和修正动作，不统一显示“重试加载”；依赖读取失败才提供重载该依赖的入口，结果未知继续使用原提交查询/精确重试。尚未提交表单的离开按钮为“继续编辑／放弃修改”；确有已发出而未明确结果的保存时，改为“留在此页／离开此页”，说明“离开不会撤销已提交的保存操作”。

一次尝试的回滚或超时不决定原提交的最终反馈。可恢复拒绝由服务端在原锁内保存；整笔事务失败仍按待确认处理：本页请求结束后自动确认至多一次，仍未知则提供手动查看入口；刷新和存储事件不自动确认。重试或resolve确定原成功、拒绝、无变化或未提交后按该终态处理；后到未知反馈不能覆盖它。拒绝诊断来自原结果，不能用重新填写内容或最新版本校验替换。

查回被当前对象/历史读取权限拒绝时，清除受限正文及内存重试包；即使已经重新填写也不能保留受限输入。字段读权收窄清理相应字段，并同步清理前序默认、自动辅助、详情及变更日志等展示缓存；成功重读当前详情后各展示区域采用同一最新权限，旧响应不得恢复受限值。仅撤写权时保留仍可读输入和结果，也不阻止解除已确认提交。读取拒绝本身不表示未保存，待确认引用继续保留。查回保持列表搜索、排序、分页和返回定位；当前默认日期仍由服务器取当日D。旧会话迟到响应不得清空新页面或改变待确认状态；离开原表单后的结果由查回入口承接。

### 4.3 两项专用启停操作

详情所选记录的更多操作提供“插入停用与重新启用”和适用时的“删除停用与重新启用”，旧通用联合和添加关联操作入口移除。

插入弹窗仅四字段：停用日期/原因、重新启用日期/原因。类型固定，原因分别为空；Go提供同一空档内最早两个合法日及范围，不足两日仅禁用入口，不加解释。日期选择联动，自动恢复日仅在用户未编辑时随停用日调整，不覆盖已编辑日期。无名称、类型选择或项目列表；点击保存一次提交两条，成功关闭并在时间轴定位停用记录，返回上下文保持。初始带值不算修改，实际编辑保留原离开保护。

删除从所选停用或恢复定位当前同一组，不让用户配对或多选；无完整组不提供入口。确认仅展示两条日期/类型，存在实际可读名称变化时显示Go返回的变化区间和值；包含后续停用继承变化，后继独立快照保持。按钮“删除两条记录”；无删除原因、保留资料、类型转换或补建选项。成功关闭并定位原停用日的新适用记录；只删除这两条，正常期间/继承重算不是隐式业务更正。

保存、冲突、权限变化及未知结果沿用既有保护。重读保留仍可读的日期/原因，保持原锚点或原组，不自动换位置/换组；用户核对后另次提交。没有手动预览、草稿插入、详情二次保存或恢复旧通用编辑的入口。旧来源及旧日志只读，原通用请求终态仍可查回。

### 5.1 未保存、日期切换与滚动

编辑时切换记录、历史模式、对象或离开页面，均先处理未保存输入：继续编辑则留在原位置，放弃则丢弃本地输入后导航。不自动保存，不产生持久业务草稿。刷新/关闭页面使用可用的离开提示，本批不承诺关闭后恢复未保存正文；已提交但结果未知按第 4.2 节单独恢复。

校验失败后聚焦错误摘要或首个错误字段，并保留其余可见输入；保存后聚焦结果和实际记录。日期导航、详情资料和日志分别能通过正常鼠标滚轮、键盘滚动读取，不以隐藏溢出使日志或按钮不可达。短确认表单打开后焦点进入，关闭后返回触发控件；长内容允许内部滚动，提交按钮不遮挡最后字段。

窄屏将列表行和资料字段重排为单列、操作进入明确菜单，保留同样语义；不另建移动工作台。日期、状态、只读和错误不能只靠颜色表达。创建/查询已有的浏览器证据按第6节说明范围；其余记录维护及未覆盖的布局、键盘行为后续补验。

顶栏、菜单及状态文字通过统一主题 token 调整。普通文字的实际前景与叠加后的背景对比度至少 4.5:1；正常、选中、悬停、聚焦状态分别核对，键盘焦点可见。测量须计入半透明选中/悬停层，不只比较原始色号；单项对比度或键盘检查不代表整体无障碍合规。

## 8 唯一原因与最小辅助

当前新建、重新启用及固定期间表单应用Go目录default，不按选项数量推断业务规则。有效手选保持；普通更正保留原记录分类，类型变化才应用新目录。程序默认不单独触发未保存提示，取消空表单可直接返回。纯名称更正继续直接保存且不自动预览；日期/分类辅助只展示实际需要的状态、删除后资料及首条无事实区间。

服务端已确认accepted/no_change后，本地待确认引用清理失败不能改成未知、重新开放保存或重发业务。引用可留供以后查回；发送前仍须可靠保存提交身份，同类对象待确认阻断规则保持。

**保存结果、离开与原操作身份。**

| 实际状态 | 页面反馈和动作 | 系统处理 |
| --- | --- | --- |
| 当前请求尚未发送 | 指出字段错误或“暂时无法开始保存”，保留输入 | 不生成虚假的“已提交”提示；读取本地引用失败也不能据此断言以前的操作未保存 |
| 正在发送保存 | “正在保存…”；防止重复点击 | 不提前启动结果确认，不新建第二笔操作 |

| 已保存／无变化 | “已保存”／“没有修改内容” | 使用服务端确切结果，定位获权记录；后续结果读取失败不能改写已确认的成功 |
| 已确认未保存或被拒绝 | “未保存”并显示具体获权原因；提供相应修改或重新保存动作 | 仅明确终态后允许开启下一笔操作；失败诊断不按当前资料重算，也不恢复已丢失的原输入 |
| 刷新或重新进入后存在待确认记录 | 显示保存结果区域和“查看保存结果” | 只恢复已有身份引用，不恢复原业务输入；不会因读取到引用就自动确认或重发保存 |

自动确认只由本页保存请求结束且结果未知触发，每笔原操作最多自动一次；刷新、组件重挂载、存储事件不追加自动请求。确认接口会在既有锁内核对或关闭原提交身份，不能把它当成随时可以后台轮询的普通查询。保存引用时尚未发出请求，不因此自动关闭该身份。

同一笔操作的自动／手动确认与原内容重试共用在途状态：确认中不能同时点击重试保存，重试保存中不能再发确认；双击只发送一次。此协调限当前页面和已有流程，不新增跨标签锁服务，跨标签并发仍由Go提交锁保证唯一终态。已经接收的accepted／no_change／rejected／not_applied不能被迟到pending或网络错误改回未知；返回身份不匹配、结果解码失败及当前无读取权限均不能当成未保存，也不能清除尚未确认的身份。

当前页若仍有完整原请求，可提供“重试保存”，明确复用同一操作；刷新后没有原请求时只提供结果确认。离开丢弃本页输入，不撤销服务端操作；已经保存的资料按既有更正／删除业务入口处理。

**重试、筛选、选择和权限。**

普通读取错误应给本区域重试入口。分页位置失效时重新建立首页位置，保留已应用关键词、状态、列条件、树范围、排序及页大小；未应用的搜索输入不自动提交。恢复后的页码由分页控件体现，不追加“原页码失效”说明。日志只在条件确实无效时提供定向重置，覆盖重复logReturn等被拒绝参数；临时服务错误不优先提供清空筛选。

详情的上一条／下一条辅助读取失败时，保留仍有权查看的当前详情，局部显示“暂时无法切换记录”及“重试”，不要求返回列表重新筛选。只有当前详情自身不可访问时才清除受限内容；不能把辅助导航故障当成详情撤权。树局部读取失败同样保持其他已获权内容，不以“选择全部”扩大范围作为恢复动作。

非空搜索输入与已应用关键词不同时，仅显示“输入已修改，点击查询后生效”，必要时显示已应用词；删除刷新、离开后是否保留的常驻解释。部门清空立即解除关键词，BU仍按其当前查询草稿合同处理。管理BU摘要显示服务端允许读取的编码／名称；名称不可读时不取旧缓存补齐，保留明确的筛选标签和清除入口。

部门与BU沿各自现行选择合同处理，不统一改成“出错就清空”或“出错就恢复”。暂时无法核对时保留可恢复的原选择意图，暂停导出；确认失效时才提示“选择已失效，请重新选择”。重新选择必须由用户发起，不能暗中重新捕获全选集合。范围页不可用与部门固定选择有效是两个状态，按[部门树与固定选择](118-department-business-requirements.md#m02-br-037)分别处理；CSV继续全量通过授权后生成，失败不输出半份文件。

首次建立选择尚无确认结果时，不显示已确认数量；失败显示“选择未完成，请重新选择”，不自动重发start捕获更新后的全选集合。已有部门草稿的纯读取暂时失败，可用原草稿做空编辑核对；增删选择请求丢响应后不能盲重放编辑或假定修订未推进，只能按当前协议确认，修订冲突则要求重新选择。BU仍按原集合版本核对；任何恢复都不把未确认的勾选数冒称实际选中数。

数量限制由Go给出实际原因和限制值：成员数量硬上限与临时资源不足分开；部门客户端按现有1024项协议自动分块；BU仍发送同一版本的完整集合，选择专用请求体上限调整为32MiB，消除正常规模逐项选择被64KiB传输上限拒绝的问题。不把BU改为多次独立导出或重新捕获集合。协议传输由系统处理。不能把“稍后重试”用于相同输入必然超限的情况，也不能把减少查询条件等同为减少固定选择成员。

实际CSV文件超过大小限制时提示“导出内容过多，请减少所选项或分批导出”；导出临时空间不足才提示稍后重试。两者由Go区分，不把文件大小超限误报为成员数量上限。

会话校验失败、登录过期和业务权限变化分别识别。请求校验失败先停止继续写入，恢复登录状态但不自动重发保存；只有确认原操作未保存并获得当前权限后才允许用户重新保存。权限降低时只保留仍有权读取的输入，不展示隐藏对象、字段、日期或原诊断；不可访问不擅自解释为没有操作权。

同实例、同账号且会话仍有效的请求校验恢复，在当前页面内保留仍有读权的输入并更新请求校验信息；不能因刷新会话就重挂表单丢失输入。确认401或退出／换账号时沿现行合同隐藏并清除受限正文和业务草稿，重新登录只恢复合法路由及属于该主体的待确认身份。业务输入不写入浏览器存储；“保留输入”不跨越账号或权限边界。会话恢复失败提供“重试”，不自动回到需要重新输入密码的登录状态。

变更被业务规则拒绝、而冲突细节无权查看时，使用“当前修改无法保存”并提供“取消本次修改”；只有服务端可安全定位到可读字段时才指出对应字段。不得提示核对隐藏日期或虚构可自助修复的步骤；取消只丢弃当前编辑，不撤销已保存的资料。
