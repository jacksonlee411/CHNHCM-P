# CHNHCM-028 X03 客户管理员首批账号与授权合同

本合同供客户安全管理员、部门经办人、岗位核编经办人及交付团队评审。首批让管理员建立本地账号、按职责授予权限并收回指定的一份授权。本文描述拟交付行为，现有登录、会话及部门和核编页面是实施起点。执行阶段、迁移与验证责任见[027 实施计划](../../plans/027-x03-local-access-rollout.md)。[登记表](../../governance/registry.json) · [X03 目标合同](../../architecture/target/modules/x03.md)

## 1 谁可以管理谁

以下分工界定首批可分别委派的操作。同一人可以兼任多项职责，服务端分别检查每项权限。客户可用同一位安全管理员走完首批样例。

| 办理人 | 可办理事项 | 目标与限制 |
| --- | --- | --- |
| 客户实例的受控运维人员 | 首次引导、失去管理入口时恢复或交接首位安全管理员 | 引导时指定本客户实例和目标账号，恢复或交接时说明事由。引导仅在实例从未完成引导时生效，重复相同请求读回原结果。恢复使用客户保管的独立受控入口，保留原主体、授权变动和业务历史，撤销受影响主体的旧会话 |
| 获得账号管理权的人员 | 查找、开户、停用或重新启用范围内的普通账号。重置凭据需单独授权 | 账号有明确管理归属。首批可选本企业内的管理 BU 或由实例直接管理。经办人仅能选择获准归属。对授权超出其管理上限的账号进行重置或启停，须交相应实例负责人。受保护管理员的恢复与接替走受控入口 |
| 获得角色或策略管理权的人员 | 编辑并发布版本、停用已发布版本 | 角色只引用可授予的业务动作和字段。停用共享版本须有权管理所有仍有效或待生效的引用授予。仅负责部分人员时，可按权限收回自己可管理范围内的单份授予 |
| 获得授予管理权的人员 | 选择获管账号、授予已发布角色、采用指定新版本、按份撤销 | 目标账号和拟授予的动作、对象、字段、用途、期限均须在其明确的可授予范围内。管理账号和授予业务权限均不自动取得该业务的明细读权 |
| 部门或核编经办人 | 登录后在业务菜单办理获权事项 | 新普通账号初始业务权限为空。业务操作与角色发布、授予、重置凭据分别授权 |

<a id="x03-br-001"></a>**X03-BR-001 首位管理员与恢复。** 部署侧在客户实例内显式引导首位管理员，登记其账号管理范围和可授予上限。并发引导最多成功建立一份首位管理资格。首次登录或既有开发账号名称均不能触发提权。日常页面阻止自授管理权、通过修改共享角色扩大自己的管理权。会移除可用管理员资格的变更须保留至少一个可用管理入口。恢复可解锁或接替指定管理职责。交接时结束原管理资格并撤销旧会话，保留历史操作者身份及此前的业务撤权。

<a id="x03-br-002"></a>**X03-BR-002 账号边界。** 账号管理归属由开户时显式指定，独立于人员档案、任职和该人负责的业务范围。有甲 BU 管理权的人只能管理归属甲的普通账号。若变更账号归属，经办人须同时覆盖原归属和新归属。重置凭据和停用在同一提交中使该主体全部旧会话失效。开户和重置复用实例现有凭据规则，通过客户受控渠道交付秘密。页面读回、查回结果和日志仅表示办理状态。[现有身份与会话合同](../m02/013-m02-technical-design.md)

误停普通账号时可显式启用原主体。本人须重新登录，仅有此时仍生效的授予可以使用，已撤或到期授予继续失效。账号启停与业务授予在页面分别显示。

### 1.1 T01 隔离实例的职责与办理入口

## 2 一份授予能办什么

<a id="x03-br-003"></a>**X03-BR-003 委派与选择。** 管理员搜索账号只得到获管主体的登录名、可用显示名和管理归属。业务对象候选只返回可授予 BU、部门、岗位的稳定身份、编码和必要名称。Go 在保存时按同一范围重新核对角色、目标及字段。角色委派范围独立于管理员本人的业务读权。控制受保护管理员、代为授予管理权、读取人员或工资明细都需要各自的明确权限。无权对象的候选、数量和错误信息不透露其存在。

委派账号管理、角色发布或业务授权职责时，每项拟授出的完整许可都须由操作者一份有效的可委派授权覆盖，包括字段、用途和期限。获授业务办理权的人不能凭此再向别人授予该权。甲 BU 的可委派维护权和乙 BU 的可委派只读权不能用来授出乙 BU 维护权。

<a id="x03-br-004"></a>**X03-BR-004 完整授予。** 每份授予有独立 `grantId`，记录主体、授予来源、角色定义版本、数据范围和字段策略版本、用途、起止时刻及当前状态。来源可区分本职、临时代理和存量迁入。同一主体可以有两份相同角色及范围的授予。对一次操作，Go 先检查每一份授予是否同时满足动作、目标、所需字段、用途和时间，再合并完整许可。一次写入同一目标所需的字段须由一份完整授予覆盖。多目标命令逐项核验，任何一项失败则整笔不落库。强制限制或显式拒绝优先。[成组授权与执行](../../architecture/target/10-ddd-and-state-contracts.md)

授予时，只有角色包含多种可委派用途才需选择。经办时由服务端按业务动作确定实际用途。确需解释变更时可另填事由。

<a id="x03-br-005"></a>**X03-BR-005 生效、变更与收回。** 新授予可选立即或将来生效，明确选择长期或填写到期时刻。开始时刻包含，到期时刻起失权，由服务端当前时刻判定。角色或策略发布新版本后，原授予继续绑定原版本。显式采用新版本时，重新检查全部委派上限，在同一授予身份下保留原绑定与本次变更修订。停用旧版本后，所有引用该版本的授予停止提供许可。撤销指定授予只结束该份，已撤销或到期的授予保留来源，再授权产生新身份。业务记录的生效日期和历史查询日期均不能延长授权。[显示和输入规范](../../adr/026-date-display-and-input-format.md)

<a id="x03-br-006"></a>**X03-BR-006 部门和核编的可见范围。** 部门按 M02 提供的当前管理归属事实裁决。维护、历史、候选、导出分别验权。岗位核编可直接授予指定岗位和核编字段。仅有该权利的经办人从「设置 → 职务配置 → 部门编制分配」进入。只展示获权的岗位定位字段、额度和可见小计，隐藏其他岗位名字、未获权部门总额、待分配数及能据以反推的数据。岗位定义目录另行授权。存量依赖岗位目录的授予保留原读取条件。[部门功能合同](../m02/119-department-functional-design.md) · [核编正常入口与统计](../m03/313-position-capacity-contract.md#5-正常入口与应用合同)

<a id="x03-br-007"></a>**X03-BR-007 历史与安全事件。** 原业务记录、操作者、原件和提交回执按所属域保存。用户今天查历史、旧提交、旧选择或下载时，服务端重判其当前权限。已经提交的合法记录在撤权后保留。账号、凭据、角色及授予发生实际变更时，X03 记录操作者、目标身份、时间、动作、结果、请求关联及必要原因。普通成功读取的授权审计写入为零。[128 审计约束](../../adr/128-authorization-evidence-removal.md)

## 3 客户管理员从哪里办理

拟在「设置 → 安全管理」下提供三个入口。列表、表单和返回沿用已交付的主数据页面，实际变更在原账号、版本或授予上可查。X03 的角色发布和授权到期采用自身语义，按实际时刻显示，不套用按日主数据的默认生效日。[参考页面与公共表单](../m02/012-m02-functional-and-interaction-design.md#m02-ui-expression) · [列表与详情](../m02/012-m02-functional-and-interaction-design.md#m02-ui-list) · [动作](../m02/012-m02-functional-and-interaction-design.md#m02-ui-actions) · [历史](../m02/012-m02-functional-and-interaction-design.md#m02-ui-history)

| 菜单 | 办理及直接呈现的字段 | 保存后的反馈 |
| --- | --- | --- |
| 账号 | 按登录名、状态和获管归属查找。开户填写唯一登录名、管理归属及初始凭据，可填显示名。重置凭据、停用及重新启用分别按权显示 | 开户后显示账号身份及尚无业务授予。重置回到原账号并显示完成时间。停用后显示状态及实际变更。凭据仅在提交时输入 |
| 角色 | 在表单编辑职责名称、动作、范围和字段，直接发布。选择动作时显示业务入口，可按需查看对应 API。有策略管理权时可在同一表单发布或停用范围／字段策略，也可选用已发布版本 | 发布后显示版本供授予时选择。停用前提示引用该版本的授予将停止提供权限。只要有一份受影响授予超出管理范围，就拒绝停用并提示权限不足。管理员仍可单独撤销自己有权管理的授予 |
| 授权 | 按账号列出各份授权。新增时选角色版本、本职或代理、目标及期限。角色已确定的字段和用途直接显示。普通撤销选中具体一份即可，纠正误授时可补充事由 | 保存后定位该份授予，显示来源、范围、版本、有效期及实际变更。撤销一份后可看其余有效授予。可显式采用新版本，误授的范围可撤销后重新授予 |

取消保留原数据，离开未保存表单沿用共用保护。输入错误就地提示。版本冲突时重读当前版本，保留仍可见的输入。提交后断连、结果未知时才按原提交身份查回。下一次打开、刷新或提交时，页面按服务端结果清除已失权的详情、候选及敏感输入，仍可读时返回原列表定位。固定选择按 [X03-AC-006](#x03-ac-006) 办理。键盘和原生缩放沿用[共享视口规范](../m02/012-m02-functional-and-interaction-design.md#m02-ui-viewport-matrix)。

## 4 三组业务走查

在自有隔离实例建立甲、乙两个 BU（`X03A`、`X03B`），各一个部门。甲部门有两个启用岗位「甲岗一」「甲岗二」（`X03P1`、`X03P2`）。同一业务日甲部门总额 10，两岗已核额度分别为 2、3，无其他分配或用量冲突。主流程用一名只有管理权的客户安全管理员和一名经办人。第三组用隔离旧库里启动脚本会初始化的只读账号作第二名经办人，同时验证重启。按场景调整同一组示例的授权。

| 场景 | 操作 | 独立预期 |
| --- | --- | --- |
| <a id="x03-scn-001"></a>**X03-SCN-001 开户与跨 BU 办理** | 管理员在「账号」开户，经办人先登录。再授予甲部门维护及相应读权、乙部门只读。从一级「部门」分别查询、维护并按已授历史权查看原记录，最后单独授予导出权 | 初次登录无业务资料。授予后甲可保存，乙可读而写入被拒。取得导出权前无法导出，取得后 CSV 仅含获权对象及可读字段。页面与历史同样裁剪。取消编辑不生成变更 |
| <a id="x03-scn-002"></a>**X03-SCN-002 单岗核编与临时代理** | 对甲岗一授予本职和短期代理两份同角色、同范围的核编权，给出该岗定位及调整所需字段。经办人从「部门编制分配」将甲岗一由 2 调为 3。管理员撤代理，随后撤本职。另一次先撤本职，只留代理直至自然到期 | 经办人只见甲岗一，可见小计由 2 变 3。看不到甲岗二、部门两岗合计 6 或待分配 4，也不能打开岗位定义目录。撤第一份后仍可办理，撤最后一份或到期后再保存失败。经办人重新取得该岗必要的读取和历史权后，可查到原调整 |
| <a id="x03-scn-003"></a>**X03-SCN-003 共享版本、历史与重启** | 两名经办人引用同版角色，可读甲部门、查历史、更正及导出。新账号的这些权限均来自该角色。发布带「新增记录」动作的版本，仅为旧库账号显式采用。两人将列表筛到甲部门、全选并保留该标签页，另开标签页查看历史、打开更正表单，再停用旧版。最后在管理页面撤尽旧库账号的部门读权，重走正常启动 | 发布时两人原权不扩张。采用者取得新增记录权，仍可用原选择导出。另一人失去必要权限，下载整笔拒绝，旧表单保存也被拒。旧库账号在撤权后及重启登录后均读不到甲部门。原办理人重新获准查回时仍能核对原提交和历史 |

## 5 验收条目

| 条目 | 预期业务结果 |
| --- | --- |
| <a id="x03-ac-001"></a>**X03-AC-001 账号与恢复** | 初次引导、并发重复引导、受控恢复有明确结果。新账号零业务权。两个既有会话在重置或停用后均失效。重置前的口令不能再登录，停用账号不能新登录。误停后显式启用，旧会话和已撤授予仍失效，原主体、历史及安全事件可追溯 |
| <a id="x03-ac-002"></a>**X03-AC-002 管理边界** | 开户、重置、发布、授予可以分别委派。页面和候选只显示获准目标，直接调用管理 API 同样拒绝越界或自提权。实例不匹配或超出已配置的代理期限上限时拒绝。只有授权管理权的人能认出获管目标，只能读该职责所需信息 |
| <a id="x03-ac-003"></a>**X03-AC-003 动作、对象与字段** | 走完甲维护乙只读及单岗案例。两份分别只含部分写字段的授予不能拼成一次完整写入。核编表单、历史、导航及统计仅返回获权岗位和字段。多岗调剂涉及一个未获权岗位时全部无变更 |
| <a id="x03-ac-004"></a>**X03-AC-004 按份收回与到期** | 撤任一重叠授予后另一份按原范围生效。最后一份撤销或在截止时刻到期后，新请求、旧编辑表单和历史读均重判。尚未生效、开始时刻、到期前、到期时刻四个边界可复验 |
| <a id="x03-ac-005"></a>**X03-AC-005 共享版本与提交顺序** | 两个主体共享角色或字段策略，分别验证显式采用和停用。两个真实连接分别让业务提交或撤权先取得相冲突的守卫。先合法提交的只出现一次，撤权先提交时业务事务拒绝且无业务副作用。来源事实失效或等待期间到期时按新事实处理 |
| <a id="x03-ac-006"></a>**X03-AC-006 全部读出口** | 部门树、列表、候选、历史及核编详情和汇总按当前权返回。全选固定对象身份，撤一份重叠授予后仍有完整权限可继续导出。选中成员失去必要读权或导出权时整笔零文件，仍有必要权时按当前字段权裁剪。响应和旧页重读均不披露无权对象及可反推的总计。[部门选择与 CSV](../m02/118-department-business-requirements.md#m02-br-033) |
| <a id="x03-ac-007"></a>**X03-AC-007 迁移、重启与历史保护** | 隔离库升级前后的全部实际权限逐主体对得上，既有拒绝条件仍生效。管理员从页面撤掉原会被初始化补齐的权限，同一经办人重启后仍失权。保留主体、原凭据、历史操作者及回执，获权者能查原提交。[迁移与重启](../../plans/027-x03-local-access-rollout.md#4-存量迁移与重启) |
| <a id="x03-ac-008"></a>**X03-AC-008 办理反馈与审计** | 经办人从正常菜单完成保存、取消及更正，刷新后仍可定位。版本冲突就地处理，断连后能查回已受理的操作。账号和授权变更可追溯到操作者和目标，页面收到拒绝或收窄结果后清除失权内容，普通成功读取不写逐次授权审计。视口走查沿用 [027 的验证安排](../../plans/027-x03-local-access-rollout.md#6-验收与关闭) |
