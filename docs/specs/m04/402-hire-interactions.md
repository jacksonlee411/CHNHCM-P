# CHNHCM-402 入职准备与办理页面合同

下列入口是本次方案的交付目标。T02 的组织和政策管理员维护办理条件，T03 的人事经办人从原人员档案办理。当前用户能看到的动作、候选、范围及错误均由 Go 返回。[实施方案](../../plans/400-hire-readiness.md) · [业务规则与验收](401-direct-hire-requirements.md) · [登记表](../../governance/registry.json)

## 1 从哪一页办理

| 角色与正常入口 | 页面任务、保存与返回 |
| --- | --- |
| 组织管理员从「设置 → 组织配置 → 法律实体 → 所选主体 → 用途与绑定」进入 | 在原主体查看各用途的生效日期、结束边界、资格依据和适用上下文。获权者新增或从原值更正，直接保存。同一主体可有多种用途。查看原件按准确版本返回，回列表恢复原筛选、页码、滚动与焦点。 |
| 职务配置管理员从「设置 → 职务配置 → 任职与占编规则」进入 | 按企业、人员类别、用途查规则。详情展示所选期间的模式及是否占编。新建或更正时，企业及类别、用途、日期和规则值一次保存。仅按职务时自动呈现零占编。显示冲突期间时按当前权限裁剪。 |
| 获权人事从「人员 → 员工 → 人员档案 → 本人 → 办理入职」进入 | 档案查询可找到尚无任职的人。首单保存后定位本人 0 号主岗的新任期、生效日及办理，员工列表以各份获权任职列行。原详情入口和既有任职链接复用同一办理。查看原件或撤销未来入职从该笔进入，返回恢复原人及名录位置。[页签与现有入口衔接](507-job-information-tab.md#job-tab-layout) |
| 需要补资料时从同一人的「个人资料」进入 | 现有资料够用时留在入职页。有权人可见实际缺项，有资料维护权者可直接去原档更正并返回，入职草稿保留。只有用工政策明确要求人工核验时才进入相应核验。 |

组织用途与岗位政策是按日配置。首次建配置默认 1900-01-01，可显式修改，所选主体或依赖未生效时指出合法边界。已有配置从所选记录进入。入职填写实际约定的业务日，更正带出原日期。读取来源历史时锁定原件并提供返回。[日期规范](../../adr/026-date-display-and-input-format.md) · [首次配置日期](../../adr/202-master-data-default-effective-date.md) · [按日对象接入矩阵](../m02/121-dated-object-admission-matrix.md)

| 按 121 对照的对象 | 新增、期间调整、停用与历史的取舍 |
| --- | --- |
| 主体用途和必要绑定 | 用途在原法律实体下维护，绑定定位到指定用途与上下文。从所选段带入原值，可新增、在已有边界之间插入、改期、更正依据或明确结束用途／绑定。调整前核全段及已接入的反向引用。结束一种用途不停止该主体的其他用途。已发布修订可查。 |
| 任职与占编政策 | 列表按规则作用范围定位，详情按所选日期维护。换版有明确起日，已发布版本通过后继修订更正、改期或结束。缺段或重叠直接指出受影响范围。旧任职的政策采用留存。 |
| 入职动作与日级任职 | 从原人发起，保留同日多动作入口、独立修订及必要的未来撤销。入职业务日按实际任用安排填写，不套配置首日、通用记录删除或启停成对动作。本批的选择用于办理单个目标，批量导出另依获准的用途。 |

## 2 入职表单与反馈

从原人进入，已有资料与任用决定带出已知值，经办人补齐拟任安排，一次保存。Go 随输入核对资格，无需先点预览、逐段确认或领取核对任务。桌面沿用共享紧凑表单，窄屏按同一顺序单列。原件、资格来源及分段明细按需查看。

| 字段或内容 | 值从哪里来、何时填写 | 拒绝与反馈 |
| --- | --- | --- |
| 姓名、人员编号 | 带入原档摘要。在获权人员范围内按入职核对用途读取最小结果，无需抄证号、上传证件或填写“已核验”。 | 现有资料无法支持本次用工规则时提示具体缺项。无证件明文权的页面、API 和迟到响应只含获权内容。 |
| 人事依据、办理原因与必要决定 | 已有任用决定或通知直接引用一次，多人通知定位本人。手工办理可直接写无编号通知等实际来源的简短说明。有可识别的单号才按原样填写。唯一原因自动带入，有多个适用原因才选。需要单独核准时优先沿用已匹配的决定。 | 缺真实依据、通知与安排矛盾或所需决定失效时指出该项。普通办理免填附件、行号、签字或复核单。能查到同一已办安排时按权限定位原办理。 |
| 关系性质、人员类别、用人单位及实际用工单位 | 根据真实安排填写。按拟任期间搜索获权且合格的主体，只有派遣等确有两个角色的安排才同时填写。数家合格时由经办人选定。 | 资格缺段时向有权者显示首个不合格期间及可查看的依据。受限者只得统一的不可办理反馈。 |
| 到岗日、任期至（含当日）、部门、职务 | 到岗日必填，结束未定可留空。任期至是最后一个拟任日，Go 将其次日作为排他上界。原单给出首个不在任日时按其明确语义换算一次。组织与职务候选随日期和范围重新读取。 | 任期至早于到岗日或来源过期时保留其他获权输入。将光标移至错误摘要或字段，筛选结果为空时可调整条件。 |
| 岗位及用量 | 仅按职务填写部门和职务。按岗段选岗位并带出部门和职务。Go 自动按日期拆段。同一岗位从免占转占编时岗位只选一次，只有需新增或改变岗位的期间才要输入。 | 政策缺失或岗位确有冲突时，向获权者显示受影响期间及原因。用量由系统核对，经办人无需提交余编证明。 |
| 主关系、主任职 | 首次只有本关系和本任职时随保存确定，两项均免选。已有有效选择时沿用。多项管理选择确需取舍时才显示相应控件，选择须符合 0 号主岗规则。首聘主岗编号 0 由系统确定。 | 原选择受限时保留其业务效果，只给当前可披露的信息。无权变动且必须重选时整笔拒绝。 |

## 3 同日记录、取消与结果未知

在人员详情区分两种问题。「该日任职」显示业务日的最终适用值。「办理记录」按日期分组，每项真实动作均能单独选中，展开时显示发生时的组织、获权差异、依据和操作者的北京时间。业务前序明确时按链解释，独立动作可稳定排列。点开一次晋升能看见当时部门，返回后保留原日期、选中动作及滚动位置。薪酬、工资及受限任职的存在性须按所属用途另行授权。[同日规则](401-direct-hire-requirements.md#m04-br-008) · [历史阅读标准](../m02/012-m02-functional-and-interaction-design.md#m02-ui-history)

从原办理更正时带入原值，Go 识别实际修改。同值可直接退出。撤销未来入职时列出本次实际影响，引用已有撤回通知或简述真实原因，一次提交。正常更正和撤销带入原办理信息。客户另有材料要求时沿用对应业务来源。只有未保存的输入触发离开保护。结果未知时系统沿原提交号查回，查明未执行后允许重新办理。业务拒绝保留仍获权的输入。切换人员、撤权、退出会话后清除受限内容，过期响应不能回填。[恢复合同](403-hire-technical-contract.md#hire-recovery)

有权经办人可在原档补证后回到原草稿。随后放弃入职，已保存的人员更正仍可查，工作关系、任职和占编均为零。需他人维护时只保留获权草稿，原档更新后重读。存储恢复定位时只保留客户、主体及提交引用，受限正文和号码不写入浏览器持久存储。
