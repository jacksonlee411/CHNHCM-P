# CHNHCM-506 M04 职务信息与任职记录业务规则

人事经办人从「人员 → 员工」打开任职行，在「职务信息」按业务日直接办理。首次入职从已登记的人员档案发起。M01 保管一份人员档案，M04 保管工作关系、任职、雇用记录编号及每笔办理，M02、M03 提供组织、职务、岗位及相应政策。首期由有权经办人直接保存，所需输入按办理事项确定。首次入职的材料和资格沿用 401，审批流留待后续业务接入。[401 入职规则](401-direct-hire-requirements.md#m04-br-003) · [507 页面](507-job-information-tab.md) · [500 实施次序](../../plans/500-personnel-roadmap.md#job-information-delivery) · [登记表](../../governance/registry.json)

## 1 一个人、多份任职与每天的资料

<a id="m04-br-009"></a>
**M04-BR-009 每人终身只有一个 0 号主岗。** 雇用记录编号由 M04 在同一客户内按人管理。首次入职建立 0 号主岗记录，离职后该号永久留给本人，再聘仍用原 0 号。兼岗编号从 1 起，新增时取本人历来已发最大号加一。已有在任主岗时，即使新兼岗是另一段并行工作关系的首份任职，也接着本人的号码分配。兼岗结束或已保存的安排被撤销后，原号仍归原记录。换部门、跨工作关系、改人员编号、调动、更正或改日都不重排已发号码。主兼岗转换在本期范围外。

| 周宁的办理顺序 | 雇用记录编号 | 打开履历所见 |
| --- | --- | --- |
| 首次在产品部入职为产品经理 | 0 主岗 | 0 号记录下有一笔入职及本段起始日。 |
| 增任产品部评审员，再增任培训部讲师 | 1 兼岗、2 兼岗 | 每份兼岗各有一行、各有首笔办理。产品部内的 0、1 两行可分别打开。 |
| 结束两份兼岗，随后离职 | 1、2 分别结束，0 号记离职 | 三份履历和各自结束日期均可追溯，离职间隔没有在任主岗。 |
| 再聘为主岗，之后新增一份兼岗 | 再聘仍用 0，新兼岗用 3 | 0 号下追加一笔再聘。前后两段工作关系、任职期间及原件分别保留，1、2 号仍为已结束。 |

人员编号标识本人。雇用记录编号区分本人的主岗和各份兼岗。每段工作关系及其实际任职各有稳定身份。再聘建立新的工作关系和任职，接入本人既有的 0 号履历。旧段止于原结束边界，新段起于实际到岗日，同一业务日最多有一段有效的 0 号任职。每笔办理固定其实际关系、任职、日期及来源。[再聘对象边界](../../architecture/target/modules/m04.md) · [读写与升级](403-hire-technical-contract.md#job-information-handoff)

401 的两层主选择用于按日确定人事管理归属。人层主关系中的主任职与当日有效的 0 号一致。另一段并行关系可以有自己的关系内主任职，在员工列表仍按其正号标兼岗。若单独结束 0 号将使仍要求主任职的期间失去覆盖，整笔拒绝，指出获权可见的冲突期间。全部退出时可为零份在任，原编号和履历继续保留。[两层主选择](401-direct-hire-requirements.md#m04-br-006)

员工列表按所看业务日将每份获权任职独立列行，同部门也分别列行。任职数按有效任职计，人数按人去重，岗位占编按各段的 M03 政策计算。一主两兼可为 3 份任职、1 人，其中免占的一份占编增量为零。[列表与页签](507-job-information-tab.md#job-tab-layout) · [计数样本](../../plans/500-personnel-roadmap.md#m04-scn-002) · [岗位采用规则](401-direct-hire-requirements.md#m04-br-005)

## 2 记录操作与业务类型的绑定

本项目参考 PeopleSoft 按任职维护 Job Data，以及本地 Bugs-And-Blossoms 的 899、894 合同。前者给出按行办理的模型，后者将新建、追加、插入、更正、删除与业务分类分开。下表取其业务区分，采用 CHNHCM 自身的首单撤销和同日多动作规则。[PeopleSoft 职务记录维护](https://docs.oracle.com/en/applications/peoplesoft/human-capital-management/9.2.055/peoplesoft-human-resources-administer-workforce/fluid-updating-job-data.html) · [本地参考版本和章节](../../reference/506-job-information-sources.json)

PeopleSoft 的 Bobby 示例在原 0 号记录上办理再聘。其 Job Indicator 单独表示组织关系内的主次。本项目采纳按雇用记录保留履历的做法，并明确约定主岗终身为 0、正号用于兼岗。[Oracle 再聘示例](https://docs.oracle.com/en/applications/peoplesoft/human-capital-management/9.2.055/peoplesoft-human-resources-administer-workforce/understanding-job-data.html) · [Oracle Job Indicator 字段](https://docs.oracle.com/en/applications/peoplesoft/human-capital-management/9.2.055/peoplesoft-human-resources-administer-workforce/fluid-adding-organizational-instances.html)

<a id="m04-br-010"></a>
**M04-BR-010 每笔办理同时确定记录操作和业务类型。** 记录操作说明“怎样处理哪条记录”，业务类型说明“发生了什么”，原因说明“为什么”。每一类业务类型绑定一种由 M04 Go 解释的处理方式，确定目标是工作关系、任职还是主选择，以及可改字段、状态变化和需要联动的对象。Go 按目标、业务日、目录版本、当前授权与前后记录返回可办理组合，提交时重核。唯一原因自动带入，有多个时只选所选类型下的有效原因。每笔保存当时的分类、规则版本、经办人、记录时刻及实际变化，有业务依据时保留其来源。[M04 动作目录](../../architecture/target/modules/m04.md) · [提交与来源](403-hire-technical-contract.md#job-information-handoff)

| 经办人的记录操作 | 允许的业务意图与目标 | 保存后的履历 |
| --- | --- | --- |
| 新建任职 | 首次入职建立 0 号，再聘在原 0 号下建立新任期。从已有关系「新增兼岗」取得本人的下一个正号。 | 实际任职与其首笔办理同笔保存。原单重送查回原结果和雇用记录编号。 |
| 新增记录 | 在所选对象履历的末日增记同日动作，或登记后来生效的动作。可办类型包括数据更改、转正、晋升、调动、结束任职或离职。 | 每个真实动作取得独立办理身份。一项决定可在一笔中调整多个字段。两项独立事实须共同生效时，可从原任职办理「晋升并调动」。[晋升规则](#m04-br-013) |
| 插入记录 | 从历史位置补登当时确已发生、此前漏记的数据更改或其他获准业务。所选日已有另一笔办理也可补登。 | 新增一笔业务记录，重核受影响日期和后继。普通任职变动须在相应任职期间内，首日有误回到创建该任职的原办理核对。 |
| 更正记录 | 选中录错的原办理，带入其日期、原类型、原原因和获权原值。可改日期、允许的字段及原因。类型纠错限处理方式和目标一致的合法分类。 | 保持原办理身份，追加不可变修订，必要时重排日期节点。原修订和原采用可查，无实质修改时零写入。跨生命周期含义的错误由相应有据撤销或专用纠错办理。 |
| 删除记录或撤销原办理 | 作用于当前来源中的原办理与期望修订。整笔普通数据更改系误建时用「删除记录」。通知取消尚未生效的入职时用「撤销入职」。误录整笔晋升时从原笔「撤销晋升」，引用能说明误录的原通知或简述误录原因。 | 撤去目标的业务效果，保留原分类、原件、处置记录、原回执及仍成立的其他办理。真实晋升仅值录错时更正原笔，后来实际降级、调回、结束兼岗或离职各另记其真实动作。 |

普通地点变更按生效日、业务原因和新地点保存，更正错字沿用原分类及已有来源，只提交实际改动。两者免填任用通知和另行说明。入职、转正、晋升等需要人事依据的事项，直接引用已有决定、通知或名单本人行，手工通知可简述来源。只有客户政策明确要求单独核准或职责分离时，系统才核对相应决定及适用范围，已满足条件的决定直接沿用。经办人无需勾选审批程序确认。[必要决定](401-direct-hire-requirements.md#m04-br-003)

放弃草稿零写入。删除、更正和改日涉及已采用记录、主选择、岗位资源或后继依赖时，服务端按本次办理校验。补录实际履职按下文的实况规则处理。[三种办理结果](401-direct-hire-requirements.md#m04-br-007) · [同日依赖与撤销](403-hire-technical-contract.md#hire-actions)

## 3 业务类型改变哪些事实

<a id="m04-br-011"></a>
**M04-BR-011 业务效果跟随事实所属对象。** 本表规定直接办理的结果。页签按实施批次开放已交付的组合，操作名称、状态和字段权均取服务端结果。

| 业务类型 | 前置及写入对象 | 经办人与下游可核对的结果 |
| --- | --- | --- |
| 入职、录用转入职 | 已有原人及任用依据，创建工作关系与首任职 | 可提前办理，自约定到岗日计入在职。M05 发出或接受录用留在招聘，T06 从已接受且资料齐备的原录用提交同一入职，原单重送只定位已办结果。 |
| 数据更改 | 所选日期内可维护的任职 | 从某日起更换工作地点，生命周期状态和雇用记录编号沿用原安排。按职务与按岗位分别取合法字段，岗位派生的部门、职务由岗位带出。人员证件、私人电话等资料从 M01 原档维护。 |
| 转正 | 适用试用、在该动作前仍处于试用中的工作关系 | 依据实际开始与实际转正日将该关系从试用中转为已转正。各任职按权展示同一事实，整段关系只计一次转正。计划日期供核对，调岗后沿原关系办理。合同约定由 T05 持有，延期、中断及跨关系试用按适用政策另核。 |
| 晋升 | 所选实际任期内有任用依据，拟任职级在该段有效且符合任职资格 | 在该任职记载原职级、拟任职级、发生部门、依据和生效日。原岗晋升沿用原岗位及适用占编。晋升可与独立调动在同日分别追溯。[晋升与共同办理](#m04-br-013) |
| 调动 | 当前关系中的原任职，以及受影响的汇报、主选择或岗位资源 | 按职务核部门与职务。按岗的拟调入核补员状态，占编段另核名额。已有工作关系下漏记实际派岗或日期有误时，有事实更正权的人事从原任职补录或更正，凭已有履职资料登记实际岗位与期间。满编或暂停补员时按适用政策记实际用量和差额。跨主体、两岗对调与交接按实际安排办理。[已实际履职](../m03/313-position-capacity-contract.md#m03-br-036) · [调动与交接](../m03/313-position-capacity-contract.md#m03-br-037) |
| 正式兼岗 | 在实际所属工作关系新增独立职责，按人分配新正号 | 新任职有自己的首笔办理、生效期间、部门、职务及适用岗位。部门相同也各有一行。岗位用量按政策另计。 |
| 结束任职、离职 | 一份在履任职或指定的有效工作关系 | 结束兼岗只结束目标任职及其实际关联。离职一并处理该关系下的任职、主选择、实际汇报和适用占编，独立关系继续按原安排有效。该笔必须处置的合同、接替或后继未解决时整笔拒绝。 |
| 再聘 | 离职后凭新的人事依据建立新的工作关系和主岗任职 | 本人人员编号及雇用记录 0 号沿用，在 0 号时间轴追加再聘。新任期自到岗日生效，旧任期、已结束兼岗及办理原件可按权查阅。 |

工作关系的在职状态、适用关系的试用状态按业务日读取，主兼岗由本人的雇用记录编号确定。例如，员工可以同时在职、处于试用期并担任一份兼岗。「尚未生效」由所看记录的生效日与服务端今日比较得出。

日期取真实业务依据。若经办人输入「最后在职日（含）」为 2027-08-31，旧关系覆盖至该日，排他上界为 2027-09-01。原通知直接给出「首个不在职日」时按该日作上界，办理保留原日期及其含义。终止记录即使落在有效期的边界，也能从已结束的关系或任职追溯。[同日交接](../../adr/106-same-day-personnel-actions-and-daily-state.md#29-同日离职与入职的对象边界) · [两岗交接](../m03/313-position-capacity-contract.md#m03-br-037)

<a id="m04-br-013"></a>
### 3.1 M04-BR-013 晋升与调动

原职级取 M04 中该任职在本动作之前的实际职级。旧任期缺记时显示「未记载」，如资格核对需要原职级，可凭原任用依据从真实生效日补登。拟任职级取 M03 同期间启用且属于目标职务可用集合的职级，按岗位办理还须满足实际适用的岗位资格。晋升性质按任用依据和适用规则认定，规则使用阶梯时取其确切版本。职级代码没有全局高低顺序。M04 保存个人任职采用及前后值，调薪金额与工资采用分别归 M09、M10。[职务可用职级](../m03/310-grade-ladder-contract.md#m03-br-017) · [职级阶梯](../m03/310-grade-ladder-contract.md#m03-br-018) · [岗位资料](../m03/312-position-contract.md)

一项晋升决定同时调整部门或岗位时，按该类型允许的字段记一笔晋升。依据分别载明晋升和调动两项事实时各计一笔，同一份通知可作为两笔的依据。逐笔办理后的安排均合法时，可以分别保存。两项必须共同成立时，从同一任职选「晋升并调动」，用同一业务日一次保存。成功后有两笔各自可查的原件、一份该日日级任职结果。占编按实际岗位变化结算一次。[106 合法组合](../../adr/106-same-day-personnel-actions-and-daily-state.md#25-来源版本与保存流程) · [313 调动口径](../m03/313-position-capacity-contract.md#m03-br-037)

有撤销权的经办人可沿用只载调动的原通知，或在原晋升上简述可追溯的误录原因，一次保存。Go 重核后继资格。若调入岗位在原职级仍合法，撤销晋升后保留调动、回到原职级。若调入岗位必须具备新职级，单独撤销整笔拒绝。原来源保留当时的职级及晋升次数，已被下游采用的修订可按权追溯。[只撤晋升的业务场景](401-direct-hire-requirements.md#m04-ac-006) · [前后来源对照](#m04-scn-018)

<a id="m04-br-014"></a>
### 3.2 M04-BR-014 关系级转正的发生部门

通知明确载明本次转正的业务发生部门时，采用与该关系、业务日相符的部门及依据。落款或签发部门本身不能确定发生部门。通知未载时，取**该工作关系在人事管理用途下、转正动作发生前的主任职部门**。同日已有调动，以经确认的业务先后还原当时的主任职归属。另一段并行关系有自己的主任职，即使该任职编号为正号，也取本关系的归属。经办人从哪份任职进入、哪份任职对读者可见，都不改变取值。[两层主选择](401-direct-hire-requirements.md#m04-br-006)

明确记载与关系或日期不符时，系统指出具体冲突。通知未载且按关系事实无法唯一还原、只影响统计归属时，系统记「发生部门未确定」，自动记录可判明的原因。该笔计入获权的关系转正总数，各具名部门计零。只有缺项会改变任职结果、资格或授权时，才请经办人核对相应事实。转正核本关系的动作权及适用组织范围。相关任职只引用同一笔转正，展示该结果无需逐岗写权或部门会签。只获转正摘要的读者，其字段、部门候选、筛选计数及原件均按披露范围裁剪。

## 4 同日办理、修订与可见范围

同一任职在同一确切来源内，每个业务日至多一份适用状态，区间为非空 `[start,end)`。时间轴按业务日分组，每项有效动作用独立身份计数。点击一笔动作读取其发生时的组织、前后值和依据。点击「该日任职」读取按所选来源核定的日级结果。关系级转正可从获权的相关行进入同笔办理。更正次数另计，多个展示入口共用同一业务身份。[同日业务规则](401-direct-hire-requirements.md#m04-br-008) · [106 的首单采纳范围](../../adr/106-same-day-personnel-actions-and-daily-state.md#first-hire-adoption)

先后由确切业务前序解释，必要依赖另行记录。原记录或通知已载明先后时，系统带入相应办理。经办人也可从同日已办事项之前补录当时漏记的事实。独立动作直接保存，可按任意顺序录入。仅在不同解释会改变任职结果、资格或权限时才请经办人核对有歧义的那一项。无法化解的同字段冲突保留原来源。业务日、实际发生时刻和系统记录时刻分别保存，来源只载日期时由系统记明，无需补填时刻。[前序与提交](403-hire-technical-contract.md#same-day-action-write)

人员、工作关系、所选任职、办理动作、字段及原件分别按当前权限读取和写入。只见兼岗的读者只见其获权行、处理结果和差异，可见范围同样用于候选、计数、原件、回执与深链接。实际改变多份任职时须具备相应办理范围，失权时只返回获准披露的反馈。薪酬、工资、招聘记录及岗位定义各由源域维护。[X03 授权](../../architecture/target/modules/x03.md)

<a id="m04-br-012"></a>
**M04-BR-012 人事事务按一笔业务办理列行。** 「人员 → 人事事务 → 办理记录」可跨人员、跨业务日查询。入职、转正、晋升、调动、离职及普通任职数据更改各按实际办理记载。任职级办理归实际任期和雇用记录编号，关系级办理归实际工作关系。从同一关系的三份任职看到一次转正，在办理列表只占一行。任职详情的「当日办理」与此行共用同一办理身份。原单重送沿用原笔，更正记入其修订。误建删除或撤销后原笔及处置依据可查，原事项的有效发生次数为零。实际发生的反向调动另记一笔。[办理记录页面](507-job-information-tab.md#personnel-action-register) · [106 事件次数](../../adr/106-same-day-personnel-actions-and-daily-state.md#26-事件次数与人员数量)

按部门查办理，用动作确切来源记载的发生部门。调动保留当时的调出和调入部门，可分别查询。员工列表的部门树取所选业务日的任职归属。按生效日期查事项，按办理时间查原经办人首次保存这笔事项的时刻。后续更正的经办人、时刻和实际修改进该笔修订。经办人按事项要求直接保存，后续需要派发的待办由 M20 承接。[员工列表口径](#m04-br-009) · [业务待办视图](../../architecture/target/modules/m20.md)

### 5.1 M04-SCN-018 从实际任职办理到原晋升撤销

沿用上一行周宁的样本。2026-12-01 的 0 号主岗为研发部、试用中、P5，2 号兼岗在培训部。同一关系的主任职为 0 号。原职务及调入职务都接受 P5、P6，转正、晋升、调动有明确业务先后，调动资格独立于晋升。从菜单实际保存三笔，每一步按**当时的来源**查询 2026-12-02。次数只计周宁当日的有效事项。[正常菜单验收](507-job-information-tab.md#m04-ac-018)

| 本次办理 | 该来源中的 0 号日级任职 | 转正／晋升／调动次数 | 核对原件 |
| --- | --- | --- | --- |
| 从 2 号兼岗进入所属关系办理转正，通知未载部门 | 研发部、已转正、P5 | 1／0／0 | 转正归该关系，发生部门为研发部。从 0 号查回同一笔。 |
| 从 0 号办理晋升 | 研发部、已转正、P6 | 1／1／0 | 晋升原件记研发部、P5 → P6，承接确切转正修订。 |
| 再从 0 号调往产品部 | 产品部、已转正、P6 | 1／1／1 | 调动承接晋升。点击晋升仍见研发部。该日仅一个日期节点，员工列表仍为三份任职、一人。 |
| 更正晋升原因 | 产品部、已转正、P6 | 1／1／1 | 原晋升身份沿用，原原因在旧修订可查。 |
| 核对原通知后发现本人的事项只有调动，从原晋升引用该通知并保存撤销 | 产品部、已转正、P5 | 1／0／1 | 转正和原调动仍有效。办理列表含已撤销时仍有三行，其中两笔有效。打开撤销前的来源仍见 P6 及晋升一次，原采用可查。另从相同初始资料只简述误录原因，也能完成同一次撤销。 |

用相同初始资料另走一次，从 0 号发起同一通知的转正，再从 2 号查回。两种入口的发生部门都是研发部。在同一试用期从两处重办同一已办安排时仅得原转正。另以通知明确载明培训部且与该关系相符的样本，验发生部门为培训部。再验一段并行关系，其人事管理主任职为质量部的 3 号，通知未载部门时该关系转正归质量部。仅获周宁原关系转正及培训任职读权、无研发部门披露权的读者仍可查看获权转正，通过部门条件、数量、原件或链接均查不到受限归属。[转正部门取值](#m04-br-014)

若通知未载部门，同日调动前后分属研发部、产品部且先后未知，经办人有本关系转正权、可独立核定资格，只见培训兼岗即可一次保存。系统记录归属未确定及原因，关系总数一笔、两个具名部门各零笔。再用须按发生部门授权的样本，系统只提示获准披露的缺项，归属仍无法核定时拒绝并保持零业务写入。

<a id="m04-scn-019"></a>
### 5.2 M04-SCN-019 只有晋升与调动共同成立才合法

使用另一份已转正的 P5 任职，原岗只允许 P5，新岗只允许 P6。同一通知明确载有晋升与调动两项独立决定，要求两项在同一业务日共同生效。单独晋升将出现「原岗、P6」，单独调动将出现「新岗、P5」，两次尝试均应拒绝，原岗及原职级仍有效。按职务模式先用两个职务各自的可用职级集合验证同一反例，按岗位模式另核实际岗位及其用量。

<a id="m04-ac-019"></a>
**M04-AC-019 专用办理的事务验收。** 从原任职直接进入「晋升并调动」。共用通知只选一次，两项各自唯一的原因自动带入。一次保存后，新岗、P6 同时生效，晋升一笔、调动一笔、该任职当日一份适用状态。两笔原件分别展示同一通知的准确来源。另用两份各载一项决定的通知，核对每笔只引用本项通知。注入第二项写入或资源写入失败，业务记录、日状态、占编变化及待发事件全部回滚。提交后断线，用原提交号重送查回同两笔及原回执。只撤晋升会使新岗使用 P5，应整笔拒绝，当前来源、两笔有效动作和岗位用量均保持。用同岗位政策另验只有一项晋升事实且同时换岗的通知，业务次数为晋升一笔、独立调动零笔。[共同提交及撤销合同](403-hire-technical-contract.md#same-day-action-write)

### 5.3 从已有任职补录实际履职

沿用 313 的门店岗样本。岗位核定 3 人、已占 3 人，明日拟调入第 4 人时，提示缺 1 编，现有安排保持。另以该员工已于 2027-04-01 至 2027-04-03 实际履职为前提，有事实更正权的人事于 2027-04-04 从原任职补录。采用能核实实际履职的现有资料，本例沿用派岗和出勤记录。一次保存后，这三天核 3、实占 4、超编 1，履职结束的次日实占回到 3。原定额、他人的预留均保留，重送沿用原办理。另验暂停补员期间已实际履职的情形。只有过去日期、缺实际履职依据或事实更正权的请求，不能走实况办理。[313 日期与用量预期](../m03/313-position-capacity-contract.md#m03-ac-129) · [职务信息入口](507-job-information-tab.md#actual-duty-entry)
