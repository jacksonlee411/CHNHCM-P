# CHNHCM-506 M04 职务信息与任职记录业务规则

人事经办人从「人员 → 员工」打开任职行，在「职务信息」按业务日直接办理。首次入职从已登记的人员档案发起。M01 保管一份人员档案，M04 保管工作关系、任职、雇用记录编号及每笔办理，M02、M03 提供组织、职务、岗位及相应政策。首次直接入职的材料和资格沿用 401，首期凭有效授权与人事依据直接保存，审批流留待后续业务接入。[401 入职规则](401-direct-hire-requirements.md#m04-br-003) · [507 页面](507-job-information-tab.md) · [500 实施次序](../../plans/500-personnel-roadmap.md#job-information-delivery) · [登记表](../../governance/registry.json)

## 1 一个人、多份任职与每天的资料

<a id="m04-br-009"></a>
**M04-BR-009 每人终身只有一个 0 号主岗。** 雇用记录编号由 M04 在同一客户内按人管理。首次入职建立 0 号主岗记录，离职后该号永久留给本人，再聘仍用原 0 号。兼岗编号从 1 起，新增时取本人历来已发最大号加一。已有在任主岗时，即使新兼岗是另一段并行工作关系的首份任职，也接着本人的号码分配。兼岗结束或已保存的安排被撤销后，原号仍归原记录。换部门、跨工作关系、改人员编号、调动、更正或改日都不重排已发号码。主兼岗转换在本期范围外。

| 周宁的办理顺序 | 雇用记录编号 | 打开履历所见 |
| --- | --- | --- |
| 首次在产品部入职为产品经理 | 0 主岗 | 0 号记录下有一笔入职及本段起始日。 |
| 增任产品部评审员，再增任培训部讲师 | 1 兼岗、2 兼岗 | 每份兼岗各有一行、各有首笔办理。产品部内的 0、1 两行可分别打开。 |
| 结束两份兼岗，随后离职 | 1、2 分别结束，0 号记离职 | 三份履历和各自结束日期均可追溯，离职间隔没有在任主岗。 |
| 再聘为主岗，之后新增一份兼岗 | 再聘仍用 0，新兼岗用 3 | 0 号下追加一笔再聘。前后两段工作关系、任职期间及原件分别保留，1、2 号仍为已结束。 |

人员编号标识本人。雇用记录编号区分本人的主岗和各份兼岗。每段工作关系及其实际任职各有稳定身份。再聘建立新的工作关系和任职，接入本人既有的 0 号履历。旧段止于原结束边界，新段起于实际到岗日，同一业务日最多有一段有效的 0 号任职。每笔办理固定其实际关系、任职、日期及来源。[再聘对象边界](../../architecture/target/modules/m04.md) · [读写与升级](403-hire-technical-contract.md#job-information-handoff)

401 的两层主选择用于按日确定人事管理归属。人层主关系中的主任职与当日有效的 0 号一致。另一段并行关系可以有自己的关系内主任职，在员工列表仍按其正号标兼岗。若单独结束 0 号将使仍要求主任职的期间失去覆盖，整笔拒绝，指出获权可见的冲突期间。全部退出时可为零份在任，原编号和履历继续保留。[两层主选择](401-direct-hire-requirements.md#m04-br-006)

员工列表按所看业务日将每份获权任职独立列行，同部门也分别列行。任职数按有效任职计，人数按人去重，岗位占编按各段的 M03 政策计算。一主两兼可为 3 份任职、1 人，其中免占的一份占编增量为零。[列表与页签](507-job-information-tab.md#job-tab-layout) · [计数样本](../../plans/500-personnel-roadmap.md#m04-scn-002) · [岗位采用规则](401-direct-hire-requirements.md#m04-br-005)

## 2 记录操作与业务类型的绑定

本项目参考 PeopleSoft 按任职维护 Job Data，以及本地 Bugs-And-Blossoms 的 899、894 合同。前者给出按行办理的模型，后者将新建、追加、插入、更正、删除与业务分类分开。下表取其业务区分，采用 CHNHCM 自身的首单撤销和同日多动作规则。[PeopleSoft 职务记录维护](https://docs.oracle.com/en/applications/peoplesoft/human-capital-management/9.2.055/peoplesoft-human-resources-administer-workforce/fluid-updating-job-data.html) · [本地参考版本和章节](../../reference/506-job-information-sources.json)

PeopleSoft 的 Bobby 示例在原 0 号记录上办理再聘。其 Job Indicator 单独表示组织关系内的主次。本项目采纳按雇用记录保留履历的做法，并明确约定主岗终身为 0、正号用于兼岗。[Oracle 再聘示例](https://docs.oracle.com/en/applications/peoplesoft/human-capital-management/9.2.055/peoplesoft-human-resources-administer-workforce/understanding-job-data.html) · [Oracle Job Indicator 字段](https://docs.oracle.com/en/applications/peoplesoft/human-capital-management/9.2.055/peoplesoft-human-resources-administer-workforce/fluid-adding-organizational-instances.html)

<a id="m04-br-010"></a>
**M04-BR-010 每笔办理同时确定记录操作和业务类型。** 记录操作说明“怎样处理哪条记录”，业务类型说明“发生了什么”，原因说明“为什么”。每一类业务类型绑定一种由 M04 Go 解释的处理方式，确定目标是工作关系、任职还是主选择，以及可改字段、状态变化和需要联动的对象。Go 按目标、业务日、目录版本、当前授权与前后记录返回可办理组合，提交时重核。唯一原因自动带入，有多个时只选所选类型下的有效原因。办理固定类型、原因、规则版本及依据，后来目录改名或停用仍能还原原义。[M04 动作目录](../../architecture/target/modules/m04.md) · [提交与来源](403-hire-technical-contract.md#job-information-handoff)

| 经办人的记录操作 | 允许的业务意图与目标 | 保存后的履历 |
| --- | --- | --- |
| 新建任职 | 首次入职建立 0 号，再聘在原 0 号下建立新任期。从已有关系「新增兼岗」取得本人的下一个正号。 | 实际任职与其首笔办理同笔保存。原单重送查回原结果和雇用记录编号。 |
| 新增记录 | 在所选对象履历的末日追加同日真实动作，或登记后来生效的动作。类型可为数据更改、转正、调动、结束任职或离职，限于该目标当前可办的项目。 | 每笔真实动作都取得独立办理身份。一次依据同时调整多个字段，可在一笔中表达完整变化。 |
| 插入记录 | 从历史位置补登当时确已发生、此前漏记的数据更改或其他获准业务。所选日已有另一笔办理也可补登。 | 新增一笔业务记录，重核受影响日期和后继。普通任职变动须在相应任职期间内，首日有误回到创建该任职的原办理核对。 |
| 更正记录 | 选中录错的原办理，带入其日期、原类型、原原因和获权原值。可改日期、允许的字段及原因。类型纠错限处理方式和目标一致的合法分类。 | 保持原办理身份，追加不可变修订，必要时重排日期节点。原修订和原采用可查，无实质修改时零写入。跨生命周期含义的错误由相应有据撤销或专用纠错办理。 |
| 删除记录或撤销安排 | 只作用于当前来源中的确切原办理与期望修订。整笔普通数据更改系误建、实际从未发生且后继可合法处置时，用「删除记录」。通知取消尚未生效的入职时用「撤销入职」。继承原办理最新有效分类，另存删除或撤销依据。 | 从当前有效集合撤去该笔效果，保留原件、撤销依据、原回执和仍成立的其他办理。已经发生的变动仅值录错时更正原笔，已生效入职的误录从原办理更正。真实调回、结束兼岗或离职另记业务动作。 |

任用决定、名单本人行或无编号通知都沿用原办理的证据规则。客户政策要求另有决定时核对实际决定及适用范围，资料齐备即可保存。放弃未提交草稿零写入。涉及已采用记录、主选择、岗位资源或后继依赖的删除、更正和改日按整笔校验，冲突时保留原安排。[三种办理结果](401-direct-hire-requirements.md#m04-br-007) · [同日依赖与撤销](403-hire-technical-contract.md#hire-actions)

## 3 业务类型改变哪些事实

<a id="m04-br-011"></a>
**M04-BR-011 业务效果跟随事实所属对象。** 本表规定直接办理的结果。页签按实施批次开放已交付的组合，操作名称、状态和字段权均取服务端结果。

| 业务类型 | 前置及写入对象 | 经办人与下游可核对的结果 |
| --- | --- | --- |
| 入职、录用转入职 | 已有原人及任用依据，创建工作关系与首任职 | 可提前办理，自约定到岗日计入在职。M05 发出或接受录用留在招聘，T06 从已接受且资料齐备的原录用提交同一入职，原单重送只定位已办结果。 |
| 数据更改 | 所选日期内可维护的任职 | 从某日起更换工作地点，生命周期状态和雇用记录编号沿用原安排。按职务与按岗位分别取合法字段，岗位派生的部门、职务由岗位带出。人员证件、私人电话等资料从 M01 原档维护。 |
| 转正 | 适用试用、在该动作前仍处于试用中的工作关系 | 依据实际开始与实际转正日将该关系从试用中转为已转正。各任职按权展示同一事实，整段关系只计一次转正。计划日期供核对，调岗后沿原关系办理。合同约定由 T05 持有，延期、中断及跨关系试用按适用政策另核。 |
| 调动 | 当前关系中的原任职，以及受影响的汇报、主选择或岗位资源 | 在原任职上形成新安排，保留调入前资料。跨用人主体时依真实安排协调新旧关系，满编对调、交接和改期按 313 从原调动整笔处理。 |
| 正式兼岗 | 在实际所属工作关系新增独立职责，按人分配新正号 | 新任职有自己的首笔办理、生效期间、部门、职务及适用岗位。部门相同也各有一行。岗位用量按政策另计。 |
| 结束任职、离职 | 一份在履任职或指定的有效工作关系 | 结束兼岗只结束目标任职及其实际关联。离职一并处理该关系下的任职、主选择、实际汇报和适用占编，独立关系继续按原安排有效。该笔必须处置的合同、接替或后继未解决时整笔拒绝。 |
| 再聘 | 离职后凭新的人事依据建立新的工作关系和主岗任职 | 本人人员编号及雇用记录 0 号沿用，在 0 号时间轴追加再聘。新任期自到岗日生效，旧任期、已结束兼岗及办理原件可按权查阅。 |

工作关系的在职状态、适用关系的试用状态按业务日读取，主兼岗由本人的雇用记录编号确定。例如，员工可以同时在职、处于试用期并担任一份兼岗。「尚未生效」由所看记录的生效日与服务端今日比较得出。

日期取真实业务依据。若经办人输入「最后在职日（含）」为 2027-08-31，旧关系覆盖至该日，排他上界为 2027-09-01。原通知直接给出「首个不在职日」时按该日作上界，办理保留原日期及其含义。终止记录即使落在有效期的边界，也能从已结束的关系或任职追溯。[同日交接](../../adr/106-same-day-personnel-actions-and-daily-state.md#29-同日离职与入职的对象边界) · [两岗交接](../m03/313-position-capacity-contract.md#m03-br-037)

## 4 同日办理、修订与可见范围

同一任职在同一确切来源内，每个业务日至多一份适用状态，区间为非空 `[start,end)`。时间轴按业务日分组，每项有效动作用独立身份计数。点击一笔动作读取其发生时的组织、前后值和依据。点击「该日任职」读取按所选来源核定的日级结果。关系级转正可从获权的相关行进入同笔办理。更正次数另计，多个展示入口共用同一业务身份。[同日业务规则](401-direct-hire-requirements.md#m04-br-008) · [106 的首单采纳范围](../../adr/106-same-day-personnel-actions-and-daily-state.md#first-hire-adoption)

先后由确切业务前序解释，必要依赖另行记录。相互独立的动作可反序补录。对同一字段提出互相冲突的结果时，经办人核对前项或回原件更正。撤回一笔只重算其影响，保留独立后项。业务日和记录时刻分别保存，日内工时需要另外的事实依据。

人员、工作关系、所选任职、办理动作、字段及原件分别按当前权限读取和写入。只见兼岗的读者只见其获权行、处理结果和差异，可见范围同样用于候选、计数、原件、回执与深链接。跨任职联动须具备全部受影响范围，失权时只返回获准披露的反馈。薪酬、工资、招聘记录及岗位定义各由源域维护。[X03 授权](../../architecture/target/modules/x03.md)

<a id="m04-br-012"></a>
**M04-BR-012 人事事务按一笔业务办理列行。** 「人员 → 人事事务 → 办理记录」可跨人员、跨业务日查询。入职、转正、调动、离职及普通任职数据更改各按实际办理记载。任职级办理归实际任期和雇用记录编号，关系级办理归实际工作关系。从同一关系的三份任职看到一次转正，在办理列表只占一行。任职详情的「当日办理」与此行共用同一办理身份。原单重送沿用原笔，更正记入其修订。误建删除或撤销后原笔及处置依据可查，原事项的有效发生次数为零。实际发生的反向调动另记一笔。[办理记录页面](507-job-information-tab.md#personnel-action-register) · [106 事件次数](../../adr/106-same-day-personnel-actions-and-daily-state.md#26-事件次数与人员数量)

按部门查办理，用动作确切来源记载的发生部门。调动保留当时的调出和调入部门，可分别查询。员工列表的部门树取所选业务日的任职归属。按生效日期查事项，按办理时间查原经办人首次保存这笔事项的时刻。后续更正的人员、时刻和依据进该笔修订。经办人凭现有授权和依据直接保存，后续需要派发的待办由 M20 承接。[员工列表口径](#m04-br-009) · [业务待办视图](../../architecture/target/modules/m20.md)
