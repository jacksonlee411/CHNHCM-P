# CHNHCM-512 工作关系合同业务规格

Staffing 维护每段工作关系的人员合同。合同经办人从「人员」名录打开获权任职，在「工作关系合同」选择订立、续订或终结。同一人的两段工作关系各有自己的合同和办理历史。[M04 对象与职责](../../architecture/target/modules/m04.md#对象身份与职责) · [登记表](../../governance/registry.json)

## 1 所属关系、日期与权限

已有工作关系是签约的前置。经办人核对所选任职对应的关系，填写合同编号、实际签订日、合同起日和约定的最后有效日。无固定期限时可留空最后有效日。工作关系已有确定结束日时，新签或续订合同的期限必须落在该结束边界内。签订日、合同起日和任职起日可以不同。只办理合同时，工作关系、任职资料及岗位占用保持原状。[首次入职与主选择](401-direct-hire-requirements.md#m04-br-006) · [按岗占用](../m03/313-position-capacity-contract.md#m03-br-027)

合同查询和办理分别核验当前权限。处置离职影响时，依通知含义确定最后在职日及当日所属部门，再核对可见合同与处置权。读者可按权查看合同期限、前后继及办理记录。操作记录保留实际经办人、业务日、记录时刻和依据。[离职影响与授权样本](../../../internal/bootstrap/employment_contract_integration_test.go)

合同中约定的试用条件归所属工作关系的合同。实际开始试用和转正由 Staffing 按真实人事动作登记。订立或续订合同本身不产生转正记录。[关系级转正](506-job-information-records.md#m04-br-014)

## 2 订立、续订和终结

| 从所选关系办理 | 成功后的事实与核对方式 |
| --- | --- |
| 订立 | 新合同归属该关系。同一关系内合同编号重复时拒绝保存。从该关系的任职入口可读回编号、签订日、约定期限和订立记录。同人其他关系的合同分别列示。 |
| 续订 | 核对原合同及其版本，记录新合同自己的编号、签订日和期限。原合同须有明确结束边界且尚无后继。新合同起日须晚于原起日，且不得早于原合同的首个无效日。保存后新旧合同可双向定位，原签订日、期限和办理历史继续可查。 |
| 单独终结 | 选择原合同，填写首个无效日与终结依据。详情保留原约定期限，并列明此次终结，以便区分自然届满和提前终结。 |
| 随离职处置 | 按明确的离职指令处理该关系在退出边界仍须处置的合同。逐份核对身份及版本，将合同终结与离职办理一起保存，双方可查到同笔离职依据。遗漏应处置合同、选中别的关系或提交旧版本时整笔拒绝。 |

取消未保存的草稿不产生办理。撤销未来入职前须核对该关系下已签合同，已有依赖妨碍撤销时保留原安排。保存中途失败时，合同、离职效果及回执一并回滚。结果未知时用原提交号核对原办理。同号原样重送只得到原结果。撤去合同读权后，原经办人能查回获权的终态，受限合同信息按当前权限裁剪。[正常菜单](../../../apps/web/src/features/hire/RelationshipContracts.tsx) · [保存与查回](../../../internal/contexts/staffing/infra/postgres/employment_contract.go)

## 3 M04-SCN-004 合同续订

对已存在的工作关系 A 登记合同并续订，前后继可相互定位，签订日、合同起日和任职起日可各不相同。仅续订时任职与编制保持。接入第二段关系后复核 A 的续订不改 B 合同。终结关系时按明确指令处置对应合同。

从 A 的新合同返回原合同，核对各自的签订日与期限。从 B 办离职时，先提交 A 的合同版本，预期拒绝且两边合同有效情况保持。再提交 B 的准确版本，预期只处置 B 的合同，并可从终结记录找到离职通知。实库及菜单已核对单关系办理、两段关系隔离、失败回滚和原件。[合同实施验收](../../verification/500-job-information-delivery-review.md#18-阶段-10-的工作关系合同) · [离职与再聘](506-job-information-records.md#m04-scn-003)
