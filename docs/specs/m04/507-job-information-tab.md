### 1.1 人事事务的办理记录

经办人从「人员 → 人事事务 → 办理记录」进入整页列表，无须预选员工或部门。控制区沿用列表标题、搜索、筛选和紧凑分页，正文每笔已保存的人事事项一行。默认按办理时间从近到远。窄屏以「办理类型 · 员工」为摘要，保留生效日期和办理对象。两个列表各自保存查询条件，员工列表的部门树只联动任职行。[012 列表与详情](../m02/012-m02-functional-and-interaction-design.md#m02-ui-list) · [办理行的计数](506-job-information-records.md#m04-br-012)

| 列表信息 | 查找与阅读 |
| --- | --- |
| 办理类型、员工、办理对象 | 可按姓名、人员编号或办理类型查找。任职事项显示雇用记录编号和主兼岗。关系级转正显示「工作关系」及获权的单位和关系期间，相关任职在明细中按权列出。 |
| 生效日期、发生部门 | 生效日期支持区间。发生部门取办理当时的组织。调动在同一行显示「调出部门 → 调入部门」，可指定调出方或调入方查询。仅获一侧部门披露权限时，展示、候选与筛选匹配都只取获权一侧。 |
| 经办人、办理时间 | 可按原经办人和办理时间范围查询提前办理及补录。生效日期显示 `YYYY-MM-DD`，首次办理时间按北京时间显示 `YYYY-MM-DD HH:mm:ss`。后续修订的经办人及时刻在明细中查看。 |
| 办理状态 | 默认包括获权的已保存事项，仍有效的未来安排标「尚未生效」。已撤销或误建删除的原笔可按处置状态筛选。撤销未来入职后，原入职在列表保留一行，独立保存的撤销依据和回执可从该行明细查阅。分页显示匹配办理笔数，该次入职的有效发生次数为零。 |

点击「办理类型」链接打开该笔明细，显示原因、发生时的组织、获权前后值和依据。从当前记录选择更正或允许的撤销，复用职务信息里的原表单和保存规则。查看旧修订时只读。从事务明细转看任职时，定位实际任期和生效日。关系级办理只列可见的相关任职。新发生的变动仍可直接在职务信息登记。首期按授权直接保存，后续审批待办由 M20 的待办入口承接。[页内维护](#job-tab-edit) · [M20 业务待办](../../architecture/target/modules/m20.md)

从原件或任职详情返回，先回到刚才那笔办理，再回原查询，恢复已应用的筛选、排序、页码、滚动和办理链接焦点。若更正改日、变更类型或失权使原行离开当前结果，重读后保留合法条件并聚焦列表标题。仅持一笔原件的阅读权限时，从已有引用查看该原件。跨人员查询、匹配数、筛选候选、可见字段及关联链接均按各自当前授权读取。[012 返回定位](../m02/012-m02-functional-and-interaction-design.md#m02-ui-list) · [M04 读写合同](403-hire-technical-contract.md#personnel-action-query)

## 3 在页内维护一笔记录

1. 当前可办首次入职时，从本人「办理入职」使用原首单表单。已有任职时，选中末端位置可「新增记录」，选中已有后继的位置可「插入记录」。前者允许同末日增记，后者允许在所选历史日补登另一笔。两种位置都由服务端核日期范围、允许的业务类型和依赖。从任职发起转正或离职时，表单自动带入所属工作关系，显示关联单位及影响范围。结束兼岗只定位所选兼岗及其实际关联。[记录操作绑定](506-job-information-records.md#m04-br-010)
2. 页内编辑只保留一份任务表单，在控制区显示「保存／取消」。更正从当前来源中选中办理的更多操作进入，带入其原值，自动识别实际修改。可编辑的选填项直接显示。操作类型和原因仅一组，真实业务差异由服务端决定字段及必填项。经办人核对本笔内容即可直接保存。
3. 「删除记录」和「撤销入职」从原办理进入，明确本人、目标任职或关系、业务日期和本次会影响的选择、任职或占编。已有依据可直接引用，确需说明时填写一次。删除成功返回 Go 指定的仍可读记录或空态，提供获权原件入口。保存普通变更后定位实际新记录，结果未知沿原提交号查回。

| 字段或反馈 | 输入、默认与保存规则 |
| --- | --- |
| 业务日、类型、原因 | 入职带原单到岗日或手输。新增／插入据真实事项填写，可从服务端允许日期中选取。选择类型后带出唯一有效原因或列出可选原因。更正带入原笔。保存时规则或原修订已变化，保留仍获权的输入并提示重核。 |
| 部门、职务、岗位、工作地点 | 仅按职务填写有效部门、职务，可维护的地点直接显示。按岗位从允许岗位中选一次，Go 带出该段的部门和职务。数据更改只开放其允许字段，调动展示原任职及拟任安排。候选随日期及授权重读。 |
| 转正、再聘、结束 | 转正带入适用工作关系及实际依据。再聘带入本人原 0 号及新的到岗日。雇用记录编号由服务端确定、只读。终止表单按输入来源标「最后在职日（含）」或「首个不在职日」。 |
| 原因、依据和人员补件 | 业务原因从类型目录取，任用决定或通知是可追溯的业务依据。只读原单按人或本人名单行带入，手工通知可简述来源。在授权允许时从个人资料补缺后回原入职草稿。 |
| 取消、冲突及失权 | 只在有实际修改时保护切换页签、人、关系、任职、日期及离开。无变化不新增修订。错误摘要可聚焦并定位字段。提交冲突重读按新来源核对，结果未知先查原号。只读者没有写入口，直达写请求执行同一授权。 |

**M04-AC-016 页面验收。** 在同一候选构建，以经办人、只读者及仅见一个兼岗的读者从菜单实操。经办人完成地点变更新增／更正、历史补录、按类型合法删除、原件返回和取消草稿。只读者可读其获权任职与办理。另验有 M04 读权但无 M01 历史权、只有 M01 历史权、当前无有效行但可查撤销原单三种组合。授权变化后重进及回退均按当前范围。使用五种 100% 内容视口，关键办理在固定外框下从 1280×900 调至原生 200%，原生 400% 按 012 的风险或客户要求专项复查。记录视觉对照和键盘到达末字段、错误、保存、历史退出及返回行的结果。[业务验收样本](506-job-information-records.md#m04-ac-010) · [012 视口矩阵](../m02/012-m02-functional-and-interaction-design.md#m02-ui-viewport-matrix)

用第 1 节三行样本，分别从全部部门和产品部打开 1 号再返回，焦点均回到原查询的 1 号行。打开 0 号按权查看个人资料及日志，再从 1 号进入时只有该岗的职务信息。对仅见 2 号的读者，核对树、分页、前后导航、刷新和深链都只呈现获权结果。最后从同一人的 0 号回看离职与再聘，原离职办理仍定位旧任期。[编号与再聘验收](506-job-information-records.md#m04-ac-014)

<a id="m04-ac-017"></a>
**M04-AC-017 从两个菜单核对同一笔办理。** 用跨员工样本分别走员工详情和办理记录，按该节视口及键盘标准验收。[两人四笔样本](506-job-information-records.md#m04-scn-017)

1. 经办人在周宁 0 号的「当日办理」打开晋升，然后从「人事事务」按生效日期、发生部门及类型找到同笔。核对两处的原件和修订，任选一处更正原因，从另一处重读，两处均显示新原因并可追溯原值，三笔仍为三笔。从三份任职进入转正时，核对同一工作关系和同一原件。
2. 从办理记录分别按生效日期、办理时间查询陈禾，核对两种日期的结果。逐项查调出研发部、调入产品部，均定位周宁的同一笔调动。从结果进入原件再返回，条件、页码及焦点落回原行。另用可撤销的未来首单从一处撤销，在另一处查回原件及撤销依据，再核对原生效日没有该次入职效果。
