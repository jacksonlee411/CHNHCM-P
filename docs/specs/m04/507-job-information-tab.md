# CHNHCM-507 人员详情职务信息与人事事务办理记录页面设计

从「人员」查本人，从「人事事务」查跨人办理。找某份任职，从人员名录进入「职务信息」直接办理。核查某段时间办过哪些事，从「人事事务 → 办理记录」跨员工查询。两处打开同一笔 M04 办理，个人资料及其变更日志归 M01。首次入职从本人档案沿用 402。[502 人员详情](../m01/502-person-directory-interactions.md#m01-change-log) · [402 入职表单](402-hire-interactions.md) · [506 业务规则](506-job-information-records.md#m04-br-012) · [登记表](../../governance/registry.json)

普通名录与详情只在真实生效记录上切换。本人办理历史列出获权原件。跨员工办理期间与部门编制指定日依各自专项合同。[123 日期边界](../../adr/123-current-maintenance-and-dated-query-boundary.md) · [510 查询及验收判据](../../plans/510-personnel-page-remediation.md)

## 1 入口与页内布局

人员名录左侧为部门树，右侧按获权任职列行。普通名录按服务端今日确定当前或最早获权未来任期，部门筛选采用该任期的实际归属。无可披露任职时按获权人员身份列行。列表显示姓名及人员编号、雇用记录编号、主兼岗、部门、职务、适用岗位、任职期间与状态。可在同一单元格分两行显示职务及岗位，按职务管理时岗位显示「—」。同部门的主兼岗也独立列行。人数按可见人员去重，分页、前后导航及返回焦点按任职行计算。

**列表示意。** 在全部部门搜索周宁，合计 3 份任职、1 人。点「产品部」显示 0、1 两行，点「培训部」只显示 2 号。多段关系通过实际单位、关系性质和期间区分。

**点行后的布局。** 详情页头显示姓名、人员编号、所属工作关系、雇用记录编号及主兼岗。两类行均直接展开所选任职的职务信息，下方依次显示生效日期、该日任职、当日办理。有办理权时，控制区提供所选记录的适用动作。

| 从哪一行进入 | 身份区下的页签 | 正文示例 |
| --- | --- | --- |
| 0 号主岗 | 个人资料、**职务信息（默认）**、变更日志。资料及其日志各按 M01 授权显示。 | 产品部 · 产品经理，在 2026-04-01 打开入职原笔。再聘后从 0 号的获权时间轴可区分两段任期和中间的离职间隔。 |
| 1 或 2 号兼岗 | 仅显示**职务信息**。任职办理历史在本页按权查看。 | 点 1 号直接看产品部评审员。其 2026-08-01 的地点更改记在 1 号下。只看得到培训部的读者点 2 号即展开讲师详情。 |

从任职行、历史或原件链接进入时，保留指定任职、实际任期和办理。本人详情直接显示获权的职务信息页签。一份可见任职直接展开，多份在本人详情内按编号、单位及期间选择。明确目标已失权时显示不可用并可返回。无可见任职时显示「暂无可查看的任职」，仍有可查原单可从「办理历史」进入，有首聘办理权者可办理入职。有相应权限时从实际所属关系「新增兼岗」。读取失败在原区域重试。[既有首单办理](../../../apps/web/src/features/hire/HirePage.tsx) · [现有路由](../../../apps/web/src/app/App.tsx)

同一人员入口服务于登记、补资料及首次入职。只有登记权时只提供登记动作。未入职人员行打开个人资料。人员日志的 `tab=history` 及原件仍各验当前授权。部门任职范围本身不授予人员档案或日志权限。[人员名录与档案](../m01/502-person-directory-interactions.md#m01-change-log)

离职至再聘之间，当日人员名录可能没有本人的任职行。再聘能力交付后，有办理权者可从「人员 → 本人」或获权的原离职办理进入「办理再聘」。系统按真实离职记录与当前授权返回该动作，保存后定位本人 0 号的新关系、新任期和再聘原笔。单凭列表无可见行不能判定已离职。[离职及再聘样本](506-job-information-records.md#m04-ac-014)

### 1.1 人事事务的办理记录

经办人从「人员 → 人事事务 → 办理记录」进入整页列表，无须预选员工或部门。控制区沿用列表标题、搜索、筛选和紧凑分页，正文每笔已保存的人事事项一行。默认按办理时间从近到远。窄屏以「办理类型 · 员工」为摘要，保留生效日期和办理对象。两个列表各自保存查询条件，人员名录的部门树只联动任职行。[012 列表与详情](../m02/012-m02-functional-and-interaction-design.md#m02-ui-list) · [办理行的计数](506-job-information-records.md#m04-br-012)

| 列表信息 | 查找与阅读 |
| --- | --- |
| 办理类型、员工、办理对象 | 可按姓名、人员编号或办理类型查找。任职事项显示雇用记录编号和主兼岗。关系级转正显示「工作关系」及获权的单位和关系期间，相关任职在明细中按权列出。 |
| 生效日期、发生部门 | 生效日期支持区间。发生部门取办理当时的组织。调动在同一行显示「调出部门 → 调入部门」，可指定调出方或调入方查询。仅获一侧部门披露权限时，展示、候选与筛选匹配都只取获权一侧。 |
| 经办人、办理时间 | 可按原经办人和办理时间范围查询提前办理及补录。生效日期显示 `YYYY-MM-DD`，首次办理时间按北京时间显示 `YYYY-MM-DD HH:mm:ss`。后续修订的经办人及时刻在明细中查看。 |
| 办理状态 | 默认包括获权的已保存事项，仍有效的未来安排标「尚未生效」。已撤销或误建删除的原笔可按处置状态筛选。撤销未来入职后，原入职在列表保留一行，独立保存的撤销依据和回执可从该行明细查阅。分页显示匹配办理笔数，该次入职的有效发生次数为零。 |

点击「办理类型」链接打开该笔明细，显示原因、发生时的组织、获权前后值和依据。从当前记录选择更正或允许的撤销，复用职务信息里的原表单和保存规则。查看旧修订时只读。从事务明细转看任职时，定位实际任期和生效日。关系级办理只列可见的相关任职。新发生的变动仍可直接在职务信息登记。首期按授权直接保存，后续审批待办由 M20 的待办入口承接。[页内维护](#job-tab-edit) · [M20 业务待办](../../architecture/target/modules/m20.md)

从原件或任职详情返回，先回到刚才那笔办理，再回原查询，恢复已应用的筛选、排序、页码、滚动和办理链接焦点。若更正改日、变更类型或失权使原行离开当前结果，重读后保留合法条件并聚焦列表标题。仅持一笔原件的阅读权限时，从已有引用查看该原件。跨人员查询、匹配数、筛选候选、可见字段及关联链接均按各自当前授权读取。[012 返回定位](../m02/012-m02-functional-and-interaction-design.md#m02-ui-list) · [M04 读写合同](403-hire-technical-contract.md#personnel-action-query)

## 2 选中任职与日期后看什么

| 区域 | 显示与操作 | 值和限制 |
| --- | --- | --- |
| 任职行与详情标题 | 列表的员工名称是可聚焦的任职行入口。窄屏在姓名旁显示雇用记录编号及主兼岗，下一行显示部门、职务等摘要。 | 初入按服务端今日读取。历史或未来日期按同一业务日读所属部门及任职安排。编号和主兼岗始终随本人雇用记录显示，筛选、排序及撤权只改变可见集合。 |
| 生效日期 | 已选任职使用共享日期轴，桌面横排，窄屏或宽度不足收为可键盘操作的日期选择器。一天一个节点，同日多笔在节点下分别可选。 | 默认选今日适用记录，只有未来首条时选该条并标「尚未生效」。已结束任职可从其真实结束办理回看。保存和深链优先定位明确目标，失效的明确目标显示不可用并可返回。 |
| 该日任职 | 桌面按「任职安排／记录信息」两组阅读，显示可见的部门、职务／岗位、实际职级、地点、实际汇报及适用的关系状态、生效日和期间。已结束时标出最后任职日。首期只展示已接通的事实。 | 状态、主／兼及派生值由 Go 给出。业务日期统一 `YYYY-MM-DD`。读业务日取 `businessAt`。同日晋升后调动的样本显示「产品部、已转正、P6」。 |
| 当日办理 | 按已知业务先后展示，独立事项稳定列出。展开可见发生部门、获权前后值、业务原因、操作者和记录时刻。有业务依据时可按权查看。原件和原采用按权提供链接，旧来源显示只读历史短条和退出入口。 | 点样本的「晋升」，明细为「研发部，职级 P5 → P6」，上方仍显示产品部当日任职。记录时刻按北京时间 `YYYY-MM-DD HH:mm:ss` 显示。已撤销办理从获权历史可回看，包括当前没有有效任职的情形。 |

切换任职时重新读该任职的日期、日状态和办理。能在多个任职看到的关系级转正链接到同一笔，明细只披露此次当前获权的组织和字段。原件返回时恢复人、关系、任职、日期、办理及触发点，回到名录再恢复筛选、排序、页码、滚动和行焦点。刷新和直接链接重核当前权限。只失写权时保留可读内容，无原件权时提供安全返回，撤字段或任职读权时清除相关子行、标签、计数与迟到响应。[同日业务规则](401-direct-hire-requirements.md#m04-br-008) · [012 历史阅读](../m02/012-m02-functional-and-interaction-design.md#m02-ui-history)

## 3 在页内维护一笔记录

1. 当前可办首次入职时，从本人「办理入职」使用原首单表单。已有任职时，末端可「新增记录」，历史位置可「插入记录」。同日已有办理时，还可选中其中一笔补录其前实际发生的事项，包括时间轴的末日。服务端核对日期范围、业务类型和依赖。从任职发起转正或离职时，表单带入所属工作关系，显示关联单位及获权影响范围。结束兼岗定位所选兼岗及其实际关联。[记录操作绑定](506-job-information-records.md#m04-br-010)
2. 页内只打开一份任务表单，控制区显示「保存／取消」。更正从当前来源中选中办理的更多操作进入，带入原值和已有来源，自动识别变化。可编辑的选填项直接显示。字段随实际办理类型确定，有权人直接保存。[同日办理表单](#same-day-job-form)
3. 「删除记录」「撤销入职」「撤销晋升」从允许处置的原办理进入，带入目标、业务日及获权影响。普通误建记录沿用原分类删除。撤销可引用已有通知或简述真实原因。保存后定位实际办理或仍可读的日状态，原件按权可查。结果未知沿原提交号查回。

| 字段或反馈 | 输入、默认与保存规则 |
| --- | --- |
| 业务日、类型、原因 | 入职带原单到岗日或手输。新增／插入据真实事项填写，可从服务端允许日期中选取。选择类型后带出唯一有效原因或列出可选原因。更正带入原笔。保存时规则或原修订已变化，保留仍获权的输入并提示重核。 |
| 部门、职务、岗位、工作地点 | 调动按职务管理时填写有效部门、职务，按岗管理时只选一次岗位，由 Go 带出部门和职务。普通地点变更直接填生效日、新地点，业务原因按目录带入或选择。从原笔纠正错字时只改地点。普通维护免填通知、附件及补充说明。 |
| <a id="actual-duty-entry"></a>拟调入与补录实际履职 | 办理「调动」时显示原任职及拟任安排，满编时提示缺额。已有任职漏记实际派岗的，有事实更正权的人事从该任职「新增记录／插入记录」选「补录实际履职」，记错日期从原办理「更正记录」进入。按权限可选当时满编或暂停补员的实际岗位，填实际开始日、已知的结束日，引用已有履职资料。一次保存后定位所补期间并按权查看实际占编和差额。[门店岗验收](506-job-information-records.md#actual-duty-case) |
| 转正、再聘、结束 | 转正带入所属工作关系和已记录的实际试用开始日。漏记开始时，在所选任职的「新增记录／插入记录」选「试用开始」，按实际日期保存至该关系。发生部门取转正通知或本关系动作前的主任职，仅统计归属未知时系统记明原因并允许保存。再聘带入本人原 0 号及新到岗日。雇用记录编号只读。终止表单按输入来源标「最后在职日（含）」或「首个不在职日」。[转正归属与授权](506-job-information-records.md#m04-br-014) |
| 人事依据和人员补件 | 入职、转正、晋升等事项可直接引用已有决定、通知或名单本人行，手工通知可简述来源。客户明确要求单独核准或职责分离时由系统核对适用决定。办理表单无需勾选“已履行审批程序”。入职确有身份资料缺项时，按权从个人资料补齐并返回草稿。 |
| 取消、冲突及失权 | 只在有实际修改时保护切换页签、人、关系、任职、日期及离开。无变化不新增修订。错误摘要可聚焦并定位字段。提交冲突重读按新来源核对，结果未知先查原号。只读者没有写入口，直达写请求执行同一授权。 |

<a id="same-day-job-form"></a>
### 3.1 晋升、同日补录与原笔撤销

周宁 0 号主岗在 2026-12-02 依次完成三笔办理后，展开晋升时的页签正文示意如下。

```text
生效日期     [2026-12-02]
该日任职     产品部  ·  已转正  ·  P6

当日办理
  ▸ 转正     研发部
  ▾ 晋升     研发部                    [更多操作]
             职级 P5 → P6              [查看原件]
  ▸ 调动     研发部 → 产品部
```

| 从正常菜单进入 | 经办人看到什么、保存后回到哪里 |
| --- | --- |
| 职务信息 → 新增记录或插入记录 → 晋升 | 表单带入所选任期、生效日和只读的原职级，显示拟任职级、原因和任用依据。一项晋升决定附带部门或岗位调整时，就在这张表单填写相应字段。候选按拟任安排及业务期间重新读取。保存后选中当日的晋升，原件显示发生部门和实际职级变化。 |
| 同一入口直接选择「晋升并调动」 | 两项共用员工、任期和生效日。共用一份通知时只录一次，有第二份通知时关联到相应事项。选择拟任职级及拟任安排，各项唯一适用的原因自动带入，有多个原因时才需选择。候选按整份拟任安排核对，可直接选定「新岗、P6」。一次保存后选中该日，两笔均可展开。取消时整份草稿一起放弃。 |
| 当日办理 → 选中调动 → 插入记录 | 显示「在本次调动前补录」，带入所选调动。补晋升时原职级和发生部门取调动前资料。原件已有明确先后时自动带入，独立事项可直接保存。只有不同解释会改变任职结果、资格或权限时才定位待核的那一项，已知的相对顺序可直接登记。保存后按业务先后定位新笔，事务列表按首次办理时间排序。 |
| 当日办理或人事事务 → 当前原晋升 → 更多操作 → 撤销晋升 | 带入原笔职级、实际任期及获权的后继影响。有撤销权的人引用能说明误录的已有通知，或简述误录原因，即可保存。系统重核后继并显示所选日的职级。从原件点「查看撤销前来源」可核对当时的日状态和办理。若单撤会使调入岗资格失效，显示获权的冲突，原结果仍可读。 |

登记时间及系统标识留在相应的记录和来源中。经办人用业务依据确定先后，无需编同日序号或拖拽排序。旧来源提供「返回当前」并重读权限与可办动作。[同日写入与原件](403-hire-technical-contract.md#same-day-action-write)

## 4 页面继承与适用差异

员工身份标题下设工作页签，工作资料内按组织、职务和地点分组，参考 Odoo 19 的员工表单。PeopleSoft 的逐行操作放入本项目现有控制区及选中记录的更多菜单。布局、主题、日期轴和原生缩放以本仓标准及已交付页面对照。[Odoo 员工表单](https://github.com/odoo/odoo/blob/74d39b2fdaa8cd60885943fa58a08bff62e53207/addons/hr/views/hr_employee_views.xml#L149-L168) · [012 共享体验](../m02/012-m02-functional-and-interaction-design.md#m02-ui-expression)

<a id="m04-ac-016"></a>
**M04-AC-016 页面验收。** 从人员名录进入 0 号仅呈现当前获权的资料、职务与日志，正号只呈现该任职的职务信息。从筛选后的 2 号返回应还焦原行；主动切签应还焦选中签，从日志原件后退应还焦原触发链接。分别核对两处消费者的权限和路由恢复。[共享页签](../m02/012-m02-functional-and-interaction-design.md#m02-ui-tabs) · [人员路由页签](../../../apps/web/src/features/personnel/PersonTabs.tsx) · [任职详情](../../../apps/web/src/features/hire/AssignmentPage.tsx) · [人员日志与返回](../m01/502-person-directory-interactions.md#m01-change-log)

在同一候选构建，以经办人、只读者及仅见一个兼岗的读者从菜单实操。经办人完成地点变更新增／更正、历史补录、按类型合法删除、原件返回和取消草稿。只读者可读其获权任职与办理。另验有 M04 读权但无 M01 历史权、只有 M01 历史权、当前无有效行但可查撤销原单三种组合。授权变化后重进及回退均按当前范围。桌面视口与关键办理的原生缩放按 012 共享矩阵选取。记录视觉对照和键盘到达末字段、错误、保存、历史退出及返回行的结果。[业务验收样本](506-job-information-records.md#m04-ac-010) · [012 视口矩阵](../m02/012-m02-functional-and-interaction-design.md#m02-ui-viewport-matrix)

经办人改地点和纠正错字时，直接保存且可查前后值。按岗模式另从同一满编门店岗分别办理明日拟调入、补录上周已履职，核对缺额提示、按日实占、原定额和他人预留。缺事实更正权时从链接直达也应被拒绝。[实际履职样本](506-job-information-records.md#actual-duty-case)

用第 1 节三行样本，分别从全部部门和产品部打开 1 号再返回，焦点均回到原查询的 1 号行。打开 0 号按权查看个人资料及日志，再从 1 号进入时只有该岗的职务信息。对仅见 2 号的读者，核对树、分页、前后导航、刷新和深链都只呈现获权结果。最后从同一人的 0 号回看离职与再聘，原离职办理仍定位旧任期。[编号与再聘验收](506-job-information-records.md#m04-ac-014)

<a id="m04-ac-017"></a>
**M04-AC-017 从两个菜单核对同一笔办理。** 首次交付跨人查询时，从陈禾的任职保存一笔地点变更，保留另一名员工的真实入职记录。从「人事事务」查询两人的办理，再按陈禾和「数据更改」筛选，从原笔更正后回任职查看。同一业务身份只有一行，旧地点修订可查。只有原件权的读者不能列出两人的办理。

转正、晋升、调动及真实兼岗到位后，用两人四笔样本补验下列组合，沿用本页视口及键盘标准。[两人四笔样本](506-job-information-records.md#m04-scn-017)

1. 经办人从实际任职依次办完转正、晋升和调动，再在周宁 0 号「当日办理」打开晋升。从「人事事务」按生效日期、发生部门及类型找到同笔。两处核对原件及修订，从一处更正原因，另一处重读新原因并能追溯原值，三笔仍为三笔。从三份任职进入转正时，核对同一关系和同一原件。[办理步骤和预期](506-job-information-records.md#m04-scn-018)
2. 从办理记录分别按生效日期、办理时间查询陈禾，核对两种日期的结果。逐项查调出研发部、调入产品部，均定位周宁的同一笔调动。从结果进入原件再返回，条件、页码及焦点落回原行。另用可撤销的未来首单从一处撤销，在另一处查回原件及撤销依据，再核对原生效日没有该次入职效果。
3. 只授予周宁身份识别、2 号兼岗和该关系转正的读权，并允许在办理列表查询该范围。该读者查周宁当日仅得一笔转正，不能从条件、计数、明细或深链获知 0 号的晋升和调动。取消查询条件、翻页和刷新均守同一范围。收回该笔办理读权后返回原筛选，结果为零，焦点回列表标题。
4. 用可查办理、无员工名录权的账号从「人员」进入，默认打开获权的办理记录。再用仅获单笔原件阅读授权的账号从其来源引用进入，可查看该原件，直接请求跨人员列表被拒绝。

<a id="m04-ac-018"></a>
**M04-AC-018 从正常菜单办理、撤销并回看同日来源。** 经办人以[周宁的逐步结果](506-job-information-records.md#m04-scn-018)为准，对照该日任职、原件和事务列表。用原通知或仅填误录说明分别验撤销，旧来源仍有三笔及 P6，当前为两笔有效及 P5。另从原任职直接打开「晋升并调动」，共用通知只录一次，一次保存后可打开两笔。单项资格不符及单撤晋升分别用独立请求验拒绝。再用只见兼岗、具有本关系转正权的经办人验统计归属未确定时能直接保存，依部门授权却无法核实时只提示该缺项。关键入口、错误和历史返回按本页视口与键盘标准验收。[共同生效样本](506-job-information-records.md#m04-scn-019)

再用三份事项均可独立合法登记的样本检查顺序。第一轮按「转正、晋升、调动」登记，事务列表按办理时间倒序显示「调动、晋升、转正」。第二轮先登记已可单独成立的调动，再依据补到的原通知，从调动前补晋升、从晋升前补关系转正。两轮「当日办理」都应按确切前序显示「转正 → 晋升 → 调动」，打开每一笔均能核对其发生部门及前后值，两轮日状态和次数相同。另用两笔确实无先后的独立动作互换录入顺序，二者可直接保存，原件均无虚构的承接关系。[106 顺序反例](../../adr/106-same-day-personnel-actions-and-daily-state.md#43-后续必须证明的反例)
