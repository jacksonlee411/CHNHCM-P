### 1.1 角色、入口与结果

管理员及查询者从“设置 → 组织配置 → 部门”进入列表。无勾选时能直接搜索、筛选、排序、翻页及打开本部门；第一次勾选或全选时系统自动建立选择依据，跨页选择和排除保持，导出前重新检查；管理员在新建或更正的关系字段直接选择行政上级，保存继续由Go校验。前置为当前有效会话、实例/企业及相应动作、范围、字段权，不按角色名称硬编码许可。

目标是在现有Go与PostgreSQL内减少每请求的全量来源头搬运、完整时间线解码、非当前页路径计算和无选择时的全量摘要。保持精确总数、完整获权集合、八列CSV、当前授权、真实首条、原历史及提交恢复；不以减少数据范围或延长超时取得容量通过。不增加预热按钮、手动核验、确认页或强制先搜索才能选择上级的步骤。

### 1.3 三个不同的依据

“来源头”是对象最新保存版本的身份，包含该版本已登记的过去/当前/未来安排，不等于今日适用记录。“当前授权归属”是Go从最新事实按本次服务端执行日D选出的BU；读取历史不切换到历史BU。“选择版本”是完整获权查询投影的摘要，只检测已建立选择的变化，不是授权票据或业务来源，不持久化成授权过程档案。

## 3 拟采用的读取流程

### 3.1 当前授权与查询计划

每请求固定一个服务端业务日D，仍执行当前会话和X03共享策略守卫。当前范围沿[120第6.1节](../specs/m02/120-dated-maintenance-technical-contract.md)：有D覆盖记录取其管理BU，停用沿继承资料，未来首条使用最新来源的真实首条BU；旧sourceVersion、所选记录、客户端BU均不改变范围。read、history.read、reference.read、export及字段权限继续独立，不把“当前范围获得历史”解释为自动授予历史动作权。

X03在Go内形成请求局部的强类型读取计划，覆盖enterprise/bu/department三种既有范围以及重叠Grant的字段合并；M02仅传递可信当前范围事实并消费结果。SQL只执行这些已确定范围/掩码的集合过滤和排序，不自行解释Grant、重写拒绝规则或复制授权引擎。不由Organization读取Access表。新端口须与现有Decide/DecideReads逐项等价对照，不持久化或跨请求缓存权限结果。

搜索、字段筛选、排序和计数在正确字段投影后执行：自由搜索只匹配可读编码/名称；显式列筛选缺权沿现行拒绝规则，不先按隐藏值缩小集合再判权；不可读排序字段沿现行空值及稳定身份排序语义。先在所有获权对象上确定合法条件，再取页，不能先LIMIT后删除无权行。跨日授权变化须由服务器自然生效，不靠刷新定时缓存。

### 3.2 可查询窄事实及写入代价

优先扩展现有department_read_segment，不再建一套完整部门/历史模型。当前段包含真实首条、适用记录及关系；T00列明新增可查询列与既有字段的对应，最少包括稳定身份、来源身份、Go生成期间、实际成员/修订、主名称/简称、管理BU、父身份及所需展示模式。编码仍来自本部门身份；可确定地复用的原字段不再复制。名称归一化、未来首条/停用处理及模式均由Go生成，SQL仅用请求给定D检索存储期间。

预首条段须保持“尚未生效”而不是伪造一条今日记录；首条日期/ID、停用前解析日及开放终点完整保留。可搜索文本的大小写/Unicode/空值/字面contains语义沿现行Go规则，SQL不因LIKE通配符、排序规则或大小写函数改变结果。新增的普通索引只针对真实过滤/排序访问计划；前后缀以外的contains与精确总数仍可能扫描大量窄行，不保证O(pageSize)。

T04在R69取消每请求全企业存储审计后，R79同输入SQL实测支持新增日期覆盖索引候选：department_read_segment的GiST(span)携带当前列表过滤/授权/排序所需窄列，避免为准确count逐行回读宽历史元组。三次SQL约107—111ms，对照约318—327ms；完整合成输入增加74170368字节索引，材料逐值相等。R80真实API验证40字符编码、200字符名称及简称可创建、更正、读取历史及全选。R81据此接入现行开发迁移，保持模型5/read-rule4及单一查询实现；迁移安装及18项定向DB/API通过，同完整合成输入普通列表400次零错误，P95为151.049/515.934ms，达到单会话300ms/20会话1000ms目标；万科、冷态及两形状写入/空间成本仍待验收。此前索引冻结作为T00历史依据保留；三次SQL及字段上限验证不替代HTTP P95或最终容量验收，固定库不因此更新。

### 3.3 事实固定与事务边界

保留现有事务及会话活动更新顺序。当前transaction.Run调用普通Begin，不能把同一事务中的多条“当前”SELECT等同为同一数据快照。PG18的[Read Committed说明](https://www.postgresql.org/docs/18/transaction-iso.html)确认不同语句可见不同提交；本方案首选单条事实捕获语句，在已持X03守卫和固定D后，一次取得该查询所需窄事实及保守依赖，后续只消费捕获值和确切不可变来源。

普通条件的捕获须包含合法查询的准确count、本页行以及这些行所需BU/祖先的当前授权范围和路径日期事实；路径条件或选择核对则捕获其完整候选范围的必要事实。递归SQL只能检索已存身份、范围和保守邻接关系，日期/资格/环路的最终判定仍在Go。不另发全量来源头请求维持森林缓存。依赖闭包中的访问范围事实按D，路径内容按实际解析日，两者不能混用。

捕获递归须有身份/期间去重及取消边界，遇循环存储不能无限递归，也不能截断后当作完整成功；最终由Go给出对应安全错误。正常写入保证窄列与原事实一致；当前准确计数仍覆盖全部匹配且获权对象，不以当前页数量代替。任意篡改投影的存储诊断按第3.7—3.8节与查询分离。

捕获语句须包含后续实际需要的不可变材料字节，或使用另经证明的存储持有协议；不可变并不等于不会回收，单独记住旧字典ID不足以保证下条语句可读。T00原型按本页捕获字典/结构及原段，已验证并发更正/新增、替换当前段及无引用字典实际删除后仍可解码旧页。捕获后不能再查询可覆盖的current/read_segment接上新头；确需另读历史时按已固定完整来源并验证可获得性。T00最终原型已验证完整祖先/BU事实闭包及并发转BU、祖先换父；正式端口接入后仍按V05复验。维护请求还要在捕获语句核对客户端expectedSourceVersion/目标修订；预读用于生成期间的目标已变则返回冲突，不将旧候选套在新对象上。

T00以实际查询原型证明上述捕获闭包可行；如需多语句重复读取可变当前事实，必须先补充一致快照及同会话活动写入的协议/反例，不能直接改全局隔离级别或恢复全森林读取后声称完成。任何重试都使用原请求总预算和重新取得的当前授权，不能返回上一轮失败前的页面或半份CSV。
