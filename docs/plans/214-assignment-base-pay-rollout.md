# CHNHCM-214 员工首次定薪与按日调薪实施计划

薪酬经办人选定一份实际任职，按生效日核定个人基本月薪。以后企业调整薪带，仍能说明这名员工的约定基本月薪及当时采用的依据。二期从首次定薪一直做到一次真实调薪、一次误录更正及按原号查回。业务办理见 [215 方案](../specs/m09/215-assignment-base-pay.md)，接线与存储见 [216 合同](../specs/m09/216-assignment-base-pay-contract.md)，设计审阅见[评审记录](../verification/214-assignment-base-pay-design-review.md)。[登记表](../governance/registry.json)

## 2 实施顺序与出口

下表从产品实施开始计进度。方案评审的结论、产品阶段的验证以及业务人员的签收分别留存。

| 阶段与责任 | 主要工作和依赖 | 从正常入口可以验收的结果 |
| --- | --- | --- |
| 1 按任职和日期查依据。M04、M03、M09、X02、X03 及体验维护者 | 准备已入职、记有 P5 的专业系列样本及一个独立兼岗。经公开端口取得有效任期、雇主、职务系列及个人职级。通过范围和基本工资组成筛选候选。接入任职页上的「个人基本工资」。 | 经办人选定任职及定薪生效日，能识别合格计划、薪带和津贴依据。只命中津贴、多个计划、旧任期缺记职级和受限任职各有可操作的结果。[选计划](../specs/m09/215-assignment-base-pay.md#m09-br-009) · [角色与页面](../specs/m09/215-assignment-base-pay.md#pay-page) |
| 2 首次定薪与调薪。M09、X03、存储及体验维护者 | 在第一阶段同一套来源解析上实现服务端核定、修订、期间及原号回执。接通同页保存、查询、更正、撤去及原件返回。 | 一人提前保存到指定日生效。真实调薪与误录可按身份区分。双人争用、失权、取消和断线重送均按合同得到确定结果。[办理规则](../specs/m09/215-assignment-base-pay.md#m09-br-011) · [事务合同](../specs/m09/216-assignment-base-pay-contract.md#pay-commit) |

## 3 验证、移交和关闭

1. 阶段一交付公开来源、页面读路径和角色样本。若配置账号仍只能查制度，按任职、个人薪酬用途和字段授予测试角色所需范围。公用薪标、旧原件及其他环境的权限由原责任方管理。
2. 阶段二按影响运行 `make boundaries`、`make check` 及 `make integration` 中的真实 DB/API 验证。以两条连接复现相同日期的首次核定和来源竞争，从旧申请号查回原笔。阶段三从正常菜单用 `make smoke` 对应场景验证 1440×900、1440×540 的 100% 与关键流程原生 200%，与同一构建的任职和薪标页面对照。容量测量须单列任职数、计划候选数、有效段数及并发会话。[共享验收](../specs/m02/012-m02-functional-and-interaction-design.md#m02-ui-viewport-matrix) · [分层验证](../governance/137-actions-and-validation.md)
3. 在隔离库完成写入、故障及重启用例。固定环境交接按 [003](../adr/003-implementation-stages.md#acceptance-environment-update) 核对实际 profile、端口与运行版本，备份并核对首期三份计划的日期段、原件、回执及用户已有数据。准备一份验收日已在任且可办的合成员工，同时保留跨年样本。记录正常菜单、角色、日期、预期和回查点，供经办人实际试用。环境的责任方和复查节点沿用 [4380 记录](../verification/210-compensation-default-port.md#3-运行交接)。
4. 三阶段实际结果、首败与复验、未覆盖项及人工签收情况写入相应验证记录。此后长期规则由 215、216 维护。设计阶段的登记状态和工作范围见[评审记录](../verification/214-assignment-base-pay-design-review.md)。
