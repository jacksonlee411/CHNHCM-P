## 3 删掉高度规则对 200% 的影响

用有界面 Chromium 打开仓内薪酬原型，从“设置 → 薪酬计划”查询 `PRO-M`，进入“专业人员月薪计划 → P5 · 月薪薪带”。从薪带返回后焦点回到原链接，返回列表后查询词仍为 `PRO-M`。同一流程在下表三种状态下均完成。

| 实测条件 | 薪带正文滚动方式 | 正文区可见高度 / 内容高度 |
| --- | --- | --- |
| 1440×900，100%，原样式 | 正文区内部滚动 | 778 / 778 像素 |
| 固定 1280×900 窗口，原生 200%，实测 640×450 | 整页滚动 | 531 / 531 像素 |
| 同一 200% 窗口，仅在页面内存中移除该高度规则 | 正文区内部滚动 | 334 / 531 像素 |

离开页面后样式试验即结束，缩放已恢复 100%。这次验证覆盖搜索和来源往返。长表单末字段、错误及取消列入实施验收。调查没有启动 API 或数据库，也没有运行已取消的两种尺寸专项。

## 5 验收与关闭

1. **薪酬原型。** 用标准桌面执行完整页面链接遍历、受限角色、来源往返及草稿取消。原生 200% 下用滚轮和键盘到达长表单末字段，触发校验、返回修正并取消，核对金额样例、返回焦点和窗口倍率恢复。在当前原型上采新结果，用独立输出路径保存。
2. **人员名录。** 在任务自有临时环境按 [405 合成样本](../../tests/fixtures/personnel/directory405.py)准备数据。经办人按“示例陈舒”查出 1 人、3 份任职，检查含下级、全选排除、服务失败重试和返回。在原生 200% 用键盘打开经办人的部门树。资料读者查同一人得到 1 人、0 份任职，页面没有部门树入口。分别传 `short`、`400`、`zoom400` 检查非零退出且没有生成文件。退出后回收临时环境。
3. **开发入口。** 用下列命令对调查基线或将来的候选提交复查直接命中，再检查三处文件中的媒体查询、循环和 CLI 条件。CHNHCM-400 是 M04 入职规则与准备的计划编号，HTTP 400 是请求状态码，两者与倍率无关。复核 [650 项收集清单](../verification/012-standard-desktop-validation.md)的发现与分配，执行 `make docs` 和 `git diff --check`。若实施实际改到共用产品组件，再对受影响正式页面按 012 验证。
