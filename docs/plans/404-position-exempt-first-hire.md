# CHNHCM-404 T03 按岗位免占编首次入职实施方案

本批由 wt-dev-e 承接。人事从已登记的员工详情办理首份 Employee 工作关系，主例的整个任期按同一岗位免占编。「免占编」是该份任职采用的政策，员工在岗事实仍须可查。[登记表](../governance/registry.json) · [400 分模式准入](400-hire-readiness.md#4-按模式进入-t03) · [401 任职模式](../specs/m04/401-direct-hire-requirements.md#m04-br-005)

截至 2026-11-26，主线已交付补员、按岗首单和办理历史。下文的原设计以 PR #5 为起点，阶段进度和 e 的剩余验收见[第 4 节](#4-阶段任务)与[同步复评](../verification/404-main-sync-reassessment.md)。

## 1 用户目标

1. **从本人详情选一次岗位。** 有权经办人从「人员 → 员工 → 已登记人员详情 → 办理入职」引用单人决定或多人名单中本人的稳定行。原单给出岗位时直接带入，缺岗位时按适用日期和授权范围选取。部门、职务随岗位带出。单位、日期、BU、地点等已有安排沿用原单，确有缺项才补。无编号通知仍只填一条可追溯说明。
2. **一次保存真实岗位任职。** Go 在保存事务中核对全任期的企业、人员类别、办理用途、岗位和补员状态，建立关系和首任职，两个层级各确定一个主选择。该岗新增一份免占编任职，占编增量为零。
3. **用正常业务操作验证。** 在可丢弃实库用合成原人和合成决定办理 2027-04-01 入职。另一名经办人预览同类安排后，由岗位管理员从岗位详情暂停补员，再保存应被拒绝。分别核对页面可见结果、提交回执与数据库终态。[402 员工详情办理](../specs/m04/402-hire-interactions.md) · [313 补员合同](../specs/m03/313-position-capacity-contract.md#m03-br-029)

### 3.1 原单、岗位和页面各从哪里取值

签发人沿 `POST /api/v1/appointment-decisions` 保存载有岗位身份与原称谓的单人决定或名单版本。经办人进入本人详情，沿现有决定候选只读本人有权采用的行。增加可选岗位成员时，保留旧版 members、摘要及缺项原意。原单未载岗位时，经办人从扩展后的 `POST /hires/targets` 选择岗位，补值只属于办理。原单已载部门或职务时，逐段与岗位推导值比对。冲突交由有权签发人更正原单，再重新读取。免交重复说明、附件、复印件和核验单。[403 签发和采用](../specs/m04/403-hire-technical-contract.md#7-系统内任用决定的签发和采用) · [当前原行](../../internal/contexts/staffing/application/hireprep/decision.go)

`POST /hires/preview` 随输入给出适用政策和按期安排，资料齐备可直接按保存。`POST /hires` 自行求值。现有 Hire 输入要求部门和职务，授权也先读拟任部门。按岗分支以岗位为输入，在服务端求出实际部门和职务后按每段校验授权，防止手填 ID、旧候选或跨部门改隶绕过范围。按职务沿用原有输入。缺读权时不得泄露其他名单行、部门、用量或既有办理的存在。页面以[员工详情](../../apps/web/src/features/personnel/Detail.tsx)和[首单办理](../../apps/web/src/features/hire/HirePage.tsx)为基准，管理员沿「设置 → 职务配置 → 岗位 → 岗位详情」办理暂停或恢复。[现有保存入口](../../internal/contexts/staffing/infra/postgres/hire.go) · [402 表单](../specs/m04/402-hire-interactions.md)

### 3.2 岗位使用从何时可核实

M03 提供岗位和补员时间线。本批优先支持由系统从设岗日起接管的受控新岗。由有权管理员正常设岗，M04 在同一事务记录接管范围及所依据的真实设岗版本。以两项事实确认 M04 零起点。对有完整补员时间线的岗位，从启用日起尚无生效暂停的段允许新增，暂停持续到恢复生效。旧岗只有 M04 已核对清楚的期间可以接管，须记录覆盖区间、事实依据及版本。实施时核对现存任职及未来安排能否完整重建。无法证明的旧岗暂不开放，由 M04 维护者核实后接入。遇补员来源未接入、使用覆盖有缺口或来源矛盾，向获权经办人指出首个无法确认的期间。经办人无须手工声明空岗或提交用量证明。[313 使用来源](../specs/m03/313-position-capacity-contract.md#m03-ac-095)

入职采纳唯一 M03 政策修订和 M04 自己的全期覆盖。组合根要把 PostgreSQL 中的真实使用接到岗位用量读取端口，按岗位、任职／办理、政策修订和有效段提供 M04 的 exempt 记录。分段交界若岗位相同而部门或职务合法变更，保留同一份任职和每段各自的组织、职务及修订，按日查询取当日那一段。余额需要的 M05 预留覆盖由 M05 提供。缺该覆盖的免占首单仍可按上述条件办理，岗位页面仅披露可核实且获权的事实。已有真实免占任职时，停岗或移动岗位日期不得切断该任职。其他依赖完整用量的收紧继续执行 313。清单中每个事实均须能在服务重启后读回。[用量求值](../../internal/contexts/staffing/domain/quota_usage.go) · [岗位用量入口](../../internal/contexts/staffing/infra/postgres/quota.go)

## 5 保存、冲突与恢复

同一 Go 事务内重核当前授权、本人及证件、原决定和准确人员行、主体全期资格与必要绑定、客户规则、M03 政策、岗位状态／归属及部门和职务。沿任期全部有效边界拆段，段段能还原当时采用。页面「任期至」含当日，存储为次日排他的区间，结束未定按开放期间判断。[403 事务](../specs/m04/403-hire-technical-contract.md#hire-transaction) · [120 日期来源](../specs/m02/120-dated-maintenance-technical-contract.md)

保存统一协调岗位与人员、关系、任职和主选择的守卫，等待后重读。原决定撤销、换人、原文与岗位安排冲突、预览后补员或授权变化时拒绝旧请求，仅返回有权查看的原因。关系、首任职、分段采用、两层主选择、办理、用量、提交回执和 Outbox 同时生效。中途失败整笔回滚，已登记原人保留。[跨域共同事务](../architecture/target/10-ddd-and-state-contracts.md#staffing-quota-transaction)

同号恢复、同号改义、不同号重办及私人回执沿用 403。单人决定按客户和原单、名单按客户和原单及稳定行防重。修订变更不产生新办理资格。生效前可按原办理撤销，保留原办理、原采用及撤销依据，重送旧请求只返回原结果。[403 来源与恢复](../specs/m04/403-hire-technical-contract.md)

### 5.1 岗位守卫、预览采用与恢复

入职、撤销未来入职、岗位暂停／恢复、岗位启停或改隶须在同一数据库上使用相同的客户＋岗位稳定守卫。复用 Staffing 既有部门及岗位守卫。需要协调部门时，同层稳定 ID 排序并遵守先部门后改动对象的既有次序。跨域端口沿 `dbtx` 传递同一事务。先解析所需目标，等待守卫后重取目标、授权及各段来源。目标集合发生变化时，退出后按完整集合重验。预览固定的版本失配则提示重新核对。用真实双连接覆盖两个提交顺序，保留等待点、提交次序、两边结果及最终行数。[岗位锁](../../internal/contexts/staffing/infra/postgres/quota.go) · [部门守卫](../../internal/contexts/staffing/infra/postgres/allocations.go)

分段采用须携带有效期、稳定岗位及修订、补员来源及修订、政策版本及生效规则修订、部门与职务身份及修订、M04 覆盖版本和免占效果。以 `businessAt` 读该日有效状态，用 `adoptedRef` 沿 `sourceVersion` 还原办理当时原件。分段须连续且恰好覆盖原任期，开放尾段须有对应来源覆盖。跨 JobOnly 与免占的已支持段按 403 分别采用空岗位和实岗，合成一份任职。#18 接入占编后，跨入占编模式的后段按当期定额、实际占用与预留核验。有名额时整单保存，后段缺额时整单拒绝，返回首个受阻日。AC-004、AC-008 的竞争结果见[同步复评](../verification/404-main-sync-reassessment.md)及[403 全段事务](../specs/m04/403-hire-technical-contract.md#hire-transaction)。

现有同单内容比对取部门、职务和任期等值。本批须将原办理实际岗位及分段安排纳入比对。同部门同职务的甲乙两岗仍可区分。同单同内容且获权者只定位原办理。同单异岗或换人返回冲突。撤销后另办也须识别原行已采用。私人回执按原经办人和当前读权查回，仅失写权与失去读权分别测试。拒绝可有自己的拒绝终态。原号查明未执行后封闭，晚到请求不得写入。模拟数据库故障时区分提交前回滚与提交成功但响应丢失。[原单防重查询](../../internal/contexts/staffing/infra/postgres/appointment.go) · [403 恢复](../specs/m04/403-hire-technical-contract.md#hire-recovery)
