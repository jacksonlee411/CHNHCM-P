# CHNHCM-210 薪酬体系配置实施路线图

首期交付可由后台维护的薪酬制度配置。薪酬管理员按获授权限在「设置 → 薪酬配置」维护职级标准，用这些标准组装月薪或年薪计划，直接保存后按日期生效。查询者可查所选生效段及其原依据。D1、D2 已形成路线图、业务方案、页面原型和独立验收预期。产品实施按下列三阶段推进。[登记表](../governance/registry.json) · [分阶段交付口径](../adr/003-implementation-stages.md) · [管理员维护与生效](../adr/213-administrator-maintenance-and-effectivity.md)

## 1 起点与交付边界

| 已有条件或将来使用方 | 对本路线的具体影响 |
| --- | --- |
| M03 职级与职务系列、M02 法律实体已有切片 | 从已存在的 P5 等目录选择来源。薪标、薪酬字段授权及被 M09 采用后的期间保护须在新的消费路径验证。[职级合同](../specs/m03/310-grade-ladder-contract.md) · [上下文与实际入口](../architecture/contexts.json) |

## 3 里程碑、顺序与责任

| 顺序 | 前置、任务及负责角色 | 可观察的出口 |
| --- | --- | --- |
| **D1 制度建模** | 薪酬业务和 Compensation 维护者用两套合成制度走查适用范围、津贴归属、薪带共享和管理员办理路径。 | 固定额、标准引用、目标比例各有实例。专业和运营计划共用 P5 月标，固定津贴归各自计划维护。年薪计划使用独立年标。[首期取舍与行业依据](../specs/m09/211-compensation-configuration.md#policy-decisions) |
| **D2 页面与设计交付** | D1 有明确基线后，体验维护者出列表、详情、维护、历史四种页面状态。薪酬及验证维护者按角色审阅。 | 经办人能从计划定位月标及年标，说清六月和七月各用哪一条。只读、失权、更正与取消各有预期。原型走查、业务代表的意见和产品验收分别记录。D1、D2 构成设计交付包。 |
| **I1 职级薪酬标准** | M09、M03、X03、体验及验证维护者接入职级来源、金额精度、授权和按日记录。以定额和连续薪带实施 Go 命令、PostgreSQL 独立修订、迁移、公开 API 和菜单。 | 一名获权管理员从正常菜单建立 P5 月薪带和年定额，提前保存七月生效段并按现权重读原版。实库验证同口径唯一、引用有效、金额合法。对应 AC-002 至 AC-006 的薪标部分。 |
| **I2 薪酬计划与组成** | M09 接入 X03 及 X02 的显式范围。企业通用、仅含计划固定额的路径可与 I1 并行。按实际选用的维度接入 M02、M03，采用职级标准的组成行再接通 I1 的费率及来源。 | 管理员可单独建一份企业通用固定额计划。范围、条款与实际引用同笔落库。PRO-M 的十月津贴只改本计划，共用 P5 月标的七月调整只改一次。覆盖 AC-001、004 至 008。 |
| **I3 联验与手工交接** | 候选包含 I1、I2 后，验证维护者与薪酬经办人从正常菜单行走两套样例，开发维护者办理环境更新和资源收尾。 | [八组业务场景](../specs/m09/211-compensation-configuration.md#design-cases)逐项关联实际构建、实库/API、浏览器结果及未覆盖项。记录首次失败与复验，向经办人交接实际地址、角色、样例和复查点。 |

D1、D2 的规格、原型和场景已形成，供业务评审。I1 已通过实库、浏览器和后台菜单验证，P5 月薪带和年定额已放入本工作树的固定验收环境。I2 的计划及组成已在同一环境录入专业月薪、运营月薪和管理年薪三份样例。I3 负责两类对象容量、八组场景汇总及正式交接。首期包含共享薪带、计划内固定津贴、定额或连续薪带，均由管理员一次保存、按生效日采用。跨计划津贴联调、离散薪档及晋档均递延。[职级薪标实施验证](../verification/210-compensation-i1.md) · [计划及组成实施验证](../verification/210-compensation-i2.md)

## 5 如何验收与交接

设计评审从管理员的两次办理着手。在共享月标增加七月记录，核对两个计划同日起取得新薪带。再从 PRO-M 详情新增十月生效记录，核对九月原额、十月新额、OPS-M 的同名津贴及保存时的薪标依据。实施验收另核单人保存直达结果。[多轮评审与复验](../verification/210-compensation-design-review.md) · [首次设计走查](../verification/210-compensation-design-walkthrough.md) · [阶段口径核对](../verification/213-administrator-maintenance-and-compensation.md) · [原型入口](../specs/m09/212-compensation-configuration-pages.md#prototype-walk)

实施时按 [121 接入矩阵](../specs/m02/121-dated-object-admission-matrix.md)用职级对照职级标准，用含成员的职级阶梯对照含组成项的计划。Go 验证金额、完整期间、幂等与权限，DB/API 查事实、来源和回执。浏览器用桌面 1440×900、短屏 1440×540 及关键流程原生 200% 核对保存、取消、键盘、正文滚动与返回。容量按两类对象各自的已定业务量、查询、保存和恢复签收，异常和跨域结果分别保留本次实测证据。[共享视口规范](../specs/m02/012-m02-functional-and-interaction-design.md#m02-ui-viewport-matrix) · [接入与容量](../guides/124-dated-object-admission-and-capacity.md)

I3 的首期容量样例采用 20 个职级，各有人民币月标和年标，共 40 份标准；另有 12 份计划，每份覆盖 5 个职级、3 项组成。两类对象各保留 6 个年度生效段。在 4 个经办会话及 4 个查询会话下，从真实 API 分别测列表、按日详情、历史原件、保存和原回执查回，记录请求数、错误和时延分位数。该规模是本次合成制度的实施假设，客户上线时可按其制度数量另行测量。

产品候选按影响运行 `make docs`、`make boundaries`、`make check`、`make integration` 及对应的 `make smoke` 浏览器场景。开发者在任务自有隔离库造数，交付前按责任更新相应手工验收环境，保留持久库、原采用及用户样本，回收本批临时资源。路线图关闭时由维护者将长期规则归回 211、212，将通过、未测、遗留事项及环境责任交给相应记录。[环境交付与收尾](../adr/003-implementation-stages.md#acceptance-environment-update) · [运行指南](../guides/017-local-bu-development.md#local-runtime-cleanup)
