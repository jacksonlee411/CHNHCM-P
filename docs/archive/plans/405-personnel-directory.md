# CHNHCM-405 人员名录交互、部门层级与验收样本整改

[登记表](../../governance/registry.json) · [原问题及验证](../../verification/405-personnel-directory.md) · [502 人员名录](../../specs/m01/502-person-directory-interactions.md) · [507 任职行](../../specs/m04/507-job-information-tab.md)

## 1 办理目标

经办人从「人员」按姓名或编号查人，在可披露的任职内按部门、主兼岗定位，可以分别阅读职务与岗位，跨页勾选实际行。只有档案权的读者沿同一入口查获权人员。对照同构建业务单元、部门与职务列表，以及 CubeBox 员工页。两轮实页发现合并登记为下列七项。

## 3 接口与继承边界

M01 持有同事务获权人员，M04 合成名录行并在分页前处理查询与计数。祖先读取走已有组织来源端口，按当前权限、实际任期日期组路径。勾选借用 012 的全查询规则，Go 核对选择及范围版本。浏览器只保存当前标签临时意图，刷新或离开清除。无新增业务写动作。只读名录扩展无须迁移，已采用的记录及原件身份保持可查。部门树复用显示与输入，人员页保留自己的可见集合。仅在获权任职内容内提供专用列筛选。普通名录日由服务端决定。

## 4 验收与交付

先用独立库验证一人在四级主岗、五级两个兼岗。按本人号查共同上级预期三份一人。取消含子部门只保留直属，筛兼岗两份一人，勾选两项，开详情返回原行。混合超过一页时核对全选、排除、翻页、失权和集合变化。另用资料读者和失效书签验证异常恢复。桌面 1440×900、1440×540 和有界面原生 200% 实操，中文列设置回退与其他公共列表一起核对。检查项目文档、Go/前端边界、构建与对应集成。

产品通过后备份原 4496 程序和数据库，用同一个固定 profile 与原卷更新，核对原人、办理、私人回执、补员及合成样本。新增数据须能在中断后重入，重复运行不重复登记或办理。用真实菜单复核后登记证据与复查责任，回收本批临时资源。[003 环境交接](../../adr/003-implementation-stages.md#acceptance-environment-update)

## 5 评审后确定的边界

资料读者的旧地址可能仍带任职筛选，服务端依现权重读，页面提供回到可见名录的入口。查询失败也保留可编辑输入。全选在 Go 的同一事务内核对实际行集合、成员身份和来源。收回任职披露权、同数换人和相同人换任期都使旧选择失效。日期、查询和会话绑定选择，排序与页码不参与集合身份。勾选不授予导出或办理权。五级链从业务根部门起算，全部节点不计层级。原单、政策和旧样本的生效日期受保护。

## 6 规则及样本交接

502 接续搜索草稿、人员行选择和返回，503 接续查询与选择接口，507 接续部门归属及职务、岗位分列。未勾选人员或空集时依当前权限显示查询，表头的勾选与原来的行返回定位各自独立。固定验收取 admin 的 P00000006，分别选择服务交付部的含子部门、直属和兼岗三种范围。reader 用同号检查档案行。四份新增首聘及两份兼岗的最后任职日为 2027-03-31。跨过该日复查时需按实际业务日解读在任数。实测、原件保护及复查责任由[405 验证记录](../../verification/405-personnel-directory.md)接续。
