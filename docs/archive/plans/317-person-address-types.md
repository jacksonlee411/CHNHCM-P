# CHNHCM-317 个人资料地址类型配置实施方案

## 1 办理目标与模型选择

配置维护人在「设置 → 人员配置 → 地址类型」维护同一客户实例共享的地址分类。人事从「人员 → 人员 → 个人资料 → 更正资料 → 地址」选用。客户增加“宿舍地址”只影响可选值和统计分组，符合轻量配置项。[316 选型](../../architecture/316-object-and-configuration-models.md) · [505 地址合同](../../specs/m01/505-personal-profile-contract.md#profile-address-types) · [登记](../../governance/registry.json)

| 个人资料中的事实 | 本次选型及理由 |
| --- | --- |
| 姓名等基本资料、实际住址、电话与邮箱、家庭成员与联系人 | M01 的人员资料与明细记录。每次更正须定位到人和原记录，按原有字段权限保存。 |
| 身份证件、教育经历、专业凭证、银行账户、健康信息 | M01 的业务记录。证件判重、最高学历或学位、主要账户、健康资料的收集与保留各有业务条件。 |
| 住址类别与实际地区 | 客户可按统计需要增加住址类别，用实例共享的轻量配置项。实际国家和行政区划继续按 M02 的身份、上级与来源选用。 |
| 联系渠道、教育记录类型、各类主要或最高标记 | 联系渠道决定号码校验，教育记录类型决定字段和最高标记资格，主要标记有唯一性。取值行为及约束由 Go 维护。 |
| 联系用途、家庭关系、凭证类别 | 本期沿用现行合同。后续若客户提出自行增减的场景，先核对是否只影响显示与统计，再决定是否复用地址类型的维护方式。 |

## 2 存储、授权与交互

M01 拥有当前项及不可变修订，按实例、不可变编码保证唯一。管理界面复用应用壳、配置列表、共享日期和离开保护，支持新增、更名、排序、停选和恢复。目录操作无员工标识。应用到地址草稿与保存整页是两步，保存时在同一事务获取所选项、当前授权及日期，版本不同则在原行重选。表单取消和无修改零业务写入。

本树采用全局迁移 00061。00059 与 00060 属于 wt-dev-c 薪酬切片，集成时须同时保护两树已有账本及业务数据。预置居住、户籍、通讯、其他四种地址。既有记录及回执原样可读，历史原文无从查证的修订留空。升级旧客户端对首次预置值的写入按原显示值核对来源，换版后需重新选择。配置修订只写本项，已办地址沿用其原名与采用日。人员更正沿用原写事务及排他保护。只处理人员资料时，X03 核验会话、人员用途与字段授权。选用 M02 地区时在同一事务读取地区授权及来源。

按 504 的万名人员、一及二十会话、每组二百次条件比较详情和整页更正查回。单会话详情 P95 不超过 300 ms，整页办理及候选不超过 500 ms。经用户本次调整，二十会话 P95 暂放宽至 1500 ms，保留原 500 ms 比较值。候选另测同口径 HTTP P95、失败数、查询范围。基线版本的候选来自本地硬编码，没有独立 HTTP 样本。记录一次改名涉及的配置、修订和员工写入数，以及实际表索引大小。按 012 核对 1440×900、1440×540、原生 200% 的操作与滚动。[504 容量基线](../../verification/504-personal-profile-fourth-batch.md)

## 4 执行结果

本地技术验收完成。实施交付了 M01 地址类型目录、按权限查询及保存、个人资料采用和旧档升级。证据包含多轮评审、真实 PostgreSQL 与 Chromium，以及基线和候选同机测量。当前产品条款由 [505](../../specs/m01/505-personal-profile-contract.md#m01-ac-021) 维护，固定用户入口与复查责任见[验证交接](../../verification/317-person-address-types.md#handoff)。
