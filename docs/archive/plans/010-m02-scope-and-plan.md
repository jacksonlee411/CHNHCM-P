## 1 用户目标

### 1.1 首批可办理任务

首批聚焦 **BusinessUnit（业务单元，BU）** 的后台直接维护：组织管理员从设置菜单进入 BU 列表，创建并保存资料，查看详情，登记过去、当天或未来的资料变更，更正错误，按规则改日、删除记录、停用或重新启用BU，并查询历史及变更来源。后台操作指内部管理员通过页面办理，仍须有真实 Go 命令、数据库与接口接线。

首批主入口采用“**设置 → 组织配置 → 业务单元**”，最后一项直接打开列表。“设置”和“组织配置”作为导航分组，无需各建一个过渡页面。该路径参考源包中的“设置 → 组织配置 → 业务单位”（ASSET-0002、ASSET-0133）；中文采用本项目术语“业务单元”，英文身份仍为 BusinessUnit。

首选中文、别名及适用边界统一登记在 [17 术语表](../../architecture/target/17-terminology-glossary.md)，本计划与 011 使用该口径。未来首条在服务端D尚未开始时统一显示“未生效”；[生效记录的场景说明](../../architecture/target/17-terminology-glossary.md#term-x01-dated-slice)不增加审批或持久状态。术语选用已确定，整体范围及业务规格的采纳状态仍分别登记。

[当前日期](../../architecture/target/17-terminology-glossary.md#term-x01-business-today)是服务端按业务时区计算的当天日期，本批采用 `Asia/Shanghai`，用于默认查询、办理日期说明及当前状态判断。普通列表按当天读取，详情按所选记录及其适用期间表达；生效日期表示业务事实从哪天开始适用；新建、资料变更、停用和重新启用表单统一使用“生效日期”。停用是操作类型，其生效日期就是通常所说的停用日期，不另设日期字段；页面提示“自该日起停用”。这些操作输入不改变当前日期；跨午夜重新校验，具体规则仍由 011 持有。

本批采用[操作类型、操作原因及记录处理](../../specs/m02/011-m02-business-requirements.md#m02-br-016)的区分：新建、资料变更、停用和重新启用表达真实业务变化，操作原因从 M02 固定目录选择；普通更正、改日、删除表达对已有记录的处理，继承目标最新已接受修订的原分类，不另填处理原因；系统自动记录动作、操作者、时间和前后结果。单条名称/日期/分类统一在更正记录，另按109仅两个固定启停操作一次保存；首条资料维护按107使用普通更正及按需另次新增/插入，不强制联合。取消独立“办理依据”字段，不以备注或补充说明替代；具体选项、历史保护及拒绝规则由 011 唯一维护。

用户已采纳的[018 来源追溯决策](../../adr/018-effective-records-and-source-history.md)采用方案 B：生效记录、不可变修订及确切来源版本。[012](../../specs/m02/012-m02-functional-and-interaction-design.md)固定简单列表详情和日期维护，后台历史能力不转化为多套日常版本选择器；本项采纳不扩大首批范围或提升业务完成状态。

当前已接通“设置 → 组织配置 → 业务单元”的真实创建/查询页面；当前检查见[多轮评审与复测](../../verification/018-multiround-review.md)，来源历史简化及升级见[018验证](../../verification/018-source-history-simplification.md)。[首批实施验证](../../verification/010-first-vertical-slice.md)保留当时的时钟故障结果，不再作为当前开工阻断。菜单不改变M02领域归属。当前第一批资料新增/普通更正已接线，见[第一批实施验证](../../verification/010-first-record-maintenance.md)；启停及删除已接线；T06改日已完成独立复审，原技术验证见[T06记录](../../verification/020-redate-implementation.md)，修复及独立结论见[复审记录](../../verification/020-redate-independent-review.md)；T08联合、首条补全和分类纠错已接线，分层验证及独立结论见[T08报告](../../verification/022-joint-implementation.md)，T07本版综合验收、容量和未接消费者边界见[T07记录](../../verification/010-t07-acceptance.md)。

交付后，获授权的管理员在页面直接保存，Go 校验成功后持久化到 PostgreSQL；资料按指定业务日期适用，未来记录保存成功也不会提前生效。反馈说明“已保存”及适用日期，失败保留可修正输入，刷新或重启后能查询已保存事实。未保存表单只是当前编辑状态，本批不建设持久业务草稿或审批状态。

### 1.2 入口与操作路径

当前列表按[113](../../adr/113-bu-list-community-adoption.md)和[111](111-bu-list-experience-upgrade.md)完成Community T01/T02代码及定向检查，012/013/023保持既定合同；Go/API不变，列拖动/固定取消，T03真实业务及七组条件已验，见[报告](../../verification/111-community-t03.md)，列条件继续评估。本计划原批次结果不抬升为新列表业务通过。

| 用户任务 | 操作入口与步骤 | 完成后的定位及保护 |
| --- | --- | --- |
| 新建 BU | 业务单元列表 → 新建 → 核对操作类型“新建”，填写资料、生效日期并选择操作原因 → 保存 | 打开新 BU 详情并定位首条记录；未来日期明确显示未生效 |
| 新增记录／插入记录（103/105已接线） | 当前BU详情选择位置 → 末条后新增记录／中间插入记录 → 自动带出获权资料及位置日期默认，类型固定资料变更、原因留空待选 → 修改后直接保存；无可插入日期只禁用按钮 | 选中新记录，保留列表返回上下文；AC030/TL-258—281实际参数见105，不计旧T07通过 |
| 更正资料错误 | BU 详情 → 选中记录 → 更多操作 → 更正记录 → 修改获权名称、原位置内日期或分类、核对差异 → 保存 | 不填写更正原因；保留记录身份，未编辑日期/分类保持；可按各修改面权限单项或组合更正，一次提交完整校验 |
| 删除记录 | BU 详情 → 选中非首条普通资料、停用或重新启用记录 → 删除此记录 → 查看原分类、目标及全期间影响后确认 | 允许已生效记录，首条保护；由 Go 核对依赖和版本，保存原件及删除留痕，明确停用删除可能恢复启用、重新启用删除可能延长停用的当前状态影响 |
| 修改生效日期 | BU 详情 → 选中记录 → 更多操作 → 更正记录 → 生效日期 → 核对原日期、新日期和期间影响后保存 | 允许已生效记录及首条；同一记录形成新修订，首条仍最早、完整启停及资料顺序合法；定位新日期，旧来源及原采用保持 |
| 停用 BU | BU详情选中生效后启用的末条 → 停用业务单元 → 核对操作类型“停用”，选择操作原因、生效日期 → 查看影响并确认 | 显示“停用”、生效日期及当前状态；未来停用安排不提前改变当前状态，不删除身份与历史，也不能因后续资料记录的旧启用标志而意外恢复 |
| 重新启用 BU | BU详情选中生效后停用的末条 → 重新启用业务单元 → 核对默认日期及Go范围、业务恢复原因并确认完整名称资料 → 直接保存 | 沿用身份/编码/首条，保留此前停用期间，形成独立资料快照；可多次启停，不自动恢复其他域业务 |
| 固定启停期间维护 | 详情选记录 → 插入停用与重新启用；或选相邻停用/恢复 → 删除停用与重新启用 | 两条一次保存，任一条非法均不保存，旧来源与原件保留 |
| 首条资料维护 | 首条 → 更正记录前移并改名 → 按需另次新增/插入原日期资料 | 每步独立保存；不提供保留选择，首条身份、最早及旧来源保护保持，见107 |
| 更正业务分类 | 所选记录 → 更正记录 → 展开业务分类 → 核对原/新类型和原因 → 直接保存；必要多目标另加关联项 | 首条只改CREATE内原因；非首条类型可纠错，按原/新类别分别授权；旧分类留在旧来源 |
| 取消编辑 | 当前表单 → 取消编辑 | 返回原列表或详情及所选记录；不产生业务写入，有输入时执行离开保护 |
| 查看历史与来源 | BU 详情 → 生效记录；需要追查操作时查看变更日志 | 分别解释某日事实及谁在何时做了什么；查询与写入均使用当前授权 |

详情是已有对象的办理中心。012 明确对象级操作与记录级操作的分组，依据服务端返回的可办动作展示入口，提交时仍由 Go 重检；不把所有操作合成一个含义不清的“编辑”。

列表进入详情时保留筛选、排序、页码及选中对象，返回时恢复这些条件。保存后定位实际保存记录，不能自动跳回今日记录；若对象不符合原列表筛选，返回时提示原因并提供查看入口，不静默改变筛选。详情刷新能恢复对象、记录和查询上下文，未保存输入的离开行为由 012 明确。
