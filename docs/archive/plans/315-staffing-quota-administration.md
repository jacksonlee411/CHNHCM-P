# CHNHCM-315 部门与岗位编制后台实施计划

## 1 交付目标

本计划实施 CHNHCM-313 的后台阶段。**第一步独立交付岗位核编和按部门的获权汇总，第二步交付部门总额与多岗调剂。** 第一步通过第 4 节对应验收即可交付。这次修订替代原计划“两步完成后统一签收”的交付安排。部门上限和按日分配仍遵循同一份业务合同。[313 核编口径](../../specs/m03/313-position-capacity-contract.md#m03-br-025) · [部门分配规则](../../specs/m03/313-position-capacity-contract.md#m03-br-040) · [原方案复核](../../verification/315-staffing-quota-administration-review.md)

编制管理员从「设置 → 职务配置 → 岗位」找到已有岗位，打开“岗位编制”。首次核编填写非负整数、生效日和原因。后续从该岗位调编，或按生效记录更正原值。取消保留原定位，保存定位实际结果。HR 从「部门编制分配」按统计日期查看部门分配，可从获权统计行进入同一岗位编制页。部门详情继承统计日。岗位详情按选定的额度记录定位，返回时恢复来处的日期和筛选。[313 后台合同](../../specs/m03/313-position-capacity-contract.md) · [123 日期决策](../../adr/123-current-maintenance-and-dated-query-boundary.md) · [直接办理与历史](../../specs/m03/313-position-capacity-contract.md#m03-br-026) · [首批菜单样例](../../specs/m03/313-position-capacity-contract.md#m03-ac-072)

### 1.1 页面与 API 的四种表达

以下为后台额度的读取约定。岗位目录按服务端今日找到获权岗位，包括尚无额度根的岗位。部门统计另按所选统计日关联岗位和额度。额度是否核定、用量是否有可靠来源、经办人可读哪些字段各自判定。例如，同一岗位可同时显示“核定 0”和“用量未知”。

| 业务情形 | 正常菜单 | 编制读 API |
| --- | --- | --- |
| 未核编 | 部门统计日在首次核定前或撤去额度期间，统计行为“未核编”。岗位详情无额度记录时显示“未核编”；有权查看未来首次核定时显示该条及尚未生效提示 | 对应未核编的统计日或未核编记录，有额度读权时返回 `quotaState=unset`、`quota=null` |
| 核定为零 | 显示“已核定”、整数 0，可查看依据和历史 | 返回 `quotaState=set`、`quota=0`，并按权返回对应生效日及来源 |
| 用量未知 | 首批展示额度。需要解释余额时显示“用量未知”，平时省去尚无来源的用量列 | 对获权的用量状态返回 `usageState=unknown`。未接入或覆盖不全的预留、占编、可用数均省略。有一方可靠来源时只返回该方已确认且获权的数，完整可用数待双方覆盖 |
| 无权查看 | 对象超范围时列表不列出。对象可见而额度字段受限时显示“受限”，只可见部分岗位的部门标“可见范围” | 返回当前可读字段清单 `readFields`，并省略受限的状态、数值、原来源及可反推的合计。缺读取动作权返回 403，对象或精确来源超范围与不存在同样返回 404。受限字段不以 null 或 0 代替 |

存量岗位首次进入额度管理时仍是未核编。人员入转离、招聘预留、任职占编和共享人数上限随真实用量接入，本期后台额度维护可独立运行。[首批与后续使用来源](../../specs/m03/313-position-capacity-contract.md#1-核编范围与交付顺序)

岗位普通详情 `GET /api/v1/staffing-quotas/positions/{positionId}` 只按服务端今日、显式 `selectedRecordId` 或准确 `sourceVersion` 定位。指定日分配由 `GET /api/v1/staffing-quotas/statistics` 及其岗位下钻读取，部门调剂使用办理生效日重读目标及限额。岗位编制与部门编制的历史页签统一命名为「变更日志」。两者共用 `GET /api/v1/staffing-quotas/history/{id}/changes`，按当前读权返回不可变前后值、操作审计及来源上界。[读取协议](../../../api/openapi.yaml)

完整范围的桌面表列、窄屏摘要和明细均称「直属岗位核定合计」，部分范围显示「可见范围 · 岗位核定小计」。「未核编岗位数」以岗位个数计。部门更正及删除预览使用「部门总额」「删除后部门总额」，未设置时为「未核定」。岗位对应字段为「核定编制」「删除后核定编制」，未设置时为「未核编」。

编制详情的修订时刻标为「操作时间」，日志表头用「记录时间」。日志筛选使用列名、中文条件和选项名称。未筛选的空日志与筛选未命中分别提示。保存、无变化和删除成功分别反馈「已保存」「没有修改内容」「已删除」，查回按同一结果显示。所选记录失效和前后切换失败沿用共享详情提示。[共享详情与日志](../../specs/m02/012-m02-functional-and-interaction-design.md#m02-ui-history)

### 1.2 部门编制时间轴

部门详情复用岗位编制的生效日期条、窄屏日期菜单和键盘操作。列表保留统计日期，详情用同一个已应用日期读取整份分配。自选月末日期保留在详情和岗位下钻的返回地址中，返回列表仍恢复进入前的日期和筛选。编辑中更换办理日须按新日带入可办目标及额度，保存后定位办理日，取消回到进入表单时的位置。

Go 在同一读事务中合并部门总额记录、岗位按日直属归属和启停、岗位额度变化，同日去重。每个岗位分别核对当前与历史读权，按可见字段取日期。受限账号可读其最后一个可见岗位转出当日的小计。列表或详情查询不写额度事实。总额记录沿用原记录身份，岗位行下钻到当日适用的岗位额度记录，日志原件按既有来源版本读取。[313 部门分配合同](../../specs/m03/313-position-capacity-contract.md#m03-br-040)

部门读取接口返回 `businessAt` 表示整页已应用日，`allocationDates` 列出获权的分配节点，`defaultEffectiveDate` 给出办理默认日。显式 `selectedRecordId` 按稳定身份定位部门总额，指定 `sourceVersion` 时只读该次原件。原件与当前整部门分配分别读取，已删除的当前记录提示重新选择。[部门 API](../../../api/openapi.yaml) · [时间轴验证与 4486 交接](../../verification/315-department-quota-allocation.md#7-部门分配时间轴)

### 2.1 核编自己的写入口

| 本批拟新增 | 保存或读取的最少内容 |
| --- | --- |
| `StaffingQuota`、`QuotaRecord` | 企业、目标类型、已有岗位或部门 ID 唯一定位额度根。首次生成稳定 `quotaId`，撤去再核沿用原根。节点有稳定 `recordId`、生效日、核定整数或明确撤去。每次有效变更保存新 `sourceVersion`、节点修订、原因、操作者和记录时刻。业务日 `businessAt` 定位当时生效节点，精确来源定位原修订，岗位已采用的职务 `adoptedRef` 仍指向原件 |

### 3.1 首次核编与可靠提交

两个管理员从同一“未核编”页面给同一岗位、同一生效日分别报 2 和 3，各用自己的提交号。Go 按首次核定意图，在目标根尚不存在时也能锁定企业、目标类型和岗位 ID。锁后重读，先提交者成功，后提交者取得 409，刷新后可另作调编。换两人先后各验一次。最终只有一个额度根、一条首节点、一个成功来源和一份业务 Outbox。拒绝可留下该主体的拒绝回执。

相同主体、同号同内容重送返回原终态，同号换内容返回 409。响应丢失后用原号查回，重启后仍可按现权取回该次结果。请求从未到达时，查回封闭原号为 `not_applied`，迟到请求不产生业务写入。另一主体不能读取该回执。业务写入中断须整体回滚，提交结果暂不可确认时沿用“查看保存结果”入口。[现有提交处理](../../../internal/contexts/staffing/application/commands.go) · [AC058](../../specs/m03/313-position-capacity-contract.md#m03-ac-058) · [AC069](../../specs/m03/313-position-capacity-contract.md#m03-ac-069)

### 3.2 后续接入真实用量

**使用来源按岗位、来源方和期间确认。** 受控新岗只有在设岗日起该来源已接管全部写入，且可用设岗版本、覆盖期间和来源记录证明没有在途承诺时，才能确认该来源零使用。存量岗位以 M05 的有效预留、录用承诺与未来安排，M04 的占编及免占编任职、已确定的起止与调动为依据，各自带覆盖期间和版本。覆盖有缺口的段显示“用量未知”。M05 接入后交付该来源的招聘预留，M04 接入后交付任职占编，完整可用余额要求两方均覆盖同一期间。纯后台阶段的存量岗可依额度与分配调减，分配数、空表或人工填零均不能充当后续用量依据。[AC095](../../specs/m03/313-position-capacity-contract.md#m03-ac-095)

原岗位核 1，原定 2027-04-01 增至 2。将增额推至 2027-04-20 会使低额度覆盖 2027-04-01 至 2027-04-19。首批需校验该段额度的隐式写权及适用的分配上限。真实用量已接管后，若四月用量未知，收紧请求返回 409。若已知 2027-04-10 至 2027-04-14 有两份占编，提示首个冲突日 2027-04-10，原日与独立后继均保留。只有一份免占编任职且无其他使用时可减至 0，停岗则仍须待该任职结束或另行安排。[AC067](../../specs/m03/313-position-capacity-contract.md#m03-ac-067) · [AC095](../../specs/m03/313-position-capacity-contract.md#m03-ac-095)

最后一个常规名额同时由招聘预留和直接入职争用时，有招聘份额的命令先取份额守卫，双方共用企业与岗位的稳定守卫，锁后重读额度、份额绑定、预留、任职及全部受影响期间。先预留则直接入职拒绝，原预留仍有效且无新增任职。先入职则保留其占编，招聘原需求仍在且未取得预留。每次只提交成功方的业务事实与 Outbox。由 M03、M05、M04 用两条数据库连接交换先后联验。[共同事务合同](../../architecture/target/10-ddd-and-state-contracts.md#staffing-quota-transaction) · [313 使用合同](../../specs/m03/313-position-capacity-contract.md#m03-br-027)
