# CHNHCM-510 人员页面二十项问题整改与验收

本计划接续 500-UI-01 至 20。正常入口统一称「人员」。经办人从人员目录识别本人和获权任职，在本人详情直接进入职务信息。首聘、更正、再聘、合同和招聘录用保持各自的办理资格。初始产品为 `b67cb72`，两份调查及 62 张登记截图已提交于 `b5dfbc6`。[首轮登记](../../verification/500-personnel-page-review.md) · [补充登记与修订口径](../../verification/500-personnel-entry-and-date-review.md) · [治理登记](../../governance/registry.json)

## 1 页面和查询合同

保留部门树及按任职识别主兼岗的能力。一个人员菜单、一张表、一个入口地址。Go 在一次获权查询中按姓名或现旧编号检索。每份获权的在任雇用记录一行，仅有未来首期时显示首条并标明「尚未生效」。已离任且没有未来或当前任职、未入职或没有任职披露权的人，在 M01 名录权允许时按人列一行，只显示获权资料。该行不推断任职状态。人员数按人去重，任职数只计实际呈现的任职行，页面行数供分页。选择部门或主兼岗后仅列匹配的获权任职，条件、排序、前后导航和计数均在分页前按同一集合确定。登记权、名录权、详情权、办理权独立判断。

普通入口使用服务端今日。详情默认服务端决定的适用节点或未来首条。办理生效日、真实动作、旧修订及采用来源继续按各自身份读取。跨员工办理的期间和部门编制统计日留在各自专项。依据 123 修订首轮 05 的验收口径。402、500、502、506、507 中双入口、档案中转、普通列表日和相关验收步骤在方案通过后同步修正。[012 页面](../../specs/m02/012-m02-functional-and-interaction-design.md#m02-ui-expression) · [121 接入](../../specs/m02/121-dated-object-admission-matrix.md) · [123 日期边界](../../adr/123-current-maintenance-and-dated-query-boundary.md) · [507 页签](../../specs/m04/507-job-information-tab.md#job-tab-layout)

普通页面使用一个当前名录接口，接收查询引用、部门、主兼岗、排序、分页与行锚点。现有按日任职查询供 506 的明确业务计数，两者复用获权集合计算。M01 提供专用于名录的同事务身份集合，保留保留期、字段权限、会话内旧号搜索与到期语义。识别指定候选的端口继续只接受明确的候选。M04 先按任职实际期间的部门、用人单位逐份核权。以人和雇用记录号分组后取今日有效或最早可披露的未来任期，排除已撤销起任。单纯人员行以人员标识、任职行以任职标识作为行锚点，服务端对两类目标分别给出前后项。部门或主兼筛选不会把隐去的任职重新变成人员行。

本人办理历史覆盖该人当前获权的各笔办理，包括关系级办理。进入时保留任职来源作为返回位置，页面明示「本人办理历史」及获权姓名、编号，每行标明自身的业务对象。即使没有可读任期，只要 Go 返回可查看的原办理，个人资料仍提供本人办理历史入口。仅有某一笔原件访问权时依该笔授权读回，不能由此推断其他任职或计数。沿用已撤销未来首聘的原验收样本，从普通菜单核对原件和返回。首聘、再聘各自按办理资格从本人详情进入。未获本人目录读取权而单独持有原件访问权者，只从已授权的办理来源回到该笔原件。

## 3 评审、验证和环境交付

[方案评审记录](../../verification/510-personnel-page-remediation-review.md)载明首轮修改与两组复审结论。先核对 A 的查询粒度、授权、搜索、未来/零行及历史查回，再评审 B–E 的路由、来源与表单。评审修订后的同一份方案通过，方开始产品实施。涉及 Go 查询及公开协议时同步生成客户端，在隔离数据库验证只见兼岗、撤权、旧编号、分页及未来再聘。同一批次对照上述 20 个编号更新实际入口的浏览器用例，替换依赖双名录与手填查看日的旧前置，保留领域动作和确切来源的断言。

统一查询沿用 [501-AC-010](../../specs/m01/501-person-registration-requirements.md#m01-ac-010) 和 [503 容量合同](../../specs/m01/503-person-registration-design.md#m01-capacity)。真实 HTTP 一万名合成人员，独立复算全范围、受限同名末页、旧号命中和各类锚点。1 与 20 会话各预热 20 次、每组计时 200 次，六条链路共 2400 次。单会话名录及当前详情 P95 ≤300ms、旧来源及更正 ≤500ms，20 会话各项 ≤500ms，记录意外错误数及所有超标组。

在一次性环境完成业务写入、取消、冲突与查回。覆盖五种 100% 视口及键盘、原生 200% 的首聘或更正和历史返回，根据本批改动复查原 400% 只读明细。按影响运行 docs、boundaries、check、integration、smoke，保存逐项首败和复验。候选通过后按 003 保全固定 f 现有库和运行资产、更新 4386，从正常菜单按原样本截图并交接。独立补验记录列出二十项结果、版本、角色及证据。实施与原库实测完成后提交，经办人验收环境继续保留。[003 验收环境](../../adr/003-implementation-stages.md#acceptance-environment-update) · [固定 f 交接](../../verification/509-t04-remediation-implementation.md#fixed-environment)
