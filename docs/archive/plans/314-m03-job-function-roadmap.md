# CHNHCM-314 M03 职类实施批次路线图

本计划承接 308 第 14 节，由 Staffing 交付企业级职类目录和职务的双维分类。308 持有业务规则和验收预期，314 持有任务顺序、责任、证据及分批交接。[职类合同](../../specs/m03/308-job-foundation-contract.md#m03-job-function) · [登记表](../../governance/registry.json)

## 1 业务目标与依赖

职务管理员从「设置 → 职务配置 → 职类」建立管理类、专业类，再从「设置 → 职务配置 → 职务」给职务各选一个同企业职类和一个职务系列。人力资源经理与财务经理同属管理类，人力资源经理与人力资源专员同属人力资源系列。查询者按任一维或两维交集查找，获导出权后可导出固定选择。两维各有稳定身份和采用来源，管理员按真实生效日变更其中一维。[分类样本](../../specs/m03/308-job-foundation-contract.md#m03-br-030) · [来源资产及合同评审](../../verification/308-job-function-contract-review.md)

307 已交付职务系列和职务，309 已交付职级、阶梯和职务可用职级，311 已分别签收岗位和岗位层级。职类使用既有企业、系列、职务及已采用职务的岗位作回归。M02 提供企业身份与日期下界，企业后移起日时通过 Staffing 公开端口读取最早首条。X03 判定动作、范围及字段权。313 首批按部门、岗位维护整数编制，两批可按任一顺序交付。独立的编制开发与签收见[315 部门与岗位编制后台实施计划](315-staffing-quota-administration.md)。招聘预留、任职占编和按职类统计实际人数由真实业务接续。[307 交付](../../verification/307-m03-job-foundation-implementation.md) · [309 交接](309-m03-grade-ladder.md) · [311 签收](311-m03-positions.md) · [313 分批](../../specs/m03/313-position-capacity-contract.md)

## 3 实施中需要一起改的地方

**升级与历史。** 切换时在同一写入边界固定已提交的 Job、sourceVersion、recordId、revision，以此识别可继承的未登记旧资料，覆盖当前头、未来节点及已删除记录的原件。只改文字或原未登记的启用记录纯改日，可保有原依据。补登到原记录须有覆盖原日的业务依据，后来确定的归类从真实生效日新增。新建含追溯新建、新增启用资料、新恢复均须具备合格职类。缺少旧依据或采用残缺按数据错误处理。迁移本身产生的业务修订数应为零。[旧记录与原采用](../../specs/m03/308-job-foundation-contract.md#m03-br-031) · [现有来源、回执与固定选择表](../../../db/migrations/00017_staffing.sql)

在 T03 的升级演练中，先排空旧写入，等在途事务提交或回滚，由 upgrader 固定旧来源集合、切换存储合同，再开放使用新规则的匹配版本。迁移中断时保持同一写入边界并重试。分别检查切换前提交、回滚和切换后追溯新建，只有已提交的旧原件可作为未登记依据。用源和修订清单核对原采用、日志、回执及 Outbox，重建读索引前后应得同一业务结果。[存储准入](../../../internal/bootstrap/runtime.go) · [读索引重建](../../../internal/contexts/staffing/infra/postgres/rebuild.go)

**提交结果。** 现有 HTTP 先检查请求形状，应用才在提交锁内查终态。旧客户端原样重送缺少职类的已成功请求，须能通过传输层，按原实例、主体、类型、提交号和原摘要查回，并按现权裁剪。新提交号进入 Go 新规则，缺类才报字段错误，同号异载荷仍冲突。AC093 须分别走原写入 URL 和结果查回 URL。[HTTP 入口](../../../internal/bootstrap/staffing.go) · [终态和事务](../../../internal/contexts/staffing/application/commands.go)

**按日引用与竞争。** Job 对两维分别保存采用日、来源版本、记录及修订。换类保留系列原采用。已登记启用记录改日时依最终日重新采用，停用继承最终前序。各动作均核对受影响启用段的资格，包括未来和开放尾段。沿既有提交身份和必要企业守卫的锁序，在 Family 与 Grade 之间按 ID 排序取 JobFunction 守卫。Job 共享锁定原、新时间线涉及的职类，职类收窄资格时排他重查受影响的现行 Job 启用段。反查沿该职类守卫读取，避免再取 Job 写锁。锁内按 READ COMMITTED 重读，集合变动按原预算回滚重规划。业务事实、准确来源、终态和本域 Outbox 同笔提交。[写入与反向保护](../../specs/m03/308-job-foundation-contract.md#m03-br-033) · [企业反向端口](../../../internal/contexts/staffing/infra/postgres/store.go)

**候选、权限与正常入口。** 职类页 `/settings/staffing/job-functions` 参照已交付的职务系列页。新资源为 `/api/v1/job-functions`，职务增加 `POST /api/v1/jobs/function-reference-context`。两项候选共用 Go 日期轴试算，分别核对本维度的引用覆盖和读权。新建时两维均无默认，每个候选按本维的日期、拟动作、底稿、覆盖段及权限查询，固定恢复端使用自己的拟日期。保存再核整份职务。X03 分别授权 `jobfunction` 和 Job 两个分类字段，普通标签按业务日、准确旧标签按封存采用和现有权限读取。[菜单与权限](../../specs/m03/308-job-foundation-contract.md#m03-br-032) · [候选实现](../../../internal/contexts/staffing/application/reads.go) · [授权目录](../../../internal/contexts/access/infra/postgres/staffing.go)

**筛选与固定选择。** 桌面表头和窄屏菜单均逐维应用、取消、清除。职类 ID 与 `jobFunctionMissing=true` 互斥，两者各可与系列取交集。首次应用分类条件替换普通列条件，反向切换也替换，关键词沿用。已应用条件失权时提示并拒绝执行，由用户移除后再查。列表、匹配数、前后导航、返回 URL 和固定选择共用同一获权查询。升级重导在同一会话、同一业务日及草稿有效期内用原选择和修订，核对原入选和已排除成员。新增匹配职务也不得混入。[列表](../../../apps/web/src/features/staffing/List.tsx) · [查询与返回 URL](../../../apps/web/src/features/staffing/api.ts) · [固定选择和导出](../../../internal/contexts/staffing/application/selection.go)
