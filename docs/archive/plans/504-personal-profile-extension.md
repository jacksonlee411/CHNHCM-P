# CHNHCM-504 M01 个人资料扩展实施方案

## 1 目标与范围

人事从「人员 → 员工 → 个人资料」为已登记的一个人维护九栏资料。经办人可以先录一名无任职人员的紧急联系人，日后在原档补录教育经历或银行账户。两次办理沿用同一人员编号。一人有多份任职时共用一份资料。只读者按各自人员范围和字段授权查看。[九栏字段及操作](../../specs/m01/505-personal-profile-contract.md#profile-nine-sections) · [500 总路线图](500-personnel-roadmap.md) · [登记表](../../governance/registry.json)

| 交付内容 | 栏目或操作 |
| --- | --- |
| 两组单值资料 | 基本信息、健康信息 |
| 七组多条资料 | 身份证件、地址、联系方式、家庭成员与紧急联系人、教育经历、专业技术职称、职业资格与技能等级证书（同一栏）、银行账户 |
| 用户排除的操作 | 「查看个人信息变更」「导出个人资料」，包括相应入口、差异查询及导出下载服务 |

504 是 T01 后独立的 M01 产品计划，可与 T02 入职规格并行。T01 已有人员编号、姓名、一份现用主要证件、多条电话和邮箱、按权更正与办理查回。扩展从这份原档开始，每一栏只维护一份权威资料。T02/T03 按用工场景确定实际入职所需项。T04 有真实兼岗后再联验任职间共享，T05 人员合同、T06 招聘交接各按 500 办理。[T01 业务范围](../../specs/m01/501-person-registration-requirements.md#m01-fields) · [T01 本地交付](../../verification/500-personnel-registration-trial.md)

## 3 实施顺序与责任

每批交付该组可用的 Go 命令和授权、真实存储、OpenAPI 及生成客户端、实际页面和对应验收。第一批三栏和第二批两栏已交付。[首批实测与验收地址](../../verification/504-personal-profile-first-batch.md) · [第二批实测与验收地址](../../verification/504-personal-profile-second-batch.md)

七类弹框的 CubeBox 参考布局已定稿，可以直接实施。各批从正常菜单验本批栏目的查看、新增、编辑，第四批汇总已通过的 21 个组合并复验受后续修改影响的部分。[弹框布局验收](../../specs/m01/505-personal-profile-contract.md#m01-ac-020)

| 顺序与负责人 | 前置、工作与交付结果 |
| --- | --- |
| 第一批　基本信息、身份证件、联系方式。Personnel、Access、存储与体验 | 在原人员详情与更正命令上接入本批字段、授权和整页保存。已登记人员可补录多证件、指定至多一份现用主要证件，电话和邮箱按渠道指定主要项。旧档继续可读，仅凭姓名仍可登记。验 011、012、016–018 的本批部分及 020 的六个弹框组合。后续栏目的存储、权限和目录随相应批次接入。 |

## 4 技术依赖与旧档升级

- **事实归属。** Personnel 负责个人资料、联系人关系和个人账户身份。X03 负责权限与用途政策，M02 负责其目录事实。跨域经公开端口由组合根接线，数据库查询在表所属上下文。M01 的各个根在同一客户内完成必要的整页事务。健康资料及账户资料不能随普通名录读取。M14 支付分配及 M16 岗位资格沿各自既有合同。[领域归属](../../architecture/contexts.json) · [目录边界](../../architecture/004-repository-layout.md) · [505 授权与条目](../../specs/m01/505-personal-profile-contract.md#profile-items-and-access)
- **迁移前置。** 原交接发现人员旧库与主线在 00026、00027 同号异构，当时另有 00028 在途。第一批写 SQL 前核对实际编号及表结构，通过统一 upgrader 验证空库安装、主线同号库与人员 00026、00027 旧库副本的前向升级、失败回滚及重试。后续有新迁移时验本批前版的升级，改到旧路径的识别或转换时再复验相应旧库。[已知旧库及持久环境](../../verification/500-personnel-registration-trial.md#personnel-4380-update) · [005 迁移协作](../../governance/005-branches-and-documents.md)
- **旧事实对账。** 用同一组升级断言按原标识比对现/旧编号、证件占用、联系项、登记单、修订、原件、办理终态、Outbox 和主线原岗位事实。旧档新增字段为空，按升级前现状迁入零或一份主要证件，历次换证的旧值仍按原来源和当前权限可读。验证重启后可查原办理，旧材料权仍按原范围生效，备份恢复沿用已生效的处置。差异可定位到具体记录。[503 事务和保留](../../specs/m01/503-person-registration-design.md#m01-recovery)
- **落点。** 扩展现有 Personnel 公开服务、所属域 Go、SQL/sqlc 与 OpenAPI，复用 `apps/web/src/features/personnel`。Go 核对业务规则、输入、授权和幂等，前端负责草稿与输入辅助。仅采纳原型的字段与体验，开发和验收使用本仓资产及合成数据。[服务入口](../../../internal/contexts/personnel/public/service.go) · [现有迁移](../../../db/migrations/00030_person_primary_document.sql)

## 5 验收与交接

1. **业务与数据。** 从仅姓名的人员和原 T01 旧档起办，各批用真实 PostgreSQL/API 验本次新增的资料项和写入规则。复用现有人员用例覆盖主要号排他、版本冲突、撤权、到期及幂等查回，新增写路径须实测。例如甲把乙占用的号码设为主要证件，同笔修改的电话也须保持原值。共用事务或恢复逻辑发生变化时复验相应的并发、回滚或恢复场景。[已有 DB/API 用例](../../../tests/integration/personnel_test.go)
2. **正常菜单。** 经办人、只读者按 012、502 检查页面、视口、原生缩放与键盘可达性，受限主体核对字段权限。弹框的逐栏字段与共用布局分别按 505 的 020 验收。多任职共享在 T04 具备真实主岗和兼岗时联验。[012 视口](../../specs/m02/012-m02-functional-and-interaction-design.md#m02-ui-viewport-matrix) · [020 弹框验收](../../specs/m01/505-personal-profile-contract.md#m01-ac-020)
3. **交付证据。** 按 137 运行受影响的文档、领域、真实库/API 与浏览器检查。一份批次交接写明受测版本、实际范围、结果及未测项，有失败时记首错和复验。基线引用已有 Git 版本和仓内数据，通过项直接链接测试输出或 CI 结果。出现布局差异或需要人工判断时再附相关截图、尺寸或日志片段。[137 分层验证](../../governance/137-actions-and-validation.md)
4. **手工验收。** 通过后按 003 更新本工作树负责的环境。更新前备份原构建及相关数据，有迁移时在匹配该环境的旧库副本上验证升级。从用户实际地址按相应角色复查，交接地址、版本和结果。临时资源按原责任回收。[003 交付与资源规则](../../adr/003-implementation-stages.md#acceptance-environment-update)

第四批九栏齐备后做一次完整详情及整页更正至读回的容量联验。沿用 503 的万人底库和 1/20 会话口径，20 份合成档案各有七栏各两条及两组单值，用预置样本直接断言读回结果和授权范围。每条链路每档 200 次，记录 P95 及错误数。目标为详情单会话 300ms、更正并读回单会话 500ms、20 会话各 500ms。前面批次按实际性能影响复测相应链路。[503 测量定义](../../specs/m01/503-person-registration-design.md#m01-capacity)
