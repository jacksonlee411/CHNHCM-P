# CHNHCM-139 岗位列表、岗位关系与结构视图实施方案

登记：[文档登记表](../../governance/registry.json)。对象：设置下的岗位维护。上游：[311原交付](311-m03-positions.md)、[312岗位及层级合同](../../specs/m03/312-position-contract.md)、[M03领域边界](../../architecture/target/modules/m03.md)。2026-11-21 按[现行岗位关系合同](../../specs/m03/312-position-contract.md#31-管理汇报的唯一入口)更新实施与验收口径。

## 1 用户目标与基线

HR只从「设置 → 职务配置 → 岗位」进入：**按部门找岗位，在岗位详情调上级，看整条汇报链时从列表「更多操作 → 查看岗位上下级」进入。** 合并菜单，不把岗位间的汇报关系变成岗位基本资料字段，不为一条关系另设“列表 → 对象详情”。

在本次讨论前段，曾从固定4390的真实菜单走查：岗位列表无部门树，详情只有基本资料和变更日志；层级是缩进清单，进入维护后须重选岗位。改选子岗位会丢失拟选上级；从2027-04-01进入、只将拟生效日改为2027-05-01再取消，浏览日也变成了后者；返回页面还会重置用途。此次编制用[页面源码](../../../apps/web/src/features/staffing/Hierarchy.tsx)复核，不把前次走查记为新方案验收。

311交付时的312第3、4节及[原签收单](../../verification/311-position-hierarchy-signoff.md)以独立层级菜单办理。139只改变后续产品的入口、查询与反馈；实施时显式修订312对应条款。旧版本、历史证据和AC053—055的领域预期不被替代，不重开311。

该日没有有效岗位时说明可换日期，不开放没有办理对象的编辑器；有可读岗位但尚未设上级则正常列出真实岗位。搜索无匹配可清除搜索，与读取失败需重试分别反馈。

### 2.1 一次调整

例如，上海销售专员岗A当前向上海销售经理岗B汇报。HR在A的详情从「更多操作 → 调整上级」进入，直接办理该岗位的管理上级调整。直接显示拟定日期上的原上级、可改的**生效日期、新上级**。从今天办理默认今天，从明确的当前结构业务日办理带入该日；不套用首次建岗的1900默认。明确选“不设上级”才解除已有关系，清空搜索词不是撤销关系。

例如改为华东销售经理岗C，日期2027-04-01：沿用[岗位表单按钮](../../../apps/web/src/features/staffing/Editor.tsx)，顶部控制区主按钮「保存」、次按钮「取消」。只需保存一次；成功后回到A及该日的关系，提示“已保存，2027-04-01 起生效”。2027-03-31仍为B，到生效日不用再发布。已有独立后续安排不被覆盖；更正已登记的安排以显式保存新结果办理，不改旧版。解除关系不删除岗位，不改所属部门或在岗人员的实际经理。

### 2.2 取消、冲突和返回

分开保存已应用的浏览条件和未提交的输入。未改直接取消；实际修改后取消、切岗位、后退或退出，按[共享离开保护](../../specs/m02/012-m02-functional-and-interaction-design.md#m02-ui-protection)继续编辑或放弃。取消回到原岗位、页签、结构日期和触发焦点，不沿用草稿日期。从列表返回恢复原行；从结构返回恢复原节点、展开位置和日期。恢复前重新授权，不用旧缓存填回失权资料。

子岗位是进入时选定的A，不再是可换的表单字段。日期手改（包括尚未输完）就属于真实输入；恢复全部原值可直接取消。完整合法的日期才查询该日原上级及候选，只接收本次编辑及该日期的响应；不覆盖用户已选且仍获权的上级。拟上级失效提示重选，不默认为无上级或替换成旧值；A在拟日未启用则留在A改日期。普通读失败可局部重试，归属或字段已失权则立即清除对应受限值。

返回地址只携带已应用条件、目标和必要来源标识，不传授权结论或未保存输入；只还原合法的本应用入口。展开、滚动及焦点属本标签。结构中选中真实岗位可用名称链接打开同份详情（含键盘、新标签）；不为上级引用名称另设快捷跳转或增加逐节点可打开性预判。新标签无滚动记忆时至少定位可见目标；目标已失权不显示旧名称，返回原条件而非放宽查询。

不要求手动预览、填写发布说明、输入版本号、另行审批或二次发布。有错误在原表单指出可见原因及首个冲突日；版本已变时显示新的获权现状，保留仍可用的拟改值，由HR重新决定。网络结果未知时只查回原提交，不能把离开叫作撤销，也不能再发一笔。只读者不显示写入口。

沿用现有层级提交身份和查回渠道，不另起岗位资料保存命令。发送中阻止重复保存；结果未知自动查回一次，仍未知才提供「查看保存结果」。已保存与无变化分别反馈，随后读取失败不能抹去已确认的结果；原号明确未生效或被拒后，重新核对再以新号保存。换入口或刷新仍以原实例、主体、提交号查回，不能让原待确认项因撤菜单消失。仍在编辑页按A及拟日定位；刷新后若原回执没有可证实的岗位／日期，只报获权终态并回已授权结构，不猜目标、不保存整份草稿。无权读取原结果时不展示其内容。

## 3 查询与业务责任

<a id="p139-scope"></a>
### 3.1 部门范围只用于找岗位

选部门筛的是**所属部门**，不是上级岗位。上海销售部的A可以向华东大区的C汇报；列表只列范围内获权岗位，但A的关系和新上级候选不按上海销售部裁剪。看见部门并不授予看岗位、看关系、导出或调整的权限。查询、上下条导航、页码、全选、跨页排除和CSV必须使用同一组已应用条件，不在浏览器筛当前页。仅改变树展开或关闭抽屉不清空选择；用户真正换范围或切换含子部门时回到首批结果、清除旧的固定选择。

普通岗位列表保持[服务端今日与未生效首条口径](../../specs/m03/308-job-foundation-contract.md)。部门树仅代表今日可导航的行政关系；未来或历史的汇报结构从来不以该树为准。无部门侧栏权限，保留独立获权的普通岗位列表；不能因为范围读取失败自动扩大到全部。

Go以同一服务端业务日D完成一次范围查询。树锚点必须是D日当前主体可选择的部门；默认含下级，未选锚点时该开关不可操作。岗位是否落入范围按稳定部门身份判定：启用看D日所属、停用看继承归属、未来首条看已登记的拟属；这两类仍分别标为“停用／未生效”。若该部门在D日尚不可导航，不造节点；该岗位仍可从独立获权的“全部”发现。不因今天的部门改挂而改写历史。无岗位所属部门字段读权或无范围权时，直接请求相同筛选也拒绝，不用总数、导航或CSV泄漏归属。

在岗位查询合同中加入“部门身份／是否含下级”，按**值**规范化，纳入已应用URL、Go查询及固定选择的身份；无锚点只表达“全部”，不能把失效锚点规范成全部。关键词／状态／列条件取交集。页码、页大小和排序不改变已捕获成员。范围变动重新授权、丢弃旧的迟到响应；导航在原条件下重算位置，不可见或已移出不强行把岗位塞回原页。只在岗位接入，其他Staffing对象不接受岗位专用条件。

同一范围指**捕获时**的完整匹配，不是导出时再查一次部门。捕获后可读的岗位调出仍保留，新调入不追加；排除按身份。导出时重验实际入选成员、字段、引用及导出权，使用获权的当前资料；已排除成员失权不影响其余。原锚点不再可导航时，不显示新范围结果或自动改条件；沿用固定选择的业务日、期限、修订及授权，仍合法的草稿可查回并导出，必要权失去则整笔无文件；不返回不可见身份。跨业务日或过期必须重新选择。

<a id="p139-relations"></a>
### 3.2 结构日期、历史版本与权限

结构日期回答“哪一天向谁汇报”；发布历史回答“按哪一次已登记的安排看这一天”。每个企业独立保存一条管理汇报发布版本链。历史中的节点、名称和上下级按该版封存来源读取，不能拿今日名称补齐、把不存在的旧版回退到当前，或从历史写入。业务日期按YYYY-MM-DD，记录时刻按[026](../../adr/026-date-display-and-input-format.md)显示北京时间；对HR显示的截止日是最后适用日。

从旧树点A，打开同一个岗位详情的**只读岗位关系**。带回的是结构日和层级版本；它不是岗位资料的来源号。若转看基本资料，Go从该层级封存清单解析A的准确岗位来源，并在该来源内定位**结构日适用的岗位记录**，分别复核权限；不能确定来源或无权时不展示这份资料，不悄悄打开今天的岗位。仅显式“返回当前结构”才退出旧版，保持日期和仍可读的定位；从当前详情的旧岗位原件亦不能反推当时层级版本或开放关系写入。

保留312实际授权分层：结构需要层级读取及岗位名称／生效日期／状态读权，编码另按权；非今日或明确读封存源还需岗位历史读权，指定层级版本另需层级历史读权；维护再验层级调整权。按需局部读取，不为岗位基本资料增加层级权前置。资料受限与合法无上级分开：仅返回获权事实，不把不可见父当根、不显示隐藏身份／数量，不以不完整的旧关系默认解除或允许替换。未获历史权不展示受限版本目录；换账号、失权清缓存及迟到结果。

层级的读取、历史读取、调整和岗位资料维护分别核权；同一个HR可以兼具职责，普通岗位写权不自动给调整权。Go按整个受影响期间检查同企业、两端有效、同一日单一管理上级、不自指、不成环；继续保留岗位停用的反向保护。取消、拒绝不得增加层级版本或事件；成功仅改变管理汇报关系，不改岗位资料修订。后台保留既有不可变版本、操作者、提交结果及准确历史，不设“发布员”，不引入新流程引擎。

## 5 风险与非目标

- 两棵树同屏容易被误读：岗位列表只放部门树；结构视图只画岗位。不显示人员经理、职级阶梯或部门行政上级作为替代。
- 不复制部门树的写入逻辑，不默认保存路径预判、权限继承或每节点详情可打开标记。列表／结构的真实节点是所选业务对象；分支的关联名称只作获权阅读，参见[128](../../adr/128-authorization-evidence-removal.md)。
- 不做拖拽改线、批量重组、审批、可编辑历史、通用版本工作台、维护原因必填或新增岗位容量。上线时若有新诉求另行定范围，不把它们变为单次保存的前置。

## 6 独立预期与验收

下表是本计划的产品走查样本，不是本轮测试结果。隔离库将今日D固定为2027-03-15：上海销售部S及其子部门S1、同企业另一可读部门E；A在S、B在S1、C在E，三岗自2027-01-01启用。管理汇报原版V1为A向B。每例从独立前置开始：分页例加足两页以上获权岗位；H04先安排2027-06-01转向另一个有效岗F；拒绝例另配端点停用、受限角色和独立会话。样本身份与日期由人工列定，不按被测算法反算预期。
