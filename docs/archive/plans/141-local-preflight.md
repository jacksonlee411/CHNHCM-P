# CHNHCM-141 本地预检结果与生成物核对优化计划

分支执行者在准备正式 PR 或补推时，通过 `make ci-ready` 确认当前候选实际跑过的检查。范围选择沿用 [137](../../governance/137-actions-and-validation.md#13-减少正式候选的全量启动次数)。计划身份与执行状态由[登记表](../../governance/registry.json)维护。

## 1 实施与验收

| 任务 | 交付与独立预期 | 验收方式 |
| --- | --- | --- |
| T01 标识候选与实际结果 | 记录基线、HEAD、工作树内容及未提交状态；无差异显示零项。区分用例清单、实际业务结果、失败与中断。 | 空候选、文档、限定未命中、全量分别检查；暂存、未暂存、新文件及运行中变更不能被错误归给旧版本。 |
| T02 保留每次运行 | 每次运行有独立目录，运行中可找到当前步骤，失败截图与复验可分别查回。 | 同一候选先失败再通过，检查两次结果、首错和遮罩截图；同一工作树并行分配不冲突。 |
| T03 减少生成物核对的重复读写 | 使用独立副本运行候选自己的生成器，记录准备、生成、比对和清理耗时。 | 同输入顺序对照旧实现；生成器新增、修改、删除、写回相同内容和候选含未提交编辑时，核对结果及原件保护。 |

## 2 依赖与执行次序

CI 维护者在现有 Git、Python、Go、pnpm、PostgreSQL 和 Chromium 环境上实施。先建立候选及运行记录，再衔接两个旧库测试和浏览器用例的实际结果，最后用相同生成输入测量复制与核对开销。现行检查仍由[本地入口](../../../Makefile)及[正式工作流](../../../.github/workflows/ci.yml)各自执行。

## 3 验证与交接

执行者负责真实前置回归、文档检查、静态检查及构建。保留首次失败、有限复验、同机计时和未运行范围。临时生成树、浏览器 profile 与数据库由相应入口回收，用户验收环境遵循[运行约定](../../guides/017-local-bu-development.md#local-runtime-cleanup)。本轮范围为本地设施交付。

三项措施的分层验收、首次失败、计时与收尾见[本地验证记录](../../verification/141-local-preflight.md)。
