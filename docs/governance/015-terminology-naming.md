# CHNHCM-015 术语中文命名规范

登记信息：[registry.json](registry.json)。适用范围：[17 术语表](../architecture/target/17-terminology-glossary.md)首选中文名称的新增、修订与复核。上游规则为 [014 文档管理规范](014-document-management.md)；本规范依据 2026-10-31 用户明确提出的命名原则登记。

## 1 命名原则

中文名**优先采用双字或四字，一般不超过六个字；超过四字一般为组合词汇。例外限于有明确权威来源或使用惯例的名称。**

- 双字、四字为优先选择，例如“部门”“业务单元”；不为凑字数改变业务含义或省略必要的区分。
- 超过四字时，一般应由含义明确的业务词组合而成，例如“组织架构＋版本”。组合词应能解释各部分的作用，避免把整句说明当作名称。
- 字数要求针对首选中文名称本身，英文对照、别名、词条 ID 和定义分别记录，不拼入名称凑数。

## 2 例外依据

采用不符合上述字数或结构原则的名称时，必须有明确的权威来源或既定使用惯例，并记录适用语境和保留理由。权威来源应能定位到具体机构、文件或产品文档中的名称；惯例应提供可核对的行业或业务用例，不能只写“通常如此”。

词条的 `sources` 记录依据，`source_note` 说明出处或惯例、适用范围及为何保留该名称；详细业务含义仍放在定义中。项目已使用、旧词条存在或暂时难以缩短，本身不构成例外依据。未核对的例外不能登记为已确认。

## 3 选词与维护

术语维护者先核对概念边界，再选择符合原则的中文名；需要例外时补齐依据。新增或改名均维护 [术语源数据](../architecture/target/data/terminology-glossary.json)，使用既有生成器更新 17。改名保留词条 ID、英文映射、显式锚点及必要的历史别名，相关现行文档按受影响范围同步。

本次增加原则，不批量更名，也不将既有长名称自动认定为例外。已有词条在后续维护或专项复核时按本规范评估；来源包、冻结输入与历史验证记录保留原文。命名简短不能改变领域责任、日期、版本或组织角色等既有语义。

## 4 检查与记录

人工检查中文名称的简洁性、组合词含义与例外依据；现有生成和文档检查只核验结构、引用及产物一致性，不自动判定权威性、惯例或语义正确性。维护结果按 014 保存审阅范围与验证记录，不以本规范生效推定全部存量名称已经合规。
