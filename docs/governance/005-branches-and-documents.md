001—009 与其他编号文档统一使用 014 的数字章节和审阅要求，不享有旧格式豁免。未指定具体 owner 时保留 `null`，不以号段分支代替人员指派。

## 5 远程操作与交付检查

远程地址、可见性与默认分支由登记表持有；未配置远程时不运行 fetch/push，也不把本地 refs 称为远程备份。远程创建、推送、PR、合并及同步分别以用户授权范围为准。新仓首次发布先推送 main 的初始化提交，再推送开发分支，通过 PR 集成业务实现；不得将已有远程仓库当作空仓覆盖。

[CHNHCM CI](../../.github/workflows/README.md)当前在面向 main 的 PR、main 推送和手动触发时运行。CI触发、范围、重跑、合并后验证及用量治理由[137规范](137-actions-and-validation.md)统一持有，自动节流由当前main工作流承接，首次发布接续见[136记录](../verification/136-actions-publication.md)。合并前确认 PR 最终候选对应的 quality、integration、browser 均为成功，并核对 head、base 与实际受测引用；未运行、取消、失败和未预期跳过均不算通过。公共仓库按 137 自动运行受影响的浏览器分片，正式 browser 汇总记录远程是否被要求及其实际结果。经完整差异证明某执行层不适用须由汇总明确记录，不计为测试已执行；分类失败或证据不完整时不得自行跳过实际必需检查。合并保留提交历史，本地验证或手动诊断成功不代替正式PR结果。main严格更新要求及保护保持，不因节流改变仓库可见性或降低保护。

采用一次性 runner 的全量候选，还须核对前置回归、两层计划分片和对应汇总的实际结果。宿主选择及计量见 [137 试点约定](137-actions-and-validation.md#12-全量前置回归与一次性-runner-试点)。

收到全部分支同步授权后，先 fetch 并核对每个本地和远程分支的祖先关系、已建立工作树的状态以及 stash；已检出的分支在各自工作树快进，未检出的分支在验证旧 ref 后快进。分支有独有提交、未提交工作或并发变化时保留现场并单独处理，不 reset、强推或删除固定分支。同步完成以本地和远程 main、wt-dev-a 至 wt-dev-f 的实际 SHA 为准；未创建的工作树目录可继续预留，不为同步分支额外建立工作树。日常开发不要求所有分支始终同 SHA。

修改前核对 cwd、当前分支、HEAD、工作区、未跟踪文件、stash 及登记；保护已有工作，不因号段或目录预留覆盖文件。文档交付运行 `make docs` 和 `git diff --check`；分支 ref 需要核对时运行 `python3 -B scripts/check-repository.py --check-refs`。提交、集成和同步按实际授权执行，检查通过不产生推送、PR 或部署授权。

## 6 并行开发与跨主机协作

共同基线使用经三项CI通过并合入main的提交，完整回归责任按[137第5节](137-actions-and-validation.md#5-合并后检查与完整回归)区分；各主机记录实际SHA。各分支在依赖需要或准备交付时同步main，不要求每次合并后立即同步所有开放PR；完整main回归失败先处理再继续集成。准备命令、运行环境及数据共享见[134指南](../guides/134-parallel-development-baseline.md)。登记表中的绝对路径描述本机固定工作树；其他主机使用自己的路径，不因用户名不同改写全仓路径或将本机预留状态误认为远端已经创建。每个固定分支同一时段由一个执行者负责写入；同一分支换主机须交接未推送提交和未提交工作，不以强推解决双写。

公共变更实施前，在任务或PR中记录负责分支、基线、变更合同、受影响消费者、迁移编号、验证和集成次序。公共面包括Go共用内核、授权与目录、请求/结果/提交恢复协议、数据库模型及迁移、共享前端流程和导入数据版本。直接受影响的分支先协调一致；没有依赖的功能可继续。号段不代表一个分支独占一个业务域，公共文件冲突由指定负责分支先合入，再由消费者同步。

公共合同及实现、调用方、测试和说明在同一交付中同步。Go仍是唯一业务权威，不在前端或其他分支建立第二套规则；不为开发分支保留双格式、双写或旧算法回退。数据库迁移序号全仓唯一，不沿用文档号段，新增前核对已合入及其他分支在途编号。存储结构变化须一起说明模型标识、完整性/原子性保护及空库初始化方式，不能把未证明的共享绑定方案直接接入产品。

每个工作树使用独立profile、数据库、卷、进程及依赖。同一主机避免端口冲突，其他主机不得远程共用4390开发库；持久库及旧模型需保留匹配程序。正式容量计时预约独占资源时段，期间暂停同机并行构建、测试和数据导入；普通功能CI可用独立runner并发。当前冷态保存及125其他容量P1按用户决定不阻断新功能；单对象维护已按[最新决定](../adr/132-query-and-validation-boundary.md#15-正式采用20记录场景并保留模型5)修正为20条验收场景并保留模型5，10000条专用性能退出当前待办。保护历史、授权和提交恢复的正确性仍是合并要求。

公共仓库仅分发合成组织样本。客户原件和带有组织明细的验收附件由私有原仓保管，见[134 组织来源规则](../guides/134-parallel-development-baseline.md#6-组织来源与公开范围)。
