00039 在 Staffing 追加签发版本、发布事件及入职采用。单人原单和名单行分别有跨版本唯一索引。新增的签发权由 Access 单独授予，原入职授权及个人回执原样保留。公共运行时要求连续 00001—00039。[任用决定合同](../../docs/specs/m04/403-hire-technical-contract.md#appointment-original)

## 银行账户和健康摘要（00040）

00039 沿用任用决定。00040 为既有人员资料增加银行账户身份、同人同银行规范账号及主要标记约束，并增加客户级银行与健康用途。既有角色通过显式授予使用新字段。统一 upgrader 从连续 00038 或 00039 升级，API 和 Worker 要求连续 00001—00040。[第四批验收](../../docs/verification/504-personal-profile-fourth-batch.md)

## 雇用记录编号（00041）

统一 upgrader 将旧首任职关联到本人永久 0 号，覆盖未来已撤销的首单。已发编号在原任用撤销后仍保留。同一客户内由人员身份与编号共同定位履历，每段任职明确关联本人、工作关系及雇用记录。API 和 Worker 要求连续 00001—00041。[职务信息读写合同](../../docs/specs/m04/403-hire-technical-contract.md#job-information-handoff)

## 任职日状态与办理修订（00042）

既有入职与撤销分别成为可读取的来源。完整保留首次办理身份、登记时刻、采用资料及原修订，原回执和事件绑定当次准确修订。当前来源在撤销后保留原件，日状态为空。每个来源在发布前写入成员和非重叠日期段；同一任职允许多笔数据更改，更正沿用原办理身份。API 和 Worker 要求连续 00001—00042。地点维护和跨人任职查询在显式启用合成经办样本时一次性授权，重复初始化保留撤权结果。[职务信息业务规则](../../docs/specs/m04/506-job-information-records.md)

## 逐份授予（00058）

00058 接续公共 00057，逐份保留主体、动作、范围和字段，沿用 00032 入职规则与 00049 岗位补员约束。API 和 Worker 要求连续 00001—00058。

## 个人资料地址类型（00061）

本分支当前账本为 00001 至 00058 加 00061。00059、00060 已由 wt-dev-c 的薪酬等级费率与薪酬方案占用，合入对应实现时再核对完整账本与实物。实例内的四个预置项各有初始修订。升级保护旧地址的原文和空采用，首次创建的客户实例由初始化器建立相同目录。此后只向本次新选的地址写确切采用。配置改名仅更新该项和追加修订。配置修订兼作成功提交的回执，查回先于提交时用单独标记阻止迟到写入。[505 地址类型](../../docs/specs/m01/505-personal-profile-contract.md#profile-address-types)
